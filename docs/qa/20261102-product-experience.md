## 설정·적용 방법과 남은 의존성

1. 일반 배포 절차에서 `lib/db/migrations/0057_player_experience.sql` 적용 필요. 이번 작업에서는 운영 DB에 실행하지 않았다. 두 신규 테이블은 RLS 활성화, 공개 접근 정책 없음.
2. 메일 복구는 `RESEND_API_KEY`, 검증된 발신 주소 `PASSWORD_RESET_FROM`, HTTPS 사이트 주소 `PUBLIC_APP_URL` 필요. 미설정 시 서비스 준비 중임을 안내한다. 실제 메일 발송·수신 성공은 미검증. 유료 구매 없음.
3. 프록시 뒤 운영 시 실제 인프라에 맞춰 `TRUST_PROXY_HOPS` 설정 필요. 무조건 전달 헤더를 신뢰하도록 바꾸지 않았다. 제한기는 현재 프로세스 단위여서 다중 인스턴스의 공통 제한 저장소는 별도 작업이다.
4. 중복 전환 기본값: 이모티콘 50, 선수 스킨 100, 챔피언 스킨 200 **일반 프리즘**. `COSMETIC_DUPLICATE_IMAGE_EMOTE`, `COSMETIC_DUPLICATE_SKIN`, `COSMETIC_DUPLICATE_CHAMPION_SKIN`으로 조절 가능(1~100000). 기존 뽑기 확률·가격·카드/챔피언 중복 정책은 그대로다. 과거 중복을 소급 보상하는 작업은 하지 않았다.
5. 메뉴의 설정에서 화면/소리/계정을 선택한다. 연출 프리셋은 기존 기기 설정에 저장하며 전투 판정에는 영향이 없다.
6. 현재 기록 동기화는 계정별 유저 기록이다. 공식 전적 검증이나 랭크 점수에 사용하지 않는다. 이미 사이트 데이터를 지워 잃은 기록을 복구할 수는 없다.
7. 실기기 Android/iOS/Safari 장기 플레이·실제 운영 PvP/재접속·메일 수신·모바일 GPU/FPS·실제 매칭 대기시간·신규 유저 사용성/피로도는 이번에 통과했다고 주장하지 않는다. 호스팅 콜드 스타트를 코드만으로 제거했다고도 주장하지 않는다.
8. 운영 배포와 main 병합은 하지 않았다. 기존 카드/챔피언 데이터·판정·스킨 소유 규칙은 변경하지 않았다. 새 기능의 운영 동작에는 마이그레이션과 구성 후 별도 확인이 필요하다.
