# 헬퍼: 선수 또는 챔피언 회복 조건

사용자 요청으로 현재 헬퍼의 턴 시작 조건을 ‘지난 자기 턴에 아군 선수와 챔피언이 모두 실제 회복’에서 **‘둘 중 하나라도 실제 회복’**으로 변경했다. 등장 시 냥냥 펀치 1장 생성, 지난 자기 턴을 검사하는 시점, 다음 턴 시작에 1회 생성, 비용과 스탯은 유지한다.

## 구현

- 기존 `ownTurnHealing`의 실제 회복 기록을 재사용한다. 새로운 회복 추정이나 단순 체력 변화 감지는 추가하지 않았다.
- `PREVIOUS_OWN_TURN_ANY_HEALED` 조건을 추가했다. 기존 BOTH 조건의 의미는 그대로 유지해 다른 카드/이전 정의에 영향이 없게 했다.
- 정확한 헬퍼 ID와 검토된 현재 문구에만 새 조건을 적용한다. 알 수 없는 이후 관리자 변경, 직접 설정한 별도 효과, 과거의 초과 회복량 조건을 일괄 덮어쓰지 않는다.
- 공개 카드 설명과 실제 대전 정의를 ‘아군 선수 카드나 아군 챔피언 중 하나라도’로 일치시켰다. 운영 카드 DB에 직접 쓰거나 관리자 기록을 수정하지 않았다. 저장된 현재 문구에 대한 호환 처리는 서버와 클라이언트의 공통 변환기를 사용한다.
- 이미 시작된 대전의 저장된 카드 능력을 중간에 바꾸지 않는다. 새 대전의 최신 카드 정의부터 적용된다.

## 검증

- 운영 공개 API를 읽어 실제 헬퍼의 ID·현재 설명·효과 설정을 확인했다. [변경 전 공개 정의](live-before.json).
- 전용 실제 엔진 테스트 **13개 통과**: 챔피언만/선수만/둘 다 회복, 미회복, 최대 체력에서 회복 시도, 회복 0, 상대만 회복, 상대 턴 회복, 헬퍼 자신의 회복, 침묵/능력 비활성, 과거 기록 없는 저장 상태, 문구 및 기존 BOTH 의미 보존, 알 수 없는 이후 정의 보호.
- 대상 선택 뒤 실제 HEAL 처리와 두 번의 END_TURN을 실행해 다음 자기 턴 생성량을 검사했다. 상태 JSON 저장/복원 뒤에도 확인했다. 둘 다 회복해도 추가 냥냥 펀치는 1장이고, 이후 회복하지 않은 다음 자기 턴에는 과거 회복으로 반복 발동하지 않는다.
- 공통 전투 엔진 회귀 **1,031개 통과**.
- 기존 관리자 카드 QA의 헬퍼 관련 **5개 통과**. 선수만/챔피언만 회복의 기대값을 새 사용자 요청에 맞췄다.
- 전체 `pnpm build`: 타입 검사 및 API·프런트 빌드 통과.

검증은 실제 공통 엔진을 사용한다. 이번 수정에서 새 브라우저 플레이 검증이나 실제 운영 유저 매치 조작은 하지 않았다. 공개 API와 배포 버전은 배포 후 별도로 확인한다.

## 변경 파일

- `game/cards/helper-healing.ts`: 정확한 현재 헬퍼 정의와 공개 문구 호환.
- `game/cards/published-cards.ts`: 공통 런타임 연결.
- `game/effects/types.ts`, `game/effects/effect-engine.ts`: ANY 조건.
- `api-server/src/routes/cards.ts`: 공개 문구 일치.
- `lib/game-engine/src/index.ts`, `lib/game-engine/tsconfig.json`: 서버/클라이언트 공통 등록.
- `game/engine/helper-either-healing.test.ts`: 새 검증.
- `game/qa/latest-admin-revisions-20261014.test.ts`: 헬퍼 기대값 수정.

별도 브랜치에서 작업하며 main 병합은 하지 않는다. 배포는 production 브랜치 및 외부 승인 SHA 검사 경로를 사용한다.
