# 기존 공개 챔피언의 신규 피니셔 연결 저장 수정

작업 브랜치: `fix/finisher-published-save`.

## 원인

앞선 연결 UI는 미공개(DRAFT) 피니셔도 고를 수 있었지만, 기존 공개(PUBLISHED) 챔피언의 저장 API는 공개 피니셔만 허용했다. 단일 카드 고장이 아니라 ‘기존 공개 챔피언 + 새로 만든 미공개 피니셔’ 전체에서 발생하는 흐름 누락이었다. 앞선 관리자 브라우저 검증은 초안 챔피언을 사용했기 때문에 이 조합을 놓쳤다. 운영 DB의 특정 카드 내용을 읽어 확인한 것은 아니며, 사용자 화면의 오류와 동일한 조합을 격리 DB에서 재현했다.

## 변경

- 기존 공개 챔피언에 미공개 피니셔를 연결하고 수정 저장하면 **피니셔 공개 후 연결 저장** 확인 화면을 표시한다. 카드 이름과 공개 대상을 보여주며, 사용자가 확인해야 해당 카드가 공개된다.
- 확인 후 카드 공개와 챔피언 연결을 **한 DB 트랜잭션**으로 처리한다. 현재 연결한 피니셔만 공개할 수 있고, 카드/챔피언 버전과 참조를 검사한다. 충돌·참조 오류는 양쪽 변경을 모두 롤백한다.
- 단일 피니셔와 복수 선택지 모두 지원한다. 동일 카드를 여러 선택지가 참조해도 공개 대상은 중복되지 않는다. 이미 공개된 피니셔는 추가 확인 없이 저장한다.
- 취소 또는 실패 시 현재 폼은 유지한다. 재시도 가능하다. 초안 챔피언을 저장할 때는 피니셔를 임의 공개하지 않는다.
- 연결 목록에 공개/미공개/비활성화 상태를 한국어로 표시한다. 단일 연결은 미공개 상태와 저장 절차를 미리 설명한다. 비활성 카드는 신규 선택을 막는다.
- 서버 오류는 선택한 카드 이름과 구체적인 원인(미공개, 비활성화, 잘못된 분류, 삭제된 참조)을 표시한다. 기존 공개 검증을 제거하거나 게임에 미공개 카드를 몰래 노출하는 방식으로 우회하지 않는다.
- 기존 카드 공개 경로의 참조 검증 및 공개 시 보정 처리를 재사용한다. 챔피언/카드 효과나 준비 조건을 새로 작성하지 않는다. DB 스키마 변경 없음.

## 실제 검증

- [엔진·HTTP 회귀 로그](tests.log): **161개 통과**, 실패 0. 신규 HTTP 6개는 재현과 공개 동의 후 저장, 복수 선택지, 카드 버전 충돌 롤백, 미공개 하위 참조 롤백, 무관한 공개 요청/비활성/분류 오류 거부, 기존 공개/초안 호환성을 검증했다. 나머지는 이전 피니셔·손패·주문·챔피언·업그레이드 및 실제 PvP 서비스 회귀다.
- [브라우저 결과](browser-results.json): 실제 관리자 라우트 + 실제 HTTP + 격리 PGlite DB. **390×844 / 844×390 / 1440×900**에서 공개 챔피언에 새 피니셔 연결, 사전 안내, 확인 취소 후 폼 유지, 명시적 공개/저장, 재진입, HAND→CAST 변경, 선택지 2개 일괄 공개/저장. JS 오류 0. 390×844에서는 확인 요청의 의도적 503 실패 → 폼·DB 보존 → 재시도도 확인했다. 다른 화면 크기에서 이 실패 주입을 반복하지는 않았다.
- 전체 타입 검사 및 API/프런트 빌드 통과. [빌드 로그](build.log).
- [모바일 확인 화면](publication-review-390.png), [PC 확인 화면](publication-review-1440.png), [복수 선택지 확인](multiple-review-390.png).

모든 데이터 쓰기 검증은 격리 DB에서 수행했다. 실기기 대신 Chromium 터치 뷰포트를 사용했다. 운영 피니셔를 자동 공개하거나 운영 DB를 수동 수정하지 않았다. 사용자가 관리자에서 확인했을 때만 실제 공개/저장이 일어난다. 운영 반영 검증은 별도 영수증에 기록한다.

## 배포 확인

소스 커밋 `8eee25afbdd35cafa63613fe49f10498ac0eb806`를 API/프런트에 배포했다. 두 서비스 live, API health·프런트 version·실제 메인/관리자 HTML의 진입 JS까지 같은 커밋임을 확인했다. 첫 읽기 전용 확인 요청은 네트워크 시간 초과였고 재시도는 통과했다. 기존 점검 상태를 유지했으며 공개 카탈로그는 점검으로 인해 별도 검사를 생략했다. 운영 대전 생성·수동 운영 DB 수정·main 병합 없음. [운영 검증 영수증](production-verification.json).
