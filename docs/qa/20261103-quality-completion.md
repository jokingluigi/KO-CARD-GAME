# 리뷰 완성도를 높이기 위한 실제 품질 패치 — 2026-11-03

이번 작업은 메타크리틱 점수를 산출하거나 80점을 입증하는 작업이 아니다. 확인한 사용성·신뢰성 결함을 실제 화면과 코드에서 수정하고, 실패 상황까지 재현해 검증했다. 기존 작업 브랜치를 유지하며 main 병합과 신규 DB 마이그레이션은 하지 않는다.

## 실제 변경

1. **응답 유실 후 카드팩 구매 복구.** 구매 전에 계정별 요청 ID와 상품·수량을 기기에 보관한다. 탭을 닫았다 다시 열어도 같은 요청으로 결과를 확인한다. 미확정 구매가 있으면 새 구매를 막고, 복구 기록을 보관하지 못하면 요청을 보내지 않는다. 서버에서 확인된 구매를 저장소 정리 실패 때문에 ‘구매 실패’로 표시하지 않는다. 보유량 새로 읽기에 실패하면 새 구매를 잠그고 읽기 재시도를 제공한다.
2. **서버 중복 처리 방지.** 기존 사용자 행의 트랜잭션 잠금과 기존 거래 원장 PK를 사용한다. 계정과 요청 키로 거래 ID를 만들기 때문에 새 테이블이나 인덱스가 필요 없다. 같은 요청은 같은 영수증으로 복구하고, 다른 상품·수량이나 계정으로 바꾸는 요청은 거절한다. 이미 완료된 구매는 판매 종료 후에도 확인할 수 있다. 가격·지급 수량·재화 정책은 유지한다. 상세 SQL 오류는 사용자에게 노출하지 않는다.
3. **대기와 실패의 명확한 구분.** 덱·컬렉션 계열 요청에 응답 본문까지 포함하는 제한 시간을 적용한다(읽기 12초, 변경 20초). 변경 요청은 자동 재전송하지 않는다. 응답을 잃으면 이미 처리됐을 가능성을 알리고 결과 확인을 안내한다. 카드팩 구매는 위의 요청 ID로 복구한다. 이 보장은 모든 종류의 변경 요청에 서버 중복 방지를 추가했다는 뜻은 아니다.
4. **거짓 로그아웃 방지.** 서버가 로그아웃을 거절했는데 화면만 로그인 화면으로 넘어가던 경로를 수정했다. 실패는 기존 화면 위의 설명창으로 안내하고 계정 메뉴에 초점을 돌려준다. 확인된 닉네임 변경은 인증 캐시에도 반영한다.
5. **기본 교환 예상 개선.** 공개 피해 오라, 실제 턴당 피해 제한, 방어·아머·회피 및 공개된 피해 보정을 반영한다. 공격 전 아군 콤보나 반응 효과가 있으면 숫자 옆에 구체적인 주의 문구를 표시한다. 보호 중인 챔피언에게 피해를 줄 수 있다고 표시하지 않는다. 숨은 손패·덱이나 난수를 사용하지 않으며, 효과를 실행해서 미래를 추측하지 않는다. 여전히 ‘기본 교환 예상’이며 실제 승패를 보장하지 않는다.
6. **팝업 위치 보정.** 예상 교환·행동 불가 안내를 실제 표시 크기로 측정해 화면 안에 배치한다. 긴 설명과 읽기 크기 변경도 반영하며, 장식 레이어가 카드 입력을 가로채지 않는다.
7. **터치 영역 일관성.** 공통 팝업 닫기, 덱 편집의 추가·목록·뒤로가기, 설정/상점의 짧은 탭, 수집 목표 링크를 보정했다. 덱 편집의 모바일 입력은 16px로 표시한다. 카드 전투의 정보 버튼을 무작정 키워 드래그 영역을 침범하는 방식은 사용하지 않는다.
8. **컬렉션 시각적 위계.** 종류와 정렬을 기존 상세 분류 안에 묶고 닫힌 제목에도 현재 선택을 표시한다. 검색과 카드가 먼저 보이게 하며 분해 가능 카드가 없으면 실행 불가능한 일괄 분해 버튼을 표시하지 않는다. 가능한 경우의 기능과 확인 절차는 유지한다.
9. **손패 읽기 일관성.** 선택 스킨과 위치 보정을 기존 전투 꾸미기 표시기로부터 가져온다. 침묵 면역과 키워드를 읽을 수 있고, 130% 읽기 설정이 참조 팝업과 규칙 설명에도 적용된다. 손패 순서가 바뀌어도 인덱스가 아닌 카드 인스턴스로 읽던 대상을 유지한다. 새 대전에서는 초기화한다.
10. **불필요한 실패 요청 감소.** 계정 기록 저장소가 준비되지 않았다는 서버 응답은 계정별 60초 동안 기억해 화면 복귀·온라인 이벤트마다 같은 실패 요청을 반복하지 않는다. 사용자의 명시적 재시도는 즉시 확인한다. 저장 위치 설명도 실제 동기화 상태를 확인하도록 수정했다. 계정 동기화/이메일 복구의 서버 준비 상태 자체를 활성화한 패치는 아니다.

## 심리학 원칙을 어떻게 사용했는가

- 인지 부하·힉의 법칙: 검색을 먼저 보이고 분류·정렬은 묶어 선택 단계를 정리했다.
- 시각적 위계·게슈탈트: 카드 이름·고유 보호·현재 수치를 인접하게 묶었다. 미확정 구매는 일반 목록과 구분한 안내에서 처리한다.
- 피츠의 법칙: 실제 클릭 가능한 영역을 검사하고 중요한 작은 컨트롤을 44px 기준으로 보정했다.
- 행동 통제감: 확정·미확정·재확인 상태를 구분하고 초점을 복원한다. 서버 결과를 잃었다고 무조건 실패로 가정하지 않는다.
- 반복 피로: 사용할 수 없는 동기화의 중복 요청과 불필요한 선택을 줄였다. 새 전투 소리·VFX를 임의로 추가하지 않았다.

이 설계가 실제 사용자의 오류율이나 만족도를 개선했다는 사용자 실험 결과는 아직 없다.

## 검증 결과

- 전체 타입 검사, API·프론트엔드 프로덕션 빌드 통과.
- 자동 테스트 **104개 통과**: 핵심·보호·세션·표시 82, 인증 16, 상점 HTTP/DB 6. 상점 테스트는 PGlite 격리 DB이며 운영 계정이나 재화를 쓰지 않았다.
- 추가로 임시 로컬 **PostgreSQL 17**에서 실제 HTTP 요청을 동시에 보냈다. 같은 키 12회 → 차감/지급 1회. 서로 다른 키 8회 → 8회 정상 처리. 총 9거래, 잔액 5,000 → 4,100, 팩 18개. 수량 변경 재시도는 409. 검사 후 임시 DB 서버를 종료했다.
- 실제 앱의 상점·컬렉션·메인·내 기록에서 390×844, 844×390, 1440×900을 검사했다. 응답 유실 → 새 탭 → 같은 구매 확인, 저장소 정리 실패, 보유량 갱신 실패, 로그아웃 거절, 초점 복원, 수동 동기화 재시도를 확인했다. API 응답과 사용자 계정은 격리된 픽스처다.
- 기존 실제 AI 진입 경로에서 같은 세 크기의 손패 읽기·선택 스킨·130% 읽기·침묵 면역의 스크롤 없는 표시를 확인했다. 손패 삽입 중 읽던 카드 유지 검사는 기존 상태 주입 하네스에서 추가했다. 테스트 스킨은 기존 QA 원화를 사용하는 픽스처이며 운영에 새 스킨을 등록하지 않았다.
- 운영 배포본의 변경 전 기본 모바일 화면 10곳을 읽기 전용으로 비교했다. 첫 화면에 보이는 44px 미만 조작 요소는 **7개 → 수정본 0개**. 수정본은 모바일 세로·가로·PC 총 30조합에서 가로 넘침·이름 없는 컨트롤·작은 표시 조작 요소·페이지 오류 0개였다. 레이블 전체로 조작 가능한 네이티브 입력은 레이블 영역을 측정했다. 화면 밖 요소나 전체 관리자 UI를 모두 측정했다는 뜻은 아니다.
- 기존 페이지/기능 검사 48조합과 비회원 실제 연습 소환 통과. 전투 예상·로그·설정 검사 6크기 통과. 모바일 드래그 중 길게 누르기 억제와 턴/초점 변경 취소 통과. 모의 온라인 통신에서 미확인 행동 1회만 전송, 읽기 재동기화, 과거 소리 재생 방지 통과. 챔피언 토큰 표시 회귀 3크기 통과.

## 남은 검증과 완료 판단

- 실제 두 계정의 장시간 PvP, 물리적인 Android/iOS의 GPU·메모리·네트워크 변동, 실제 사용자 탐색 시간·실수·피로 검사는 이번 결과에 포함되지 않는다.
- 최신 전체 SFX의 청감 평가나 전체 카드 밸런스/메타의 장기 검증을 완료했다고 주장하지 않는다. 그 분야의 등급을 올렸다는 수치도 제시하지 않는다.
- 계정 동기화·메일 복구는 별도 서버 준비가 필요하다. 이 작업에서는 신규 운영 마이그레이션을 적용하지 않았다.
- 이 패치만으로 ‘메타크리틱 80점 달성’이나 전체 게임 완료를 선언하지 않는다. 확인 가능한 결함 수정과 회귀 방지가 이번 결과다.

배포 결과는 별도 API/프론트엔드 영수증과 배포본 화면 검사로 기록한다. 운영 QA 구매·실계정 데이터 주입 없이 확인한다.

## 배포본 최종 확인

- 서버와 화면 모두 작업 브랜치 소스 `df87911780e6e320fd13a263910d7953a9ac92a6`를 수동 배포했다. main 병합은 하지 않았다. API/프론트 health 응답 200, 점검 설정은 기존 false를 유지했다.
- 배포 직후 첫 HTML 확인은 이전 엔트리를 반환했다. 이후 새 엔트리로 전환된 것을 확인하고 **136개 JS/CSS의 SHA-256이 로컬 동일 리비전 프로덕션 빌드와 전부 일치**함을 검사했다.
- 배포된 실제 프론트엔드에서 격리 API를 연결해 구매 복구·재고 읽기 실패·로그아웃 거절·필터·초점·중복 동기화 억제의 3화면 크기 검사를 다시 통과했다. 운영 구매나 로그아웃 요청을 전송하지 않았다.
- 배포된 실제 AI 진입 화면에서 3화면 크기의 손패 읽기·스킨·침묵 면역·130% 읽기를 다시 확인했다. 결과 파일의 마지막 손패 재정렬 항목은 로컬의 상태 주입 하네스 검사이며 실제 양측 PvP 검사가 아니다.
- 배포본 10경로 × 3화면 크기에서 측정 범위 내 작은 조작 요소·이름 없는 컨트롤·가로 넘침·페이지 오류는 0이었다.
