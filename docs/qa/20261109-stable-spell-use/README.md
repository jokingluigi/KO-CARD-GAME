# 주문 사용 버튼 입력 안정화

## 재현 및 원인

기존 실제 공통 대전 화면에서 주문을 선택하고 ‘사용’ 버튼에 터치를 시작한 뒤 손가락을 약 15px 이동시켰다. 버튼에서 카드 드래그 고스트가 1개 생성됐고 주문은 손패에 남았으며 상대 체력은 20으로 유지됐다. [수정 전 측정](baseline.json).

버튼의 `data-hand-drag-card-id`를 문서 캡처 단계의 카드 드래그 처리기가 특별히 드래그 시작점으로 허용하고 있었다. 버튼의 React `stopPropagation`은 이미 실행된 캡처 단계 처리를 막지 못했다. 약간의 손가락 이동이 카드 드래그로 바뀌어 클릭이 소모됐다. 버튼 자체도 손패의 스크롤·선택 표시 영역 안에 있어 안정된 조작 위치가 아니었다.

## 수정

- 주문 선택 시 ‘사용’을 손패 카드 위 대신 **중앙 턴 조작줄의 타이머 옆**에 표시한다. 턴 종료 버튼은 별도 칸에 유지한다. 손패 스크롤이나 카드 확대/정렬 애니메이션이 버튼을 움직이지 않는다.
- 버튼에서 카드 드래그를 시작하는 예외를 제거했다. 카드 몸체를 드래그해 주문을 사용하는 조작은 유지한다.
- 버튼은 최소 64×44px이다. 터치 스크롤·카드 모션에 종속되지 않는다.
- 버튼 내에서 손을 떼면 사용한다. 약간의 움직임 때문에 브라우저가 click을 생성하지 않아도 정상 처리한다. 포인터 취소, 버튼 밖에서 손을 떼기, 포커스/뷰포트 이탈은 사용하지 않는다.
- 포인터 해제와 이어지는 합성 click이 중복으로 주문을 쓰지 않도록 분리했다. 키보드·보조기기의 기본 click은 유지한다.
- 상대 턴·골드/대상 부족·진행 중인 입력/연출에는 기존 사용 가능 판정과 부모 입력 잠금을 따른다.
- 카드 효과·비용·대상 판정·게임 규칙은 변경하지 않았다.

## 실제 검증

`docs/qa/stable-spell-use-browser.mjs`에서 실제 `GameStatePreview`와 공통 엔진을 실행했다. 정적 목업이 아니다. Chromium CDP 터치로 다음 크기를 확인했다.

- 360×740, 390×844, 844×390 터치.
- 1440×900 마우스.
- 버튼 내 15px 움직임에도 고스트 없이 정확히 1회 사용, 체력 20→18, 골드 6→5.
- 7장 손패를 가로로 스크롤한 뒤에도 버튼 위치 변화 1px 미만.
- 대상 주문은 기존 사전 선택을 사용하고 대상 확정 후 실제 비용/효과 적용.
- 터치 취소·버튼 밖 해제 시 주문·골드 보존.
- 키보드 Enter 사용.
- 골드 부족/상대 턴에는 사용 버튼을 열어 사용하지 못함.
- 페이지 오류 0, 가로 화면 넘침 없음.

[브라우저 결과](browser-results.json) · [모바일 화면](mobile.png) · [PC 화면](desktop.png).

기존 `mobile-spell-drag-browser.mjs`도 360/375/390/412px 모바일 및 1440px PC에서 통과했다. 카드 몸체 드래그, 챔피언/선수 대상 드롭, 취소, 필드 밖 드롭, 손패 가로 스크롤, 기존 제한을 확인했다. 이 실행기의 오래된 대상 owner 표기 `OPPONENT`를 현재 엔진의 `ENEMY`로 정정했으며 버튼 자체 드래그는 이제 사용되지 않는다는 요구에 맞춰 기대값을 수정했다.

`pnpm build` 타입 검사 및 API·프런트 빌드 통과. 물리적 Android/iOS 기기 검증 및 운영 유저의 실제 매치 조작은 실행하지 않았다. 로컬 검사에서 계정/DB/보상 쓰기는 하지 않았다.

## 배포

운영 전용 production 브랜치에 빠른 감기 방식으로 반영하고, 승인 SHA를 고정하는 안전 배포 실행기로 배포한다. 실제 배포와 공개 버전 확인 결과는 별도 배포 확인 JSON에 기록한다. main 병합과 운영 카드 데이터 수정은 하지 않는다.

배포 완료: `694b27341bf600c373b310b1b892392ba39b5aac`를 API·프런트 모두 live 확인했다. 공개 health와 version.json이 같은 커밋을 제공하고, 실제 배포된 UI 청크에서 고정 사용 버튼 처리와 기존 버튼 드래그 표식 제거를 확인했다. [운영 확인](production-verification.json). 승인 SHA와 production 기본 브랜치 보호도 유지했다.
