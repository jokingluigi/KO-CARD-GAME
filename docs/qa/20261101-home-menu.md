# 홈 대전 모드와 관리자 메뉴 일러스트

브랜치: `feat/home-battle-mode-art`. 기존 출전 덱/챔피언 배너를 유지하고 실제 홈과 기존 관리자 미디어 화면을 확장했다. main 병합과 DB 스키마 변경 없음. QA에서는 운영 계정/DB/스토리지에 이미지를 등록하거나 설정을 쓰지 않았다.

## 실제 변경

- 큰 **대전 모드** 버튼에서 온라인·AI·드래프트를 선택한다. 온라인은 기존 빠른/친구 대전 선택으로, AI는 현재 출전 덱 시작으로, 드래프트는 기존 진입 경로로 연결한다. 이용 불가 상태는 기존 availability API를 따른다.
- 덱 편집·컬렉션·꾸미기를 바로가기 세 개로 남기고 보상·상점·기록·튜토리얼 등 기존 메뉴를 전체 메뉴 창에 넣었다. 기존 기능을 삭제하지 않았다. 홈 자체는 스크롤 없이 유지하며 긴 공지/전체 메뉴는 모달 안에서 스크롤한다.
- 대표 배경의 검은 덮개를 80%에서 24%로 줄이고 중복 배경 레이어/필터를 없앴다. 모바일도 실제 배경 이미지가 보인다. 대표 이미지는 기존 관리자 설정을 유지하고 화면 비율에 따라 cover로 크롭한다.
- 버튼 일러스트는 아직 등록하지 않아도 정상 동작한다. 이미지를 올리면 기존 실제 버튼의 오른쪽에 표시하며 텍스트와 프레임은 코드에서 유지한다. 임시 챔피언 그림을 제품 기본 버튼 그림으로 하드코딩하지 않았다.
- 선택 과정을 모드 단위로 나누어 인지 부하와 선택 부담을 줄이고, 가장 큰 터치 대상에 대전 행동을 배치했다. 이미지 위 텍스트 가독성, 선택/누름/키보드 포커스와 모션 감소를 처리했다. 사용자 만족도 개선을 실험으로 입증한 것은 아니다.

## 관리자 등록 방법

1. **관리자 → 백그라운드 관리(`/admin/media`) → 홈 메뉴 이미지 · 대전 모드**로 이동한다.
2. 캐릭터 그림을 투명 PNG 또는 WebP로 올린다. 최대 10MB. 글자/버튼 프레임을 그림에 넣지 않는 편이 배치하기 좋다.
3. **배치 화면**에서 모바일과 PC를 각각 선택해 확대·축소, 가로/세로 기준점, 좌우 반전, 전체 보기/여백 없이 채우기를 조절한다. 두 화면 설정은 독립적으로 저장된다.
4. 실제 버튼과 같은 컴포넌트의 표본 크기 미리보기를 확인하고 **홈 메뉴 저장**을 누른다. 홈으로 다시 들어가면 반영된다.
5. **등록 해제 → 저장**하면 그림 없는 버튼으로 돌아간다. 현재 저장된 메뉴에서 사용 중인 이미지는 삭제할 수 없다. 해제 저장 후 등록 이미지를 다시 선택하면 삭제 확인을 거쳐 파일/미디어 레코드를 제거할 수 있다.

설정 불러오기에 실패하면 저장을 막고 재시도를 제공한다. 업로드·저장은 중복 요청을 막는다. 응답 대기를 취소해도 서버 저장이 완료됐을 수 있음을 안내한다. 최초 상태를 읽지 못한 기본값으로 기존 설정을 덮어쓰지 않는다.

## 저장 구조와 범위

기존 `game_media`의 텍스트 mediaType과 기존 관리형 이미지 저장소를 사용한다. `HOME_MENU_ART`는 실제 이미지이며 기존 전투/타이틀 배경 풀에 섞이지 않도록 비활성 플래그를 고정한다. `HOME_MENU_LAYOUT`는 서버가 생성한 작은 JSON 리소스의 미디어 레코드다. 설정을 파일명이나 URL 쿼리에 숨기지 않는다. 고정 설정 레코드가 새 불변 JSON 파일을 가리키도록 트랜잭션에서 갱신하고, 저장 실패 시 새 파일을 회수한다. 활성 이미지 삭제와 설정 저장은 같은 advisory lock을 사용한다. 이미지 ID는 해당 미디어 유형으로 확인한다. 공개 API에 관리자 설정을 쓸 수 있는 경로가 없다.

## 직접 실행한 검증

- 프런트/API 타입 검사와 양쪽 production 빌드 통과.
- 모델 범위/유한 수 검증, 저장·재조회·캐시 복사·DB 실패 시 파일 회수·유형 격리·사용 중 삭제 금지, 실제 HTTP 관리자 인증/403/유효성 검사 및 기존 스토리지/공지 정책 **11개 통과**. DB/스토리지는 메모리 대역으로 테스트했다.
- 실제 홈 React 경로: **12해상도**에서 5개 주요 컨트롤이 화면 안에 표시되고 클릭 대상이 겹치지 않음, 44px 이상 터치, 페이지 스크롤 없음, 회전 후 배치 유지, 공지·닉네임·음량·설치 안내와 모드/전체 메뉴 창 확인. 배경 이미지 decode 및 opacity/filter 확인.
- 실제 관리자 React 경로: 최초 조회 503 시 저장 차단/재시도, 파일 업로드 요청→PUT→완료→미디어 등록, PC/모바일 독립 배치, 저장 후 재진입, 같은 설정의 홈 반영, 활성 이미지 삭제 버튼 차단, 해제 저장 후 삭제, 온라인 모드 선택 경로 확인. HTTP/업로드는 로컬 가로채기 대역을 사용했다.
- 390×844와 1440×900에서 실제 홈 → 대전 모드 → AI 시작을 포함해 출전 덱 변경/저장/재진입, 스킨 표시, 빠른 대전 자동 진입/취소, AI 준비 확인. 미선택/무효 덱에서 매치 시작 안 됨, 503 재시도·계정 변경·늦은 큐 ACK 회귀 확인. HTTP/WS는 모의했다.
- 기존 관리자 로그인/승패 음악 조작 회귀 확인. 세션 지연 테스트의 요청 수 가정은 기존 1500ms 복구 조회를 허용하도록 수정했다. 인증 제품 코드는 변경하지 않았다.

## 남은 검증

최종 캐릭터 원화의 구도·텍스트 대비·투명 여백은 이미지 등록 후 조정해야 한다. 실제 운영 관리자 계정의 업로드/스토리지 왕복, 물리적 Android/iOS 터치와 저사양 성능, 실제 두 사용자 PvP/드래프트 전체 플레이는 이번에 수행하지 않았다. 별도의 플레이 규칙·보상·카드 데이터 수정 없음.

## 배포 결과

기존 자동 배포 승인에 따라 소스 `b8da47ef17777c477017c7f5b3f9face2922bb6b`를 API → 프런트 순서로 반영했다. 두 배포 모두 같은 커밋에서 live, health 200. 운영 JS/CSS **113개 전체 SHA-256**이 로컬 검증 빌드와 일치한다. 프런트 live 전환 직후 첫 HTML 조회에서 잠깐 이전 진입 파일이 반환돼 불일치 검사가 중단됐고, 재조회에서 새 진입 파일과 전체 리소스 일치를 확인했다. 점검 비활성 상태를 유지했다.

공개 main-content 200, 기존 대표 배경 ID 유지, 초기 메뉴 설정 version 1/이미지 미등록, 비인증 관리자 설정 요청 401 확인. 운영 DB·저장소에 QA 쓰기 없음, main 병합 없음. [API 배포](20261101-home-menu-api-deployment.json) · [프런트 배포](20261101-home-menu-front-deployment.json) · [공개 읽기 검사](20261101-home-menu/public-read-check.json).

배포된 실제 번들을 390×844 Chromium에서 실행해 대표 배경 decode, 스크롤 없음, 대전 모드 선택 창의 세 항목 표시를 추가 확인했다. 계정 데이터만 브라우저에서 대역으로 응답했고 모든 POST는 차단했다(기존 접속 상태 소켓 티켓 요청도 차단). 운영 관리자 로그인/업로드 또는 실사용자 계정 검증을 대신하지 않는다. 실행 환경의 인증서 체인 오류 때문에 이 브라우저 검사만 ignoreHTTPSErrors로 실행했으므로 TLS 인증서 검증 결과로 해석하지 않는다.
