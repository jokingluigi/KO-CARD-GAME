# 연속 카드 목록과 태그 관리 편의성

브랜치: `feat/catalog-scroll-and-tag-tools`. 기존 피니셔·복귀 스탯·러쉬 패치 위에 작업. main 병합 없음.

## 변경 내용

- 컬렉션/카드 제작 및 덱 편집의 12장/18장 페이지 이동 제거. 첫 40장, 하단 접근 시 40장씩 이어서 표시. 관찰 API 미지원 환경에서도 더 보기 버튼 제공.
- 기본 모아 보기/크게 보기. 모바일 기본 3열, 크게 보기는 2열. PC는 사용 가능한 너비에 맞춰 열 수 조절. 이미지 지연 로딩 유지.
- 검색/필터 고정. 짧은 가로 화면과 펼친 상세 필터는 자연스럽게 스크롤하도록 처리.
- 검색·필터·표시 크기와 불러온 카드 수·스크롤을 세션에 보관. 카드 상세 닫기, 카드 추가, 새로고침, 모바일 현재 덱에서 목록으로 복귀할 때 유지. 소유권·카드 성능은 저장하지 않음.
- 모바일 하단 ‘현재 덱 N/25’ 고정 접근 버튼. 기존 실제 편집기 사용.
- 태그 관리자: 이름 저장, 태그/선수 검색, 연결 상태·공개 상태·등급·비용 필터, 이름/비용 정렬, 검색 결과 전체 선택, 선택 유지, 일괄 연결/해제, 개별 연결/해제, 연결 개수와 변경 결과 표시, 등록 이미지 썸네일.
- 일괄 적용은 서버 트랜잭션 및 기존 태그별 락 사용. 존재하는 선수 카드만 변경. 잘못된 ID/주문이 섞이면 전체 거부. 다른 태그 유지. 같은 연결을 재요청하면 불필요한 버전 증가 없음.
- 이름 변경은 안정적인 내부 태그 키와 표시 이름을 분리해서 구현. 기존 카드/챔피언 효과 JSON, 태그 조건, 카드 연결을 다시 작성하지 않음. 컬렉션·덱 필터, 카드 상세/인스펙터·태그 탐색기 및 명시적인 ‘태그’ 텍스트에 표시 이름 적용. 카드 이름 자체는 변경하지 않음.
- 카드 관리자에서 변경된 표시 이름으로 태그를 입력해도 기존 태그 키로 연결.

## 관리자 사용

태그 관리 → 태그 선택 → 이름 입력 후 **이름 저장**.

카드 이름/태그 검색과 필터로 범위를 좁히고, 카드 체크박스 또는 **검색 결과 모두 선택**을 사용한 다음 **선택 카드 연결 / 선택 카드에서 해제**를 누른다. 검색을 바꾸어도 선택한 카드는 유지된다. 작업 전 선택 장수·연결/미연결 장수를 확인할 수 있다. 한 요청은 최대 1000장이다.

표시 이름이 바뀌어도 효과 편집기의 내부 참조 키와 이미 저장된 카드 효과는 유지된다. 중복 표시 이름은 거부한다.

## 검증

- 관련 회귀/표시 이름 테스트 **32/32 통과**: 컬렉션 읽기, 덱 읽기/소유권/검증, 태그 비교, 표시 이름이 카드 이름을 바꾸지 않는지.
- 실제 HTTP API + 격리 PGlite **5/5 통과**: 마이그레이션 반복 적용, 이름 저장/재조회, 중복·없는 태그 거부, 이름 변경 후 실제 태그 조건 효과 발동, 선택한 선수만 일괄 변경, 주문/잘못된 ID 포함 시 원자적 거부, 재요청 시 무변경, 권한 검사, 동시 이름 변경/연결, 삭제 후 다른 태그 유지.
- 실제 컬렉션/덱 페이지 브라우저 검증: 390×844, 844×390, 1440×900. 첫 40장, 자동 추가 표시, 크기 선택, 상세창/새로고침 위치 유지, 검색, 덱에 카드 추가 후 위치 유지, 모바일 현재 덱 왕복, 가로 넘침 없음. API는 명시적 121장 테스트 목록으로 격리했다.
- 실제 태그 관리자 브라우저 + 실제 관리자 API/격리 DB: 같은 3개 크기에서 이름 변경·새로고침 후 유지, 복합 필터, 검색 변경 후 선택 유지, 일괄 연결/해제, 개별 변경 확인. 단순 목업 서버가 아니다.
- 브라우저 각 시나리오 JS 오류 없음. `catalog-browser.json`, `tag-browser.json`, 스크린샷 참조.
- `pnpm build` 통과: 라이브러리·클라이언트·서버 타입 검사 및 배포 빌드. 기존 UI sourcemap 경고가 있으나 빌드는 성공했다.

## DB와 검증 범위

`0057_card_tag_display_names.sql`은 기존 card_tags에 nullable display_name 컬럼만 추가한다. 서버가 시작 전에 기존 멱등 마이그레이션 경로로 적용하며, 기존 카드·효과 데이터를 일괄 수정하지 않는다. 운영 DB에 테스트 태그/카드를 만들거나 운영 매치를 생성하지 않았다.

브라우저는 Chromium 터치/뷰포트 검증이다. 실제 휴대전화 하드웨어 및 화면 낭독기 검증은 수행하지 않았다. 관리자 전체의 정보 구조와 모든 편집기를 통합하는 개편은 이번 패치 범위가 아니며 별도 검토 대상이다.
