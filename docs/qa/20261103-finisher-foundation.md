# 피니셔 기반: 준비 UI·공통 손패 규칙·고유 능력 교체

작업 브랜치: `feat/finisher-foundation`. 운영 DB 변경·마이그레이션·운영 배포·main 병합은 하지 않았다. 챔피언별 피니셔 카드, 이름, 비용, 효과, 신규 희귀도는 추가하지 않았다. 진단용 카드와 능력은 격리 테스트 안에서만 만들었다.

## 1. 피니셔 준비 표시

- 대전 양측 HUD, ALT/터치 상세, 챔피언 컬렉션 상세, 덱 편집의 챔피언 상세, 준비 진행·완료 알림, 완료 연출, 대사 라벨, 전투 로그, 결과 요약, 튜토리얼·도움말에서 챔피언 퀘스트를 **피니셔 준비**로 표시한다.
- 개별 조건의 이름·설명, 목표 횟수, 진행 이벤트, 완료 판정, 생존 조건, 내부 `quest*` 필드·API·이벤트는 유지했다. 일일·시즌·보상 퀘스트는 기존 명칭을 유지한다. 미니언 A에게 조건을 만들지 않았다.
- `preparationCompletionReward()`로 완료 처리의 호환 경계를 분리했다. 현재는 기존 토큰 소환·능력 강화 등의 완료 효과를 그대로 적용한다. 상세와 완료 패널에 **피니셔 획득 / 현재 완료 효과** 및 “피니셔 카드 연계 전까지 기존 완료 효과가 적용됩니다”를 표시한다. 확정되지 않은 피니셔를 받았다고 가장하지 않는다.

## 2. 공통 손패 처리

최대치는 기존 `MAX_HAND_SIZE = 7`을 사용한다.

| 상황 | 구현된 처리 |
|---|---|
| 드로우 아닌 획득, 빈자리 있음 | 새 카드를 정상 추가한 후 해당 카드의 실제 손패 진입 반응 처리 |
| 드로우 아닌 획득, 손패 가득 참 | 기존 손패 중 1장 선택 → 명시적 확인 → 선택 카드 묘지 이동 → 새 카드 추가 → 원래 효과 재개 |
| 다수 생성·획득 | 새 카드들을 직렬화 가능한 대기 프레임에 보관. 카드마다 공간을 검사하며 선택을 한 장씩 진행 |
| 정상 드로우 | 덱에서 한 장을 꺼내 기존 드로우/준비 처리 적용 |
| 초과 드로우 | 덱에서 꺼냄 → 양측 공개 → `removedFromGame`으로 제외. 손패·묘지에 추가하지 않고 해당 카드의 준비/손패 진입 효과도 실행하지 않음 |
| 연속 드로우 | 카드별 공간 검사. 드로우 도중 다른 효과의 손패 선택이 끼면 남은 드로우와 원래 후속 효과를 선택 후에 재개 |
| 빈 덱 | 기존 피로 처리 유지 |

생성, 무작위 생성, 미니언 A 능력, 묘지·덱·필드에서의 손패 이동, 훔치기, 챔피언 토큰의 손패 대체 이동을 공통 `addCardsToHand()`에 연결했다. 손패가 찼다고 무작위 버리기·신규 카드 제외·덱 위 이동을 수행하지 않는다. 보상 토큰 출전 과정에서 기존 선수를 손패로 돌려보내야 할 때도 같은 선택을 거친다. 기존 각성 단계의 예약 토큰은 선택 중 중복 소환되지 않게 보존한다.

버리기는 기존 묘지 정규화 처리를 재사용하고 별도의 `CARD_DISCARDED`로 기록한다. 리타이어·파괴·소멸로 취급하지 않는다. 초과 드로우의 `CARD_DRAWN` 기록은 `OVERDRAW` 사유로 남겨 기존 드로우 집계를 보존하며, 손패 진입 트리거와 손패로 날아가는 연출은 실행하지 않는다. 공개는 `CARD_REVEALED`, 제외는 기존 `CARD_REMOVED`/`removedFromGame`을 사용한다.

### 선택·연출·동기화

- 기존 대상 선택 액션을 재사용하지만, 손패 결정은 사용 전 미리보기가 아닌 **이미 확정된 처리의 선택 대기**다. 카드 추가 효과·골드 지불을 다시 실행하지 않는다.
- 전용 선택창에서 카드 하나를 선택한 후 **선택한 카드 버리고 받기**로 확정한다. 선택 윤곽선·선택 카드 이름, 확대·상세, 최소 44px 버튼, 스크롤 가능한 카드 목록과 고정된 확인 영역을 제공한다. 모바일 세로·가로에서도 카드 목록과 확인 동작을 분리했다.
- 상대는 숨겨진 카드 목록 대신 “상대가 손패에서 버릴 카드를 선택하고 있어요”만 본다. 선택 소유자·유효 대상·요청 버전은 서버가 검사한다. 대기 카드나 내부 시작 처리 큐가 상대에게 노출되지 않게 한다.
- 선택 대기는 취소할 수 없고, 다른 전투 행동도 허용하지 않는다. AI는 기존 합법 행동/평가기를 통해 자기 손패에서 자동 선택한다.
- 시간 만료가 대기 프레임을 삭제하거나 인간의 버릴 카드를 대신 선택하지 않는다. 원래 기한이 지나도 필수 선택은 마칠 수 있다. 연결 종료 시 기존 재접속·접속 종료 패배 정책을 유지한다.
- 턴 종료·게임 시작 효과에서 손패 선택이 발생하면 다음 턴 시작/초기 배분을 직렬화한 상태로 대기한다. 재접속 후 남은 처리를 이어간다. 대전 종료 후 대기 선택을 실행하거나 결과 화면 위에 선택창을 남기지 않는다.
- 초과 드로우는 카드 이름·일러스트·현재 수치를 순서대로 약 1.2초씩 공개한다. 판정은 이미 확정되어 있고 이 표시가 서버나 입력을 기다리게 하지 않는다. 과거 공개 연출은 재접속 시 자동 재생하지 않는다. 로그의 공개 기록은 남는다.

## 3. 주문을 통한 실제 능력 교체

새 효과 액션 **`REPLACE_CHAMPION_ABILITY`**를 공통 Effect Registry와 서버 검증·런타임에 추가했다. 특정 챔피언 ID나 이름으로 분기하지 않는다.

현재 챔피언에 등록된 강화 능력을 선택하는 최소 설정은 다음과 같다. 이는 카드 배포나 피니셔 정의가 아니라, 향후 확정된 주문에 연결할 수 있는 효과 설정 예시다.

```json
{
  "effects": [{
    "trigger": "ACTIVE",
    "action": "REPLACE_CHAMPION_ABILITY",
    "values": {
      "abilityReplacement": { "variant": "UPGRADED" }
    }
  }]
}
```

관리자의 기존 카드 효과 설정 JSON에서 `effectId: STRUCTURED_EFFECTS_V1`과 함께 사용할 수 있다.

| 설정 | 의미 |
|---|---|
| `abilityReplacement.variant: "UPGRADED"` | 현재 챔피언에 이미 등록된 강화 능력을 선택. 등록된 강화 능력이 없으면 새 능력을 임의 생성하지 않음 |
| `abilityReplacement.variant: "BASE"` | 원본 기본 능력으로 변경 |
| `abilityReplacement.ability` | `id`, `name`, `description`, `cost`, `effects: StructuredEffect[]`를 명시한 별도 능력 정의. 기존 능력 데이터와 독립적으로 적용 |
| `values.duration` 생략 또는 `PERMANENT` | 이번 게임 종료까지 유지 |
| `THIS_TURN` / `UNTIL_NEXT_TURN` | 해당 턴 경계에서 원래 능력 선택 방식으로 복귀 |

- 해결된 능력 전체를 매치 상태의 `abilityOverride`에 저장한다. 이름·설명·ID·골드 비용·대상 범위·효과가 함께 바뀐다. 이후 다른 주문으로 다시 교체할 수 있다.
- 공통 `currentChampionAbility()`를 엔진, 버튼/상세, 온라인 입력 경로, 연출의 능력 표시에서 사용한다. AI와 서버 합법 행동 판단도 실제 현재 능력의 효과를 사용한다.
- 챔피언 체력, 준비 진행도, 완료 상태, 스킨, 그 턴의 능력 사용 여부를 초기화하지 않는다. 이미 사용한 턴에는 교체 후에도 재사용할 수 없다.
- 능력 교체가 준비 완료나 능력 사용 사건으로 오인되지 않도록 별도의 `CHAMPION_ABILITY_CHANGED`를 로그에 남긴다. 원본 기본·강화 능력은 수정하지 않는다.
- 변경 상태는 양측 스냅샷과 DB 저장/복원에 포함된다. 새 게임은 원본 정의에서 시작한다.

## 4. 실제 실행한 검증

[기계 판독 결과](20261103-finisher-foundation/test-results.json)에 각 실행 묶음을 기록한다. 서로 겹치는 테스트가 있으므로 숫자를 모두 더해 고유 테스트 수라고 해석하지 않는다.

- 공통 엔진 전체 단위 검사: **973개 통과**. 손패·드로우·묘지·소환·전투·퀘스트·각성·턴·효과·타겟팅·AI·게임 시작 및 치명적인 등장 피해 회귀 포함.
- AI/저장된 콘텐츠 검사: 339개 통과. 고정된 공개 콘텐츠 스냅샷을 사용한 **100개 결정론적 실제 엔진 대전**을 포함한다.
- 서버/계약 검사: 112개 통과. 효과 메타데이터·검증, 온라인 대상 검증·비공개 정보 처리, 기존 주문 등급·덱 규칙 포함.
- 신규 실제 온라인 서비스/격리 DB 검사: 3개 통과. 관리자 설정 저장 및 잘못된 정의 거부, 요청 중복, 상대의 무단 선택, 시간 만료 후 선택, 첫 버리기 후 런타임 제거/DB 복원, 여러 장 생성 후 한 번의 후속 처리, 능력 변경 후 실제 대상·비용 변경, 양측 표시, 같은 턴 재사용 방지 및 능력 복원을 확인했다.
- 브라우저는 **390×844, 844×390, 1440×900** 각각에서 실제 `/online/match/:id` 화면 두 개를 연결했다. WebSocket 전달만 Playwright로 가로채 실제 온라인 서비스와 격리 PGlite DB로 보냈다. 정적 데모로 대체하지 않았다. 카드 선택·확인·확대·목록 끝 카드 조작, 선택 중 새로고침, 상대 대기, 챔피언 토큰 주문 사용, 변경된 능력 비용 표시와 재접속 유지, 양측 공개·제외를 검증했다.
- 이미지 없는 대체 표시와, 운영 공개 이미지 **읽기만** 하여 테스트에 연결한 일러스트 표시를 각각 확인했다. 녹화의 능력·덱은 명확한 격리 테스트 구성이다. 실제 챔피언/피니셔의 새 밸런스가 아니다.
- 전체 타입 검사와 API/프론트엔드 빌드가 통과했다.

### 추가 신고: 헬뻑의 치명적인 등장 피해

- 2026-11-04 신고를 재현했다. 헬뻑의 등장/소환 피해로 체력 1 선수가 즉시 리타이어하면, `DAMAGE`의 치명타 분기가 전역 `DAMAGE_TAKEN` 관찰자를 호출하지 않고 종료했다. 피해를 받고 생존하는 경우에는 호출하고 있었다.
- 치명적인 효과 피해에도 공통 피해 관찰자를 호출하도록 수정했다. 이탈 효과에서 추가 피해가 생겨도 원래 피해 사건을 보도록 사건 인덱스를 고정했다. 기존 자체 피격 반응과 리타이어 처리 순서, 카드 원본·성능은 유지했다.
- 공개 카드 정의를 최소 스냅샷으로 고정한 **새 검사 5개**가 통과했다. 수정 전에는 그중 2개가 실패했다. 체력 1 즉사/체력 2 생존, 아군 고통 수집가 두 장의 동시 강화, 상대 선수 피해 제외, 피해를 받은 선수 자신의 드로우와 고통 수집가 강화가 각각 한 번 실행됨을 확인했다. 이 5개는 위 973개에 포함되므로 별도로 합산하지 않는다.
- 실제 공통 대전 컴포넌트의 손패 선택 → 빈 슬롯 클릭으로 체력 1 검증 선수를 출전시키는 흐름을 **390×844 / 1440×900**에서 실행했다. 공격력 **1 → 2**, 검증 선수의 묘지 이동 **1회**, 손패 제거를 확인했다. 이 추가 검사는 로컬 공통 대전 하네스를 사용했으며 네트워크 PvP로 보고하지 않는다. 전용 임시 선수와 이미지 누락 대체 표시를 사용한 기능 검증이다.
- [최소 재현 테스트](../../artifacts/ko-game/src/game/engine/entry-lethal-damage.test.ts), [공개 정의 스냅샷](fixtures/20261104-entry-lethal-damage.json), [브라우저 실행 코드](entry-lethal-damage-browser.mjs).

### 확인한 문제와 수정

- 미니언 A 생성 초과 제외, 일반 생성의 무제한 손패 증가, 이동/토큰의 덱 위 대체를 같은 손패 대기 경로로 통합했다.
- 중첩 드로우가 손패 선택 전에 계속되거나 후속 효과를 건너뛸 수 있는 재개 프레임을 보완했다.
- 각성 예약 토큰이 손패 선택 중 빈 슬롯을 보고 중복 배치되지 않게 했다.
- 능력 교체 시 기존 미니언 A 특수 후보 목록 조건이 다른 교체 능력에 남지 않게 했다.
- 기존 Effect Library 검사에는 이미 추가되어 있던 `DAMAGE.amountReference`를 허용하지 않는 오래된 정확 일치 기대값이 있었다. 기준 커밋에서도 같은 실패를 재현한 뒤, 기존 필수 입력과 새 교체 능력 설정의 노출을 검증하도록 검사만 수정했다. 피해 효과는 바꾸지 않았다.
- `shop-decks.ts`의 빈 쿼리 결과 타입 추론을 명시했다. 실행 동작은 그대로다.

## 5. 남은 문제와 미검증

- 옛 `latest-admin-card-semantics-20261013.test.ts`의 루나·하늘을 떨구는 자 아머/침묵 기대값 **2건은 기준 커밋 `31ce1fe`에서도 동일하게 실패**한다. 이전 챔피언 토큰 침묵 면역 정책과의 기대값 문제를 별도로 검토해야 하며, 이번 요청에서 카드 효과를 임의 변경해 맞추지 않았다. 저장소 전체 검사가 모두 통과했다고 보고하지 않는다.
- 실물 Android/iOS 장시간 플레이, 실제 인터넷 지연·패킷 손실 하에서의 장시간 두 계정 PvP, 운영 DB를 사용한 수동 검증은 수행하지 않았다. 운영 배포도 하지 않았다.
- 개별 피니셔 지급과 효과·밸런스는 미구현이다. 사용자 승인으로 확정된 카드가 준비된 뒤 기존 완료 보상 호환 경계를 전환해야 한다.
