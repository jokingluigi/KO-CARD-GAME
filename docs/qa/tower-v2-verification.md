# Tower V2 검증 및 운영 안내 — 2026-10-09

## 기존 구현 조사
기존 타워는 실제 공통 전투 엔진, 계정 소유권, 서버 런 저장/CAS, 전투 재시작, 계정 보상 원장, 컷씬, 24종 유물을 갖추고 있었다. 단일 활성 시즌/16층/고정 보스 위치와 일반 상대의 바닐라 챔피언, 유물 최소 9종·획득 최대 3개 등의 V1 제약이 V2 사양과 달랐다. 기존 V1 런과 관리자 데이터를 삭제하지 않고 V2 설정·공개 버전·런 스냅샷을 추가했다. 태그 고유 효과/시너지는 구현하지 않았다. 덱 평가에 분류용 태그만 사용한다.

## 구현
- 다중 타워, 임의 연속 층 및 보스 위치, 초안 편집/불변 공개 버전/보관, 사용·공개·정렬·이미지·OST.
- 독립적인 보유 챔피언과 공통 25장 스타터 덱 선택. 타워에서만 중복 제한 없음.
- 일반 적 후보의 가중치·쉬움/보통/어려움. 시드·비용 곡선·희귀도·챔피언/효과/태그/키워드 연계로 실제 25장 생성 및 저장.
- 공개/미공개 공통 카드 풀. 토큰·삭제/비활성·시스템 카드·실행 불가능한 효과 제외. 동일 희귀도 분포로 무작위 2장+시너지 1장, 서로 다른 ID, 작은 풀 안전 처리.
- 보상 재선택/취소/스킵/제거 카드 선택/미리보기/원자적인 25장 교체와 중복 요청 차단.
- 고정 25장 보스/체력/다중 능력/우선순위/조건/횟수/공개 정보. 보스와 유물은 기존 effect runtime을 사용한다.
- 유물 다중 효과/AND·OR/대상 필터/자동 선정/전투·런 지속/턴·전투·런 횟수. 파생 이벤트로 보스·유물끼리 연쇄하지 않는다. 실행되지 않은 효과는 횟수 미차감. 런 능력치의 baseline 및 덱 위치 기록, 재시작 중복 누적 방지, 유물 HP 감소 1 하한.
- 카드 및 유물 보상은 후보와 상태를 저장. 유물은 다음 전투부터 사용, 공통 풀에서 보유 유물 제외, 작은 풀/빈 풀/획득 개수 안전 처리.
- 오프닝/층·보스 인트로/일반·히든 엔딩, 8표정·배치·반전·이동·배경·OST·SFX·흔들림·페이드·암전·등퇴장, 진행/스킵/완료 저장.
- 서버 조건의 히든 분기 및 최초/반복 복수 계정 보상. 동일 보스 재사용 층은 지급 ID를 층별 분리한다. 테스트 런은 자산/클리어 기록 지급 없음.
- 기능 OFF는 데이터 보존 및 일반 사용자 진입 차단. 관리자 진단은 별도 권한 경로.
- 전투의 저장된 카드 카탈로그로 미공개 카드 이름·그림·상세 표시. 타워 정보 버튼은 설정 메뉴 내부에 두어 챔피언 공격 터치를 가리지 않는다.

## 발견 및 해결
- 타워 신규 정보 버튼이 상대 챔피언 공격 터치를 가림 → 설정 메뉴로 이동.
- 런에 고정된 미공개 카드가 화면에서 알 수 없는 카드로 표시 → 전투 렌더/상세가 state.cardPool 사용.
- 런 지속 능력치가 손패 복귀 때 baseline 복원으로 사라질 가능성 → base/current를 일관되게 갱신, 다음 전투 1회 적용 테스트.
- JSON 저장으로 undefined contentVersion이 사라져 기존 런 비교 테스트 실패 → 값이 있는 V2에만 저장.
- 동일 보스를 여러 층에서 사용할 때 같은 런 영수증이 중복 취급 → 층 포함 멱등 ID.
- V2 목록의 초안 이름·이미지 노출 → 최신 공개 스냅샷 메타데이터 사용.

## 관리자 사용법
1. 관리자 → 타워 관리 → 새 V2 타워. 이름/설명/이미지/사용/공개/정렬 설정.
2. 층 탭: 층 추가/제거와 연속 번호, 일반 후보 챔피언·가중치·난이도, 보스 참조·유물 위치·배경/OST/확률 지정.
3. 보스 탭: 챔피언, 실제 카드 25장, 시작/최대 HP, 난이도, 능력 목록, 최초·반복 보상 배열.
4. 기존 스타터 편집: 카드 검색·수량으로 25장 작성. 계정 카드 보유 불필요. 유저 챔피언 보유는 서버 검증.
5. 유물 편집: 다중 효과 라이브러리 사용 → 시점·효과·대상·수치·지속·횟수·우선순위. 설명 자동 생성. AND/OR 및 복잡한 필터는 구조화 JSON 편집.
6. 등장인물/컷씬 편집: 8표정 이미지 등록 및 줄별 연출 설정. V2 컷씬·히든 탭에서 연결/조건 설정.
7. 확률은 Normal/Epic/Legendary 합계 100. 층별 덮어쓰기 가능.
8. 초안 저장 → 공개·테스트 → 저장 후 공개 전 검증 → 공개 버전 생성. 새 런만 새 버전 적용. 기존 런은 고정.
9. 같은 화면에서 전체 진행 또는 층·챔피언·일반 적·보스·히든·덱·유물 지정 진단 실행. 계정 보상 없음.
10. 전역 타워 ON/OFF. 개별 타워 보관은 기존 런/기록을 삭제하지 않는다.

## DB / 배포
추가 테이블 tower_versions와 0051_tower_v2_versions.sql. 기존 schema/data 삭제 없음. startup schema가 추가 migration 적용. 신규 환경 변수 없음. 프로젝트는 Supabase 인증/RLS가 아니라 서버 쿠키 인증 + Drizzle/PostgreSQL이며 Supabase는 스토리지에 사용한다. 권한은 서버에서 authenticated user·admin 및 런 소유자를 확인하고 거래/잠금/원장으로 보호한다. DB 키는 프런트엔드에 배포하지 않는다.

## 남은 검증
실기기 터치/게임패드·실제 장시간 네트워크 실패, 실제 서비스 콘텐츠 전체를 대상으로 한 모든 유물/보스 조합, 모든 상점·제작·분해/PvP 수동 플레이는 별도 검증이 필요하다. 지원하지 않는 listener/수동 targeting/예방 hook 등의 효과는 라이브러리에서 제외해 장식용 설정으로 공개하지 않는다. 초기 16층은 관리자 제작용 템플릿이며 실제 보스·후보·컷씬·OST는 저장된 콘텐츠로 설정해야 한다.
