# 챔피언 움직임·감정표현 구현 검증 (2026-10-28)

작업 브랜치: `feat/final-sprite-reactions-review`. main 병합·운영 배포·Production DB 변경 없음.

## 구현 범위

기존 실제 공통 대전 UI의 ChampionBattleActor와 이벤트 커서를 확장했다. 관리자와 실제 대전은 같은 ChampionSpriteVisual, 움직임 프로파일, 표정 선택·우선순위 로직을 사용한다. 별도 시연 전용 구현이 아니다.

- 기본 호흡(1.2px/5.2초), 저체력 명암·느린 호흡(7.6초), 턴 시작 강조.
- 주문 전진360ms, 고유능력520ms, 일반 소환260ms, 레전더리 소환480ms.
- 피격220ms/강한 피격320ms. 기준 이동6px/14px를 표시 크기와 사용자 강도로 보정한다. 모바일 보정 하한70%. 실제 공격 출발 위치를 알면 그 방향으로 반동한다.
- 자해는 반동40%와 작은 명암 변화로 구분하고 외부 충돌·카메라 효과를 생성하지 않는다.
- 놀람360ms(80ms 멈칫), 회복500ms 알파 실루엣 빛, 각성700ms 중220ms에서 세트 교체. 기존 세트 유지도 동일한 강조를 사용한다.
- 승리·패배는 확정 결과에 따라 지속 자세를 유지한다. 패배 시 기존 초상화 유리 파괴가 우선 보이므로 해당 순간에는 패배 상체 자세가 가려질 수 있다.
- 단일 피해 대상이 기존 효과 선언에서 명확한 경우에만 챔피언 앞쪽→대상으로 짧은 연결 효과를 사용한다. 전체 대상·지원·알 수 없는 스크립트에 단일 투사체를 만들지 않는다.
- 기존 공격 접촉·카메라 관리자를 재사용하고 챔피언 대상의 중복 루트 흔들림·범용 능력 컷인·회복 입자를 정리했다. 카드 대상의 기존 연출은 유지한다.
- HUD·클릭 대상은 고정하고 그림 하위 레이어만 움직인다. 상대 자동 좌우 반전은 유지한다.
- 페이지 숨김·회전·설정 변경·새 대전·컴포넌트 해제 시 임시 애니메이션과 연결 효과를 정리한다. 이미 처리한 사건을 설정 변경으로 재생하지 않는다.
- 게임 결과·타이머·네트워크를 연출 완료까지 기다리게 하지 않는다.

## 감정표현

기존 텍스트 감정표현 6종의 확정 `CHAMPION_EMOTE` 이벤트를 연결했다. 새 표정 슬롯은 추가하지 않았다.

| 감정표현 | 기본 표정 연결 |
|---|---|
| 인사 HELLO | 기본 |
| 감사 THANKS | 안도 |
| 칭찬 WELL_PLAYED | 승리 |
| 사과 SORRY | 피격 |
| 실수 OOPS | 놀람 |
| 위협 THREATEN | 공격 |

약1초 후 현재 기본/저체력으로 돌아간다. 칭찬의 승리 표정은 실제 승리 판정이 아니다. 전투 반응·각성·승패가 우선하며 지난 감정표현을 대기열에 쌓지 않는다. 현재 선택 스킨의 현재 일반/각성 세트 안에서만 표정을 선택한다. 누락 시 같은 세트 기본 이미지, 관리자 OFF 선택 시 현재 지속 표정을 유지한다.

별도 꾸미기 이미지 이모티콘 4슬롯에는 자동 표정 추론을 추가하지 않았다. 이번 연결 대상은 기존 챔피언 텍스트 감정표현이다.

## 관리자 등록 방법

1. 관리자 → **스프라이트 관리**(`/admin/battle-sprites`)에서 챔피언과 스킨을 선택한다.
2. 일반/각성 세트를 선택하고 기존10표정의 PNG·WebP와 배치를 등록한다. 기본 한 장만으로도 동작한다.
3. **현재 세트의 강조색·효과 출발점**에서 색상과 내/상대 위치의 X·Y(0–100%)를 지정한다. 원점 표시는 관리자 확인용이며 실제 대전에는 나오지 않는다.
4. **감정표현과 현재 세트의 표정 연결**에서 자동·사용 안 함·등록된 표정을 선택한다. 일반/각성 세트별로 독립 저장한다.
5. 움직임 버튼과10표정 버튼으로 내/상대 배치를 확인하고 저장한다. 각성 버튼은 가림→세트 전환→복귀를 같은 표시 로직으로 확인한다.

이미지 등록 해제 시 해당 이미지의 감정표현 참조를 정리한다. 저장 형식은 기존 스킨/기본 외형의 스프라이트 설정을 확장했으며 별도 DB 테이블은 만들지 않았다. 파서는 저장 데이터를 순수하게 복사하고, 실제 내/상대 방향 정규화는 표시 단계에서 수행하도록 정리했다.

## 남은 검증과 한계

전용 최종 스프라이트가 제공되지 않아 명확히 QA TEMPORARY로 표시한 이미지로 기능을 검증했다. 실제 캐릭터의 눈·얼굴 정렬, 크롭, 일반/각성 실루엣 차이와 최종 미술 품질은 에셋 등록 후 검증해야 한다.

인터넷상의 두 실제 클라이언트 전체 PvP, 운영 AI·빠른 대전·타워·드래프트의 전체 매치, 실제 모바일 GPU/메모리 장시간 측정은 미검증이다. 공유 UI/로컬 엔진·격리 서버 통합 통과를 이들 모드의 전체 성공으로 보고하지 않는다. 실제 사용자 만족도나 심리적 개선은 사용자 실험을 하지 않아 입증하지 않았다.
