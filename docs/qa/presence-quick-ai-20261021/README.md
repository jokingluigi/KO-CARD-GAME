# 사이트 접속 표시 · 빠른 대전 AI 자동 매칭 · 최신 관리자 효과

기준 main: `257660110f1a3f42d4f5eebc752e859be2ca4c75`. 작업 브랜치: `feat/site-presence-and-quick-ai`.

## 구현

- 온라인 배틀 제목 옆 LED: 다른 로그인 계정이 사이트의 어느 화면에 있든 초록, 자신만 있으면 빨강, 연결 상태 미확인/실패는 회색. 동일 계정의 여러 탭은 한 명으로 계산한다. 기존 인증된 WebSocket 하나를 사이트 전체에서 공유하며 계정 ID·명단을 전송하지 않는다. 로그아웃은 다른 탭에도 반영한다.
- 비정상 종료는 서버의 native ping/pong으로 최대 약 60초 안에 정리한다. 정상 연결 중 접속 상태 갱신과 heartbeat에는 SQL 호출이 없다. 연결 생성/재연결 때 기존 인증 절차는 필요하다. 기존 유지보수 상태 조회는 별개로 유지한다.
- 빠른 대전은 서버의 원래 참가 시각 기준 30초 동안 PvP 우선이다. 동일 로비 잠금 안에서 PvP 성사·취소·AI 전환 중 하나를 결정한다. 중복 참가 요청으로 시간을 초기화하지 않는다.
- AI 전환은 기존 AI 덱 목록·정렬·시드 선택 함수와 엔진을 재사용한다. 선택된 덱 이름을 VS·전투·결과에 유지한다. 별도 AI 선택 화면/안내 팝업 없이 진입한다. 보상·퀘스트·사용 통계는 기존 AI 결과 처리 경로를 이용하며 PvP 기록으로 위장하지 않는다.
- 기존 `ai_quest_matches`의 JSON에 handoff 메타데이터를 추가한다. 기존 인덱스로 사용자별 활성 ID만 조회하고 전체 상태는 소유자에게 한 번 전달한다. 새 테이블/인덱스/마이그레이션은 없다. 종료 시 활성 표시를 해제하며 클라이언트의 해제 중복 요청을 제한한다.

## 실제 관리자 데이터

인증된 운영 `/api/admin/cards`, `/api/admin/champions`를 읽었다. 카드 163개, 챔피언 11개. 스냅샷은 [manifest](../snapshots/20261021-admin/manifest.json)에 출처·생성 시각·개수·SHA-256을 기록했다. 2026-10-19 스냅샷 대비 변경 카드는 8개, 챔피언 1개이며 추가/삭제는 없다. 운영 카드/챔피언 저장 요청은 하지 않았다.

초기 수집 05:55 UTC → 재확인 06:27 UTC의 파일 해시가 일치했다. 효과 텍스트 저장만으로 코드가 자동 생성되지는 않는다. 새 브리간다·여울 문구는 ID+문구를 확인한 명시적 바인딩이며, 과거 문구의 동작은 진행 중 경기의 호환성을 위해 남겼다.

## 검증과 실행 방법

- `pnpm run build`: 전체 TypeScript + 프런트엔드 Vite + API 빌드.
- `node docs/qa/current-card-engine.mjs`: 공통 엔진/카드 회귀. 기존 historical catalog 전용 4개 스위트는 러너가 원래부터 제외하므로 통과 수에 포함하지 않는다.
- 현재 관리자 변경 전용 테스트 8개 포함. 최신 스냅샷으로 별도 AI 100경기 검사도 실행한다. 이 100경기는 로컬 엔진 계산이며 운영 DB를 사용하지 않는다.
- Presence 단위 테스트 3개, auth/shared AI selector 13개.
- PGlite + 실제 Express/WebSocket 통합 3개: 사용자/중복 탭/접속 종료, 30초·PvP 우선·취소·중복 참가·타인 handoff 차단·AI 보상 17 지급 및 재전송 중복 방지, pong 없는 연결 정리·유휴 SQL 0회.
- `node docs/qa/site-presence-quick-ai-runner.mjs`: 격리된 로컬 DB/HTTP/WS + 실제 production build UI. 코드에 기대 숫자를 넣는 목업이 아니라 서버 대기부터 AI 전투·항복·서버 결과 확정까지 검사한다.
- 기존 실제 2계정 PvP 스킨/이모티콘/재접속, 드래프트 동기화, 타워 KO→결과→보상→25장 교체 회귀 검사.
- 덱 공유 8그룹, 로그인·메뉴·복구 4그룹, 모바일 덱 조작 4뷰포트 회귀 검사.
- 화면은 360×740, 375×812, 390×844, 412×915, 1440×900 브라우저 에뮬레이션이다. 실제 스마트폰 및 운영 계정 2인 실전은 미실행이다. QA 계정/보상은 로컬 PGlite에만 생성했다.

최종 수치와 모바일 캡처는 이 폴더의 `verification.json` 및 PNG에 보존한다. CI에 새 통합/브라우저 러너를 추가했다.

## 비용·제한·배포

별도 Presence DB/Reatime 서비스는 없다. 한 탭당 기존 WS 연결 한 개, 계정별 Set 집계, 변하지 않는 LED 상태는 재전송하지 않는다. 대기열은 항목당 timeout 한 개이며 몇 초마다 DB를 읽지 않는다. AI 전환 때만 기존 덱 검증/카탈로그/AI 상태 저장을 이용한다. 신규 DB 구조나 보상 정책 변경은 없다.

현재 Render 단일 API 프로세스에 맞춘 구조다. 다중 인스턴스 확장 시 로비와 presence 모두 공유 backplane이 필요하다. Render 무료 플랜의 유휴 자동 정지는 그대로이며, 서버가 잠든 동안 접속 표시가 회색일 수 있다. 네트워크 장애 중 즉시 타인 접속 여부를 보장하지 않는다.

승인된 배포는 기능 브랜치 PR 검증 후 병합하여 두 Render 서비스에 적용한다. 실제 배포 완료 여부/커밋/검증한 정적 파일 해시는 별도 배포 영수증으로 확인한다. 운영 DB 스키마·카드·챔피언 데이터 수정을 하지 않는다.
