# 홈 메뉴의 정보·구도·알림 패치

2026-11-02. `feat/home-battle-mode-art`에서 추천했던 여섯 항목을 실제 홈과 기존 관리자 화면에 연결했다.

보상 조회는 병렬로 실행하되 홈/로그인을 기다리게 하지 않는다. 5초 후 요청을 중단하고 화면 이탈/계정 변경 때 정리한다. 창 복귀 시에는 최소 30초 간격으로 재조회한다. 보상을 실제로 수령하는 요청은 기존 보상 화면에서만 수행한다.

인지 부하를 줄이기 위해 계정의 보조 행동을 묶고 출전 덱 이름과 주요 행동은 바로 보이게 했다. 공지/보상은 실제로 새 정보나 받을 것이 있을 때만 강조한다. 사용자 만족도나 탐색 시간 개선을 사용자 실험으로 입증한 것은 아니다.

## 관리자에서 배경 조정

1. `/admin/media`의 **홈 메뉴 이미지 관리 → 대표 배경 · PC/모바일 구도**를 연다.
2. ‘배경 미리보기 화면’에서 모바일 또는 PC를 선택한다.
3. 가로·세로 위치를 조절한다. 배경은 여백 없이 채우므로 실제로 잘리는 축에서 위치 변화가 보인다. 원본 이미지를 변경하지 않는다.
4. 양쪽 구도를 맞춘 뒤 **홈 메뉴 저장**을 누른다. ‘현재 화면 배경 위치 초기화’는 선택한 화면만 중앙으로 되돌린다.

배경 위치는 현재 홈의 대표 배경에 적용하는 전역 구도 설정이다. 배경 이미지 자체를 바꾼 뒤에는 새 그림에 맞춰 구도를 확인한다. 설정이 없거나 예전 형식이면 기존 중앙 배치를 유지한다. API는 저장된 설정을 `backgroundPlacement`로 공개하고, 임의 파일 경로나 외부 이미지를 추가하지 않는다.

## 실제 검증

- 프런트/API 타입 검사와 양쪽 production 빌드 통과. 공유 타입은 `tsc -p lib/cosmetics/tsconfig.json --types node --typeRoots /workspace/KO-CARD-GAME/artifacts/ko-game/node_modules/@types`로 선언을 갱신했다. 기존 cosmetics 테스트 파일이 Node 타입 없이 라이브러리 빌드에 포함되는 설정 때문에 Node 타입 경로를 명시했다. 전체 workspace 기본 빌드 통과를 주장하지 않는다.
- 정책 검사 3개: 보상 집계/중복·비활성 제외/부분 응답, 공지 최신순·수정 식별, 예전 설정 호환·독립 구도 직렬화·잘못된 숫자 거부 통과.
- 실제 HTTP 관리자 라우트 검사 1개: 미로그인 401·일반 사용자 403·관리자 정상 처리·잘못된 배경 좌표 400·검증 전 저장 호출 없음 통과. DB/저장소는 테스트 대역.
- 실제 홈 경로 320×568·390×844·740×360·1440×900: 보상 응답 보류 중 홈 사용 가능, 실제 미수령 3건, 출전 덱 제목, 계정/닉네임 메뉴와 포커스, 최신 공지·읽음 재진입·수정 후 재표시·다른 계정 분리, PC/모바일 구도, 보상 화면 연결, 이미 수령/조회 실패 알림 숨김, 주요 버튼 44px·스크롤 없음·런타임 오류 없음 통과. 운영 데이터 대신 HTTP 대역 사용.
- 일반 계정/관리자 각각 12해상도: 홈 클릭·공지·음량·닉네임·설치 안내·회전·버튼 겹침·화면 안 표시·스크롤 없음 통과.
- 실제 관리자 경로: 기존 업로드·배치·저장·재진입·사용 중 삭제 보호·등록 해제/삭제·실패 복구에 더해, 모바일 80%/40%와 PC 20%/60% 배경 위치 저장·재진입·실제 홈 적용·미리보기 cover 표시를 확인. HTTP/업로드/저장소 응답 대역 사용.
- 실제 홈→덱 선택/저장→빠른 대전/취소→AI 준비/전투 경로를 모바일/PC에서 실행. 출전 챔피언/스킨·기존 접근성 설정 유지, 무효/미선택 덱 미진입 통과. HTTP/WS 대역과 실제 클라이언트 엔진 사용.

카드/챔피언 원본 데이터·전투 판정·보상 정책·스키마 변경 없음. main 병합 없음. 실물 Android/iOS·스크린리더·실제 사용자 PvP·실사용자 만족도는 이번에 검증하지 않았다.

## 배포 확인

소스 `556e6d07d8d2cbd32d0279a130b0ff971cc0d09e`를 기존 자동 배포 승인에 따라 API→프런트 순서로 배포했다. API/프런트 모두 Render live·health 200이며 점검 비활성을 유지했다. API의 공개 `backgroundPlacement` 필드와 기존 설정의 중앙 배치 호환을 읽기 요청으로 확인했다. 운영 배경 위치를 테스트 값으로 저장하지 않았다. 별도 운영 DB 편집/마이그레이션 작업은 수행하지 않았고 기존 API 시작 절차는 변경하지 않았다.

사전 상태 조회는 한 차례 양쪽 경로에서 18초 시간 초과였으며 재조회에서 정상 응답한 뒤 진행했다. 운영 JS/CSS **118개 SHA-256 전체**가 검증 빌드와 일치한다. [API 영수증](20261102-home-lobby-actions-api-deployment.json) · [프런트 영수증](20261102-home-lobby-actions-front-deployment.json).

390×844에서 실제 배포 번들을 실행해 공개 배경 decode, 계정 메뉴의 닉네임 변경/로그아웃 항목과 닫기, 부분 보상 응답 시 가짜 건수 없음, 홈 스크롤 없음, 홈→네 가지 대전 모드 이동, 기존 진입 모션을 확인했다. 계정·보상 응답은 브라우저 대역이며 모든 POST를 차단해 운영 데이터 변경 요청은 전송하지 않았다. 실행 환경 인증서 체인 문제로 이 브라우저 검사만 `ignoreHTTPSErrors`를 사용했으므로 TLS 인증서 검증 결과가 아니다.
