# 업그레이드 1골드 고정 · 카드 편집 미리보기 · 프레임 정렬

## 변경
- 업그레이드는 기본 카드 비용을 낸 뒤 유효 조건/대상과 잔여 골드를 확인해 추가 1골드를 자동으로 지불합니다. 골드나 유효 대상이 없으면 카드의 일반 사용은 유지하고 추가 효과만 건너뜁니다.
- ‘업그레이드: 효과’ 문법을 지원합니다. 이전 PROGRAM 식별자, 프로그램/업그레이드(n) 표기, 기존 programCost 필드는 호환 입력으로 유지하되 실제 지불은 항상 공통 상수 1입니다. 새 작성 데이터에는 programCost 생략도 허용합니다.
- 툴팁·효과 강조·표시용 카드 설명에서 숫자 괄호를 없앴습니다. 전투 로그는 실제 결제 이벤트 금액을 표시하므로 과거 대전의 이미 결제된 기록은 거짓으로 바꾸지 않습니다. 운영 카드 DB의 원문을 일괄 수정하지 않습니다.
- 카드 관리자에서는 미리보기 전환 버튼을 사용하지 않고 편집 영역과 카드를 함께 표시합니다. PC는 옆, 모바일은 바로 아래입니다. 확대/위치 슬라이더와 드래그 미리보기, 저장 하단 영역을 유지했습니다. 챔피언 편집의 보기 방식은 유지합니다.
- 모든 선수 카드에 일반 프레임 좌표를 강제하던 부분을 제거하고 등급별 실제 기본 PNG에 맞춰 이름·비용·효과·공격력·체력을 배치합니다. 챔피언 프레임은 왕관/이름판/설명판의 별도 위치를 사용합니다.
- 프레임 보정과 텍스트 보정의 방향이 반대로 적용되던 오류를 수정했습니다. 프레임 확대·가로/세로 이동 시 모든 내용이 같은 기준으로 따라갑니다. 금색 기본 프레임의 이름과 효과는 어두운 글자로 표시합니다. 주문에는 공격력·체력이 표시되지 않습니다.

## 검증
- pnpm build: 전체 타입 검사 및 프로덕션 빌드 통과.
- 파서/공통 엔진/표시 테스트 35개 통과. 기본 2골드 카드에서 보유 2/3/4/6골드, 실제 비용 감소/증가, 대상 없음, 결제 중복·취소, 골드 누적 준비 조건, 효과 처리 순서, 여러 업그레이드 그룹, AI의 3골드 승리 수 선택, 기존 숫자 0/2/999 및 비용 필드 없는 정의의 1골드 소비를 검증했습니다.
- 실제 온라인 서비스·일회용 PGlite의 서버 통합 테스트 3개 통과: 관리자 저장·잘못된 값 거절, 양측 골드 동기화, 상대 대상 선택 금지, 중복 요청, 재접속 및 대상 선택 복원, 골드 부족 소환.
- 실제 온라인 대전 페이지 2개와 실제 권한 판정 서비스를 연결한 Chromium 검증: 390×844, 844×390, 1440×900에서 기본 2 + 추가 1 결제, 모바일 터치 대상 선택, 상대 대기, 재접속, 효과 1회 적용, 새 툴팁을 확인했습니다. 네트워크 전송은 격리된 연결로 처리했으며 운영 대전을 생성하지 않았습니다. 결과는 match/results.json, 동작 영상은 match/mobile.webm입니다.
- 실제 관리자 카드 편집/API의 PC·모바일 가로·세로 검증: 전환 없이 미리보기 표시, 슬라이더 변경의 실제 이미지 scale 반영, 오류 복구/저장/재진입 및 기존 관리자 기능 보존. JS 오류 0건. browser-results.json 참조.
- 실제 프레임 관리자와 공통 CardRenderer: 4등급 × 3화면 크기, 총 12조합에서 PNG의 실제 투명 숫자 칸 중심과 DOM 숫자 중심을 비교했습니다. 이름·효과 영역과 가로/세로 +2% 이동 시 전체 내용의 동일 방향 이동을 확인했습니다. 주문의 능력치 미표시도 확인했습니다. frame-results.json 참조.

## 남은 검증 범위
- 모바일 검증은 터치 옵션을 설정한 Chromium이며 물리 기기를 직접 실행한 검증은 아닙니다.
- 프레임 좌표 검증은 프로젝트 기본 제공 프레임을 기준으로 했습니다. 임의로 다른 구조의 사용자 프레임 이미지를 분석해 위치를 자동 추출하는 기능은 만들지 않았습니다.
- 현재 운영 사이트는 점검 설정으로 공개 카드/프레임 조회가 차단되어 있습니다. 이 설정은 변경하지 않습니다. 배포 확인 시 서버·화면의 정확한 버전과 실제 HTML 모듈을 확인하고, 점검으로 차단된 카탈로그 점검은 실행하지 못한 항목으로 기록합니다.
- 운영 DB를 직접 변경하지 않고 main에 병합하지 않습니다. 이전 변경을 모두 포함하는 SHA를 보호된 production 브랜치에 fast-forward 배포합니다.
