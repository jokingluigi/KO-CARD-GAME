# AI intro stuck: reproduction and repair

On production, Pandora vs Calavera AI match reproduced a persistent intro overlay. The underlying mulligan counted down and the turn timer ran, so game initialization and loading had already succeeded. The actual DOM retained one match-intro-overlay after the 4.5-second deadline. The intro and GameStatePreview were sibling elements with the identical match gameId as React key. The custom admin deck restart change introduced the game screen key; the AI intro already used that ID. Namespace keys as intro:<gameId> and game:<gameId> so reconciliation can remove the intro without confusing the board. Ordinary online match has no such duplicate sibling keys; its server clock path is unchanged.

10 existing opening, admin custom deck and AI scheduler tests passed. Frontend typecheck and build passed. Minion A implementation is preserved.

Production verification on 2026-10-01 used deployed bundle index-Byq8HKgQ.js. The automatic intro ended and its DOM overlay count became zero, with no waiting screen left. The starting-hand dialog appeared. With the existing Pandora deck, turns advanced, the Yeoul AI used its ability, and WarThunder was actually played: gold went from 3 to 0, the wrestler entered the field, and its entry effect generated Dokung in hand. Screenshot: /workspace/scratch/ai-intro-fixed-gameplay-1790817716482.jpg.

A fresh Pandora vs Yeager match also verified SKIP: click while the intro was visible, observe the normal brief start wait, then observe both overlays removed and the starting-hand replacement dialog displayed. The prior persistent overlay is resolved in production. This was an AI-specific sibling-key collision, rather than stalled server loading. Ordinary online match has a different intro path without this key collision; real two-player PvP was not played during this verification, so broader PvP acceptance is not claimed.
