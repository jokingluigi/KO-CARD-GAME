# 기존 세션 복원 지연 후속 패치 — 2026-10-20

사용자가 최초 접속 시 재시도 전용 화면을 다시 제보했다. 재확인 시 운영 API와 프런트 프록시의 기존 세션 읽기는 모두 200/authenticated=true(약 0.29~0.35초)였으며, 캡처 당시 지연 원인은 재현·확정하지 못했다. Render 로그 API는 403이라 읽지 못했다. 첫 패치의 정상 로그인 검증만으로 간헐적인 접속 문제가 해결됐다고 볼 수 없다.

기존 세션 읽기와 HTML 사전 조회는 여전히 8초에 중단돼 22.6초처럼 늦은 응답을 받을 수 없었다. 로그인 POST 전 준비 대기만 길어진 첫 패치와 구분해, 세션 읽기 기본 상한도 60초로 맞췄다. 로그인 폼은 별도로 1.2초 후 열리므로 입력을 60초 동안 막지 않는다. 명시적인 짧은 호출 제한, 단일 동시 요청 공유, 로그아웃/로그인 후 늦은 응답 무효화, 권한 확인 및 세션 수명은 보존한다.

관리자/덱의 연결 실패 복구도 기존 AuthPage를 사용하여 입력·수동 확인·자동 세션 재확인을 함께 제공한다. 기존의 큰 오류 문구와 재시도 버튼만 표시하는 화면을 제거했다. 실패를 로그인 성공이나 guest로 바꾸지 않는다. 자동 로그인 POST나 서버 상시 깨우기 타이머는 추가하지 않았다. 서버가 계속 응답하지 않으면 실패는 입력 폼에 표시된다.

검증: 타입 검사/API·Vite 빌드 PASS, 인증·시작·메뉴·서버 제한 자동 검사 30/30 PASS. localhost 브라우저에 기존 세션 응답을 25초(모바일)/9초(데스크톱) 늦춰 최초 세션 GET 한 번으로 기존 로그인을 복원하는 회귀 검사를 추가했다. compiled 브라우저 시나리오 28개(러너 8개)가 모두 통과했다. GitHub 전용 CI [39445724350](https://github.com/jokingluigi/KO-CARD-GAME/actions/runs/39445724350)도 같은 검사·빌드·브라우저 검증을 통과했다. 기존 장기 회귀 CI 39445724488은 별도로 실행 중이다. 최종 운영 배포 결과는 아래에 기록한다. 실제 스마트폰 검증은 미실행이다.

운영 기능 점검은 기존 세션 GET을 사용했다. 아래 검증 도구 오류 정리를 위한 테스트 세션 로그아웃 및 사전 승인된 기존 관리자 로그인 1회는 예외다. 운영 스키마/카드/챔피언/재화/보상/플랜/설정은 변경하지 않았다. 플랫폼 최초 응답 지연 자체를 없앤 패치라고 주장하지 않는다.

## 배포 후 확인

PR #63 수동 병합, 웹/API 모두 `ac30343bab4758da185160df8dd6834008965e95`로 live. 웹은 15:14:54, API는 15:15:39 UTC 완료. 390×844/DPR 2 모바일 에뮬레이션에서 기존 세션 첫 진입 1.670초, 최초 auth GET 1회, 새로고침 후 세션 유지, 관리자 접근, 실제 배포된 사전 조회 제한 60초, pageerror 0, 해당 최종 브라우저 API 쓰기 0을 확인했다. 정상 상태 측정이며 플랫폼 cold start 자체가 사라졌음을 뜻하지 않는다.

최초 운영 브라우저 검증은 첫 진입·새로고침·관리자 접근 후 Playwright의 별도 APIRequestContext에서 `EAI_AGAIN` DNS 오류로 중단됐다. 오류 출력에 자동 첨부된 QA 세션 쿠키가 포함된 사실을 발견해 해당 세션만 즉시 로그아웃했고, 이전 토큰으로 auth/me가 authenticated=false임을 확인했다. 원본 비공개 로그에서는 값을 제거했다. 테스트 계정 생성이나 전체 사용자 세션 폐기는 하지 않았다. 사전 승인된 같은 관리자 로그인으로 검증 세션만 교체했으며, 비밀번호/API 키는 보고서·코드·Git에 저장하지 않았다. 마지막 리소스 확인은 브라우저 내부의 credentials:omit GET으로 바꿔 정상 완료했고 오류 출력에서 인증 헤더를 표시하지 않도록 했다.

원인 미확정 범위: 제보 당시 운영 지연과 캡처가 정확히 표시된 경로는 재현하지 못했다. 사용자 설명은 최초 접속이며, 코드상 기존 복구 화면은 관리자/덱 가드에서도 사용했다. 이번 변경은 그 가드 및 최초 접속 공통 세션 제한 모두를 다룬다. Render 로그 API 403으로 플랫폼 내부 원인을 확인할 수 없었고 접근을 우회하지 않았다.
