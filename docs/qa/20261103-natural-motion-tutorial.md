# 자연스러운 UI 모션과 튜토리얼 최초 완료 보상

2026-11-03. 기존 작업 브랜치에서 구현했다. 카드·챔피언 효과, 전투 판정, 스킨 선택 규칙을 바꾸지 않았다. 요청에 따라 튜토리얼의 보상 정책만 추가했다. 기존 보상 원장·팩 인벤토리를 사용하며 신규 DB 테이블/마이그레이션과 main 병합은 없다.

## 화면 움직임의 실제 변경

| 범위 | 변경 |
|---|---|
| 메뉴/탭 | 제목만 움직이던 방식에서 보이는 패널도 240ms 동안 짧게 들어오도록 확장했다. 그룹 간 간격 24ms, 지연 상한 96ms. 같은 패널은 상태 갱신/폴링 때 다시 등장하지 않는다. 화면 밖 항목의 연출은 생략한다. 설정·규칙·복구 화면도 공통 경로에 포함한다. |
| 버튼 | 마우스·터치·키보드 눌림 때 버튼 표면의 명암과 안쪽 글리프를 압축하고 140ms로 복원한다. 버튼 바깥 크기와 터치 영역은 유지한다. pointercancel·키 해제·창 이탈·경로 이탈에서 눌림 상태를 정리한다. 전투 입력에는 메뉴용 눌림 처리를 덧붙이지 않는다. |
| 팝업 | 기존 Radix 열기/닫기 수명 주기에서 220ms 등장, 130ms 퇴장으로 통일한다. 중심 배치 좌표와 작은 정착 움직임을 분리해 갑자기 커지는 기본 확대 연출을 교체했다. 삭제 확인창도 동일한 방식이다. |
| 카드 | 드래그 위치는 포인터를 즉시 따라가고 기울기만 부드럽게 연결한다. 취소 시 220ms 동안 현재 손패 위치를 계속 확인해 복귀한다. 선택 해제·손패 정렬로 목표 위치가 바뀌어도 오래된 위치로 날아가지 않게 했다. 드래그 사본 정리와 원본 표시를 연결한다. 손패 신규 카드에는 짧은 들어 올림/등장, 진행 중 재배치에는 현재 보이는 위치에서 이어지는 처리를 적용한다. |
| 목록 | 유지되는 카드의 재배치를 240ms로 처리하고 새 항목은 160ms로 나타난다. 진행 중 재정렬은 현재 위치에서 연결한다. 문서 스크롤을 이동 거리로 오인하지 않게 좌표를 보정한다. 큰 이동·화면 밖·화면 회전은 장거리 비행 대신 제한하거나 생략한다. |
| 수치 | 실제 값을 즉시 표시한 채 280ms 동안 상승/감소 방향으로 짧게 강조한다. 골드·퀘스트 진행·메인 재화에도 기존 MotionNumber를 연결했다. 퀘스트 바는 280ms로 이어지며 중간 전투 수치를 만들어 보여주지 않는다. |
| 챔피언 | 기존 표정·우선순위·스킨/각성·프리셋 시스템을 유지한다. 주문/소환/능력의 준비, 힘을 내는 구간, 자세 회복의 easing을 분리했다. 강한 피격의 좌우 반동과 피해량별 강도는 유지한다. 이미 분리된 지속 자세·호흡·순간 반응에 같은 흔들림을 중복 추가하지 않았다. |
| 결과/보상 | 고정된 결과/HUD 위치는 유지하고 승패 글자만 340/280ms로 정착시킨다. 실제 보상 응답이 확인된 경우에만 지급 숫자에 360ms 정착 연출을 적용한다. 다음 행동을 잠그거나 긴 결과 대기를 추가하지 않는다. |

움직임 감소 모드에서는 공간 이동·확대·회전을 생략/축소한다. 중요한 정보는 즉시 읽을 수 있고, 입력과 게임 진행은 애니메이션 완료를 기다리지 않는다. 새 임시 VFX·합성 SFX나 원화는 추가하지 않았다.

시각적 위계와 게슈탈트(패널 순서), 행동 통제감(즉시 눌림/정확한 복귀), 기대감과 대비(준비/가속/회복), 피츠의 법칙(고정 터치 영역), 반복 피로 감소(진입 반복 금지·화면 밖 생략)를 적용했다. 실제 사용자 실험으로 만족도가 입증됐다고 주장하지 않는다.

## 튜토리얼 보상

- 첫 소환과 승리 / 선수끼리의 전투 / 러쉬 / 주문과 대상 선택 / 액티브 / 고유능력과 퀘스트: **각 최초 완료 노멀팩 3개**.
- 6개 모두 완료하면 **확정 챔피언팩 1개 추가**. 최대 합계 **노멀팩 18개 + 확정 챔피언팩 1개**.
- 계정별 최초 1회. 재연습·재접속·동시 요청·설정 변경으로 재지급하지 않는다. 비회원 연습에는 지급하지 않는다.
- 기기의 완료 체크만 신뢰하지 않는다. 기존 튜토리얼 로직을 공용 모듈로 옮겨 브라우저와 서버가 같은 준비 상태·목표 판정을 사용한다. 실습 시작의 난수/카드 인스턴스 ID를 재현 가능하게 관리하고, 서버 소유의 고정 실습 카탈로그에서 실제 행동을 다시 실행해 완료를 검증한다. 클라이언트가 보내는 체력·승패·완료 플래그·카드 정의로 지급하지 않는다.
- 기존 보상 원장의 유일 키와 사용자 행 잠금을 사용해 항목/전체 완료 지급을 트랜잭션으로 묶었다. 팩의 연결 대상이 바뀌어도 수령 횟수는 초기화되지 않는다.
- 정상적으로 열 수 있는 공개 팩만 사용한다. 연결할 수 있는 유효한 확정 팩이 하나로 식별되지 않으면 튜토리얼 전용 팩을 준비한다. 전체 완료 지급 또는 관리자 저장 요청에서만 1장·챔피언 100%인 전용 팩을 생성하며, 최초 생성 시 공개된 챔피언 풀을 저장한다. 조회/부팅만으로 운영 데이터를 만들지 않고 기존 상품 팩의 확률을 바꾸지 않는다. 관리자에 의해 비공개/삭제된 전용 팩을 자동 복구하지 않는다. 확정 팩은 챔피언 외 추첨 비중이 0이고 챔피언 풀이 유효해야 한다. 이름이 ‘확정’이라는 이유만으로 선택하지 않는다.
- 완료 시 자동 확인/지급한다. 완료 처리기는 결과창 표시/애니메이션과 분리되어 즉시 실행되고, 결과창은 같은 진행 중 요청을 공유한다. 서버가 이미 지급을 확인한 항목은 재연습 때 다시 지급 요청을 보내지 않는다. 응답을 잃으면 계정별 완료 행동 기록을 기기에 보관하고 ‘보상 다시 확인’으로 복구한다. 새 탭에서 서버 수령 기록도 읽는다. 저장소 자체가 차단되고 요청도 서버에 도달하지 않은 채 화면을 닫으면 재실습이 필요할 수 있다.
- 예전의 기기별 완료 체크는 서버에서 검증할 수 없으므로 자동 보상으로 전환하지 않는다. 이전에 연습만 완료한 사용자는 다시 완료해 최초 보상을 받을 수 있다.

### 관리자 사용법

**관리자 → 보상 설정 → 매치 보상·출석 → 튜토리얼 보상**에서 ‘노멀팩 보상 연결’과 ‘확정 챔피언팩 보상 연결’을 선택하고 저장한다. 지급 수량은 요청대로 3개/1개로 고정된다. 같은 이름의 노멀팩이 여러 개이면 명시적으로 연결한다. 기본 연결이 없을 때는 유일하게 식별되는 노멀팩과 유효한 확정 챔피언팩을 사용한다. 확정 팩을 하나로 식별하지 못하면 위의 튜토리얼 전용 확정 팩을 준비한다. 설정되지 않았거나 팩이 유효하지 않으면 완료 기록을 보관하고 준비 중 안내를 제공한다. 임의의 다른 팩으로 바꿔 지급하지 않는다.

## 실제 검증

- 전체 타입 검사, API/프론트 프로덕션 빌드 통과.
- 모션/표정/실습 단위 검사 **76개**, HTTP + 격리 PGlite DB 보상 검사 **8개** 통과.
- 보상 검사: 로그인 필요, 위조 완료/미완료/다른 행동 주체 거절, 동일 항목 동시 요청 8회에 3팩 1회, 마지막 항목 동시 요청 5회에 전체 보상 1회, 계정당 보상 원장 7건, 설정 재저장 후 재지급 없음. 받은 확정 팩을 실제 개봉해 CHAMPION_UNLOCK을 확인했다. 적합한 팩이 없는 두 번째 계정에서는 조회 시 생성하지 않음 → 6개 완료 시 전용 팩 생성/18+1 지급 → 실제 챔피언 개봉을 확인했고, 일반 사용자의 관리자 저장 거절과 관리자 비활성 팩의 자동 재생성 방지도 검사했다.
- 실제 Home/공통 대전 UI의 6개 실습을 390×844, 740×360, 1440×900에서 조작했다. 서버가 검증하고 임시 DB 인벤토리에 정상 지급했다. 첫 지급 응답을 일부러 503으로 바꾼 뒤 재확인하여 중복 없이 복구했다. 새 실습·재접속·화면 회전·드래그·취소 후 확정·액티브·각성을 확인했다.
- 관리자 화면의 저장 → 새로고침 → 연결 팩 유지 확인. 실제 저장 요청은 격리 서버/DB만 사용했다.
- 실제 메뉴 및 AI 진입 경로에서 390×844, 844×390, 1440×900와 모바일 움직임 감소를 검사했다. 버튼 눌림 중 바깥 크기 유지, 패널의 실제 WAAPI 프레임, 팝업 열기/닫기 CSS 애니메이션, 목록 재배치, 드래그 취소와 원본 복원, 실제 소환·골드 감소, 실제 항복·승패·보상 표시를 확인했다. 가로 화면의 검사 목록은 화면 밖에 있어 연출이 생략되는 것도 확인했다.
- 위 모션/보상 흐름은 개발 서버와 프로덕션 빌드에서 모두 실행했다. 계정·카탈로그·AI/대전 결과 응답은 QA 픽스처다. 실제 운영 계정이나 재화를 쓰지 않았다. 일부 카드 그림은 격리된 원화 요청 때문에 표시되지 않으며 원화 최종 검증 자료가 아니다.
- 기존 모바일 드래그/상태 변경 취소 검사, 덱 편집 복구 검사, 48개 메뉴/화면 조합 및 비회원 실제 소환 통과. 10경로×3크기 첫 화면 컨트롤의 작은 대상·가로 넘침·이름 없는 대상·페이지 오류 0개.
- 챔피언 제어 하네스에서는 각 600프레임, 3크기, headless rAF p95 16.8ms를 기록했다. 실물 모바일 GPU 성능/60fps를 입증하는 결과는 아니다.

[영상·화면·검사 결과](20261103-natural-motion-tutorial/). MP4는 실제 브라우저 녹화를 합친 것이며, 테스트 오디오는 비활성 상태다. 실물 기기의 청감 검사 영상이 아니다. 독립적인 정적 시연 화면으로 실제 게임 검증을 대신하지 않았다. 제어된 상태 주입 검사는 위에서 ‘하네스’로 구분했다.

## 남은 검증

실물 Android/iOS의 장시간 열/배터리/GPU, 실사용자의 조작 오류·선호·반복 피로, 실제 두 계정 장시간 PvP는 이번 결과에 포함하지 않는다. 실제 사용자에게 보상을 지급하는 운영 QA도 하지 않았다. 90점이나 게임 전체 품질 완료를 선언하지 않는다.

## 배포 확인

- API는 소스 `ec7e95a9e19e0c1376f400f0adb9e0bcb69c1062`로 배포했다. 프론트엔드의 최종 완료 처리기 보완은 별도 배포 영수증에 기록한다. main은 병합하지 않았다.
- 운영 읽기 전용 `/api/tutorial/availability`에서 `ready:true`, 노멀팩, 튜토리얼 확정 챔피언팩, 항목당 3개·전체 1개를 확인했다. 이 조회로 팩 생성이나 보상 지급을 실행하지 않았다. 실제 계정의 전체 완료 요청 시 전용 팩을 등록하고 지급할 수 있는 상태다. 챔피언 중복 획득은 기존 팩 중복 보상 규칙을 따른다.
- health 응답 200, 기존 점검 설정 false 유지. 배포 엔트리와 JS/CSS 136개의 SHA-256이 로컬 동일 리비전 빌드와 전부 일치했다.
- 배포 URL에서 4가지 화면/움직임 설정의 실제 메뉴·AI 진입·드래그 취소·소환·골드 변화·항복 결과 및 보상 표시를 다시 통과했다. 관리자 저장/재진입도 배포 UI + 격리 서버에서 재검사했다. 운영 유저의 덱·보상·재화를 QA로 변경하지 않았다.
