# 보상 모두 받기

사용자 요청: 튜토리얼뿐 아니라 현재 받을 수 있는 다른 보상도 한 번에 수령한다.

## 구현

- 메인 하단, 퀘스트, 출석 화면에 `보상 모두 받기`를 추가했다. 클릭 한 번으로 즉시 시작하며 결과창에서 실제 지급 합계를 보여준다. 버튼 터치 영역은 최소 44px이다.
- 일일·활성 시즌·평생 퀘스트, 일일 퀘스트 완료 추가 보상, 당일 출석, 현재 계정에 남은 검증 가능한 튜토리얼 완료 기록을 처리한다. 미완료 조건을 건너뛰거나 이미 지급된 보상을 다시 주지 않는다.
- 기존 수령 서비스와 트랜잭션·원장을 그대로 사용한다. 클라이언트가 보상 종류·수량을 지정할 수 없다. 튜토리얼 증명은 기존 게임 엔진으로 재검증한다.
- 계정 일치 검사, 중복 클릭 병합, 서버 지급 원장으로 반복 요청을 방어한다. 일부 보상 실패는 성공한 보상을 취소하지 않는다. 남은 보상만 다시 수령할 수 있다.
- 응답 유실 때 자동 재지급 요청을 보내지 않는다. `지급 상태 다시 확인`은 조회 요청이며, 실제 미수령 항목을 확인한 뒤 수동으로 재시도한다.
- 수령 후 메인 재화·퀘스트·출석·보유 팩 요약을 갱신한다. 기존 튜토리얼 자동 지급과 개별 보상 수령도 유지한다.
- 게임 규칙·카드·챔피언 효과와 보상 수량은 변경하지 않았다. 신규 DB 마이그레이션 없이 기존 구조를 사용했다.

## 검증

- `claim-all-rewards-http.test.mjs`: 격리 PGlite DB와 실제 API에서 5개 통과. 인증, 계정 불일치, 잘못된 입력, 통합 수령, 동시 반복, 일부 실패 후 재시도를 검증했다.
- 통합 사례: 12건 수령, 크레딧 62, 노멀팩 20, 확정 챔피언팩 1. 이는 테스트 설정의 결과이며 운영 지급 수량 설정을 뜻하지 않는다. 동시 5회 재요청 시 추가 지급 0.
- 기존 `tutorial-rewards-http.test.mjs`: 8개 통과.
- `claim-all-rewards-browser.mjs`: 390×844, 844×390, 1440×900, 360×740에서 실제 React 화면과 격리 API를 연결했다. 한 번 수령, 중복 클릭 1회 요청, 미수령 증명 정리, 재화 갱신, 부분 실패 후 남은 항목 수령, 응답 유실 후 조회를 검증했다. 메인은 세로 스크롤 없이 유지됐다.
- `product-experience-browser.mjs`: 4개 해상도 × 12개 경로 및 게스트 실제 소환 검증을 통과했다.
- `quality-surface-audit-browser.mjs`: 3개 해상도 × 10개 화면에서 가로 넘침·44px 미만 버튼·이름 없는 버튼 없음.
- 전체 타입 검사, API 및 프론트엔드 빌드 통과.

브라우저 자료는 실제 UI와 격리 테스트 계정·DB를 사용한다. 운영 계정에 QA 보상을 지급하지 않았다. 실물 Android/iOS 및 실제 사용자의 선호·피로도 검증은 수행하지 않았다. 처음 개발용 브라우저 검사에서 테스트 계정 닉네임 중복 제약으로 중단됐으며, 계정별 닉네임을 분리한 뒤 전체를 재실행했다.

## 실행

```sh
node --test docs/qa/claim-all-rewards-http.test.mjs
node --test docs/qa/tutorial-rewards-http.test.mjs
node docs/qa/claim-all-rewards-browser.mjs
# 빌드 또는 배포 UI + 격리 API
KO_UI_ORIGIN=http://127.0.0.1:5187 KO_CLAIM_ALL_OUT=qa-results/claim-all-production node docs/qa/claim-all-rewards-browser.mjs
```

화면·영상·배포 확인 자료는 [첨부 폴더](20261103-claim-all-rewards/)에 기록한다. main 병합은 하지 않는다.

## 배포

- 소스 `294369271b536a5191452c57af57eebff6541033`을 기존 기능 브랜치에서 API → 프론트엔드 순서로 배포했다. 두 서비스 모두 해당 커밋의 `live` 상태를 확인했다. main 병합과 서비스 브랜치 변경은 하지 않았다.
- 운영 주소의 엔트리 및 JS/CSS 140개가 로컬 동일 커밋 빌드와 SHA-256까지 일치했다. health 200, 기존 점검 설정 false를 유지했다. 새 보상 조회·수령 API의 비로그인 응답은 모두 401이었다.
- [서버 배포](20261103-claim-all-rewards/api-deployment.json), [화면 배포 및 파일 검증](20261103-claim-all-rewards/front-deployment.json). 운영 DB에 수동 변경이나 QA 보상 지급을 수행하지 않았다.
- 운영 URL의 실제 UI를 격리 API/DB에 연결해 같은 4개 해상도 검사를 다시 통과했다. [결과](20261103-claim-all-rewards/deployed-results.json), [메인 화면](20261103-claim-all-rewards/deployed-home-390.png), [수령 결과](20261103-claim-all-rewards/deployed-collected-390.png), [짧은 동작 녹화](20261103-claim-all-rewards/claim-all-mobile.mp4). 결과 JSON의 특정 시나리오 `false`는 해당 크기에서 그 시나리오를 실행하지 않았음을 뜻하며 실패 판정이 아니다. 응답 유실 검사는 가로 화면, 부분 실패 검사는 360px에서 실행했다. 녹화에는 오디오가 없으며 실물 모바일에서의 검증은 남아 있다.
