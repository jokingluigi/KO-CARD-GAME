# 통합 뽑기 확률·이모티콘 보상 및 AI 스킨 복구

브랜치 `feat/final-sprite-reactions-review`. 실제 관리자·사용자 팩 화면·추첨/지급/중복 개봉 복구·AI 대전 경로를 수정했다. **현재 로컬 구현/검증 완료, 운영 DB 변경 및 이번 변경 배포는 하지 않았다.** 이전 운영 DB 변경 금지 조건 때문에 아래 스키마 추가는 별도 승인이 필요하다. main 병합 없음.

## 뽑기

- 일반·에픽·레전더리·챔피언·스킨·이모티콘 **여섯 확률의 합계 100%**. 슬롯마다 보상 종류 추첨은 한 번이다. 기존 스킨 별도 선행 추첨을 제거했다.
- 예: 일반 70 + 에픽 10 + 레전더리 5 + 챔피언 3 + 스킨 10 + 이모티콘 2 = 100%. 스킨/이모티콘은 추가 보너스가 아니라 한 보상 칸을 차지한다.
- 스킨 안에서는 기존 카드팩 스킨+챔피언 스킨 풀을, 이모티콘 안에서는 활성 이미지 이모티콘 풀을 균등 추첨한다. 개별 확률은 해당 종류 확률 / 실제 유효 풀 수.
- 기존 스킨 원본 지급·챔피언 토큰 묶음·중복 정책은 유지한다. 이모티콘은 기존 꾸미기 보유 테이블에 한 번 지급하고, 중복이면 `alreadyOwned`로 표시한다. 새 중복 환급 정책은 만들지 않았다. 자동 장착 없음.
- 단일·일괄 개봉, 보상 합산, 서버 저장 claim 재조회, 관리자 확률/강제 미리보기, 사용자 구성품/개별 확률, 실제 획득 공개 화면과 API 계약을 모두 연결했다.
- 관리자 여섯 입력과 실시간 합계, 이모티콘 풀 체크박스를 제공한다. 이모티콘 미등록이면 확률 0으로 시작한다. 이후 꾸미기 관리에서 이미지 이모티콘을 등록하면 풀에 선택할 수 있다.
- 합계가 틀리거나 양수 확률의 풀이 비어 있으면 공개/개봉을 거절한다. 이미 공개된 팩을 잘못된 설정으로 변경하려 해도 저장 전에 거절한다. 오류 시 트랜잭션을 되돌려 팩/보상/claim을 부분 소모하지 않는다. 비공개 초안은 미완성 상태로 보관 가능하다.
- 사용자에게 실제 합계를 표시하고, 잘못된 합계는 개봉 버튼과 안내에서 명확히 구분한다. 관리자 미리보기는 저장된 설정을 쓰므로 미저장 편집이 있으면 먼저 저장하도록 안내한다. 모바일 입력/풀 선택의 주요 터치 높이 44px.

## AI 스킨 원인·수정

1. 첨부 안내는 `aiCosmeticsAvailable()`가 `public.ai_deck_cosmetics` 테이블을 찾지 못할 때 나오는 경로다. 테이블 없이 장착을 저장하지 못하는 원인은 CSS나 스킨 소유 문제가 아니다. 이 로컬 작업에서 운영 DB를 직접 조회하지 않았으며, 화면과 해당 코드 조건을 근거로 한다.
2. AI 목록은 현대식 `cosmetic_items`만 조회해서, 아직 소유자 조회/변환이 안 된 기존 카드팩 선수 스킨을 누락했다. 이제 공개된 기존 스킨을 읽기 전용으로 합쳐서 제공한다. 목록을 조회한다고 플레이어 소유권을 주지 않는다.
3. AI 저장 시 선택된 기존 스킨만 기존 `syncLegacySkin` 브리지로 같은 트랜잭션에서 동기화한 뒤 연결한다. 꾸미기 쓰기 잠금 안에서 활성 여부·덱 대상·중복 슬롯을 다시 검증한다. 기존 저장/복제/AI 인트로/HUD/선수 카드/빠른 대전 loadout 경로를 그대로 활용한다.
4. 스킨 저장 테이블이 없을 때 기존 AI 덱은 계속 사용할 수 있고, 실패 메시지는 필요한 스키마 업데이트를 명확히 알려준다. 테이블이 없는 상태를 저장 성공처럼 처리하거나 설정을 버리는 우회는 하지 않았다.

## 필요한 스키마와 운영 전환

검토할 SQL:

- [0055_ai_deck_cosmetics.sql](../../lib/db/migrations/0055_ai_deck_cosmetics.sql): AI 덱↔스킨 연결 테이블, 외래키, RLS. 기존 덱/계정/보유 데이터 변경 없음.
- [0056_pack_emote_rates.sql](../../lib/db/migrations/0056_pack_emote_rates.sql): 팩에 `emote_rate`(기본 0), `emote_pool`(기본 빈 배열) 두 열 추가. 기존 팩 확률/보유량을 자동 변경하지 않는다.

승인 후 적용 순서는 0055/0056 → API 배포 → 프런트 배포다. 스키마 없이 새 API를 배포하면 팩 조회가 실패할 수 있으므로 지금 운영 배포를 진행하지 않았다. 운영 환경의 DB 연결로 `psql -v ON_ERROR_STOP=1 -f ...`를 실행할 대상이며 이 문서에는 연결 문자열/자격 증명을 포함하지 않는다. 전체 `drizzle push --force`나 기존 스키마 삭제는 필요 없다.

**기존에 등급만 100%이고 스킨을 별도로 설정한 팩은 새 합산 방식에서 총합이 100%를 넘을 수 있다.** 자동 재분배/정규화는 하지 않았다. 관리자가 여섯 확률의 합계를 100%로 맞춰 저장해야 한다. 전환 후 잘못된 합계의 팩은 보유량을 유지한 채 개봉을 막는다. 운영 전환 때 기존 팩 설정 확인/조정이 함께 필요하다. 아직 기존 운영 팩 설정값이나 공개 상태를 변경하지 않았다.

## 실제 검증

- TypeScript: 공유 라이브러리·API·프런트 통과. API/프런트 프로덕션 빌드 통과.
- **22개 단위 검사 통과**: 여섯 종류의 모든 100개 정수 추첨 구간 정확성, 각각 100%/0%, 합계 오류·비정수 거절, 기존 스킨 재추첨 없음, 이모티콘별 합산, 저장 claim 재생 및 malformed claim 거절.
- **30개 격리 DB/HTTP 통합 검사 통과** (`pack-unified-emotes.test.ts`, 기존 cosmetics/AI 검사 포함): 정상 관리자/유저 권한, 설정·저장·공개·미리보기, 개별 확률, 단일/일괄 이모티콘 실제 지급·중복·재요청, 팩 수량·claim 원자성, 빈/비활성 풀 실패, 사용 중 이모티콘 삭제 차단, 100% 스킨, AI 챔피언/현대식 선수/미소유 기존 카드팩 선수 스킨 저장·재조회·복제·빠른 AI loadout 동결, 플레이어 소유권 불변. AI 테이블 미준비 때 안전한 실패도 확인했다.
- `unified-packs-ai-browser.mjs`: 실제 앱과 격리 HTTP/PGlite 서버 사용. API를 정적 응답으로 대체하지 않았다. 관리자 AI 스킨 저장 후 새로고침 지속, 360×740/375×812/390×844/412×915/1440×900 가로 넘침 없음. 모바일에서 여섯 확률 20+80=100 저장 후 0+100=100 복구. 사용자 이모티콘 구성품 조회 → 실제 로컬 팩 개봉/지급 → 보상 이미지 공개 통과. 실제 로컬 AI 대전 시작에서 인트로/HUD 챔피언 스킨과 AI가 소환한 기존 카드팩 선수 스킨 이미지 URL을 검사했다. 기본 원본 이미지 URL과 다른 스킨 URL을 확인했다.
- 통합 검사 초기에 테스트 모듈 import 경로를 수정했고, 브라우저 검사 중에는 동일 이름의 초안/공개 팩 선택, 봉인 종료 대기, 실제 턴 종료 확인 문구에 맞춰 자동화 선택자를 바로잡았다. 최종 실행은 통과했다. 게임 동작 오류를 테스트에서 숨겨 통과시키지 않았다.
