# 피니셔 연결 / 완료 시 처리

2026-11-11 · 작업 브랜치 `feat/finisher-reward-delivery`.

## 구현과 사용법

관리자 → 챔피언 → 수정 → **피니셔 연결**에서 기존 챔피언 등급 토큰 주문을 선택하고 완료 시 처리를 저장한다.

- **손패에 추가**(기본): 준비 완료 시 선택한 카드를 지급. 손패가 가득 차면 기존 손패 1장을 선택해 버린 뒤 지급한다.
- **즉시 발동**: 기본 카드 비용 없이, 손패를 거치지 않고 기존 주문 효과를 실행. 필요한 대상은 기존 선택 UI에서 지정한다. 필수 선택은 취소할 수 없고, 원래 선택 사항인 효과는 건너뛸 수 있다. 업그레이드 등 효과 자체의 추가 지불 규칙은 원래 효과 엔진을 따른다.
- 복수 선택지: **피니셔 준비**의 각 선택지에서 독립적인 조건·피니셔·처리 방식을 설정. 먼저 완료한 선택지가 잠기며 같은 처리에서 동시에 완료하면 기존 선택 UI를 사용한다. ‘피니셔 연결’ 탭에도 각 선택지의 설정 요약이 표시된다.
- 연결 해제 시 기존 완료 보상을 사용한다. 기존 능력용 선수 토큰 참조는 보존한다. 기존 연결을 자동으로 새 피니셔로 바꾸거나 운영 카드·조건을 만들지 않는다.
- 공개 챔피언에는 공개된 챔피언 등급 토큰 주문만 연결 가능. 초안 참조는 초안 편집에서 허용한다. 존재하지 않는 카드·잘못된 분류·잘못된 처리 방식은 서버가 거부한다.

저장 구조: 단일 `questCondition.finisher = {cardDefinitionId, delivery: 'HAND'|'CAST'}`. 선택지별로는 기존 `questCondition.finisherChoices[]`의 `cardDefinitionId`와 `delivery`를 사용한다. 과거 선택지에서 delivery가 없으면 HAND다. 추가 DB 스키마·희귀도 없음.

공통 전투 엔진에서 단일 준비/선택지 모두 같은 지급 함수를 사용한다. 즉시 발동 대기는 직렬화되는 `pendingFinisherCasts`로 관리하고, 현재 대상 선택 뒤에 이어서 처리한다. 실행 전 큐에서 제거하고 결정적인 카드 ID와 준비 완료 상태로 중복 지급을 방지한다. 정상 주문과 공통 후속 효과 해석기를 사용하고 CARD_PLAYED의 FINISHER_AUTO_CAST 원인을 기록한다. 필수 대상 선택은 연속 프레임 표식으로 보호하며 타임아웃·재접속에서도 유지한다. 상대에게는 선택 대기 사실만 전달한다. 기본 비용 지불·손패 진입·기존 보상·자동 능력 강화는 실행하지 않는다. 주문이 명시적으로 능력을 바꾸는 효과는 그대로 적용한다.

## 실제 검증

- **155개 테스트 통과**: 새 지급·즉발·재접속·선택지·큐 처리 테스트, 기존 손패/피니셔 기반/선택지/주문/업그레이드/챔피언/대상 취소/게시 데이터 변환 회귀, 실제 PvP 서비스 3개 포함. [엔진·서비스 로그](tests.log).
- 실제 관리자 라우트 + HTTP + 격리 PGlite DB: 390×844, 844×390, 1440×900에서 연결·HAND/CAST 전환·저장·재진입·연결 해제·독립 선택지 저장·기존 조건 보존. 잘못된 설정 3개 거부. [결과](admin/results.json).
- 실제 온라인 대전 페이지 **양쪽 클라이언트** + 실제 PvP 서비스/격리 DB: 위 세 화면 크기에서 선수 카드 사용 → 준비 완료 → 6골드 피니셔 무료 발동 → 필수 대상 선택 → +2/+2 한 번 적용. 상대 대기 안내와 자기 화면 새로고침 복구 확인. 브라우저 JS 오류 0. [결과](battle/results.json).
- 서버 테스트는 대전 런타임을 제거하고 DB에서 다시 로드한 복구, 이미 지난 턴 제한시간, 상대의 선택·취소 거절, 중복 요청 방지, 손패 가득 참 → 버리기 → 지급까지 확인했다.
- 전체 타입 검사·API/프런트 빌드 통과. 기존 UI 의존성의 sourcemap 위치 경고는 남지만 빌드는 성공한다. [빌드 로그](build.log).

## 범위와 남은 확인

모든 데이터 쓰기 검증은 폐기 가능한 격리 DB와 명확한 검증용 카드로 실행했다. 운영 챔피언/카드 데이터는 자동 수정하지 않았다. 실제 운영 피니셔별 밸런스·대사·일러스트 검수는 해당 카드 연결 후 필요하다. 대전 영상은 실제 운영 경기가 아닌 실제 온라인 라우트/엔진을 사용한 격리 검증이다. 실기기 테스트가 아닌 Chromium 터치 뷰포트 검증이며, 운영 점검 중 실제 사용자 간 경기는 실행하지 않았다. 각 모드를 별도 수동 완주했다고 주장하지 않는다.

API/프런트 배포 및 운영 읽기 전용 검증 결과는 별도 `production-verification.json`에 기록한다. main 병합·수동 운영 DB 수정 없음.
