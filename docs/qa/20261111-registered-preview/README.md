# 실제 등록 프레임을 기준으로 카드 미리보기 수정

## 수정
- 앞선 기본 프레임만의 검증으로 놓친 실제 등록 프레임을 확보해 수정했습니다. 테스트에 사용한 6개 PNG는 운영 저장소에서 읽기 전용으로 받은 원본입니다. 프레임 원본은 변경하지 않았습니다.
- 등록 프레임의 실제 빈 영역을 읽어 이름판·코스트·공격력·체력·효과 칸을 찾고, 기존 프레임 확대/이동 보정과 함께 적용합니다. 새 프레임 로딩 시 늦게 도착한 이전 이미지가 새 배치를 덮지 않도록 검사합니다. 해석할 수 없는 프레임/외부 픽셀 접근이 허용되지 않는 프레임은 기존 좌표로 대체합니다.
- 이름은 실제 이름판 폭·높이에 맞춰 전체 문자열의 글자 크기를 맞춥니다.
- 관리자/상세 미리보기 효과는 말줄임하지 않습니다. 실제 효과 칸에 맞춰 글자 크기를 조정하고, 아주 긴 내용은 칸 안에서 스크롤할 수 있습니다. 관리자에는 큰 글자의 효과 설명 전문도 함께 표시합니다. 전투 손패의 짧은 요약 표시 규칙은 유지합니다.
- 파일 선택 직후 네트워크 요청보다 먼저 로컬 미리보기를 표시합니다. 업로드 실패해도 선택한 이미지가 유지되고 다시 업로드할 수 있습니다. 업로드가 실패한 새 이미지를 표시하면서 이전 이미지/이미지 없음으로 잘못 저장하는 것은 차단합니다.
- 점검 상태가 공개 카드 이미지 읽기까지 차단하던 문제를 먼저 배포해 해결했습니다. 공개 카드/꾸미기 PNG·JPEG·WebP의 GET/HEAD만 허용하며, 점검 설정·대전·카드 목록·이미지 업로드·관리자 권한은 그대로 보호합니다.
- 운영 DB 및 저장소 원본 수정 없음. 코드의 이미지 표시와 편집 동작만 수정했습니다.

## 실제 검증
- pnpm build: 전체 타입 검사 및 프로덕션 빌드 통과.
- 단위 테스트 12개 통과: 실제 등록 PNG 6종의 숫자 칸 좌표, 해석 불가능한 이미지, 불투명 아트 영역 처리, 점검 이미지 읽기 허용과 쓰기/대전 차단.
- 실제 카드 관리자 화면 + 실제 인증/업로드 요청/완료 서명/카드 저장 API + 일회용 PGlite. 파일 전송용 저장소만 메모리 어댑터로 격리했습니다. 운영 저장소에 파일을 업로드한 검증은 아닙니다.
- 390×844, 844×390, 1440×1000: 새 챔피언 등급 주문 작성 → 실제 파일 선택 → 완료 요청 실패 → 로컬 이미지 유지 → 잘못된 저장 차단 → 재업로드 → 실제 저장 → 재진입 후 서버 URL 이미지 복원까지 통과했습니다.
- 실제 등록 챔피언 프레임의 코스트·이름판과 DOM 위치를 확인했습니다. 이름이 이름판 안에 들어가는지, 효과 본문이 생략되지 않는지, 긴 설명 8회 반복도 스크롤로 유지되는지 확인했습니다. JS 오류 0건. browser-results.json 참조.
- 기본 프레임 4등급 × PC·모바일 가로·세로 3화면, 총 12조합의 기존 숫자 위치 및 프레임 보정 동작 회귀도 통과했습니다. bundled/frame-results.json 참조.
- 실제 업로드 시나리오에는 등록된 챔피언 프레임 원본을 동일하게 사용하는 격리 주문을 사용했습니다. 이 테스트 카드는 운영 카드 풀에 추가하지 않았습니다.

## 사용
관리자 → 카드 → 새 카드/수정 → 이미지에서 파일을 고르면 즉시 아래/옆 미리보기에 표시됩니다. 실패하면 미리보기의 ‘이미지 다시 업로드’를 누릅니다. 효과 칸에는 전체 텍스트가 유지되며, 긴 설명은 칸 안 또는 아래 ‘효과 설명 전체’에서 읽습니다.

## 한계
물리 모바일 기기와 모든 운영 커스텀 프레임을 각각 육안으로 검사한 것은 아닙니다. 빈 영역이 분리되지 않은 디자인은 확인 가능한 칸만 보정합니다. 브라우저가 외부 이미지의 픽셀 접근을 허용하지 않으면 안전하게 기존 좌표를 사용합니다. 실제 대전 전체 회귀는 이번 편집/프레임 수정에서 실행하지 않았습니다.

운영 배포 확인은 production-verification.json에 기록합니다. main 병합 없음. 점검은 유지합니다.
