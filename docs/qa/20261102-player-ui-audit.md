# 플레이어 화면 점검 및 UI 개선

## 조사와 변경 범위

실제 앱의 홈, 대전 모드, 빠른 대전, 친선전, 드래프트, 상점, 내 팩, 출석, 퀘스트, 내 기록, 덱 편집, 컬렉션을 Chromium에서 점검했다. 대표 계정/카탈로그 응답으로 실제 라우트와 컴포넌트를 실행했으며 별도 목업을 만들지 않았다. 조사 중 완성도가 특히 낮았던 6개 화면과 공통 팩 상세·로딩 안내를 개선했다. 점검 범위와 수정 범위는 동일한 뜻이 아니다.

| 화면 | 발견한 문제 | 구현한 변경 |
|---|---|---|
| 출석 보드 | 긴 그리드 뒤에 수령 버튼, 잘리는 보상 이름, 수령 불가와 완료의 혼동 | 오늘 받을 보상/수령을 먼저 배치하고 전체 여정을 별도로 정리. 완료·잠금·다음 보상에 글자/아이콘 병용. 오늘 완료·전체 완료·현재 수령 불가를 구분 |
| 퀘스트 | 반복 카드와 설명으로 진행도·보상·행동이 분산 | 목표→설명→진행→보상/수령의 일관된 행 구조. 수령 가능한 목표를 미완료 추가 보상보다 먼저 배치. 실제 서버 상태로만 수령 가능 여부 표시 |
| 상점 | 등록된 상품 이미지보다 팩 이미지만 참조, 이미지 없으면 큰 선물 아이콘 반복 | 상품 표지를 우선 사용, 없으면 팩 표지, 둘 다 없으면 KO 브랜드 슬리브 대체 표시. 이미지/설명/수량/총액/구매의 위계를 정리 |
| 내 팩 | 조밀한 확률 문장과 여러 버튼 | 보유 수량·개봉 수량을 구분하고 6종 확률을 읽기 쉬운 표로 배치. 상점/내 팩 간 이동, 비어 있는 화면과 조회 재시도 보강 |
| 내 기록 | 긴 설명·전적·수집 목표와 반복 버튼이 한 화면에 혼재 | 기록/수집 탭, 모드 필터, 전적 요약, 덱별 기록과 최근 경기 분리, 20개씩 더 보기. 목표 해제는 확인 후 처리하고 로컬 기록의 저장 범위를 안내 |
| 드래프트 진입 | 관리 양식처럼 보이는 두 버튼, 중복 제목 | 실제 선택 흐름(챔피언→25장→대전) 안내, 현재 카드 풀의 원화 또는 KO 대체 표시, AI/빠른 대전 행동의 설명. 기존 시작/선택/종료 요청을 그대로 사용 |

검정·절제된 금색·확정 폰트·원본 일러스트/카드 프레임을 유지했다. 표지 대체 슬리브와 드래프트의 KO 대체 표시는 UI용 HTML/CSS이며 새 등록 게임 에셋이나 전문 아트 에셋이라고 주장하지 않는다. 등록된 이미지는 그대로 우선 사용한다. 새로운 전투 효과·사운드는 추가하지 않았다.

## 상태와 정보의 정확성

- 출석의 보상 카탈로그 조회를 실제 출석 상태 조회와 분리했다. 카탈로그 이미지 조회 실패가 보상 수령을 막지 않는다. 이미지 실패 시에도 수량/종류와 대체 아이콘은 보인다.
- 출석/퀘스트의 비어 있음과 조회 실패를 구분하고 읽기 재시도를 제공한다. 조회 중 화면 이탈·재조회는 오래된 응답을 정리한다. 실제 수령 중 반복 입력과 포커스 복귀 조회가 결과를 덮지 않게 한다. 서버 판정/금액/보상 조건은 바꾸지 않는다.
- 팩 상세의 “스킨은 별도 보너스”라는 오래된 안내를 현재 6종 합산 방식과 일치시켰다. 표시하는 확률 값은 기존 데이터다. 스킨·이모티콘의 슬롯 점유 및 현재 합계도 안내한다.
- 기존 구매 확인/취소, 수량 상한, 팩 요청 키와 미확정 개봉 복구 잠금, 제작·덱·계정·보상 정책은 유지한다.
- 내 기록은 기존 계정별 브라우저 저장 키를 그대로 쓴다. 서버 공식 전적으로 표시하지 않는다. 기존 기록/보유 아이템을 삭제하거나 이전하지 않는다. 잘못된 날짜의 과거 로컬 기록도 화면을 중단시키지 않게 했다.

## 적용한 심리학 원칙

시각적 위계: 오늘 받을 보상, 수령 가능한 목표, 총 구매 금액과 확정 행동을 우선한다. 인지 부하·게슈탈트: 관련 정보를 묶고 반복 버튼을 줄인다. 힉의 법칙: 기록과 수집, 일일과 시즌, 상점과 보유 팩을 구분한다. 피츠의 법칙: 주요 조작은 최소 44px 높이를 확보한다. 행동 통제감: 선택/구매 확인/수령 결과와 실패를 구분하고 재시도를 제공한다. 강약 대비·반복 피로: 잠긴 보상과 받은 보상은 물러나고 사용 가능한 행동만 금색으로 강조한다. 호버는 장식만 움직이고 조작 좌표를 바꾸지 않는다. 모션 감소에서는 새 장식 움직임과 전환을 줄인다. 보상 연출은 기존 확정 응답 이후에 재사용한다. 사용자 만족도·탐색 시간 개선을 실제 사용자 실험으로 입증한 것은 아니다.

## 검증

- 모바일 390×844·PC 1440×1000에서 12종 실제 화면, 총 24개 캡처: 가로 넘침·pageerror 없음. 컬렉션·덱 편집 등 기존 화면도 점검했으며 이 결과를 전체 기능 회귀 통과라고 확대하지 않는다.
- 실제 UI + 통제한 API/WS 응답: 360×740·390×844·844×390·1440×1000에서 출석 단일 수령/재진입, 퀘스트 단일 수령·시즌 전환·추가 보상, 구매 확인·취소·확정과 정확한 수량, 6종 팩 상세, 일괄 개봉 요청 키/보유 수량, 기록 필터·목표 해제 확인·재진입 확인. 조회 실패 복구 4화면, 비어 있는 화면 5화면, 보상 없음이 수령 완료로 표시되지 않는 경계 상태 포함.
- 실제 격리 PGlite/Express 퀘스트 HTTP/브라우저 8개 통과. 관리자 등록→일반 유저 실제 목표 진행/수령, 일일/시즌, 계정 격리·중복·롤백 포함. 운영 빌드의 일반 유저 화면을 1440·390·320 너비에서 확인했다.
- 실제 격리 완성 덱 DB/HTTP 22개 및 브라우저 7개 통과: 관리자 등록/업로드, 정확한 구성·가격·부족분 지급·저장·출전 덱 지정, 360/375/390/412 너비, 구매한 덱으로 실제 AI·양측 PvP 진입. 추가로 보상 카탈로그 요청을 실패시켜도 실제 출석 수령이 가능하고, 수령 요청 1회·잔액 +123·기록 1개·재진입 완료 상태를 확인했다. 이 123은 격리 테스트 설정이며 운영 보상 값이 아니다.
- 실제 격리 드래프트 HTTP 사전 회귀 18개와 일반 유저의 새 진입→실제 AI 드래프트 시작→챔피언 선택→정상 종료/진입 복귀를 390×844·1440×900에서 확인했다. 챔피언 선택 후 덱 카드는 0/25가 정상이며 선택한 챔피언을 카드 한 장으로 잘못 계산하지 않았다.
- 기존 팩 개봉/요청 키 클라이언트 검사 8개 통과.
- 프런트 타입 검사와 운영 빌드 통과.

기존 브라우저 검사에 남아 있던 ‘대표 덱 선택’과 수동 ‘매치 시작’ 선택자는 현재의 출전 덱 지정/자동 AI 진입 동작에 맞게 갱신했다. 실패한 오래된 선택자 검사를 통과한 것으로 처리하지 않았으며 갱신 후 실제 흐름을 다시 실행했다.

검증은 실제 앱을 사용한다. 레이아웃/에러/반복 입력 검사는 명시적인 API fixture이고, 별도로 설명한 격리 DB/HTTP 검사는 실제 저장·수령·구매·대전 흐름이다. 운영 사용자 데이터로 거래하거나 보상을 받지 않았다. 물리 모바일/Safari/전체 장기 플레이/정량 FPS/실제 사용자 선호도는 미검증이다.
