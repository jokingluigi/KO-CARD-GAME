# Home screen fits one viewport

The user clarified that the entire home menu must fit without scrolling. This supersedes the previous page-scroll implementation.

## Implementation

- MainMenu now uses a 100dvh layout with independent toolbar, compact brand/account header, notice summary and grouped menus. Background artwork no longer consumes an extra block above the menu on phones.
- All 13 enabled menu actions remain available at once. Portrait phones stack the three groups; utility actions use three columns. Desktop/landscape puts the three groups beside each other. Smaller-height layouts reduce decoration and secondary copy before reducing controls.
- Main menu actions retain >=44×44 CSS px targets, growing to 68px tall where phone height allows. Small screens show action names, with descriptions retained through accessible descriptions and titles; roomy desktop layouts show descriptions inline.
- Notices use an accessible dialog with its own long-content reading area. Nickname editing also uses a dialog so neither flow pushes home actions offscreen. Escape closes each dialog and restores focus. Long notice text may scroll inside its dialog; the home screen itself does not scroll.
- Install instructions open as a bounded overlay; audio and installation controls remain available. Short phones use labeled icon buttons for nickname edit/logout, preserving accessible names. Existing navigation, sound settings, account functions and battle features are retained.
- Dedicated home component styles compose with the existing art direction. The new layout explicitly replaces the old blanket section frame and battle text sizing that caused overflow during the first layout pass. No gameplay, API or database changes.

## Design rationale

Retain the three functional groups to reduce search/choice effort. Give primary actions stable positions, keep touch targets large, and move occasional long content into focused dialogs. Use remaining viewport height to enlarge buttons instead of shrinking the whole page or hiding offscreen controls.

## Executed validation

Real application home route/MainMenu, mocked API/auth data, existing local illustration fixture, six long notices, Android user-agent installation instructions, long nickname and seven-digit currency balance. Tower and draft enabled to exercise every menu.

Chromium at 320×568, 360×568, 360×640, 360×740, 375×812, 390×844, 412×915, 740×360, 844×390, 768×1024, 1024×768 and 1440×900:

- Document width/height equals viewport; wheel scrolling leaves scrollY at zero.
- Every one of 13 menu buttons is entirely within the viewport, >=44×44px, and receives original elementFromPoint hit testing without overlap.
- Notices open/read/close; nickname dialog edits locally then cancels; install instructions fit horizontally; volume settings open/close.
- Viewport dimensions swapped and restored; all menu bounds remain within the rotated viewport and the document remains fitted.
- No browser page errors. Frontend typecheck and production build passed.
