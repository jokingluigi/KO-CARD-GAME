# 이미지 이모티콘 기본 지급

2026-11-02 · 작업 브랜치 `feat/home-battle-mode-art` · main 병합 없음.

## 관리자 사용법

관리자 → 꾸미기 관리 → 이미지 이모티콘 선택(또는 새 아이템) → **기본 지급** 체크 → **아이템 저장**. 체크 상태와 목록의 기본 지급 표시가 저장 후 재진입해도 유지된다. 유형을 다른 꾸미기로 바꾸면 이 옵션은 제공하지 않는다.

활성 이모티콘에만 적용한다. 기존·신규 계정 모두 꾸미기 보유 목록 조회/장착/대전 꾸미기 조회 시 아직 없는 기본 이모티콘을 한 번 지급한다. 오프라인 계정을 일괄 수정하지 않는다. 유저는 꾸미기 → 이모티콘에서 원하는 슬롯에 직접 장착한다. 자동 지급으로 기존 장착 슬롯을 바꾸지 않는다.

옵션 해제는 이후 자동 지급만 중단하며 이미 보유한 선물은 유지한다. 옵션 해제 후에는 기존 개별 회수 기능을 사용할 수 있다. 기본 지급이 켜진 활성 이모티콘의 개별 회수는 명확한 오류로 막아 조회 직후 재지급되는 혼란을 방지한다. 비활성 아이템은 새 지급/장착에서 제외된다. 기본 지급 해제와 아이템 삭제는 서로 다른 기존 동작이다.

유저 보유 목록에는 **기본 지급 이모티콘**을 표시한다. 관리자 체크 영역은 44px 높이의 클릭/터치 영역을 제공하고, 지급 시점·기존 장착 유지·옵션 해제의 의미를 옵션 바로 아래에 설명한다. 변경 결과를 예측하고 실수를 줄이려는 설계이며 사용자 연구로 효과를 입증한 것은 아니다.

## 구현과 데이터 보호

기존 cosmetic_items.image_assets JSON의 검증된 메타데이터 `__defaultGrant: "true"`를 사용한다. 새 테이블/컬럼/마이그레이션은 없다. 관리자 API는 이모티콘 유형·정확한 값·실제 이미지 등록을 검증하며 메타데이터를 이미지 주소로 검증하지 않는다. 다른 꾸미기 유형이나 boolean true 등 잘못된 설정은 거부한다.

서버 `ensureDefaultEmotes`가 기존 user_cosmetics에 DEFAULT_EMOTE 출처로 소유권을 생성한다. 실제 존재하는 사용자 및 활성 이모티콘만 대상이며 PK 충돌 시 중복 삽입/기존 획득 출처 덮어쓰기를 하지 않는다. 권한은 실제 소유 테이블로 확인하므로 기존 장착·경기 스냅샷 구조를 그대로 사용한다. 이미지 메타데이터는 전투 규칙에 전달하지 않는다.

첫 꾸미기 조회 전에 기본 지급 이모티콘이 팩에서 나오는 경우에도 기존 팩 트랜잭션 안에서 기본 소유권을 먼저 반영해 중복 보유 여부가 일관된다. 팩 확률·풀·보상 정책은 바꾸지 않는다. 카드/챔피언/스킨/카드 뒷면 소유권과 전투 판정도 변경하지 않는다. 운영 카탈로그에서 임의의 이모티콘을 기본 지급으로 지정하지 않았으며, 실제 기본 지급할 항목은 관리자가 선택한다.

## 실제 검증

- PostgreSQL 호환 격리 PGlite DB와 실제 Express API/업로드 검증/장착/PvP 스냅샷·이미지 이모티콘·팩 처리 회귀 24개 통과.
- 추가한 검사: 관리자 외 설정 거부, 잘못된 유형/값/이미지 없는 설정 거부, 기존/신규 사용자 지급, 동시 조회 중 중복 방지, 기존 장착 유지, 실제 장착과 재조회, 활성 기본 지급 중 개별 회수 거부, 옵션 해제 후 보유 유지/회수 유지, 비활성 제외/재활성 지급, 팩 첫 개봉 전 기본 소유권과 중복 보유 표시.
- 실제 관리자/유저 UI 390×844·1440×900: 이미지 업로드→기본 지급 체크→저장→재진입→유저 보유 확인→슬롯 장착→재진입, 기본 지급 해제 후 보유 유지 및 회수 후 재지급되지 않음, 다른 유형에 옵션 미노출, 44px 라벨 확인. 격리 HTTP/DB를 사용했고 운영 데이터에는 쓰지 않았다.
- 공유 꾸미기 라이브러리·API·프런트 타입 검사 및 API/프런트 운영 빌드 통과.
