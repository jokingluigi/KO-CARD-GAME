# 카드 위의 사용 버튼 위치 유지

사용자가 중앙 조작줄로 옮기는 방식을 원하지 않아, ‘사용’ 버튼을 카드 위 기존 위치로 복원했다. 이전에 수정한 버튼 입력 안정화는 유지한다.

## 구현

- 버튼을 중앙 턴 조작줄에서 제거하고, 선택한 카드의 레이아웃 기준점에 붙인다. 손패를 직접 가로로 넘길 때는 해당 카드와 함께 이동하며 화면의 다른 위치에 떠 있지 않는다.
- 버튼은 카드 그림의 선택 확대·이동·이펙트 레이어와 형제 관계로 분리했다. 카드 그림이 움직여도 버튼은 그 모션을 상속하지 않는다.
- 버튼이 나타날 때 손패 간격이 애니메이션으로 벌어져 버튼을 밀던 현상을 없앴다. 해당 상태에서 간격은 즉시 확정하고 카드 자체의 확대/선택 표시는 유지한다.
- 버튼의 일반 누름 축소·1px 이동 효과도 제거한다. 색과 명암 피드백만 사용한다.
- 누르는 순간의 기본 포커스 자동 스크롤을 막고, 포커스는 `preventScroll`로 맞춘다.
- 기존 포인터 캡처·버튼 안 해제 시 사용·취소/밖 해제 시 미사용·합성 click 중복 방지·키보드 사용은 유지한다. 버튼을 카드 드래그 시작점으로 다시 추가하지 않는다.
- 카드 효과·기본 비용·대상 판정·손패 및 필드 카드 크기를 변경하지 않았다.

## 실제 검증

실제 공통 대전 UI와 엔진을 사용하는 `docs/qa/anchored-spell-use-browser.mjs`를 Chromium에서 실행했다.

- 터치 360×740, 390×844, 844×390과 마우스 1440×900에서 각각 통과.
- 동작 감소를 끈 상태로 같은 검증을 두 번 반복해 통과.
- 선택 직후 여러 프레임의 버튼 좌표, 버튼을 누르고 120ms 유지했을 때 위치·크기 변화를 1px 미만으로 확인했다.
- 카드 위에 버튼이 있고 중앙 조작줄에는 없는지 확인했다.
- 손패 가로 스크롤 후 카드 기준점과 버튼의 상대 위치가 같은지 확인했다.
- 15px 손가락 이동에도 정확히 1회 사용, 고스트 없음, 비용 한 번 지불을 확인했다.
- 대상 주문, 터치 취소/버튼 밖 해제, 키보드 Enter, 골드 부족 및 상대 턴 제한 확인.
- 페이지 오류 0, 가로 넘침 없음.

카드 몸체의 기존 주문 드래그 회귀 검증도 수행한다. 타입 검사와 API·프런트 `pnpm build`는 통과했다. 물리적 휴대전화 및 운영 유저 경기 조작은 실행하지 않았다.

[모바일 화면](mobile.png) · [PC 화면](desktop.png) · [검증 결과](results.json).

이 검증은 카드를 손으로 가로 스크롤할 때도 버튼이 화면에 고정돼 있다는 의미가 아니다. 사용자가 요청한 카드 위 위치를 유지하며, 선택·누름·카드 그림 효과 때문에 버튼이 흔들리는 것을 분리한 것이다.

## 배포

production 브랜치와 승인 SHA 고정 배포 절차로 반영한다. main 병합·운영 카드 데이터 변경은 하지 않는다. 운영 확인 결과는 별도 JSON에 기록한다.

배포 완료: `ab7b26509dbf6ab0ded25726a042e310845828c3`를 서버·프런트 모두 live로 확인했다. 실제 공개 버전과 첫 화면에서 로드되는 진입 JS가 해당 커밋인지 확인했고, 운영 UI 청크에서 카드 기준점(`ko-hand-use-action`)과 개선된 버튼 입력 처리를 확인했다. [운영 확인](production-verification.json).

배포 확인 중 첫 화면 HTML이 CDN에서 이전 진입 JS를 가리킨 채 최대 300초 캐시되는 현상을 확인했다. Render에서 `/`, `/index.html`, `/version.json`에 `no-cache, no-store, must-revalidate` 헤더를 설정하고 프런트를 동일 승인 커밋으로 다시 배포했다. 실제 루트와 index.html에서 새 진입 JS 및 새 헤더를 확인했다. 이미지·해시 자산의 캐시 정책은 바꾸지 않았다. [헤더 설정](cache-headers.json).

기존 주문 드래그 회귀는 360/375/390/412px 모바일 및 1440px PC에서 통과했다. 기존 안정화 브라우저 실행기도 카드 기준점 배치에 맞춘 상대 좌표 검사로 갱신하고 4개 화면 크기에서 통과했다.
