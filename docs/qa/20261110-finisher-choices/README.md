# 필드 조건 · 피니셔 선택지 · 카드 복귀 · 러쉬 우선

작업 브랜치: `fix/finisher-choices-and-card-return`. main 병합 및 운영 DB 직접 수정 없음. 배포 증빙은 `production-verification.json` 참조.

## 실제 구현

- 아군 필드 존재 조건: source 인스턴스 제외. 동일 카드의 다른 인스턴스는 허용. 기존 BOARD_HAS_TAG와 지속 필드 부여의 동작을 유지하고 SCRIPT_V1의 SELECT/COUNT → IF 존재 검사 및 BOARD_COUNT의 존재 검사에 적용. 명시적인 카드 수 합산·효과 대상 목록은 변경하지 않음.
- 피니셔 선택지: 기존 `questCondition` JSON의 `finisherChoices`에 독립 조건과 실제 챔피언 토큰 주문 카드 참조 저장. 기본 퀘스트 엔진 및 기존 챔피언의 보상은 선택지를 따로 설정하지 않으면 그대로 동작.
- 하나만 완료하면 자동으로 해당 피니셔를 지급하고 나머지를 영구 비활성화. 같은 효과/행동에서 여러 개 완료하면 확인 버튼이 있는 선택 창 표시. 중간 대상 선택이나 버리기가 남으면 기존 처리를 끝낸 뒤 확정. 주문 사용 후에도 잠금 유지.
- 확정된 피니셔는 일반 비드로우 손패 추가 경로 사용. 손패 초과 시 기존 손패에서 직접 1장 버리기. 서버 저장 상태에 완료·선택·대기 정보를 유지하고 중복 요청, 재접속, 상대 대기를 처리. 선택 중 턴 시간 만료가 강제 확정/취소하지 않음.
- 필드에서 손패·덱으로 복귀: 현재 비용·공격력·최대 체력을 유지하고 완전히 회복. 필드의 기절·침묵·사용 상태와 이전 만료 타이머는 정리. 묘지 초기화 규칙은 유지. 효과 자체가 지정한 별도 비용 변경은 계속 적용.
- 러쉬+기습: 등장 턴에도 러쉬에 따라 선수 및 챔피언 공격 가능. UI 공격 가능 표시와 실제 판정 일치. 기절·도발·토큰 보호·공격 횟수 제한 유지.
- 대전 도움말에 복귀 스탯, 러쉬 우선, 피니셔 선택지 규칙 추가.

## 관리자 등록

챔피언 관리 → 편집 → 피니셔 준비 기능을 켜고 **피니셔 선택지**에서 2~8개 설정.

1. 각 선택지의 고유 ID, 이름, 조건 설명 입력.
2. 카드 관리에서 미리 만든 **챔피언 등급 토큰 주문** 선택. 새 등급/카드는 자동 생성하지 않음.
3. 기존 조건 편집기로 행동 누적, 턴, 체력, AND/OR 조건 각각 설정.
4. 저장 후 재진입하여 확인. 챔피언 공개 시 참조 주문도 공개되어 있어야 함.

선택지 사용 해제를 누르면 기존 단일 조건·보상으로 복귀한다. 선택지를 사용하는 동안 기존 단일 보상을 추가로 지급하거나 고유 능력을 자동 강화하지 않는다. 고유 능력 교체는 설정된 주문의 실제 효과가 담당한다.
