# 자동 로그인 복원·로그인 지연 개선 — 2026-10-29

기존 기능 브랜치에서 작업. main 병합·스키마 변경·Production DB 직접 변경 없음.

## 조사 결과와 확인 범위

사용자의 모바일 캡처는 세션 복구 대기 UI다. 이 이미지 자체만으로 쿠키 삭제나 특정 서버 장애를 확정할 수 없다. 조사 시 운영 비로그인 `/auth/me`는 프런트 프록시0.38초, 직접 API0.83초, 프런트 health0.49초였다. 당시 장애가 재현되지는 않았다.

Render API 조회로 운영 API의 플랜이 free임을 확인했다. 휴면 인스턴스의 시작 지연은 클라이언트 코드만으로 없앨 수 없다. 유료 플랜 전환·서비스 종류 변경·외부 상시 깨우기는 이번 작업에서 하지 않았다.

코드에서는 다음 불필요한 대기/경합을 확인했다.

1. 일반 로그인도 health GET이 완료돼야 비밀번호 POST를 보냈다.
2. 초기 세션 GET이 한 연결에서 멈추면 최대60초 동안 그 요청만 공유했다. 관리자 진입도 별도 세션 요청 하나의8초 제한에 묶였다.
3. 로그인 전의 점검 상태 요청이 로그인 후에도 재사용될 수 있었다. 이미 새 요청이 시작됐는데 오래된 요청의 finally가 새 공유 요청을 지울 가능성도 있었다.
4. 점검 상태 확인에서 검증한 관리자 세션을 같은 HTTP 요청의 관리자 처리에서 다시 읽는 중복이 있었다.

## 구현

- 기본 로그인은 즉시 POST를 한 번 보낸다. 기본 경로의 health 사전 요청을 제거했다. 명시적인 `wakeTimeoutMs` 호출만 기존 GET 준비 확인을 사용한다.
- 일반/관리자 세션 GET에 공통 `restoreSession`을 적용했다.1.5초 넘게 지연되거나 일시적인 전송 오류가 나면 새 GET을 **한 번만** 허용하고, 먼저 검증된 정상 응답을 사용한다. 빠른 응답이면 추가 GET은 없다.
- 실패한 보조 조회가 원래 요청의 늦은 정상 응답을 폐기하지 않는다. 마감/완료/화면 이탈 시 타이머와 남은 요청을 취소한다.
-401/403 같은 권한 거부는 재시도하지 않는다. 통신 실패를 guest나 로그인 성공으로 바꾸지 않는다.
- 로그인/로그아웃 후 점검 상태를 새로 읽고 이전 세대 응답은 화면 상태를 덮지 못하게 한다. 오래된 finally는 새 공유 요청을 지우지 않는다.
- 같은 HTTP 요청 안에서 검증한 관리자만 재사용한다. 요청 간 인증 캐시나 권한 완화는 추가하지 않았다.
- 로그인 POST 상한은 기존20초에서60초로 조정했다. 이는 건강한 서버의 응답을 늦추는 대기가 아니라, 늦은 서버 응답을20초에 끊고 다시 비밀번호를 입력하게 만드는 일을 줄이기 위한 최대 제한이다. POST 자동 재전송은 없다.
- 기존30일 HttpOnly/SameSite 쿠키, 서버 검증, 취소, 로그인/로그아웃 세대 무효화, 확정 세션의 짧은 페이지 이동 캐시를 유지했다. 비밀번호·세션 토큰을 localStorage에 저장하지 않는다.

## 실제 검증

- 인증/세션/시작/관리자/점검 관련 자동 검사 **37 통과, 실패0**.
- 격리 PGlite API의 실제 로그인 경로와 브라우저 HttpOnly 쿠키를 사용했다. 운영 DB·계정으로 테스트 로그인하지 않았다.
-390×844/1440×900 모두 실제 쿠키로 새 브라우저 컨텍스트·새로고침 후 POST 없이 로그인 복원. 쿠키30일 만료·HttpOnly·SameSite=Lax 확인.
- 브라우저 재접속 복원: 모바일514ms/PC536ms. 첫 GET만 의도적으로 멈춘 경우2000ms/1995ms에 두 번째 GET으로 복원. 관리자 진입의 같은 조건은2110ms/2022ms.
- 로그인 입력/클릭/메뉴 표시를 포함한 로컬 작업 시간: 모바일935ms/PC882ms. 각 경우 로그인 POST1회, 기본 health 사전 요청0회.
-21초 늦춘 로그인 POST 응답은 약21.86초 후 정상 수신. 비밀번호 입력 유지, 중복 POST 없음.
- 로그아웃으로 폐기한 쿠키를 새 컨텍스트에 다시 주어도 인증되지 않음.
- 늦게 도착한 로그인 전 점검 거부가 로그인 후 메인 화면을 덮지 않음.
- 전체 세션 응답을25초(모바일)/9초(PC) 늦춘 검사도 통과. 기존 GET을 유지하면서 추가 GET은 최대 한 번이며 로그인 POST는0회.
- 기존 로그인 경합·로그인 화면 깜빡임·페이지 이동 세션 재사용·관리자 메뉴 검사가 통과했고 브라우저 pageerror는0이었다.
- 프런트 타입 검사·프로덕션 빌드, API 빌드 통과.

위 수치는 로컬 Chromium/격리 API에서 측정한 값이다. 운영 모바일 네트워크의 지연·무료 서버 절전 해제 시간을 보증하거나 개선 전후의 실기기 수치로 주장하지 않는다. 사용자가 겪은 정확한 과거 실패 요청은 캡처에 없으므로 원인 전체를 확정하지 않았다.
