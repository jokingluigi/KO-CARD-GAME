인지 부하 감소를 위해 준비 상태와 다음 행동을 붙이고, 힉의 법칙에 따라 덱 선택과 편집을 분리했다. 스킨/이름 동시 교체는 지각적 일치를, 중복 요청 차단과 실패 복구는 행동 통제감을 지원한다. 사용자 만족도나 행동 시간 개선은 실제 사용자 실험으로 입증한 결과가 아니다.

## 침묵 면역

`rarity === CHAMPION`이며 토큰(`isToken` 또는 `isChampionToken`)인 카드에 적용한다. 생성, 챔피언 토큰 직접 배치, 필드 이탈 초기화, 일반 침묵, 복합 약화/기절/침묵 경로를 연결했다. 이전 저장 상태의 면역 플래그가 false여도 현재 카드 정의로 판단한다. 클라이언트와 서버가 사용하는 공통 엔진에 적용된다.

일반/레전더리 토큰과 비토큰 챔피언 등급 카드는 새 면역을 받지 않는다. 약화·기절·리타이어·파괴·소멸은 기존대로 적용된다. 이미 과거에 침묵되어 소실된 강화 정보를 소급 복원하지 않는다. 카드 원본 데이터와 설명, 기타 판정은 변경하지 않았다.

## 실제 검증

- 엔진 회귀 264개 통과 후, 마지막 추가 경계 검사를 포함한 집중 검사 70개 통과. 두 집합은 중복되므로 합산하지 않는다.
- 프런트/API 타입 검사 및 운영 빌드 통과.
- 실제 홈 경로 390×844 / 740×360 / 1440×900: 덱 검색·선택·재진입, 중복 요청, 선택 실패 복구, 지연된 스킨/제목 동시 교체, 잘못된 덱 차단, 구성 요약, 보유 팩, 이미지 실패 확인.
- 일반/관리자 계정 각각 12개 화면 크기(320×568~1440×900): 주요 버튼 배치, 겹침 없음, 홈 스크롤 없음, 터치 영역, 화면 회전 확인.
- 실제 덱 편집→저장→빠른 대전 자동 시작/취소→AI 대전 진입: 모바일/PC 통과. 덱 없음/잘못된 덱에서 임의 대체 덱으로 시작하지 않음.
- 실제 빠른 대전 경로에서 WebSocket 메시지로 연결 요청→검색→MATCH_FOUND→VS→공통 전투 화면 전환 확인. 중복 참가 요청 없음.
- 실제 공통 전투 UI/엔진 390×844 / 1440×900: 주문 선택·사용·대상 지정 후 챔피언 토큰 능력치/키워드 유지, 일반 선수 침묵 정상, 주문 비용 정상 소비.

브라우저 검사는 Chromium 및 격리된 HTTP/WebSocket 데이터로 수행했다. 운영 계정·덱·보상·팩 소비 데이터를 쓰지 않았다. 공통 전투 UI 검사는 DEV 진입점을 통해 실제 엔진 상태를 주입했으며, 전체 운영 PvP 경기를 수행한 것은 아니다. 물리 모바일 기기, 외부 사용자 양측 실제 PvP, 실제 서비스 장시간 네트워크 지연은 미검증이다. 기존 모바일/PC 게임 기능 전체를 전수검사했다고 주장하지 않는다.
