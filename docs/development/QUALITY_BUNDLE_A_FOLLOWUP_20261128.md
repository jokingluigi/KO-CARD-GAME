# 묶음 A 후속 — 공통 업그레이드 안내와 고유 능력 표제

사용자의 후속 지시: 신입 사이드킥 이외 업그레이드 및 이후 추가 카드에 공통 적용되는지 확인하고, 개별 고유 능력 이름 표시는 제거한다.

## 업그레이드 적용 범위

- 기존 `card-play-preview.ts`는 이름/ID별 목록이 아니라 활성 효과의 공통 `PROGRAM` 구조를 검사한다. 등장 시 또는 기술 사용 시의 업그레이드 형식으로 추가되는 새 카드에도 별도 등록 없이 적용된다. 이 구조는 유지했다.
- 공개 규칙을 고정한 7종(신입 사이드킥, 파일럿 사이드킥, 세라핌 블로우, 스칼렛 파우더, 레인보우 라이더, 떼껄룩(에스페란사), 라 토마티나)을 실제 엔진 실행과 비교했다. 나토마토(에스페란사)의 업그레이드 비용 면제도 각 카드에 대해 검사했다.
- 대상 선택이 먼저인 효과는 ‘선택 전까지의 비용’ 및 ‘선택 후 결정’을 표시한다. 선택/후속 조건이 남아 있는 비용을 확정 최종값으로 표현하지 않는다. 이번에 이 기존 구분을 삭제하지 않았다.
- 임의의 새 이름·ID를 가진 2골드 3/2 카드를 테스트에서 직접 작성했다. 업그레이드 추가 1골드와 +2/+1 효과가 별도 preview 등록 없이 합계 3골드·5/3으로 계산되고 실제 사용 결과와 일치했다.
- 새로운 엔진 액션이나 별도의 발동 방식까지 자동 지원한다는 뜻은 아니다. 이번 검증은 현행 공통 등장/사용 업그레이드 구조를 대상으로 한다.

## 이름 표시 제거

- `battle-action-explanation.ts`의 챔피언 능력 표시 표제는 항상 ‘고유 능력’이다. 효과 본문/비용/대상은 계속 현재 능력/override에서 읽는다.
- `game-state-preview.tsx`의 버튼·설명창·대상 선택 안내·접근성 이름에서도 예전 개별 능력 이름을 노출하지 않는다. 일반 카드/기술의 이름은 그대로 유지한다.
- 기존 능력 ID, 카드 데이터, 능력 실행, 골드/사용 횟수/밸런스는 변경하지 않았다.

## 검증

- 관련 회귀 178개 통과(최초 A 대비 신규 업그레이드 확인 16개 추가).
- 라이브러리/프런트/API 타입 검사, 프런트/API 빌드 및 diff 검사 통과. 명령과 결과는 `docs/qa/20261128-quality-a/verification.json` 참조.
- 데스크톱 및 390×844 모의 터치에서 ‘고유 능력’ 표제, 기존 효과·비용·대상 설명, 설명 열기/닫기의 무지불을 확인했다. 선택 설명창에는 예전 판도라 능력 이름이 없음을 검사했다.
- `public-upgrades.json`, `public-upgrade-support.json`은 공개 카드 정보의 필요한 필드만 저장한 테스트 스냅샷이다. 실제 휴대전화·운영 한 판·새로운 규칙 문법의 전수 검증은 하지 않았다.
- 운영 미배포, 원격 푸시/운영 데이터 변경 없음.
