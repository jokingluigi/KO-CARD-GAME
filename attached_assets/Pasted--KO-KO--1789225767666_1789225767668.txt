현재 KO 카드게임의 전체 게임 연출을 개선해줘.

목표:
게임플레이 규칙은 변경하지 않고,
디지털 카드게임에서 느껴지는 자연스럽고 명확한 타격감과 피드백을
KO 전체 게임에 적용한다.

특히 다음 흐름이 자연스럽게 보여야 한다.

사용자 행동
→ 카드/캐릭터 움직임
→ 효과 발생
→ 대상 반응
→ 수치 변화
→ 사망/소환/후속 효과
→ 다음 행동 가능

현재처럼 결과가 갑자기 숫자로만 바뀌거나
여러 효과가 동시에 튀어나와 무엇이 일어났는지 알기 어려운 상황을 줄여줘.

중요:
하스스톤의 그래픽 자산이나 UI를 복제하지 말고,
KO의 현재 디자인을 유지하면서
"디지털 카드게임다운 연출 리듬과 피드백"만 적용해.

==================================================
0. 가장 중요한 구조
==================================================

게임 로직과 애니메이션을 분리해.

Game Engine
→ Game Event 생성
→ Animation/Presentation Queue
→ UI Animation
→ 다음 Event

구조로 만들어.

예:

CARD_PLAYED
ENTER_FIELD
DAMAGE
BUFF
HEAL
ATTACK
RETIRE
DESTROY
DRAW
QUEST_PROGRESS
QUEST_COMPLETED

같은 기존 Event Log를 최대한 재사용해.

게임 규칙을 animation callback 안에 넣지 마.

애니메이션은 GameState의 결과를 표현하는 역할만 해야 한다.

==================================================
1. Animation Queue
==================================================

한 번의 카드 효과로 여러 이벤트가 발생할 때
전부 동시에 터뜨리지 말고
짧은 Animation Queue로 순서대로 보여줘.

예:

카드 등장
→ 150~300ms
→ 등장 효과 강조
→ 대상 highlight
→ damage
→ target hit reaction
→ HP 감소
→ RETIRE
→ 후속 소환

처럼 읽을 수 있게 한다.

단 너무 느려서 게임이 답답해지면 안 된다.

일반적인 작은 효과는 빠르게,
중요한 효과만 조금 더 강조해.

==================================================
2. 애니메이션 속도 기준
==================================================

전체적으로 빠른 카드게임 템포 유지.

권장 범위:

micro feedback:
80~150ms

일반 효과:
150~300ms

카드 플레이:
250~450ms

공격:
300~600ms

큰 카드 / 큰 피해:
400~700ms

Quest 완료 / Champion 변신:
700~1200ms

필요하면 현재 프로젝트에 맞게 조정해.

효과 하나마다 1~2초씩 기다리는 느린 게임으로 만들지 마.

==================================================
3. 카드 손패 Hover / Tap
==================================================

Desktop:
손패 카드 hover 시

- 카드가 살짝 위로 올라옴
- 약간 확대
- 주변 카드보다 높은 z-index
- 부드러운 easing

Mobile:
tap/select 시 동일한 방식으로 위로 올라오고 확대.

선택 해제 시 자연스럽게 원위치.

카드가 갑자기 크기 변경되지 않게
transform transition 사용.

==================================================
4. 카드 플레이
==================================================

선수 카드를 손에서 플레이하면:

손패
→ 살짝 확대
→ 선택한 Board Slot 방향으로 이동
→ Field에 착지
→ 아주 짧은 bounce/impact
→ ENTER_FIELD 처리

순서로 보여줘.

카드가 순간이동하듯 사라졌다가 Field에 나타나면 안 된다.

기존 FLIP/getBoundingClientRect 방식이 있다면 재사용.

==================================================
5. Cost에 따른 등장 무게감
==================================================

기존 KO 규칙:

0~2 Cost
3~5 Cost
6+ Cost

를 연출에도 사용해.

0~2:
빠르고 가벼운 착지

3~5:
조금 묵직한 착지

6+:
강한 착지 + 아주 짧은 board impact

단 과도한 화면 흔들림/파티클은 금지.

기존 ENTER_COST SFX와 정확히 동기화.

==================================================
6. 선수 등장
==================================================

카드가 Field에 도착한 순간:

1. 카드 Landing
2. ENTER SFX
3. 카드 전용 Entrance Music이 있으면 재생
4. ENTER_FIELD effect 시작

순서가 자연스럽게 연결돼야 한다.

ENTER_FIELD가 카드가 착지하기 전에 실행되는 것처럼 보이면 안 된다.

==================================================
7. 등장 효과 강조
==================================================

등장 효과가 발동하면
해당 source 카드가 짧게 강조되어

"지금 이 카드의 효과가 발동했다"

는 것을 알 수 있게 해.

예:

- 약한 glow
- 살짝 위로 떠오름
- frame pulse

중 하나.

과도한 번쩍임은 금지.

==================================================
8. PLAYER_CHOICE Targeting
==================================================

선택 대상이 필요한 효과는:

카드 등장
→ source 강조
→ valid target만 highlight
→ 나머지 대상 약간 dim
→ 플레이어가 target 클릭/tap
→ target 짧게 선택 강조
→ effect 실행

흐름으로 한다.

선택한 순간 바로 effect가 자연스럽게 이어져야 한다.

별도 불필요한 확인 버튼은 만들지 마.

==================================================
9. Target 연결 연출
==================================================

효과가 특정 대상에게 적용되는 경우
source와 target 관계를 짧게 보여줘.

예:

- 짧은 arc/light
- 작은 energy trail
- source pulse → target pulse

정도.

화면 전체를 가리는 거대한 레이저를 기본 연출로 쓰지 마.

중요한 것은
"누가 누구에게 효과를 사용했는지"
즉시 알 수 있는 것이다.

==================================================
10. Technique 카드
==================================================

기술 카드는 선수와 다른 플레이 감각을 줘.

손에서 사용:

손패
→ 화면 중앙 근처로 빠르게 이동
→ 약간 확대
→ 카드 효과 영역 강조
→ 효과 발동
→ 카드가 사라짐/Graveyard 이동

Field Slot으로 내려놓지 않는다.

PLAYER_CHOICE가 필요하면
Technique 카드가 중앙에서 짧게 유지된 상태로
targeting mode에 진입 가능.

효과 resolution 후 자연스럽게 사라지게 해.

==================================================
11. Technique 효과 시각 구분
==================================================

기술 카드의 보라색/magic UI 컨셉과 어울리게

- 짧은 purple accent
- magic trail
- subtle glow

등을 사용 가능.

단 실제 카드 프레임/KO 디자인을 우선하고
과도한 파티클 도배 금지.

==================================================
12. 공격 시작
==================================================

선수가 공격하면:

1. attacker 살짝 뒤로 당김 (wind-up)
2. target 방향으로 빠르게 돌진
3. collision
4. Attack SFX
5. Damage 적용
6. Hit SFX
7. screen shake
8. target hit reaction
9. attacker 원위치

흐름.

==================================================
13. 공격 중 카드 2장 버그 방지
==================================================

공격 animation clone/overlay를 사용하는 경우:

원래 Field card의 layout 공간은 유지하되
visual만 숨기고

움직이는 animation card 한 장만 표시.

공격 중 동일 카드가:

원래 자리
+
움직이는 카드

두 장으로 보이면 안 된다.

animation 종료:

clone 제거
→ original visual 복원

순서를 정확히 맞춰.

==================================================
14. 공격력/피해량 타격감
==================================================

공격 애니메이션 자체는 attacker CURRENT ATTACK을 참고해
무게감을 조절할 수 있다.

하지만 실제 collision screen shake와 hit impact는
실제 적용된 DAMAGE를 기준으로 한다.

기존 피해 등급:

1~3
4~6
7~10
11+

을 사용해.

1~3:
작은 충격

4~6:
중간 충격

7~10:
큰 충격

11+:
매우 강한 충격

단 짧게.

==================================================
15. 실제 피해 0
==================================================

Dodge/회피 등으로:

damageApplied = 0

이면:

- 강한 screen shake 없음
- 일반 hit impact 없음
- Damage SFX 없음

대신 회피 전용 반응이 있다면 사용.

공격 자체의 movement는 정상 재생.

==================================================
16. 피해 숫자
==================================================

Damage 발생 시 target 근처에서:

- "-3"
- "-8"

등 실제 DAMAGE 숫자를 짧게 보여줘.

작은 damage:
작은 움직임

큰 damage:
조금 더 큰 숫자/impact

숫자는 위로 살짝 떠오른 뒤 fade out.

한 화면에 오래 남아있지 않게 해.

==================================================
17. 체력 변화
==================================================

HP가:

10 → 6

으로 감소하면
숫자가 즉시 6으로 순간 변경되는 것보다

짧은 transition을 사용해.

예:

현재 HP 표시
→ hit
→ 짧은 flash
→ 새로운 HP

너무 긴 count animation은 필요 없음.

==================================================
18. Heal
==================================================

Heal 발생:

- target 약한 상승/breath effect
- +Health 숫자
- 짧은 positive glow
- Heal SFX

Damage와 명확히 다른 느낌.

==================================================
19. Buff
==================================================

Attack/Health 증가:

target card 약하게 pulse
→ 변경된 stat 강조
→ +X 표시

예:

Attack +2
Health +3

Attack 숫자 또는 Health 숫자가
짧게 커졌다가 정상 크기로 복귀.

==================================================
20. Debuff
==================================================

Attack/Health 감소:

짧은 negative pulse
→ 감소된 stat 강조

Buff와 시각적으로 구분되게 해.

==================================================
21. MULTIPLY / SET / SWAP
==================================================

특수 stat 변화도 구분 가능하게 해.

예:

MULTIPLY_STATS:
기존 수치
→ 짧게 강조
→ 새 수치 크게 pulse

SWAP_ATTACK_HEALTH:
Attack/Health 값이 서로 이동하는 듯한 짧은 transition

SET_STATS:
기존 숫자 fade
→ 새 숫자 나타남

게임 로직 변경 없이 presentation만.

==================================================
22. Keyword 획득
==================================================

도발 / 러쉬 / 기습 / 회피 등 Keyword 획득 시

해당 keyword icon 또는 작은 label이
짧게 나타났다 카드 UI에 정착하게 해.

Keyword를 잃으면 역방향으로 사라짐.

==================================================
23. SILENCE
==================================================

침묵 발생:

target card
→ 짧은 desaturation/neutral flash
→ ability/keyword presentation 제거

침묵 결과를 유저가 확실히 알아야 함.

카드 자체를 지나치게 회색으로 영구 표시할 필요는 없고
현재 UI 규칙에 맞춰.

==================================================
24. STUN
==================================================

기절 상태가 적용되면
카드 위에 명확하지만 작은 상태 표시.

기절이 해제되면 자연스럽게 사라짐.

==================================================
25. Dodge
==================================================

회피로 damage를 막으면:

attacker collision
→ target이 아주 짧게 옆으로 흔들리거나 회피 표현
→ "회피" 작은 표시
→ damage number 없음
→ hit damage SFX 없음

==================================================
26. Draw
==================================================

카드 Draw:

Deck 위치
→ hand 방향으로 카드 이동
→ hand에 자연스럽게 삽입

손패 전체가 순간 재정렬되지 말고
부드럽게 공간을 만들면서 배치.

==================================================
27. Overdraw
==================================================

Hand가 꽉 찬 상태에서 Draw된 카드가
removedFromGame으로 가는 경우:

Deck에서 카드가 나온 뒤
Hand에 들어가지 못했다는 것을 잠깐 보여주고
removed 방향으로 사라지게 해.

너무 긴 연출은 필요 없음.

기존 KO overdraw rule은 변경하지 마.

==================================================
28. 카드 생성
==================================================

GENERATE로 Hand에 카드가 생성되면

Deck에서 Draw한 것처럼 보이지 않게 해.

작은 생성 효과
→ 카드 appearance
→ Hand에 삽입

Generated 카드임을 시각적으로 구별하는 기존 표시가 있으면 유지.

==================================================
29. Summon
==================================================

효과로 Field에 선수가 소환되면:

빈 Slot에
작은 spawn/appearance
→ card scale 0.85→1
→ landing
→ ENTER_FIELD

순서.

손에서 나온 것처럼 Hand에서 이동시키지 마.

==================================================
30. 특정 카드 소환
==================================================

CARD_REFERENCE로:

"잔상을 소환"

같은 효과가 실행되면
해당 CardDefinition 이미지가 정상적으로 spawn animation에 사용돼야 한다.

placeholder 카드로 먼저 보였다가 바뀌면 안 된다.

==================================================
31. Token 등장
==================================================

Token도 일반 Field Entry animation을 사용하되
Token 생성 특유의 짧은 spawn 느낌을 줄 수 있다.

Champion Token은 별도 아래 규칙 사용.

==================================================
32. Champion Token 전개
==================================================

DEPLOY_CHAMPION_TOKEN은
일반 summon보다 더 중요한 연출로 보여줘.

흐름:

Champion effect 발동
→ 연결된 Champion Token card 등장 준비
→ Field에 강하게 전개
→ Token HP 계산 표시
→ Champion portrait에 Protected 상태 표시
→ Champion Token 활성화

과도한 cinematic은 금지.

대략 700~1200ms 안에서 끝나게 해.

==================================================
33. Champion 보호 표현
==================================================

Champion Token 활성화 후
본체 Champion은:

- untargetable
- damage immune

상태임을 UI에서 알아보기 쉽게
작은 shield/protected overlay 표시.

Targeting 시 highlight 대상에 포함하지 마.

==================================================
34. RETIRE
==================================================

카드 HP가 0 이하가 되어 RETIRE하면

hit
→ HP 감소
→ 짧은 delay
→ card 흔들림/무너짐
→ Field에서 fade/shrink
→ Graveyard 이동

순서.

Damage와 Retire가 같은 프레임에 동시에 사라지지 않게 해.

"왜 죽었는지" 보일 정도의 짧은 간격을 둬.

==================================================
35. DESTROY
==================================================

DESTROY는 Damage/Retire와 시각적으로 구분.

예:

card fracture / vanish

같은 짧은 제거 연출.

Damage 숫자를 표시하지 마.

Graveyard 처리 규칙은 기존 엔진 따름.

==================================================
36. REMOVE_FROM_GAME
==================================================

REMOVE/ERASE는 RETIRE/DESTROY와 다르게

card
→ 다른 방식으로 빠르게 소멸

하게 해.

Graveyard로 날아가는 것처럼 보이면 안 된다.

==================================================
37. Graveyard / Removed UI
==================================================

카드가 이동할 때
화면 구석 Graveyard까지 실제로 길게 날아갈 필요는 없다.

짧은 direction cue 정도만 사용하고
전투 템포를 유지.

==================================================
38. Quest 진행
==================================================

Quest progress:

3/7 → 4/7

이 되면 Champion Quest UI가
짧게 pulse하고 숫자가 업데이트되게 해.

매번 화면 중앙에 큰 연출을 띄우지 마.

==================================================
39. Quest 완료
==================================================

QUEST_COMPLETED는 중요한 순간이므로
일반 progress보다 강하게 표현.

예:

Quest UI pulse
→ "QUEST COMPLETE" 또는 현재 KO UI에 맞는 표시
→ Champion upgrade
→ optional portrait change
→ Quest Completion Music 전환

약 700~1200ms 내에서 깔끔하게.

==================================================
40. Champion Portrait 변경
==================================================

Quest 완료 portrait 옵션이 활성화된 Champion은

기존 portrait
→ 짧은 fade/flash
→ 새로운 portrait

로 자연스럽게 전환.

갑자기 이미지가 바뀌는 느낌을 줄이지 마.

==================================================
41. Champion Ability
==================================================

Champion Ability 사용 시:

ability button press feedback
→ Champion portrait/ability UI 짧게 강조
→ target 필요 시 targeting mode
→ effect resolution

순서.

Champion Ability가 카드 효과와 동일한
Animation/Event 시스템을 사용할 수 있게 해.

==================================================
42. Gold 사용
==================================================

카드/Champion Ability 사용 시
Gold가 감소하면

Gold 숫자가 짧게 pulse한 뒤 감소.

Gold 부족 invalid action이면:

- animation 시작 금지
- 카드 이동 금지
- 짧은 invalid feedback/toast만

==================================================
43. Turn Start
==================================================

턴 시작:

현재 Player 영역이 짧게 강조
→ "내 턴" 표시
→ Gold refresh
→ Draw

순서가 자연스럽게 연결.

너무 큰 fullscreen 연출은 피한다.

==================================================
44. Turn End
==================================================

Turn End 버튼 클릭:

button feedback
→ 턴 상태 전환
→ 상대 영역 활성화

빠르게 처리.

==================================================
45. Victory / Defeat
==================================================

Champion HP <= 0 또는
Active Champion Token RETIRE로 승패가 결정되면

마지막 Damage/Retire animation을 먼저 보여준 뒤
결과 화면으로 전환해.

피해가 들어가는 순간 바로 화면이 사라져
마지막 장면을 못 보는 일이 없게 해.

==================================================
46. Champion Token 패배
==================================================

Active Champion Token이 RETIRE:

Token RETIRE animation
→ 짧은 dramatic pause
→ defeat result

순서.

==================================================
47. Card Frame 반응
==================================================

NORMAL / LEGENDARY / CHAMPION 카드 프레임에
작은 연출 차이를 둘 수 있다.

하지만 게임 결과의 타격감은 rarity보다
실제 Cost / Attack / Damage를 우선한다.

Legendary라고 1 damage가 10 damage보다 세게 느껴지면 안 된다.

==================================================
48. Random 효과
==================================================

RANDOM/FULL_RANDOM 결과가 결정되면

결과 카드가 짧게 reveal되게 할 수 있다.

단 RNG 결과를 animation에서 새로 계산하지 마.

Engine에서 결정된 결과를 UI가 보여주는 것만 해야 한다.

==================================================
49. 여러 대상 효과
==================================================

ALL / multi-target damage 등은

완전히 동시에 모든 카드가 번쩍이는 대신
짧은 stagger를 사용 가능.

예:

target 1
target 2
target 3

사이 40~80ms 정도.

단 게임 속도를 느리게 만들지 마.

==================================================
50. 연쇄 효과
==================================================

A 등장
→ B 소환
→ B 등장
→ C damage

같은 chain에서는
Animation Queue가 순서를 보존해야 한다.

사용자가 무엇이 발동했는지 이해할 수 있어야 한다.

무한 animation loop가 발생하지 않도록
기존 engine safety와 연동.

==================================================
51. Event Log와 동기화
==================================================

가능하면 Play History/Event Log가
애니메이션보다 먼저 모든 결과를 한꺼번에 보여주지 않게 해.

현재 presentation event와 맞춰
적절한 시점에 로그 항목을 추가/강조.

단 Game Event 원본 기록은 즉시 저장 가능.

==================================================
52. SFX 동기화
==================================================

기존 SFX Manager를 재사용.

CARD ENTER:
Cost tier SFX

DAMAGE:
실제 Damage tier Hit SFX

ATTACK:
Attack SFX

HEAL:
Heal SFX

BUFF:
Buff SFX

RETIRE:
Retire SFX

DESTROY:
Destroy SFX

REMOVE:
Erase SFX

DRAW:
Draw SFX

등 기존 등록된 SFX가 있다면
animation impact frame과 정확히 맞춰 재생.

==================================================
53. 음악 우선순위 유지
==================================================

기존 음악 규칙 유지:

Temporary Wrestler Entrance Music
>
Latest Quest Completion Music
>
Match BGM

Entrance Music 종료 후
항상 최신 BASE MUSIC으로 복귀.

모든 MUSIC 시작/복귀는 반드시 Fade-In.

SFX는 Fade-In 적용하지 않음.

==================================================
54. Animation과 Audio 정확히 맞추기
==================================================

예:

Attack SFX
→ attacker collision 순간

Hit SFX
→ damage impact 순간

Enter SFX
→ card landing 순간

Retire SFX
→ retire animation 시작 순간

처럼 시각 효과와 소리가 따로 놀지 않게 해.

==================================================
55. Screen Shake
==================================================

Screen Shake는 실제 Damage 기반.

0:
없음

1~3:
very light

4~6:
light/medium

7~10:
heavy

11+:
very heavy

짧게만 사용.

여러 damage가 연속 발생할 때
shake가 계속 누적되어 화면이 제어 불가능해지지 않게
중앙 ScreenShakeManager에서 관리.

==================================================
56. 카메라/화면 전체 이동 최소화
==================================================

일반 카드 효과마다 화면을 줌인/줌아웃하지 마.

전체 화면 효과는:

- 아주 큰 공격
- Quest 완료
- Champion Token 전개
- 승패

정도에 제한.

기본 게임은 안정적으로 보이게 유지.

==================================================
57. Mobile 지원
==================================================

모바일 portrait에서도 동일한 연출 의미가 유지되어야 한다.

단 좌표는 Desktop 값을 재사용하지 말고
실제 DOM bounding rect 기준으로 계산.

모바일의 큰 Board 카드와 겹친 Hand 카드에서도
animation이 정상 작동해야 한다.

==================================================
58. Desktop 보호
==================================================

기존 Desktop layout 자체를 재설계하지 마.

Animation layer만 추가/개선.

현재 카드 크기/보드 배치/Champion 배치는 유지.

==================================================
59. 성능
==================================================

transform / opacity 중심으로 구현하고
불필요한 layout thrashing을 피한다.

가능하면:
transform
opacity

우선.

매 프레임 React state update를 남발하지 마.

==================================================
60. Animation Clone
==================================================

이동 애니메이션용 visual clone은

pointer-events: none

이어야 한다.

게임 대상/클릭 대상이 되면 안 된다.

종료 후 반드시 cleanup.

동일 instance의 animation clone이 여러 개 중복 생성되지 않게 해.

==================================================
61. Re-render 안전성
==================================================

애니메이션 중 GameState update로 React rerender가 발생해도

- clone 중복
- 카드 순간이동
- 원본이 갑자기 나타남
- animation cancel

등이 발생하지 않게 해.

presentation state와 game state 연결을 안정적으로 관리.

==================================================
62. Reduced Motion
==================================================

prefers-reduced-motion 사용자는:

- screen shake 제거/축소
- 이동거리 축소
- 긴 animations 축소

하지만 게임 정보 전달은 유지.

==================================================
63. invalid action
==================================================

Invalid Action에서는 화려한 animation을 실행하지 마.

예:

Gold 부족
Invalid target
Already attacked
Summoning sickness
Board full
Opponent turn

→ GameState unchanged
→ animation 없음
→ 짧은 UI feedback/toast

기존 KO invalid action 규칙 유지.

==================================================
64. Animation Debug Mode
==================================================

개발 편의를 위해 가능하다면
개발 환경에서만 사용할 수 있는 작은 animation debug option 추가 가능.

예:

Animation Speed:
0.5x
1x
2x

하지만 production UI에는 노출하지 않아도 된다.

이번 작업의 핵심이 아니므로
큰 개발 패널은 만들지 마.

==================================================
65. 공통 Animation Registry
==================================================

카드마다 animation 코드를 하드코딩하지 마.

예:

if card.name === "나토마토"

금지.

공통 Event/Action 종류로 animation 선택:

CARD_PLAY
ENTER_FIELD
DAMAGE
HEAL
BUFF
ATTACK
RETIRE
DESTROY
REMOVE
DRAW
SUMMON
QUEST_COMPLETED

등.

카드의 구체적인 Effect는 기존 Engine이 결정하고
Presentation Layer는 Event 종류와 context를 읽는다.

==================================================
66. 특수 카드 효과
==================================================

새로운 카드 효과가 추가되더라도
기존 Event 조합이면 별도 animation 코딩 없이
자동으로 기본 연출이 적용돼야 한다.

예:

새 카드:

ENTER_FIELD
DAMAGE
CARD_GENERATED

→ 기존 animation들이 자동 연결.

68. 가장 중요한 완료 조건
==================================================

게임 플레이 시 사용자가:

"무슨 카드가 발동했는지"
"누가 누구를 공격했는지"
"누가 피해를 받았는지"
"왜 카드가 죽었는지"
"어떤 효과로 능력치가 변했는지"
"어떤 카드가 새로 생성/소환됐는지"

를 별도의 로그를 읽지 않아도
화면 연출만 보고 자연스럽게 이해할 수 있어야 한다.

하지만 동시에:

연출 때문에 게임이 느려지거나
행동 하나마다 기다려야 하는 느낌이 들면 안 된다.

FAST + CLEAR + IMPACTFUL

이 세 가지를 우선해.

==================================================
69. 절대 하지 말 것
==================================================

- 게임 규칙 변경 금지
- Effect Engine 의미 변경 금지
- Card 이름별 animation 하드코딩 금지
- Desktop layout 전체 재설계 금지
- RNG를 animation에서 다시 계산 금지
- damage를 animation 코드에서 계산 금지
- animation 완료 여부 때문에 실제 GameState가 잘못되는 구조 금지
- 과도한 particle spam 금지
- 모든 행동에 screen shake 사용 금지
- 전체 프로젝트 대규모 리팩터링 금지

현재 Game Event / Event Log / AudioManager / Card Renderer /
Targeting / Combat 시스템을 최대한 재사용해.

필요한 Presentation/Animation Queue 계층만 추가/정리하고,
기존 정상 게임 로직은 건드리지 마.

마지막으로 실제 매치를 여러 턴 플레이해서
Animation Queue가 꼬이거나 중복 카드가 나타나거나
오디오가 중복 재생되는 문제가 없는지 검증한 뒤 종료해.
