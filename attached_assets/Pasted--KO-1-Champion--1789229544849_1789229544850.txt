현재 KO 카드게임에 "덱 편집 / 계정별 덱 저장 1차 버전"을 구현해줘.

이번 작업의 목표:

로그인한 사용자가
자신의 Champion과 카드들로 덱을 만들고,
저장/수정/삭제하고,
사용할 대표 덱을 선택할 수 있게 한다.

중요:
이번 작업에서는 덱 편집만 구현한다.

아직 구현/연결하지 말 것:

- AI Match 실제 시작
- Online Match
- Matchmaking
- Shop
- 카드 구매
- 카드 보유량
- 재화
- 랭크
- 전적

게임 엔진 자체도 불필요하게 수정하지 마.

==================================================
1. Main Menu 연결
==================================================

현재 Main Menu의:

[덱 편집]

버튼만 실제 Deck 페이지와 연결해.

예:

/decks

또는 현재 프로젝트 route 구조에 맞는 경로 사용.

나머지:

- AI 매치
- 온라인 매치
- 상점

은 기존처럼:

"준비 중입니다."

상태를 유지해.

AI 매치 버튼을 임시로 Test Game에 연결하지 마.

==================================================
2. 로그인 필수
==================================================

Deck 기능은 로그인 사용자 전용이다.

로그인되지 않은 사용자는
Deck API와 Deck 페이지를 사용할 수 없어야 한다.

현재 Auth/Session 시스템을 재사용해.

Deck의 소유자는 반드시:

userId

기준으로 관리한다.

클라이언트가 전달한 임의 userId를 신뢰하지 말고
서버 Session의 현재 User ID를 사용해.

==================================================
3. Deck 데이터 구조
==================================================

현재 DB/ORM 구조에 맞게 Deck을 추가해.

개념적으로:

Deck {
  id
  userId
  name
  championDefinitionId
  cardDefinitionIds
  isSelected
  createdAt
  updatedAt
}

실제 프로젝트에 더 적합한 normalized 구조가 있다면 사용 가능.

중요:

Champion은 카드 20~30장 안에 포함하지 않는다.

Deck 구성:

Champion 1명
+
Card 20~30장

==================================================
4. 덱 카드 수 규칙
==================================================

KO 덱 규칙:

최소 20장
최대 30장

Deck Editor에서 현재 카드 수를 항상 표시해.

예:

18 / 30

20 / 30

30 / 30

30장을 넘어서 카드를 추가할 수 없게 해.

20장 미만인 덱은 저장 자체는 허용해도 된다.

대신:

"미완성 덱"

상태로 표시하고
실제 사용 덱으로 설정할 수 없게 해.

VALID DECK 조건:

- Champion 선택됨
- 카드 20~30장

==================================================
5. 중복 카드 규칙
==================================================

현재 프로젝트에 이미
동일 카드 최대 장수 규칙이 있다면 그것을 사용해.

그런 규칙이 아직 없다면
이번 작업에서 임의로:

2장 제한
3장 제한
Legendary 1장 제한

같은 새 규칙을 만들지 마.

현재 단계에서는 기존 KO 규칙만 사용해.

==================================================
6. 사용할 수 있는 카드
==================================================

Deck Editor에는 현재 Card Admin의:

PUBLISHED

카드만 기본적으로 표시해.

카드 타입:

- WRESTLER
- TECHNIQUE

모두 덱에 넣을 수 있다.

하지만 시작 덱에 직접 들어가는 카드가 아닌:

isToken = true
isChampionToken = true

카드는 Deck Builder 후보에서 제외해.

DRAFT / DISABLED 카드도 일반 사용자에게 표시하지 마.

==================================================
7. 카드 보유 시스템은 아직 없음
==================================================

이번 단계에서는 사용자의 카드 소유 여부를 검사하지 않는다.

즉 로그인한 사용자는
현재 PUBLISHED 된 일반 카드라면 모두 Deck에 사용할 수 있다.

향후 Shop / Collection 시스템에서
"보유 카드만 사용 가능" 규칙을 추가할 수 있도록
Deck 구조를 깨끗하게 분리해.

이번 작업에서는 Inventory를 만들지 마.

==================================================
8. Champion 선택
==================================================

Deck Editor 상단에:

[Champion 선택]

영역을 만들어.

현재 PUBLISHED Champion 목록을 보여줘.

Champion 하나를 선택하면
현재 Deck의 championDefinitionId에 저장.

한 Deck에는 Champion 하나만 선택 가능.

Champion Token은 Champion 선택 목록에 표시하지 마.

Champion 카드/Token 데이터와
ChampionDefinition을 혼동하지 마.

==================================================
9. Deck Editor 기본 레이아웃
==================================================

Desktop에서는 대략:

왼쪽/중앙:
카드 Collection

오른쪽:

상단:
Deck 이름 + Champion

│                           │ 카드 목록        │

현재 KO 디자인 스타일을 유지해.

일반 SaaS 관리자 페이지처럼 만들지 마.

==================================================
10. Card Collection
==================================================

카드 목록에서 최소한 다음을 볼 수 있게 해:

- 카드 이미지
- 이름
- Cost
- 카드 타입
- Attack / Health (Wrestler)
- Rarity

현재 공통 Card Renderer를 재사용해.

카드 클릭:

→ Deck에 1장 추가

또는 명확한 [+] 버튼 제공.

30장이면 추가 불가.

==================================================
11. Deck Card List
==================================================

현재 덱에 들어있는 카드 목록을 보여줘.

카드별:

- 이름
- Cost
- 장수

정도를 빠르게 확인 가능하게 해.

같은 CardDefinition이 여러 장 들어가 있다면
가능하면:

나토마토 ×2

처럼 묶어서 표시해도 된다.

클릭 또는 [-] 버튼:

→ 1장 제거

모두 제거 기능을 추가해도 된다.

==================================================
12. 정렬
==================================================

Deck 목록은 기본적으로:

Cost
→ Name

순서처럼 읽기 쉽게 정렬해.

Collection에는 최소:

- 이름 검색
- WRESTLER / TECHNIQUE 필터

정도만 제공해.

현재 Rarity 시스템이 있으므로
필요하면 Rarity 필터도 추가 가능.

이번 단계에서 복잡한 고급 검색 시스템은 만들지 마.

==================================================
13. 카드 상세 보기
==================================================

Deck Editor에서도 기존 Card Renderer / Card Inspector를 재사용해.

Desktop:
Hover 또는 기존 상세보기 방식

Mobile:
Tap / Long Press / Info

카드 효과를 확인하기 위해
새 Card Detail 시스템을 별도로 만들지 마.

==================================================
14. Deck 이름
==================================================

사용자가 Deck 이름을 지정할 수 있게 해.

예:

"판도라 컨트롤"

빈 이름은 저장하지 못하게 하거나
현재 프로젝트 스타일에 맞는 기본 이름을 지정해.

이름 길이는 합리적인 범위로 제한해.

예:
1~30자

서버에서도 validation.

==================================================
15. 저장
==================================================

[덱 저장]

버튼 제공.

저장 시:

- name
- championDefinitionId
- cardDefinitionIds

를 현재 로그인 User의 Deck으로 저장.

저장 후 새로고침해도 그대로 유지되어야 한다.

Game/CardDefinition 전체 데이터를 Deck record에 복사하지 마.

Deck에는 안정적인 Definition ID reference를 저장해.

==================================================
16. Deck 목록
==================================================

/decks에서 사용자가 만든 기존 Deck들을 볼 수 있게 해.

각 Deck:

- 이름
- Champion
- 카드 수
- VALID / 미완성
- 선택된 Deck 여부

표시.

가능한 동작:

[편집]
[삭제]
[사용할 덱으로 설정]

==================================================
17. 대표 Deck
==================================================

유저가 실제 매치에서 사용할 대표 Deck 하나를 선택할 수 있게 해.

예:

selectedDeckId

또는 현재 DB 구조에 맞는 방식.

버튼:

[사용할 덱으로 설정]

VALID Deck만 설정 가능.

미완성 Deck:

Champion 없음
또는
20장 미만

이면 설정 불가.

현재 선택된 Deck에는:

✓ 사용 중

표시.

==================================================
18. 삭제
==================================================

Deck 삭제 전에 확인 UI 제공.

예:

"이 덱을 삭제하시겠습니까?"

삭제 후 다른 Deck에는 영향 없어야 한다.

현재 selected Deck을 삭제했다면
selectedDeckId를 안전하게 null 처리.

다른 Deck을 자동 선택하지 마.

==================================================
19. 다른 사용자 Deck 접근 금지
==================================================

매우 중요.

User A가 User B의:

deckId

를 URL/API로 직접 입력해도:

- 조회
- 수정
- 삭제

할 수 없어야 한다.

모든 Deck API에서:

deck.userId === session.user.id

를 서버에서 검증해.

프론트에서 숨기는 것으로 끝내지 마.

==================================================
20. CardDefinition 변경 대응
==================================================

Deck에는 CardDefinition ID를 저장한다.

Card Admin에서 카드 내용이 나중에 변경되면
Deck 자체를 다시 저장할 필요는 없다.

새로운 Match 시작 시
현재 정상 CardDefinition Snapshot을 사용하게 될 수 있도록 구조를 유지해.

단 이번 작업에서 Match 시스템 연결은 하지 마.

==================================================
21. DISABLED 카드 처리
==================================================

Deck에 저장된 카드가 나중에 Admin에서:

DISABLED
삭제
존재하지 않음

상태가 되면
Deck Editor가 crash하면 안 된다.

해당 Deck에:

⚠ 사용할 수 없는 카드가 포함되어 있습니다.

표시.

이 Deck은 VALID 상태가 아니게 처리.

사용할 Deck으로 설정하지 못하게 해.

삭제된 카드를 임의의 다른 카드로 대체하지 마.

==================================================
22. Champion 비활성 처리
==================================================

Deck에 연결된 Champion이
DISABLED/삭제 상태라면 동일하게:

⚠ 사용할 수 없는 Champion

표시.

Deck은 INVALID.

26. Admin과 분리
==================================================

Deck Editor는 일반 사용자 기능이다.

/admin Card Manager와 혼동하지 마.

Deck Editor에서는:

- 카드 생성
- 카드 스탯 변경
- 효과 변경
- Champion 수정

을 할 수 없다.

오직 기존 PUBLISHED Definition을 선택해서
Deck을 구성한다.

28. 테스트
==================================================

반드시 실제 서로 다른 두 계정을 사용해서 확인해.

TEST 1
User A 로그인
→ 새 Deck 생성
→ Champion 선택
→ 카드 추가
→ 저장

TEST 2
새로고침
→ Deck 유지

TEST 3
20장 미만
→ 저장 가능
→ 미완성 표시
→ 대표 Deck 설정 불가

TEST 4
20~30장 + Champion
→ VALID
→ 대표 Deck 설정 가능

TEST 5
30장 상태
→ 31번째 카드 추가 불가

TEST 6
Deck 수정
→ 저장
→ 새로고침 후 변경 유지

TEST 7
Deck 삭제
→ DB에서 해당 User Deck 삭제

TEST 8
User B 로그인
→ User A의 Deck이 목록에 나타나지 않음

TEST 9
User B가 User A deck API 직접 요청
→ 접근 거부

TEST 10
PUBLISHED가 아닌 카드
→ Collection에 표시되지 않음

TEST 11
Token / Champion Token
→ Collection에 표시되지 않음

TEST 12
Deck에 포함된 카드가 DISABLED
→ Deck INVALID 경고
→ 대표 Deck으로 사용 불가

TEST 13
모바일 세로
→ Deck Editor 정상 사용 가능
