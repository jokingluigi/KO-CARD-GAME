KO CARD GAME — SEV-1 BGM ASSET 404 RESTORATION

현재 Development에서 Main BGM과 활성 Match BGM 2개가 모두
404 "오디오를 찾을 수 없습니다"
오류로 실패하고 있다.

이번 작업은 다른 기능을 건드리지 말고
오직 음악 asset 404 문제를 끝까지 추적해서
실제 브라우저에서 소리가 재생되는 상태까지 해결한다.

다른 기능:
- 카드 태그
- 퀘스트
- 덱
- 모바일
- 카드 효과
- Match Intro
- 기타 UI

전부 건드리지 말 것.

==================================================

==================================================

최근 작업에서:

- BGM routing/state logic 수정 완료
- AI/Online match-selected music은 battle scope
- title/admin-preview music은 non-battle scope
- autoplay block과 media-load failure 분리
- KO typecheck/build PASS
- audio tests 11/11 PASS

Main BGM

"오디오를 찾을 수 없습니다"

→ media endpoint

==================================================
3. URL이 어떻게 만들어지는지 끝까지 추적
==================================================

각 음악에 대해:

DB/config stored value
→ Audio metadata
→ URL/path resolver
→ API/static route
→ storage/file lookup
→ final URL
→ browser request

전체를 추적한다.

반드시 찾아야 할 것:

- DB에는 어떤 경로/ID가 저장되어 있는가
- Frontend가 그것을 어떤 URL로 바꾸는가
- 그 URL을 어느 서버가 처리하는가
- 실제 file/object가 어디에 존재하는가
- DB reference와 실제 object key가 일치하는가

==================================================
4. 실제 파일 존재 여부 확인
==================================================

Main BGM 및 Match BGM 두 개 각각:

- repository 안에 실제 파일이 존재하는가
- public/static directory에 존재하는가
- build output에 포함되는가
- persistent object storage에 존재하는가
- DB storageKey와 실제 key가 같은가
- 확장자가 같은가
- filename 대소문자가 같은가
- URL encoding 문제가 없는가
- 파일명이 한글/공백을 포함할 경우 정상 decode되는가

Linux에서는 파일명 대소문자가 다르면
실제 404가 날 수 있으므로 반드시 확인.

==================================================
5. 반드시 조사할 404 원인
==================================================

다음 가능성을 전부 검사한다.

1.
DB에 예전 audio URL/path가 남아 있음.

예:

DB:
`/uploads/audio/main.mp3`

실제:
`/media/audio/main.mp3`

2.
파일명 대소문자 mismatch.

예:

DB:
MainTheme.mp3

실제:
maintheme.mp3

3.
오디오 파일이 git/build에 포함되지 않음.

4.
.gitignore 때문에 audio가 배포되지 않음.

5.
개발 환경 local filesystem에만 파일이 있었고
restart/deploy 후 사라짐.

6.
audio upload directory가 ephemeral filesystem임.

7.
DB에는 media record가 있지만
실제 storage object는 삭제됨.

8.
media endpoint route가 잘못됨.

9.
frontend가 잘못된 hostname 또는 old path를 사용함.

10.
SPA catchall이 media request를 가로챔.

11.
Admin preview에서는 다른 URL을 사용하고
Normal User playback에서는 broken URL을 사용함.

12.
media API가 asset ID 대신 잘못된 definition ID를 조회함.

13.
signed URL 또는 storage key 생성이 잘못됨.

==================================================
6. EPHEMERAL FILESYSTEM 여부 최우선 확인
==================================================

이 부분 매우 중요.

오디오 업로드 파일이:

uploads/
public/uploads/
tmp/
local filesystem

등 서버 로컬 디스크에만 저장되는 구조인지 확인.

Replit/Render 재시작이나 deploy 후
파일이 사라지는 구조라면
단순히 path를 다시 연결하는 것으로 끝내지 말 것.

현재 프로젝트에서 사용하는
기존 persistent storage 구조가 있다면 그것을 사용한다.

예:
Supabase Storage 등 기존 architecture.

새 외부 서비스를 임의로 추가하지 말 것.

8. MEDIA API ROUTE 확인
==================================================

Audio URL이 다음 같은 API route라면:

GET /api/audio/:id
GET /api/media/:id
GET /api/music/:id

실제 route를 추적.

확인:

- route가 서버에 등록돼 있는가
- frontend `/api/*` rewrite가 Node API로 향하는가
- SPA catchall보다 먼저 처리되는가
- auth middleware가 잘못 적용되지 않았는가
- path parameter가 올바른가
- DB media record lookup이 성공하는가
- storage object fetch가 성공하는가

404를 다음으로 정확히 분류:

ROUTE_NOT_FOUND

MEDIA_RECORD_NOT_FOUND

STORAGE_OBJECT_NOT_FOUND

INVALID_PATH

OTHER

Content-Type: text/html

로 index.html을 반환할 수도 있다.

이건 FAIL이다.

확인:

HTTP:
200 또는 206

Content-Type:
audio/mpeg
audio/ogg
audio/wav
등 실제 파일 형식

가능하면:
Content-Length
Accept-Ranges
Range request

도 확인.

        ↓

Legendary 음악이면 또 다른 special path

- Match BGM #1 URL 실제 200/206
- Match BGM #2 URL 실제 200/206
- response가 실제 audio bytes

- Normal User playback이 Admin 권한에 의존하지 않음
- Main/Non-Battle continuity 회귀 없음
- Battle BGM handoff 회귀 없음
- common audio resolver/storage 구조 사용
- Production 데이터 mutation 없음
- typecheck/build/tests PASS

실제 audible playback은 절대 PASS라고 쓰지 말고

29. 핵심 지시
==================================================

지금 문제는
"음악을 재생하라는 코드가 없다"
가 아니다.

설정된 실제 BGM 파일을 요청했을 때
404 "오디오를 찾을 수 없습니다"
가 발생하는 것이 핵심 문제다.

따라서:

DB/config reference
→ Shared Audio Resolver
→ media/static endpoint
→ actual persistent asset
→ HTTP audio response
→ browser playback

이 전체 체인을 끝까지 추적한다.

Main BGM 하나만 path hardcode해서 고치지 말 것.

Match BGM과
향후 Legendary 선수 전용 음악까지
동일한 Shared Audio Asset Pipeline을 이용할 수 있도록
공통 원인을 해결한다.

404를 숨기는 것이 아니라
실제 audio asset이 정상적으로 존재하고
브라우저가 실제 재생할 수 있는 상태를 만들어라.
