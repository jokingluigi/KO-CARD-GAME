KO CARD GAME — PANDORA TOKEN ATTACK ABSORB RUNTIME BUG ONLY
증상: 챔피언 판도라(폭주)의 등장 파괴는 정상 작동하지만,
"이 카드가 필드에 있을 때 이 카드가 리타이어 혹은 파괴 시킨 선수의 공격력을 이 카드의 공격력에 더합니다."
부분만 전혀 작동하지 않는다.

중요:
이번 작업은 판도라의 다른 효과를 다시 만들거나 재해석하는 작업이 아니다.
등장 파괴는 정상 작동 중이므로 건드리지 말 것.
문제 범위는 오직 "판도라 자신이 제거한 선수의 공격력을 흡수"하는 지속 효과다.

==================================================
1. 현재 기대 효과
==================================================

판도라(폭주) 원문 의미:

- 이 카드가 FIELD에 있는 동안만 활성
- 이 카드가 WRESTLER를 RETIRE 또는 DESTROY시켰을 때
- 제거된 그 WRESTLER의 "제거 직전 현재 공격력"을 읽음
- 그 수치만큼 판도라 자신의 현재 공격력을 증가
- 체력은 증가하지 않음
- 다른 아군 카드가 죽인 대상은 흡수하지 않음

예:

Pandora ATK = 5

상대 WRESTLER:
printed ATK = 2
buffed current ATK = 7

Pandora가 직접 제거
→ Pandora ATK = 12

+2가 아니라 +7이어야 함.

==================================================
2. 현재 알려진 사실
==================================================

현재 Stored/Fresh Analyzer에는 이미
REGISTER_LISTENER
→ SOURCE_CAUSED_TARGET_REMOVAL
→ ADD_AGGREGATED_ATTACK
→ LAST_CAUSED_TARGET_REMOVALS
→ CURRENT_ATTACK_SUM

구조가 들어 있는 것으로 보인다.

따라서:
"listener를 다시 추가"하는 식으로 끝내지 말 것.

실제 Runtime에서 왜 listener가 발동하지 않는지 추적해야 한다.

==================================================
3. 첫 failing layer를 반드시 찾을 것
==================================================

다음 trace를 실제로 확인:

Pandora enters FIELD
→ REGISTER_LISTENER executor called?
→ listener attached to Pandora instance?
→ listener remains active while Pandora is FIELD?

그 다음 제거 경로:

A. ENTER_FIELD DESTROY
Pandora chooses enemy WRESTLER
→ DESTROY event
→ source instance metadata?
→ SOURCE_CAUSED_TARGET_REMOVAL emitted?
→ listener matches?
→ victim currentAttack snapshot available?
→ ADD_AGGREGATED_ATTACK runs?
→ Pandora ATK changes?

B. COMBAT RETIRE
Pandora attacks enemy WRESTLER
→ damage
→ target HP <= 0
→ RETIRE
→ attacker instance metadata preserved?
→ SOURCE_CAUSED_TARGET_REMOVAL emitted?
→ listener matches?
→ victim currentAttack snapshot available?
→ Pandora ATK changes?

C. EFFECT-CAUSED RETIRE
Pandora effect directly causes retire if such fixture exists
→ same trace

최종 보고에 first failing layer를 정확히 적을 것.

==================================================
4. 가장 의심되는 원인
==================================================

특히 다음을 집중 검사:

- combat RETIRE path에서 causalSourceInstanceId가 유실됨
- DESTROY path에는 source가 있는데 RETIRE path에는 source 없음
- removal event가 victim만 담고 source를 안 담음
- listener registration은 되었지만 source instance ID와 event source ID 포맷이 다름
- source가 CardDefinition ID로 저장되고 event는 CardInstance ID 사용
- listener가 Champion Token context에서 등록되지 않음
- listener는 등록되지만 다음 reducer tick에서 사라짐
- source FIELD 여부 검사에서 Champion Token을 잘못 제외
- victim currentAttack snapshot을 제거 후 읽어서 undefined/0
- LAST_CAUSED_TARGET_REMOVALS가 채워지지 않음
- ADD_AGGREGATED_ATTACK이 SELF target을 원래 Pandora가 아니라 잘못 resolve
- event ordering 때문에 source가 이미 제거된 뒤 listener 평가
- replay/dedupe 로직이 첫 event부터 duplicate 처리
- online serializer가 causal metadata를 drop

추측으로 하나만 고치지 말 것.

==================================================
5. SOURCE identity는 CardInstance 기준
==================================================

반드시 "이 판도라 인스턴스가 제거했다"를 기준으로 판정.

사용해야 할 identity:
CardInstance ID

사용 금지:
- 카드 이름
- CardDefinition 이름
- "판도라" string
- Champion 이름 hardcode

같은 definition의 다른 인스턴스가 제거한 것은
이 판도라가 흡수하면 안 된다.

==================================================
6. RETIRE causality
==================================================

가장 중요한 실제 버그 경로:

Pandora attacks
→ enemy WRESTLER HP 0
→ RETIRE

여기서 반드시 attacker source identity가
damage → lethal → retire까지 이어져야 한다.

권장 event metadata 예시는 현재 엔진 naming에 맞게:

sourceInstanceId
sourceActionId
sourceActionType
causedByInstanceId

등 기존 필드 재사용.

새 필드를 남발하지 말 것.

==================================================
7. DESTROY causality
==================================================

등장 DESTROY는 현재 작동한다고 했지만
흡수는 안 된다고 했으므로 반드시 별도 검증.

REGISTER_LISTENER가 DESTROY보다 먼저 활성화되어야 한다.

순서:
1. listener register
2. target choice
3. destroy
4. removal event
5. listener consumes
6. attack gain

현재 stored effect order가 맞아도
runtime executor가 병렬/재정렬하는지 확인.

10. FIELD lifetime
==================================================

원문:

새 listener lifecycle.

==================================================
11. source와 victim 동시 RETIRE
==================================================

상호 전투로:

Pandora와 상대가 동시에 0 HP가 되는 경우
현재 엔진의 공식 event ordering을 확인.

원문상:
"이 카드가 필드에 있을때"

따라서 victim removal event가 처리되는 시점에
Pandora가 이미 FIELD를 떠났다면
흡수하지 않는 것이 자연스럽다.

하지만 기존 canonical ordering이
source removal 전에 victim removal listener를 평가하도록 되어 있다면
그 기존 규칙을 우선.

중요:
임의로 카드 전용 예외를 만들지 말 것.

==================================================
12. unrelated removal
==================================================

Pandora가 FIELD에 있다고 해서
모든 적 제거를 흡수하면 안 됨.

예:

Pandora FIELD
ally A attacks enemy B
B retires

→ Pandora +0

Pandora FIELD
Technique destroys enemy C
source = Technique

→ Pandora +0

오직 THIS Pandora instance가 직접 caused removal.

==================================================
13. duplicate prevention
==================================================

같은 removal event가:
- reducer replay
- reconnect
- websocket rebroadcast
- event rehydration

으로 다시 들어와도 한 번만 흡수.

same removal eventId:
first → +X
replay → +0

두 distinct removals:
각각 정상 흡수.

==================================================
14. Champion Token context
==================================================

이 판도라(폭주)가 Champion Token으로 FIELD에 배치되는 경우도 정상 작동해야 한다.

중요:
흡수 효과를 고치면서 Champion Token 특수 규칙 깨뜨리지 말 것.

유지:
- Token own HP/stat
- original Champion HP와 분리
- Token RETIRE != immediate loss
- Token FIELD 동안 original Champion protected
- Champion Ability 사용 가능
- Token leave 후 protection 해제
- SILENCE/DESTROY/REMOVE immunity current official rule 유지

흡수는 token/current card instance 공격력만 증가.

original Champion attack/HP 같은 별도 state를 건드리지 말 것.

중요:

card text effect를 혼동하지 말 것.

26. 완료 조건
==================================================

1. Pandora의 등장 DESTROY는 기존대로 정상.
2. Pandora가 직접 RETIRE시킨 WRESTLER의 현재 공격력 흡수.
3. Pandora가 직접 DESTROY한 WRESTLER의 현재 공격력 흡수.
4. victim currentAttack snapshot 사용.
5. unrelated removal 흡수 0.
6. duplicate event 흡수 0.
7. health 변화 0.
8. source CardInstance identity 기반.
9. Champion Token 규칙 회귀 없음.
10. AI/Online 동일 canonical behavior.
11. effect text에 `&` 같은 구분자 요구하지 않음.
12. Production DB mutation 없음.

핵심:
이번 문제는 "효과 문장이 두 개로 안 나뉘어서"가 아니라,
이미 등록된 지속 listener가 실제 removal causality를 받지 못하는 Runtime 문제인지
반드시 증명하고 고쳐라.

판도라의 다른 효과는 정상 작동 중이므로
흡수 지속 효과 경로만 정밀하게 수정하라.
