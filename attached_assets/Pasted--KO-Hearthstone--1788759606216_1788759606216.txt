현재 KO 카드게임의 카드 효과 시스템에 "플레이어 직접 대상 선택" 기능을 추가해줘.

목표는 Hearthstone 같은 전통적인 디지털 카드게임처럼,
대상을 지정해야 하는 효과가 발동하면 플레이어가 실제 게임 화면에서 직접 유효한 대상을 클릭해서 선택하게 만드는 것이다.

기존 게임 엔진과 Structured Effect 시스템을 최대한 유지하고,
대상 선택이 필요한 Effect에만 공통 Target Selection 시스템을 추가해줘.

==================================================

1. 기본 동작
   ==================================================

Structured Effect의 selection 값이:

PLAYER_CHOICE

인 경우 효과를 즉시 실행하지 않는다.

대신 게임을 "대상 선택 대기 상태"로 전환한다.

예:

카드 효과:

"등장: 적 선수 하나에게 피해 2"

분석 결과:

Trigger:
ENTER_FIELD

Action:
DAMAGE

Target:
ENEMY_WRESTLER

Selection:
PLAYER_CHOICE

Amount:
2

실제 게임 진행:

1. 카드를 플레이한다.
2. 카드가 필드에 등장한다.
3. ENTER_FIELD가 발생한다.
4. DAMAGE Effect가 PLAYER_CHOICE 대상이 필요하다는 것을 확인한다.
5. 게임이 Target Selection Mode로 들어간다.
6. 선택 가능한 적 선수만 화면에서 강조한다.
7. 플레이어가 적 선수 하나를 클릭한다.
8. 게임 엔진이 해당 대상이 여전히 유효한지 다시 검사한다.
9. 유효하면 피해 2를 준다.
10. 효과 처리를 계속한다.

==================================================
2. TargetingState / PendingEffect
=================================

대상 선택 중이라는 상태를 명확하게 GameState 또는 UI interaction state에서 관리해줘.

예:

targetingState: {
active: true,
sourceInstanceId: "...",
effectId: "...",
action: "DAMAGE",
allowedTargetType: "ENEMY_WRESTLER",
minTargets: 1,
maxTargets: 1,
selectedTargetIds: []
}

정확한 타입 이름은 현재 코드 구조에 맞게 정해도 된다.

중요한 것은 대상 선택 대기 중인 Effect 정보를 잃지 않는 것이다.

선택이 끝나기 전에는 해당 Effect를 완료 처리하면 안 된다.

==================================================
3. 유효 대상 자동 계산
==============

게임 엔진에 공용:

getValidTargets()

또는 비슷한 Target Resolver를 사용한다.

Effect 설정을 보고 실제 선택 가능한 대상을 반환한다.

예:

ENEMY_WRESTLER
→ 상대 필드 선수만

ALLY_WRESTLER
→ 내 필드 선수만

OTHER_ALLY_WRESTLER
→ 자신을 제외한 내 선수

ALLY_HAND_WRESTLER
→ 내 손패 선수 카드

ANY_WRESTLER
→ 양쪽 필드 선수

ENEMY_PLAYER
→ 상대 챔피언/플레이어

PLAYER
→ 내 챔피언/플레이어

ANY_TARGET
→ 해당 Effect가 허용하는 선수 또는 챔피언

등.

UI에서 임의로 대상을 결정하지 말고
게임 엔진의 Target Resolver 결과를 사용한다.

==================================================
4. 대상 강조 UI
===========

대상 선택 모드가 시작되면
선택 가능한 대상만 명확하게 강조한다.

예:

* 밝은 테두리
* 가벼운 빛 효과
* 마우스 Hover 강조
* 선택 가능 커서

등.

선택 불가능한 카드나 챔피언은 강조하지 않는다.

하지만 기존 카드 정보는 계속 볼 수 있어야 한다.

화면 중앙이나 적절한 위치에:

"대상을 선택하세요"

메시지를 표시한다.

가능하면:

"적 선수 하나를 선택하세요."

처럼 실제 Target 조건에 맞는 문구를 표시한다.

==================================================
5. 잘못된 대상 클릭
============

대상 선택 중 선택 불가능한 대상을 클릭해도:

게임 오류
게임 초기화
페이지 새로고침

이 발생하면 안 된다.

대신 Effect는 그대로 대기 상태를 유지한다.

필요하면 짧은 Toast:

"이 효과의 대상으로 선택할 수 없습니다."

를 표시한다.

==================================================
6. 대상이 필요한 카드는 대상이 없으면 사용 불가
============================

중요하다.

카드를 사용하기 전에 반드시
필수 대상이 존재하는지 검사할 수 있게 한다.

예:

"등장: 적 선수 하나를 파괴합니다."

그런데 상대 필드에 선수가 0명이라면
필수 PLAYER_CHOICE 대상이 없다.

이 경우 기본적으로 해당 카드를 플레이할 수 없게 한다.

사용하려고 하면:

"선택 가능한 대상이 없습니다."

라고 표시한다.

카드는 손패에 유지한다.
골드도 소비하지 않는다.
게임 상태도 변경하지 않는다.

단, 해당 Effect가 "대상이 없어도 카드 자체는 플레이 가능"하도록 별도로 정의된 경우에는
Effect Schema에서 optionalTarget=true 같은 설정을 사용할 수 있게 확장 가능하도록 한다.

기본값은 필수 대상이다.

==================================================
7. 카드 플레이 시 대상 선택 시점
====================

대상이 필요한 일반적인 카드 사용은 UX가 자연스럽게 작동해야 한다.

가능하면 다음 두 형태를 지원할 수 있는 구조로 만든다.

A. PLAY 후 Target

손패 카드 클릭
→ 보드 위치 선택
→ 카드 등장
→ 대상 강조
→ 대상 클릭
→ 등장 효과 해결

B. Effect별 Target Selection

이미 필드에 존재하는 카드의 액티브 능력
→ [액티브] 클릭
→ 대상 강조
→ 대상 클릭
→ 효과 해결

현재 기존 카드 사용 UX와 충돌하지 않는 방식을 사용한다.

==================================================
8. 자연어 Effect Analyzer와 자동 연결
=============================

현재 관리자 Natural Language Effect Analyzer와 연결한다.

관리자가:

"등장: 적 선수 하나에게 피해 2"

라고 입력하면:

Target:
ENEMY_WRESTLER

Selection:
PLAYER_CHOICE

Count:
1

로 분석되어야 한다.

이 카드를 게임에서 사용하면 자동으로 Target Selection Mode가 발생해야 한다.

관리자가 별도로 코드를 작성할 필요가 없어야 한다.

다음 표현은 PLAYER_CHOICE로 분석한다.

"원하는"

"선택한"

"하나를 선택"

"적 선수 하나"

"아군 선수 하나"

"카드 한 장"

등 문맥상 특정 대상을 플레이어가 직접 골라야 하는 표현.

반면:

"무작위"

"랜덤"

은 RANDOM이므로 대상 선택 UI를 띄우지 않는다.

"모든"

"전부"

는 ALL이므로 대상 선택 UI를 띄우지 않는다.

==================================================
9. SAME_TARGET 연속 효과
====================

한 번 선택한 대상에 여러 Effect가 연속으로 적용될 수 있다.

예:

"등장: 적 선수 하나를 침묵시키고 파괴합니다."

플레이어는 적 선수를 한 번만 선택한다.

그 후:

1. SILENCE
2. DESTROY

가 같은 대상에게 순서대로 적용된다.

두 번째 Effect에서 대상을 또 선택하라고 하면 안 된다.

Resolution Context에:

selectedTargetId

또는:

LAST_TARGET

을 보관해서 SAME_TARGET으로 재사용한다.

==================================================
10. 여러 대상을 직접 선택하는 효과
=====================

향후 다음 같은 Effect도 지원 가능하게 구조를 만든다.

"적 선수 2명을 선택하여 피해 1"

이 경우:

maxTargets = 2
minTargets = 2

처럼 설정할 수 있게 한다.

첫 번째 대상 클릭
→ 선택 표시

두 번째 대상 클릭
→ 선택 완료
→ Effect 실행

같은 대상을 두 번 선택할 수 있는지 여부도 Effect 설정으로 제어할 수 있게 한다.

현재 카드에서 필요하지 않다면 UI를 과도하게 구현할 필요는 없지만
TargetingState 자체는 다중 선택 확장이 가능하게 설계한다.

==================================================
11. 대상 선택 취소
============

대상 선택 과정에서 취소가 가능한 상황을 지원한다.

가능하면:

ESC 키
또는
[취소]

버튼으로 취소한다.

단, 카드가 이미 정상적으로 필드에 등장한 뒤 강제 Trigger가 발생한 상황이라면
단순 취소로 Effect 전체를 무시할 수 있으면 안 된다.

따라서:

카드 사용 확정 전 대상 선택
→ 취소 가능

이미 확정된 필수 Trigger 해결 중
→ 취소 불가 또는 원래 행동 전체 롤백

처럼 현재 엔진 구조에 맞는 안전한 정책을 적용한다.

가장 중요한 것은 카드/골드/Effect가 반쯤 처리된 잘못된 상태로 남지 않는 것이다.

==================================================
12. 액티브 / 챔피언 능력에도 공통 사용
========================

이 Target Selection 시스템을 카드 등장 효과만을 위해 만들지 않는다.

향후 다음도 같은 시스템을 사용한다.

액티브:

"적 선수 하나에게 피해 1"

챔피언 능력:

"선수 카드에게 피해 1"

강화 챔피언 능력:

"원하는 대상에게 피해 1"

기술 카드:

"적 선수 하나를 파괴"

모두 동일한 Target Resolver / Target Selection Mode를 사용한다.

카드마다 별도 대상 선택 코드를 작성하지 마.

==================================================
13. 판도라 같은 효과 예시
================

예를 들어 챔피언 판도라의 기본 고유 능력:

2G:
선수 카드에게 피해 1

사용 흐름:

[고유 능력 클릭]

→ 선택 가능한 선수 카드 강조

→ 선수 하나 선택

→ 2G 소비 여부 최종 validation

→ 피해 1

강화 고유 능력:

1G:
원하는 대상에게 피해 1

사용 흐름:

[고유 능력 클릭]

→ 유효한 모든 대상 강조

→ 대상 선택

→ 피해 1

이 구조를 공용 Target Selection 시스템으로 처리할 수 있어야 한다.

==================================================
14. 도발과 공격 대상 선택은 기존 규칙 유지
==========================

일반 공격에도 대상 선택 UI가 있지만
카드 Effect Targeting과 일반 Attack Targeting은 Action 종류를 구분한다.

공격:

ATTACK_TARGETING

카드/능력:

EFFECT_TARGETING

처럼 구분해도 된다.

기존 도발 규칙은 일반 공격 대상으로만 적용되는 현재 게임 규칙을 유지한다.

카드 효과가 도발 때문에 강제로 도발 대상을 선택하게 만들지 마
(해당 카드 효과가 별도로 그렇게 정의되어 있지 않은 한).

==================================================
15. Target Validation은 엔진에서 다시 수행
=================================

UI에 강조된 대상이라고 해서 바로 신뢰하지 않는다.

실제 클릭 후 Game Engine에서 최종 validation을 다시 수행한다.

특히 향후 온라인 대전을 위해 중요하다.

검사 예:

* 대상이 아직 존재하는가
* 올바른 owner인가
* 올바른 zone인가
* 올바른 cardType인가
* 침묵/면역 등 특수 제약이 있는가
* 해당 Effect가 그 대상을 선택할 수 있는가

validation 실패:

Effect 실행 안 함
게임 초기화 안 함
Targeting Mode 유지 또는 안전하게 취소
경고 표시

==================================================
16. 챔피언 토큰 보호 규칙 유지
===================

기존 챔피언 토큰 직접 출전 규칙을 반드시 유지한다.

챔피언 자신의 효과로 직접 출전한 Champion Token:

* 침묵 불가
* 효과로 DESTROY 불가

따라서 SILENCE나 DESTROY Effect의 Target Resolver에서도
해당 카드가 불가능한 대상이면 선택 후보에서 제외하거나
엔진 validation에서 거부한다.

일반 DAMAGE 대상은 될 수 있다.

==================================================
17. 대상 선택 중 다른 행동 방지
====================

필수 Target Selection Mode가 진행 중일 때
관련 없는 행동을 동시에 실행해서 GameState가 꼬이지 않게 한다.

예:

대상 선택 중
→ 다른 카드 플레이
→ 턴 종료
→ 다른 챔피언 능력 사용

등을 기본적으로 막는다.

화면에는:

"먼저 효과의 대상을 선택하세요."

라고 표시할 수 있다.

단 카드 상세정보 Alt+Hover 같은 비게임 정보 기능은 계속 사용할 수 있어도 된다.

==================================================
18. 게임 초기화 절대 금지
================

대상 선택 과정에서:

잘못된 대상
대상 없음
대상 선택 취소
validation 실패

가 발생해도:

window.location.reload()
createInitialGameState()
새 게임 시작
GameState 초기화

를 하지 마.

이는 정상적인 게임 입력 흐름이다.

필요한 경우 Toast 경고만 표시한다.

==================================================
19. 테스트
=======

반드시 다음을 테스트해줘.

TEST 1

"등장: 적 선수 하나에게 피해 2"

→ 카드 등장
→ 적 선수 강조
→ 대상 선택
→ 해당 대상만 피해 2

TEST 2

"등장: 적 선수 하나를 침묵시키고 파괴"

→ 대상 한 번만 선택
→ 침묵
→ 같은 대상 파괴

TEST 3

"등장: 자신에게 +2/+2"

→ SELF 효과이므로 대상 선택 UI 없음
→ 자동 실행

TEST 4

"등장: 무작위 적 선수 하나에게 피해 2"

→ RANDOM이므로 대상 선택 UI 없음
→ 자동 랜덤 선택

TEST 5

"등장: 모든 적 선수에게 피해 1"

→ ALL이므로 대상 선택 UI 없음
→ 모든 대상 자동 적용

TEST 6

필수 적 대상이 없는 상태에서:

"등장: 적 선수 하나를 파괴"

카드 사용 시도

→ 카드 사용 거부
→ 골드 소비 없음
→ 카드 손패 유지
→ "선택 가능한 대상이 없습니다." 표시

TEST 7

대상 선택 중 잘못된 카드 클릭

→ 효과 발동 안 함
→ 게임 초기화 안 됨
→ 정상적인 경고 표시

TEST 8

챔피언 고유 능력의 PLAYER_CHOICE Effect

→ 같은 Target Selection 시스템 사용

TEST 9

직접 출전 Champion Token에게 DESTROY 시도

→ 선택 불가 또는 validation 거부

TEST 10

대상 선택 중 턴 종료 시도

→ 턴 종료되지 않음
→ "먼저 대상을 선택하세요." 표시

==================================================
20. 완료 조건
=========

최종적으로 Structured Effect의:

selection = PLAYER_CHOICE

가 있으면

Effect 발동

↓

게임이 대상 선택 모드로 전환

↓

유효 대상 강조

↓
