==================================================
8. CARD reward
==================================================

Admin에서 CARD reward 설정 시 최소:

- CardDefinition 선택
- quantity 설정

가능.

서버에서 다시 검증:

- definition 존재
- reward 가능한 실제 카드인지
- quantity >= 1
- Token 직접 보상 금지 여부는 기존 카드 소유 규칙을 따름
- disabled/unpublished 카드 보상 허용 여부는 현재 운영 규칙을 따름

임의 정책을 만들지 말고 기존 ownership/catalog 규칙 사용.

==================================================
9. PACK reward
==================================================

Admin에서 PACK reward 설정 시 최소:

- 기존 PackDefinition / Pack product 선택
- quantity 설정

가능.

중요:

팩 보상을 받았다고
자동으로 팩을 개봉하지 마.

현재 게임에 "보유 팩/inventory" 개념이 있으면
그 inventory에 정확한 pack을 지급.

현재 pack architecture가
"팩 아이템 소유"가 아니라 즉시 open만 지원한다면
임의 구현하지 말고 구조를 확인한 뒤
현재 공식 pack semantics에 맞게 처리.

21. Presentation과 canonical engine 분리
==================================================

Quest 성공 팝업/연출 때문에
canonical AI turn progression이 영구 정지하면 안 된다.

필요한 presentation delay가 있다면
종료 후 scheduler resume.

단 AI가 클라이언트 연출 완료 신호가 없으면
영원히 기다리는 구조는 금지.

==================================================
22. Timeout fallback은 성공 아님
==================================================

다음은 FAIL:

Quest 완료
→ AI 20~30초 멈춤
→ timer timeout
→ 겨우 다음 턴.

정상:

Quest complete/reward resolution 이후
일반 AI think delay 안에
next action 또는 END_TURN.
