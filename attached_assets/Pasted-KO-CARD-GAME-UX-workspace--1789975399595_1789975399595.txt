KO CARD GAME 중요 규칙/UX 통합 패치를 진행해줘.

중요:
현재 workspace에 이미 구현된 기능을 먼저 조사하고,
기존 구현을 최대한 보존하면서 아래 최종 규칙에 맞게 수정한다.

Production Supabase / Production DB / 실제 유저 데이터는 절대 수정하지 않는다.
git push도 하지 않는다.
개발 코드, 개발 DB, migration, tests만 수정하고 최종 보고 후 기다린다.

새 cards.tags 시스템

==================================================
1. 구 게임 키워드 "태그" 완전 제거
==================================================

이번에 새로 만든 cards.tags는 유지한다.

제거할 것은 예전 combo-like keyword인 "태그"다.

기존 의미:

"이번 턴에 먼저 손에서 플레이된 다른 아군 WRESTLER와
공통 태그가 있으면 효과 발동"

같은 mechanic.

이 구 키워드는 활용도가 낮고
새 cards.tags와 이름도 충돌하므로 제거한다.

Repository 전체를 조사해서 관련된:

- keyword enum/type
- keyword registry
- condition
- parser
- event listener
- turn play provenance
- previous-play tracking
- SHARES_TAG_WITH_PREVIOUSLY_PLAYED_ALLY_THIS_TURN 계열
- ALT keyword 설명
- keyword badge
- tooltip
- tests
- 문서
- seed/default data

를 정리한다.

다른 mechanic에서 사용하지 않는 코드라면 제거한다.

하지만 다음은 절대 제거하지 않는다:

- cards.tags
- sharesCardTag()
- hasCardTag()
- matchesCardTagFilter()
- tagsAny
- tagsAll
- tagsNone

앞으로 사용자에게 보이는 "태그"라는 말은
오직 cards.tags의 종족/소속/분류를 의미한다.

예:

키워드
[도발] [러쉬]

태그
[용병] [인간]

구 keyword:

[태그]

는 더 이상 표시되면 안 된다.

==================================================
2. cards.tags는 Effect Engine의 공식 필터로 유지
==================================================

태그는 단순 UI 정보가 아니다.

향후 다음 효과들이 가능해야 한다.

- 용병 태그를 가진 아군에게 +1/+1
- 마족 태그를 가진 카드를 뽑는다
- 언데드 태그 적 선수에게 피해
- 같은 태그를 가진 카드를 생성
- 특정 태그를 가진 묘지 카드 부활

특정 태그 이름을 엔진에 하드코딩하지 않는다.

generic filter 구조 유지:

tagsAny
tagsAll
tagsNone

그리고 기존:

ownership
zone
cardType
target type

등과 조합 가능해야 한다.

예:

ownership: ALLY
zone: BOARD
cardType: WRESTLER
tagsAny: ["용병"]

새로운 Token/generated card도
자신의 canonical CardDefinition.tags를 사용한다.

==================================================
3. Champion Token HP 합산 제거
==================================================

기존 Champion Token 배치 시
원본 Champion의 HP를 Token HP에 합산하는 규칙을 제거한다.

Champion Token은 자신의 CardDefinition 기본 스탯만 사용한다.

예:

챔피언 판도라(폭주)
Attack 6
Health 10

원본 Champion currentHP가 13이어도:

Token = 6/10

이어야 한다.

6/23 같은 결과는 금지.

원본 Champion currentHP/maxHP는
Token deploy 전 상태 그대로 보존한다.

==================================================
4. Champion Token RETIRE 즉시 패배 제거
==================================================

기존:

활성 Champion Token RETIRE
→ 소유자 즉시 패배

규칙을 제거한다.

Champion Token이 일반 피해/전투로 HP 0 이하가 되어 RETIRE되면:

- 정상 RETIRE
- graveyard 이동
- RETIRE event 정상 발생
- 게임은 계속 진행
- owner 즉시 패배 금지

==================================================
5. Champion Token 원본 Champion 보호는 유지
==================================================

정상 DEPLOY_CHAMPION_TOKEN 경로로
Champion Token이 활성화되어 있는 동안:

- 원본 Champion 보호
- 원본 Champion target 후보 제외
- 원본 Champion damage/effect target 불가
- 원본 Champion ability 사용 가능

을 유지한다.

Champion Token이 실제로 필드를 떠나면:

- active Champion Token 상태 종료
- 원본 Champion 보호 해제
- 원본 Champion 다시 targetable
- 원본 Champion 다시 damage/effect 대상 가능

원본 Champion HP는 이전 값 그대로 유지한다.

stale active state가 남으면 안 된다.

==================================================
6. Champion Token 침묵 면역 유지
==================================================

Champion Token의 기존 SILENCE 면역은 반드시 유지한다.

Champion Token은 침묵될 수 없다.

단 침묵 면역 때문에:

- 일반 attack
- 일반 damage
- stat modification

까지 막혀서는 안 된다.

SILENCE만 기존 규칙대로 면역.

==================================================
7. Champion Token 즉사 면역 유지
==================================================

Champion Token의 기존 instant-kill/즉사 효과 면역도 유지한다.

먼저 현재 구현을 조사해서
정확히 어떤 effect가 즉사 면역 대상인지 확인한다.

현재 의미를 임의로 확대하거나 축소하지 말 것.

예를 들어 현재 DESTROY가
Champion Token 즉사 면역에 포함된다면 그대로 유지.

중요:

즉사 면역 != damage 면역

일반 damage로:

10 HP → 0 HP

가 되면 정상 RETIRE 가능해야 한다.

REMOVE_FROM_GAME 등이 기존 즉사 면역 범위에 포함되는지는
현재 코드 기준으로 조사하고 최종 보고에 명시한다.

==================================================
8. 같은 Definition의 일반 SUMMON과 구분
==================================================

Champion Token 특수 보호 상태는
정상 Champion Token deploy instance에만 적용한다.

같은 CardDefinition을:

- SUMMON
- FULL_RANDOM
- 일반 effect

등으로 생성했다고 해서
원본 Champion 보호를 활성화하면 안 된다.

카드 이름으로 판정하지 말 것.

entryCause / deploy metadata / canonical state를 사용한다.

==================================================
9. Champion Token 최종 공식 규칙
==================================================

최종 규칙:

Deploy:
- 자신의 기본 Attack/Health 그대로
- 원본 Champion HP 합산 없음

Active:
- 원본 Champion 보호
- 원본 Champion 비대상
- Champion ability 사용 가능
- Champion Token SILENCE 면역
- Champion Token 기존 즉사 효과 면역
- 일반 damage/combat 정상 적용

일반 damage/combat으로 RETIRE:
- 즉시 패배 없음
- 정상 graveyard
- active state 종료
- 원본 Champion 보호 해제
- 원본 Champion 다시 targetable
- 원본 Champion HP 그대로

==================================================

현재 Champion 최대 체력 20 하드코딩을 제거한다.

Champion마다 maxHealth를 별도로 설정할 수 있게 한다.

DB:

champions 테이블에
max_health 정수 컬럼 추가.

기존 Champion 기본값:

20

조건:

- NOT NULL
- 기본값 20
- 정수
- 최소 1 이상

현재 naming convention에 맞게
DB max_health ↔ API maxHealth 형태로 연결한다.

새 migration 파일 작성.

기존:

0015_card_tags.sql

은 유지하고 수정/삭제하지 않는다.

다음 migration:

0016_champion_max_health.sql

형태를 우선 사용.

Production에는 실행하지 않는다.

12. 실제 경기에서 Champion maxHealth 사용
==================================================

Match 시작 시:

currentHP = champion.maxHealth
maxHP = champion.maxHealth

로 초기화.

Champion HP를 20으로 가정하는 코드를 repository 전체에서 조사한다.

다음 포함:

- match initialization
- game state
- heal max cap
- damage
- AI
- UI
- reconnect
- serialization
- online snapshot
- victory
- Champion Token 관련 코드

단 무작정 숫자 20을 replace하지 말고
Champion HP 의미인 곳만 수정한다.

예:

Champion maxHealth=15
currentHP=10
heal 10

→ 15

20까지 올라가면 FAIL.

==================================================

기존:

20~30장

규칙을 제거한다.

새 공식 규칙:

+

14. Legendary 전체 제한 = 최대 5장

Deck에 들어갈 수 있는 LEGENDARY는:

최대 5장

==================================================
15. Legendary 동일 카드 중복 금지
==================================================

LEGENDARY는 동일 CardDefinition을
Deck에 2장 이상 넣을 수 없다.

즉:

Legendary 전체 최대 5장

그리고

각 Legendary definition 최대 1장

두 규칙을 모두 적용한다.

중복 판단은 CardInstance ID가 아니라
canonical card definition ID 기준.

skin/frame/image 차이가 있더라도
같은 card definition이면 동일 카드다.

예:

Legendary A x1 → 허용
Legendary A x2 → INVALID

Legendary A/B/C/D/E 각각 x1
→ 총 5장 VALID

Legendary A/B/C/D/E/F 각각 x1
→ 총 6장 INVALID

주의:
벨로나가 Legendary라고 가정하지 말 것.
실제 rarity는 현재 published data를 기준으로 한다.

==================================================
16. Normal 등 기존 중복 규칙 유지
==================================================

Legendary 이외 카드의 중복 제한은
현재 공식 게임 규칙을 유지한다.

이번 작업 때문에 Normal의 기존 deck-copy 규칙을
임의로 변경하지 않는다.

TOKEN은 기존처럼 일반 Deck에 넣을 수 없어야 한다.

17. 기존 저장 Deck 안전 처리
==================================================

기존 20~30장 Deck을 자동 삭제하거나 자르지 않는다.

30장 Deck을 25장으로 자동 truncate 금지.

새 규칙에 맞지 않는 기존 Deck은:

수정 필요 / INVALID

로 표시.

Deck은 열고 수정 가능해야 한다.

사용자가 직접 정상화한다.

마찬가지로 기존 Deck에:

- Legendary 6장 이상
- 동일 Legendary x2 이상

이 들어 있더라도 자동 삭제 금지.

원본 deck contents 보존.

반드시:

maxHealth=20
→ 시작 20/20

maxHealth=25
→ 시작 25/25

maxHealth=15
→ 시작 15/15

15 max Champion:
10 HP에서 heal 10
→ 15

Champion A maxHealth 변경이
Champion B에 영향 없어야 함.

Champion Token deploy/retire 후에도
원본 Champion currentHP/maxHP 보존.

==================================================
26. Deck 규칙 테스트
==================================================

반드시:

24장 → INVALID
25장 → VALID
26장 → INVALID

Legendary 4장 → 허용
Legendary 5장 → 허용
Legendary 6장 → INVALID

25장 + Legendary 5종 각 1장
→ VALID

25장 + Legendary 총 5장이지만
같은 Legendary x2 포함
→ INVALID

25장 + 동일 Legendary x2
→ INVALID

Champion 0 → INVALID
Champion 1 → 정상 조건
Champion 2 → INVALID

기존 TOKEN/cardType/rarity legality도 회귀 테스트.

==================================================
27. cards.tags 테스트 유지
==================================================

새 tags 시스템 테스트는 계속 통과해야 한다.

- [] 정상
- 1개 정상
- 3개 정상
- 4개 거부
- 중복 거부
- 공백 거부
- trim 정책
- tagsAny
- tagsAll
- tagsNone
- Token/generated definition tags
- ALT 표시
- Card Detail 표시

구 keyword "태그"를 제거하면서
새 tags 테스트를 삭제하면 안 된다.
