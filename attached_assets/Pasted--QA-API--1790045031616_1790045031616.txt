앞서 요청한 전체 자율 QA를 브라우저 조작 없이 진행해줘. 브라우저 도구 설치는 하지 말고, 실제 게임 엔진·서버 행동 처리·API·자동 테스트를 통해 버그 발견 → 수정 → 재검증을 반복해라. 계획이나 코드 리뷰만 하고 끝내지 마.

### 1. 실제 게임 처리 경로 사용

기존 테스트 도구와 게임 처리 진입점을 확인하고, 실제 서비스가 사용하는 로직을 호출하는 테스트 하네스를 구성해라.

* 게임 규칙을 테스트용으로 별도 구현하지 않는다.
* 초기 상태는 fixture로 준비하되, 검증 대상 행동은 실제 행동 처리 경로로 실행한다.
* 가능하면 Action → Event → GameState를 연결해 검증한다.
* 기대 결과는 공식 규칙과 카드 정의에서 도출한다. 현재 구현 결과를 그대로 정답으로 사용하지 않는다.
* 규칙·설명·구현이 충돌하고 정답이 불명확하면 임의 변경하지 말고 기록한다.

### 2. 모든 카드·챔피언 개별 테스트

현재 데이터에서 전체 카드와 챔피언 목록을 추출하고 각각의 테스트 상태를 기록해라.

각 효과에 해당하는 조건을 검사한다.

* 정상 발동 및 발동 조건 미충족
* 유효한 대상, 대상 없음, 잘못된 대상
* 비용 지불, 자원 부족, 사용 제한
* 효과 수치, 적용 대상, 적용 횟수
* 지속 시간, 중첩, 해제, 초기화
* 등장·공격·피격·사망·턴 시작·턴 종료 처리
* 실제 존재하는 복사·변신·소환·부활·침묵·면역 효과
* 연쇄 발동, 동시 사망, 효과 도중 대상 소멸
* 승패 판정과 게임 종료 이후 처리

카드가 생성되거나 사용됐다는 이유만으로 통과 처리하지 말고 최종 결과를 assertion으로 검증해라.

공통 효과 테스트와 별도로 각 카드의 정의가 실제 효과 처리에 올바르게 연결되는지도 확인해라.

### 3. 자동 매치 반복

실제 AI와 실제 행동 처리 경로를 사용해 서로 다른 유효 덱으로 자동 매치를 진행해라. 양쪽 자동 플레이가 가능하면 AI 대 AI로 구성한다.

* 먼저 소규모 실행으로 하네스를 검증하고, 초기 목표 100회까지 확대한다.
* 재현 가능한 난수는 seed를 고정하고, 그 외 비결정적 요소도 기록한다.
* 실패 시 초기 상태, 덱, seed, 행동 순서, 이벤트, 오류를 저장한다.
* 매치별 시간·행동 수 상한으로 무한 루프와 교착을 탐지한다.
* 성공·실패·시간 초과·중단을 각각 집계한다.
* 무작위 매치에서 나오지 않은 효과는 개별 시나리오로 보완한다.

매치 수가 많다는 이유만으로 전체 카드 검증을 완료했다고 판단하지 마.

### 4. 매 행동 후 상태 검증

게임 규칙에 맞춰 다음을 확인해라.

* 비용과 효과가 정확히 한 번 적용되는가?
* 잘못된 행동이 상태를 변경하지 않고 거부되는가?
* 수치에 NaN, undefined 또는 규칙 밖의 값이 발생하는가?
* 카드가 여러 영역에 잘못 중복되거나 사라지는가?
* 소유자·조종자·대상 참조가 일관적인가?
* 사망·퇴장·턴 전환 처리가 올바른가?
* AI가 불가능한 행동을 반복하거나 멈추는가?
* 종료된 매치에서 추가 행동이나 보상이 발생하는가?

상태를 정상값으로 강제 보정해서 오류를 숨기지 말고 원인을 수정해라.

### 5. API·저장·퀘스트 통합 테스트

격리된 테스트 환경에서 실제 요청 처리 경로로 다음을 검사해라.

* 덱 유효성 검사와 저장·불러오기
* 행동 권한, 턴 소유자, 잘못된 입력 거부
* 중복·동시 요청과 오래된 상태 기반 요청
* 지원되는 재접속·상태 복원
* 퀘스트 진행 조건과 중복 집계
* 승패 기록과 보상 중복 지급 방지
* 서버 확정 상태와 클라이언트에 전달되는 상태의 일치

관련 클라이언트 reducer나 이벤트 소비 로직을 브라우저 없이 실행할 수 있다면 함께 검사한다.

Production DB와 실제 계정 데이터는 변경하지 않는다. 테스트 환경이 없으면 안전한 로컬 fixture 등으로 가능한 범위를 진행하고 제한을 보고한다.

### 6. 연출 관련 로직 검사

브라우저 없이 확인 가능한 이벤트 순서, 연출 큐, 완료·취소 처리, 입력 잠금 해제 로직은 검사해라.

단, 이 테스트가 통과해도 애니메이션이 시각적으로 자연스럽다고 보고하지 마. 화면 배치·실제 클릭·시각적 타이밍은 미검증으로 남겨라.

### 7. 발견한 버그 직접 수정

각 버그는 다음 순서로 처리한다.

1. 재현 조건과 기대·실제 결과 기록
2. 가능하면 수정 전 실패하는 테스트 확보
3. 원인 확인 후 최소 범위 수정
4. 재현 테스트 재실행
5. 같은 처리 경로를 사용하는 기능의 회귀 테스트

카드 이름 하드코딩, 원본 밸런스 변경, 기능 비활성화, 오류 무시, 테스트 약화로 해결하지 마. 기존 공통 엔진과 구조화된 효과 정의를 활용해라.

### 8. 완료와 보고

전체 카드·챔피언별로 미실행 / 통과 / 실패 / 수정 후 통과 / 차단 / 규칙 확인 필요 상태를 남겨라.

최종 보고에는 다음을 포함한다.

* 실제 검사한 범위와 커버리지
* 자동 매치 실행·성공·실패·중단 수
* 수정한 버그와 원인·검증 증거
* 미해결 및 미검증 항목
* 브라우저 없이 확인할 수 없었던 항목
* typecheck, 관련 테스트, build, git diff --check 결과

검증이 통과하면 의도한 변경만 커밋하고 평소 사용하는 remote와 브랜치로 git push해라. 기존 사용자 변경과 관련 없는 파일은 포함하지 말고 force push는 하지 마. Render 배포는 별도로 실행하지 마. push가 운영 자동 배포를 유발한다면 push 직전까지 완료하고 보고해라.

지금부터 실제 테스트와 수정을 시작해라.
