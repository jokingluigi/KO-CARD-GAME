현재 KO 카드게임에서 아래 3개 작업을 한 번에 진행해줘.

1. 사용자 Pack Shop에서 팩 구성품 / 등장 확률 확인
2. Match에서 TECHNIQUE 주문 공개 연출 + Champion Quest 성공/보상 연출
3. Shop을 포함한 여러 화면에서 "메인 화면으로" 이동하지 못하는 Navigation 버그 전역 수정

중요:
- 기존 Game Engine / Effect DSL / Pack RNG / Shop 경제 규칙을 변경하지 말 것.
- 특정 카드/Champion/Route 이름을 임시 하드코딩해서 땜빵하지 말 것.
- 기존 Router / AudioManager / Presentation Queue / CardRenderer를 최대한 재사용.
- 전체 프로젝트 불필요한 대규모 리팩터 금지.
- 수정 후 TEST USER로 실제 브라우저 테스트.
- UI만 겉으로 고치고 실제 Route/GameState 문제가 남아 있으면 PASS 처리 금지.

==================================================
PART 1. PACK SHOP 구성품 / 확률 공개
==================================================

현재 사용자 /shop에서 판매 중인 Pack 상품을 구매하기 전에
사용자가 실제 Pack 구성품과 확률을 확인할 수 있게 해줘.

Shop 상품에서:

[구성품 및 확률 보기]

버튼을 제공.

Pack 이미지나 상품 상세에서도 진입 가능.

==================================================
1-1. Pack 상세 정보
==================================================

Pack Detail에 표시:

- Pack 이름
- Pack 이미지
- 설명
- cardsPerPack
- 판매 가격
- 상품당 Pack 수량

그리고 섹션:

[등장 확률]
[포함 카드]
[팩 전용 스킨]

==================================================
1-2. 실제 등장 확률
==================================================

반드시 실제 PackDefinition 데이터를 사용.

예:

일반 카드        90%
레전더리 카드     7%
챔피언             3%

하지만 90/7/3 하드코딩 금지.

Admin에서 Pack 확률이 변경되면
사용자 화면에도 자동 반영.

표시명:

NORMAL_CARD
→ 일반 카드

LEGENDARY_CARD
→ 레전더리 카드

CHAMPION_UNLOCK
→ 챔피언

==================================================
1-3. 포함 카드 목록
==================================================

실제 Pack Pool에 들어 있는 콘텐츠 표시.

예:

[일반 카드]
벨로나
레이븐
휴먼쿠커
...

[레전더리 카드]
...

[챔피언]
챔피언 판도라
챔피언 예거
...

CardDefinition / ChampionDefinition의
현재 이미지와 이름 사용.

기존 CardRenderer / Champion Detail UI 재사용.

==================================================
1-4. 개별 카드 확률
==================================================

실제 Pack RNG가 Category 내부에서
동일 확률 추첨이라면:

개별 확률 =
categoryRate / eligiblePoolCount

형태로 정확하게 계산.

예:

일반 90%
Pool 30장

각 카드:
3.00%

하지만 Pool 내부 Weight가 존재한다면
실제 Weight까지 반영한 정확한 확률 사용.

실제 서버 RNG와 다른 계산법 금지.

==================================================
1-5. 확률 기준 표시
==================================================

확률 옆이나 하단에:

"카드 1회 추첨 기준"

이라고 명확하게 표시.

Pack이 5장 Pack이라고 해서
카드 1장 확률을 5배해서 보여주지 마.

"팩에서 최소 1번 나올 확률"은
별도로 계산하지 않아도 된다.

==================================================
1-6. Champion
==================================================

CHAMPION_UNLOCK은:

CardDefinition rarity=CHAMPION

이 아니다.

실제 ChampionDefinition Pool을 보여줘.

==================================================
1-7. Skin Bonus
==================================================

Skin은 일반/레전더리/챔피언 확률과 별도 Bonus Roll.

예:

카드 보상 확률
일반 90%
레전더리 7%
챔피언 3%

────────────

스킨 추가 보너스
0.10%

처럼 분리.

Skin 확률을 기본 100% 합계에 넣지 마.

해당 Pack의 실제 Skin Pool:

- 스킨 이미지
- 스킨 이름
- 적용 대상 Card

표시.

현재 Skin 규칙이
"해당 원본 카드가 Reward로 나왔을 때만 Skin Roll 가능"
구조라면 그 조건도 짧게 안내.

==================================================
1-8. 표시 가능한 콘텐츠
==================================================

사용자에게는 실제 현재 Pack에서
획득 가능한 콘텐츠만 표시.

DISABLED / 삭제된 Card / Champion / Skin 제외.

단 Pack 설정 오류로:

확률 > 0
하지만 eligible Pool = 0

이라면 확률 자동 재분배 금지.

기존 Pack Validation에 따라
해당 Pack을 invalid 상태로 처리.

==================================================
1-9. ShopListing / PackDefinition 구분
==================================================

ShopListing:

- 가격
- 판매 수량
- 기간

PackDefinition:

- 확률
- Reward Pool
- Skin Bonus

source of truth 유지.

같은 PackDefinition을:

1팩
5팩
10팩

상품으로 팔아도
팩 구성품/확률 내용은 동일해야 한다.

==================================================
PART 2. TECHNIQUE 주문 공개 PRESENTATION
==================================================

실제 Match에서 TECHNIQUE 카드를 사용하면
카드 효과가 바로 터져서 무엇을 사용했는지
확인하기 어려운 문제를 개선해줘.

TECHNIQUE 사용 시:

Technique Play
→ 중앙 Card Reveal
→ 확인 시간
→ Fade Out
→ Technique Effect Presentation

순서로 보여줘.

==================================================
2-1. 주문 카드 중앙 공개
==================================================

TECHNIQUE_REVEAL Presentation 추가.

화면 중앙 또는 약간 위쪽에
사용한 Technique Card를 크게 표시.

기존 CardRenderer 재사용.

Desktop:

일반 필드 카드보다 대략 1.5~2배 정도 크게.

Mobile:

화면 밖으로 나가지 않도록 Responsive.

보여야 하는 정보:

- Artwork
- 카드 이름
- Cost
- Effect Text
- Technique Frame

TECHNIQUE는 Attack / Health 표시 X.

==================================================
2-2. 사용자 / 상대 표시
==================================================

내 Technique:

"주문 사용"

상대/AI Technique:

"상대가 주문을 사용했습니다"

정도의 작은 안내 문구 표시.

카드 자체가 핵심.

==================================================
2-3. 유지 시간
==================================================

순간적으로 번쩍이고 없어지면 안 된다.

대략:

Fade In 0.2~0.3초
Hold 1.4~1.8초
Fade Out 0.2~0.3초

총 약 1.8~2.4초.

시간은 Presentation 상수로 관리.

예:

TECHNIQUE_REVEAL_HOLD_MS

여러 setTimeout을 여기저기 만들지 마.

==================================================
2-4. Technique는 Board Card가 아니다
==================================================

기존 규칙 유지:

TECHNIQUE는 Board Slot 사용 X.

Board가 4/4여도 Technique 사용 가능.

Reveal 카드 이미지는:

Presentation Clone

일 뿐이다.

GameState.board에 TECHNIQUE를 추가하지 마.

Reveal 종료 후 Clone cleanup.

==================================================
2-5. Presentation Queue
==================================================

기존:

Game Engine
→ Game Event
→ Presentation Queue
→ Animation
→ Next Presentation

구조 사용.

Technique가 DAMAGE / DESTROY / RETIRE 등을 발생시켜도:

Technique Reveal
→ 해당 Effect Animation

순서를 보장.

UI가 Game Rule 계산을 지연시키는 방식 금지.

==================================================
PART 3. CHAMPION QUEST 성공 / 보상 PRESENTATION
==================================================

Champion Quest가 완료되면
현재보다 명확하게 성공 순간과 Reward를 보여줘.

실제 Quest Completion Event를 source로 사용.

UI가 Quest Progress를 다시 계산하지 마.

==================================================
3-1. 내 Quest 성공
==================================================

내 Champion Quest 완료:

화면 중앙에 크게:

퀘스트 성공!

표시.

필요하면 아래에 Champion 이름 표시.

==================================================
3-2. 상대 Quest 성공
==================================================

상대/AI Quest 완료:

상대의 퀘스트 성공!

표시.

viewer 기준으로:

viewer === questOwner
→ "퀘스트 성공!"

viewer !== questOwner
→ "상대의 퀘스트 성공!"

Generic하게 처리.

==================================================
3-3. Quest Reward 공개
==================================================

성공 문구 후:

[퀘스트 보상]

을 화면 중앙에 보여줘.

흐름:

Quest Complete
↓
성공 Banner
↓
Quest Reward Reveal
↓
Fade Out
↓
Match 계속

계속 떠 있는 Modal이 아니다.

자동으로 사라져야 한다.

==================================================
3-4. Reward 데이터
==================================================

반드시 실제 ChampionDefinition의 데이터를 사용.

예:

questReward
upgradedChampionAbility
championTokenDefinitionId

등.

카드/챔피언 이름별 UI 하드코딩 금지.

==================================================
3-5. Ability Upgrade Reward
==================================================

Reward가 Champion Ability Upgrade라면:

[퀘스트 보상]

강화된 고유 능력

비용
효과 설명

을 실제 upgradedChampionAbility에서 읽어서 표시.

==================================================
3-6. Champion Token Reward
==================================================

Reward가 Champion Token Deploy를 포함하면:

기존 CardRenderer로
실제 Champion Token 카드를 크게 보여줘.

Champion Token Definition의 현재 데이터를 사용.

==================================================
3-7. 복수 Reward
==================================================

Reward가:

- Ability Upgrade
- Champion Token Deploy

등 여러 개인 경우

한 Reward Panel에 같이 표시하거나
Presentation Queue에서 순서대로 표시.

너무 오래 끌지는 말 것.

==================================================
3-8. Quest Presentation 시간
==================================================

Quest는 Technique보다 조금 더 강조.

예:

성공 Banner
약 1.0~1.3초

Reward Reveal
약 1.8~2.5초

전체 약 3~4초.

사용자가 확인할 시간은 주되
Match 흐름을 지나치게 끊지 마.

==================================================
3-9. Quest Music
==================================================

현재 Match의 Quest Completion Music 규칙은
절대 변경하지 마.

Quest 성공 Presentation이 끝난다고
Quest Music을 끄면 안 된다.

기존 AudioManager 규칙 유지.

==================================================
PART 4. AI 행동과 PRESENTATION 동기화
==================================================

AI가 Presentation 중에 다음 행동을 해버리지 않게 해.

예:

AI Technique
→ Technique Reveal
→ Effect Animation
→ AI Delay
→ 다음 AI Action

Quest 완료 시:

Quest Banner
→ Reward Reveal
→ 관련 Reward Animation
→ AI Delay
→ 다음 AI Action

Presentation Queue가 busy인 동안
AI는 다음 Major Action 실행 금지.

AI 판단 알고리즘 자체는 변경하지 마.

==================================================
PART 5. 메인 화면으로 이동 안 되는 NAVIGATION 버그
==================================================

현재 상점 등 일부 화면에서:

[메인 화면으로]
[뒤로]
[홈]
[메인 메뉴]

버튼을 눌러도
Main Menu로 정상 이동하지 않는 버그가 다시 발생했다.

Shop만 임시 수정하지 말고
프로젝트 전체 Navigation을 점검해줘.

==================================================
5-1. Main Menu 공식 Route 확인
==================================================

먼저 프로젝트에서 실제 Main Menu의
canonical route를 확인.

예:

/
또는
/main
또는
/menu

기존 Router 설정에 있는 실제 Route를 source of truth로 사용.

새 Main Menu Route를 중복 생성하지 마.

==================================================
5-2. 모든 Main Menu 이동 버튼 점검
==================================================

최소 다음 화면을 모두 확인:

- Shop
- Pack Shop / Pack Detail
- Pack Opening
- Collection
- Deck Editor
- Deck Select
- AI Match Setup
- AI Match Result
- Actual Match Result
- Champion / Card Detail
- Prism / Craft
- Skin 관련 화면
- User Account/Profile 화면
- Admin에서 User Main으로 돌아가는 버튼이 있다면 그것도 확인

각 화면의:

[메인 화면으로]
[메인 메뉴]
[홈]
[뒤로]

버튼이 의도한 Route로 정상 이동하는지 테스트.

==================================================
5-3. Router 사용
==================================================

React Router 등 현재 프로젝트의
기존 Router API 사용.

예:

navigate(MAIN_MENU_ROUTE)

형태.

절대:

window.location.reload()
location.href
강제 page refresh

로 문제를 숨기지 마.

==================================================
5-4. 클릭 이벤트 버그 점검
==================================================

버튼이 눌리지 않는 원인을 실제로 확인.

예:

- overlay가 pointer event를 가로채는 문제
- invisible modal
- presentation layer
- z-index
- disabled state가 풀리지 않음
- preventDefault 문제
- stale callback
- 잘못된 route path
- nested route 상대경로 문제
- navigation lock
- pending modal
- loading state
- stale match state

등을 확인.

단순히 버튼에 onClick 하나 더 붙이고 끝내지 마.

==================================================
5-5. 상대경로 Navigation 금지
==================================================

예:

navigate("../")

같은 방식으로 Main Menu를 추정하지 마.

현재 Route Depth에 따라 다른 곳으로 갈 수 있다.

Main Menu는 항상
canonical absolute route를 사용.

가능하면:

ROUTES.MAIN_MENU

같은 shared route constant 사용.

==================================================
5-6. Presentation/Input Lock Cleanup
==================================================

화면을 떠날 때 Presentation Lock이나 Input Lock이
남아서 Navigation까지 막는지 확인.

Route Exit 시:

- presentation locks
- temporary UI locks
- stale overlay
- pending timers

등을 정상 cleanup.

단 Match GameState를 임의 변경하지 마.

==================================================
5-7. Audio Cleanup
==================================================

이전에 발생했던:

Deck Select / Game 화면에서 Main으로 나가도
Game BGM이 계속 재생되는 문제도 함께 회귀 테스트.

Game 관련 Route를 떠나면:

- Game BGM fade out
- stale music timer cleanup
- temporary reveal audio cleanup

Main Menu에 별도 BGM이 있다면
기존 Main Menu Audio 규칙대로 재생.

Shop BGM이 따로 있다면
Shop → Main 이동 시 동일하게 cleanup.

==================================================
5-8. Match 중 Main으로 나가는 경우
==================================================

실제 진행 중 Match에서
사용자가 의도적으로 Main Menu로 나가는 기능이 이미 있다면
기존 Confirm UX를 유지.

이번 작업에서
강제 Surrender 규칙이나 Match Result 규칙을 새로 만들지 마.

Navigation 버그만 수정.

==================================================
5-9. Browser Back
==================================================

브라우저 뒤로가기 때문에
깨진 Match / Shop Overlay가 남는지도 확인.

Router history를 정상 사용하고
이전 화면의 stale UI가 남지 않게 cleanup.

==================================================
PART 6. 공통 PRESENTATION UI
==================================================

Technique Reveal / Quest Reward 모두:

- 중앙 표시
- 약한 Background Dim
- 게임 Board가 완전히 안 보이게 하지 않음
- 자동 Fade Out
- 과도한 Particle 금지
- 텍스트 가독성 우선

Presentation 중 accidental input:

- Card Play
- Attack
- Champion Ability
- End Turn

이 실행되지 않도록
기존 Presentation Input Lock 재사용.

Presentation 종료 후 자동 해제.

Navigation 버튼 자체까지
영구적으로 막으면 안 된다.
