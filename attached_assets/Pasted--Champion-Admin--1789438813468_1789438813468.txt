현재 구현 중인
"선수 카드 전체 효과 구현 프롬프트 생성"
기능과 동일한 개념을 Champion Admin에도 추가해줘.

기존 선수 카드 기능은 삭제하거나 변경하지 마.

==================================================
1. Champion Admin 버튼
==================================================

Champion Admin에:

[챔피언 전체 구현 프롬프트 생성]

버튼 추가.

버튼 클릭 시 현재 등록된 모든 ChampionDefinition의
효과/퀘스트를 최신 Effect Analyzer 기준으로 다시 분석해.

==================================================
2. 분석할 Champion 영역
==================================================

각 Champion에서 다음 Slot을 모두 검사:

- CHAMPION_ABILITY
- QUEST_CONDITION
- QUEST_REWARD
- UPGRADED_CHAMPION_ABILITY

Quest가 없는 Champion은
존재하는 Slot만 분석.

Champion Token 효과 자체는 Champion Admin에서 새로 분석하지 마.

Champion Token CardDefinition의 효과는
기존 Card Admin / Wrestler Effect Analyzer가 Source of Truth다.

단 Champion에 연결된:

championTokenDefinitionId

정보와 해당 CardDefinition의 현재 상태는
통합 프롬프트에 참고 정보로 포함 가능.

==================================================
3. 반드시 최신 상태로 재분석
==================================================

저장된 오래된 Analyzer 결과를 그대로 사용하지 말고
버튼을 누를 때 최신:

- Effect Registry
- Trigger
- Action
- Target
- Value
- Condition
- Duration
- Listener
- PLAYER_CHOICE
- Quest Event/Filter
- Natural Language Analyzer

기준으로 다시 분석.

stale cache 금지.

==================================================
4. 상태 분류
==================================================

각 Slot을:

SUPPORTED

NEW_MECHANIC_REQUIRED

ANALYSIS_FAILED

로 분류.

SUPPORTED:
실제 Engine에서 실행 가능.

NEW_MECHANIC_REQUIRED:
의미는 이해했지만 공통 Engine 기능이 부족함.

ANALYSIS_FAILED:
텍스트 의미 자체를 안전하게 분석할 수 없음.

==================================================
5. 통합 프롬프트 생성
==================================================

모든 Champion의
NEW_MECHANIC_REQUIRED 항목을 하나로 모아서
Replit Agent용 통합 구현 프롬프트를 생성해.

각 항목에 최소:

- ChampionDefinition ID
- Champion 이름
- Slot 종류
- 원본 효과 텍스트
- Analyzer가 이해한 내용
- supportedParts
- unsupportedParts

포함.

==================================================
6. 중복 Mechanic 제거
==================================================

여러 Champion이 같은 미구현 기능을 요구하면
각각 따로 구현하지 말고
Generic Mechanic 하나로 합쳐.

예:

Champion A와 Champion B가 모두
"다음 개인 턴 Gold 추가"

를 요구한다면

NEXT_TURN_GOLD_BONUS

같은 공통 mechanic 하나를 구현하도록 프롬프트 생성.

Champion 이름 기반 하드코딩 금지.

==================================================
7. 기존 Effect Library 우선 재사용
==================================================

생성되는 프롬프트에는 반드시:

"먼저 현재 Effect Library를 검사하고
기존 Trigger / Action / Target / Value / Condition /
Listener / Duration / Sequence를 조합해서 구현하라."

를 포함.

이미 존재하는 기능을 새로 만들지 마.

==================================================
8. PLAYER_CHOICE 공통 사용
==================================================

Champion Ability 또는 Reward에:

"선택한 선수"
"선택한 대상"
"선택한 챔피언"

같은 표현이 있으면
기존 공통 PLAYER_CHOICE 시스템을 사용.

공식 의미:

대상 = WRESTLER + CHAMPION
선수 = WRESTLER
챔피언 = CHAMPION

Champion 전용 Target Picker를 따로 만들지 마.

==================================================
9. Quest 분석
==================================================

QUEST_CONDITION은 일반 Effect와 달리
Event + Filter + Progress 구조로 분석해야 한다.

예:

"선수 카드를 7번 생성"

→ CARD_GENERATED
→ type WRESTLER
→ progress +1
→ target 7

"판도라의 고유 능력으로 선수 5명을 RETIRE"

같은 조건은
Event attribution/context까지 필요할 수 있다.

특정 Champion 이름을 Engine에 하드코딩하지 말고
source/context filter로 Generic하게 구현.

==================================================
10. Quest Reward / Upgrade
==================================================

Quest 완료 후:

- Ability 교체
- Reward 실행
- Champion Token 직접 배치
- Portrait 변경
- Quest Completion Music

같은 기존 시스템이 있다면 반드시 재사용.

새로운 별도 Quest Engine을 만들지 마.

==================================================
11. Champion Token 참조
==================================================

ChampionDefinition의:

championTokenDefinitionId

는 기존 CardDefinition ID reference를 사용.

통합 프롬프트 생성 시 필요하면:

- 연결된 Token 이름
- Definition ID
- PUBLISHED 상태
- isChampionToken 여부

정도는 참고 정보로 포함.

Token의 스탯/효과를 ChampionDefinition에 복제하지 마.

==================================================
12. 특수 Champion Token 배치
==================================================

효과 텍스트가:

"챔피언을 소환합니다."

의미라면 기존 Generic:

DEPLOY_CHAMPION_TOKEN

메커니즘을 재사용.

일반 SUMMON으로 바꾸지 마.

기존 Champion 보호 /
Token RETIRE 시 패배 /
현재 Champion HP 추가 규칙을 유지.

==================================================
13. ANALYSIS_FAILED
==================================================

ANALYSIS_FAILED가 있어도
전체 프롬프트 생성은 가능해야 한다.

프롬프트 하단에:

[분석 실패 - 수동 확인 필요]

섹션으로:

- Champion
- Slot
- 원문
- 실패 이유

표시.

의미를 추측해 구현하지 마.

15. 구현 완료 후 재분석
==================================================

같은 화면에:

[전체 구현 완료 - 다시 분석]

버튼 추가.

최신 Effect Registry 기준으로
모든 Champion Slot을 다시 분석.

모두 SUPPORTED라면:

ALL CHAMPION EFFECTS SUPPORTED

또는

모든 챔피언 효과 구현 완료

표시.

==================================================
16. 생성되는 Replit 프롬프트의 완료 조건
==================================================

자동 생성 프롬프트에는 반드시 다음 요구를 포함:

- 기존 Effect Library 우선 재사용
- 없는 기능만 Generic Mechanic으로 추가
- Effect Registry 등록
- Natural Language Analyzer 등록
- Quest Event/Filter 등록
- PLAYER_CHOICE 실제 선택 테스트
- 실제 Engine execution 테스트
- Champion별 실제 Ability 사용 테스트
- Quest progress/completion 테스트
- 재분석 후 SUPPORTED 확인

Analyzer가 알아듣는 것만으로
SUPPORTED 처리하지 마.

실제 Executor가 실행 가능해야 한다.

17. 선수 카드 기능과 함께 유지
==================================================
