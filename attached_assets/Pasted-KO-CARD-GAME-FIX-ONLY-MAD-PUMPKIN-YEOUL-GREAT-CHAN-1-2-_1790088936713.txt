==================================================
0. 작업 방식
==================================================

이번 작업은 QA 보고서가 아니다.

각 카드마다 반드시:

재현
→ authoritative effect 확인
→ root cause 확인
→ 실제 source/config 수정
→ 전용 regression test
→ 관련 회귀 테스트
→ typecheck/build

순서로 끝내라.

세 카드 모두 조사만 한 뒤
마지막에 조금 수정하는 방식 금지.

반드시:

매드 펌킨 수정+테스트
→ 여울 수정+테스트
→ 그레이트 챤 수정+테스트

순서로 진행한다.

==================================================
PART A — 매드 펌킨
==================================================

현재 실제 신고:

매드 펌킨 효과에서
필드의 하스이를 대상으로 선택했지만

- 해당 선수가 손으로 돌아오지 않음
- 비용 감소도 적용되지 않음

즉 PLAYER_CHOICE까지는 보이지만
선택 이후 effect resolution이 실패하는 것으로 보인다.

==================================================
1. 매드 펌킨 공식 효과 확인
==================================================

먼저 현재 authoritative source에서
매드 펌킨의 정확한 효과를 확인한다.

우선순위:

1. CardDefinition
2. effectConfig / SCRIPT / Structured Effect
3. Admin saved data
4. seed/catalog
5. git history

수치나 조건 추측 금지.

공식 설명이:

"선수 하나를 손으로 돌리고
그 카드의 비용을 X 감소"

형태라면 그 정확한 X를 사용한다.

==================================================
2. 매드 펌킨 실패 경로 추적
==================================================

확인:

PLAY / ACTIVE / trigger
→ PLAYER_CHOICE
→ selected CardInstance ID
→ continuation
→ RETURN / MOVE_TO_HAND
→ 동일 instance 비용 수정

특히 확인:

- selected target ID가 continuation 이후 사라지는가?
- target object를 stale snapshot으로 참조하는가?
- BOARD → HAND 이동 후 새로운 instance가 생성되는가?
- 비용 감소가 이동 전 instance에만 적용되는가?
- result reference가 RETURN 결과를 가리키지 못하는가?
- effect 중간에 target legality 재검증이 실패하는가?

==================================================
3. 매드 펌킨 기대 동작
==================================================

공식 대상이 WRESTLER라면:

target 선택
→ 그 동일 CardInstance가 FIELD에서 제거
→ 같은 owner HAND로 이동
→ 그 동일 카드에 공식 비용 감소 적용

카드가 복사되거나
새 CardInstance로 바뀌면 안 된다
(현재 엔진의 공식 MOVE semantics가 instance 유지라면).
