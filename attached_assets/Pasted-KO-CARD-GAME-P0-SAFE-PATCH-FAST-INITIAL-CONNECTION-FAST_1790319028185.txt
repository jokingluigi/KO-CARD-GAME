OBSERVED BUG
==================================================

The Online Match connection is not permanently broken.

Observed behavior:

- Enter Online Match
- For some initial period, connection is unstable/not ready
- END TURN may not advance
- UI shows:
  "연결이 끊겼습니다. 재연결 중..."
- After some time passes, connection recovers
- Then END TURN works normally

The delay is NOT confirmed to be exactly 60 seconds.

Goal:

MAKE INITIAL CONNECTION AND RECONNECTION HAPPEN QUICKLY AND RELIABLY.

Do NOT invent a hardcoded 60-second fix.

==================================================
2. PRIMARY GOAL
==================================================

When the backend/API is already available:

Online Match should connect immediately or within a very short reasonable time.

If WS connection drops:

reconnect should begin quickly.

Do not make the player wait unnecessarily before the next retry.

==================================================
3. RECONNECT STRATEGY
==================================================

Use a bounded, safe reconnect strategy.

Example behavior:

first retry:
very soon

then:
short increasing delays

cap the delay at a reasonable value.

Example concept only:

1s
2s
3s
5s
5s...

Do NOT blindly copy these exact values if the existing architecture already has a better mechanism.

The important requirement is:

- retry quickly
- avoid retry storms
- do not wait tens of seconds unnecessarily
- recover immediately once backend/WS becomes available

==================================================
4. FRESH WS TICKET
==================================================

Check whether a reconnect requires a fresh one-time WS ticket.

If tickets are single-use or expire:

do NOT reuse an old ticket.

On each reconnect attempt where required:

authenticated request
→ obtain fresh WS ticket
→ open fresh socket

Do not weaken authentication.

Do not bypass ticket validation.

==================================================
5. STALE SOCKET CLEANUP
==================================================

Before creating a replacement connection:

ensure the old/stale socket is correctly abandoned/closed.

Avoid:

- multiple simultaneous sockets for same match/user
- old socket callbacks overwriting new connection state
- old reconnect timer opening another socket after success
- duplicate event listeners
- duplicate authoritative snapshots
- duplicate END TURN sends

==================================================
6. CANCEL RECONNECT TIMERS AFTER SUCCESS
==================================================

When WS successfully reconnects:

cancel all pending reconnect timers immediately.

There must be only ONE active connection/reconnect loop.

Do not allow an older scheduled retry to fire after a healthy socket is already open.

==================================================
7. MATCH READY STATE
==================================================

The client must distinguish:

CONNECTING
CONNECTED BUT WAITING FOR SNAPSHOT
READY
RECONNECTING

Gameplay should be considered READY only when:

- authentication resolved
- correct match confirmed
- WebSocket OPEN
- authoritative state/snapshot received

Do NOT fake READY.
