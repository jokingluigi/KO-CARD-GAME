현재 KO 카드게임의 자연어 카드 효과 Analyzer와
"Replit 구현 프롬프트 생성" 기능에
특정 카드 이름을 직접 참조하는 기능을 추가해줘.

목표:

카드 효과 문장에 실제 Card Admin에 등록된 카드 이름이 들어가 있고
그 카드를 생성/소환/참조하는 효과라면,

단순 텍스트로 처리하지 말고
해당 CardDefinition과 실제로 연결되게 해줘.


================================
1. 예시
================================

Card Admin에 다음 카드가 존재한다고 가정:

이름:
잔상

CardDefinition.id:
card_afterimage_001


효과:

등장: "잔상"을 소환합니다.

또는:

등장: 잔상을 소환합니다.


Analyzer는 이를:

SUMMON {
  cardDefinitionId: "card_afterimage_001"
  count: 1
}

와 같은 구조로 변환해야 한다.

실제 프로젝트 DSL 구조에 맞춰 구현해.


================================
2. 카드 이름 → CardDefinition 연결
================================

Natural Language Analyzer가 효과를 분석할 때
현재 Card Registry / CardDefinition DB의 카드 이름도 조회할 수 있게 해.

다음 표현을 인식:

"잔상을 소환합니다."
"'잔상'을 소환합니다."
"「잔상」을 소환합니다."
"잔상 1장을 소환합니다."
"잔상을 2장 소환합니다."

등.

카드 이름이 발견되면:

cardName = "잔상"

만 저장하지 말고

cardDefinitionId

를 resolve해서 Structured Effect에 저장해.


================================
3. 이름은 분석할 때만 사용
================================

런타임에서:

getCardByName("잔상")

처럼 카드 이름으로 계속 찾지 마.

이름은 Admin의 자연어 분석 단계에서
CardDefinition을 찾는 용도로만 사용한다.

분석 완료 후 Structured Effect에는 안정적인:

cardDefinitionId

를 저장해.

그래야 나중에 카드 이름이 변경돼도
기존 효과 연결이 깨지지 않는다.


================================
4. 카드 Reference 타입
================================

기존 Effect DSL에 TOKEN_REFERENCE / CARD_REFERENCE 등
비슷한 범용 구조가 있다면 반드시 재사용해.

없다면 범용:

CARD_REFERENCE

를 추가해.

예:

cardReference: {
  cardDefinitionId,
  displayName
}

또는 현재 프로젝트 구조에 맞는 동등한 형태.

특정 카드마다 별도 Action을 만들지 마.

금지:

SUMMON_AFTERIMAGE
SUMMON_WIRINYE
if (cardName === "잔상")

대신:

SUMMON {
  cardReference,
  count,
  destination
}

같은 범용 구조로 만들어.


================================
5. Replit 구현 프롬프트 생성에도 포함
================================

NEW_MECHANIC_REQUIRED 때문에
Replit 구현 프롬프트를 생성하는 경우에도

원본 효과에 특정 카드 이름이 들어 있다면
Prompt Generator가 해당 카드 정보를 자동으로 포함해야 한다.

예:

원본 효과:
"등장: 위리녀를 소환합니다."

생성 프롬프트에는 자동으로:

Referenced Card:
- Name: 위리녀
- CardDefinition ID: xxx
- Type: WRESTLER
- Token: true/false
- Champion Token: true/false

등 현재 필요한 최소 정보를 포함해.

그리고 Replit Agent에게:

"문자열 이름으로 하드코딩하지 말고
해당 CardDefinition ID/reference를 사용해서
실제 카드 인스턴스를 생성/소환하세요."

라고 명확히 지시해.


================================
6. 특정 카드 소환
================================

특정 이름의 카드를 소환하는 효과는
랜덤 카드 Pool을 사용하지 않는다.

예:

"잔상을 소환"

→ 정확히 잔상 CardDefinition 사용.

"무작위 선수를 소환"

→ 기존 RANDOM 규칙.

"완전히 무작위 선수를 소환"

→ 기존 FULL_RANDOM 규칙.

서로 혼동하지 마.


================================
7. 명시적 카드 참조는 Token도 허용
================================

특정 카드 이름이 직접 명시된 경우에는
그 카드가:

- 일반 카드
- Token
- Champion Token

중 무엇이든 명시적 참조 자체는 가능하게 해.

RANDOM에서 Token을 제외하는 규칙은
명시적 CARD_REFERENCE에는 적용하지 않는다.

예:

"잔상을 소환"
→ 잔상이 Token이어도 정상 소환.

"챔피언 판도라(폭주)를 소환"
→ CardDefinition 참조 자체는 가능.


================================
8. Champion Token 보호 규칙 주의
================================

단 특정 효과가 이름으로 Champion Token을 소환했다고 해서
자동으로 DIRECT_DEPLOY_CHAMPION_TOKEN 보호 상태를 주면 안 된다.

isChampionToken = true

와

Champion 자신의 고유 효과를 통한 직접 전개

는 별개다.

기존 DIRECT_DEPLOY_CHAMPION_TOKEN 규칙이 명시된 효과에서만:

- Silence 면역
- 효과 Destroy 면역
- Champion HP 대표
- Retire 시 패배

등 특수 규칙 적용.

단순:

SUMMON "챔피언 판도라(폭주)"

만으로는 자동 적용 금지.


================================
9. 효과로 새로 만들어진 카드 인스턴스
================================

특정 CardDefinition을 효과로 새로 생성/소환한다면
KO의 기존 Generated 규칙을 적용해.

즉 효과가 새로운 카드 인스턴스를 만든 경우:

isGenerated = true

로 생성.

그리고 Field에 바로 소환됐다면:

ENTER_FIELD

도 정상 발생해야 한다.

해당 카드 자체의 "등장" 효과도 정상 발동해야 한다.


================================
10. 카드 이름을 찾지 못한 경우
================================

효과:

"무무킹을 소환합니다."

인데 Card Admin에
"무무킹"이라는 카드가 없다면
임의로 비슷한 카드를 선택하지 마.

분석 결과에:

CARD_REFERENCE_NOT_FOUND

또는 현재 구조에 맞는 명확한 오류를 표시해.

UI에:

참조할 카드를 찾을 수 없습니다:
무무킹

을 표시.

가능하면:

[카드 선택]

기능을 제공해서 관리자가
기존 CardDefinition을 직접 선택해서 연결할 수 있게 해.


================================
11. 이름이 중복되는 경우
================================

동일한 이름의 CardDefinition이 여러 개 있으면
임의 선택 금지.

예:

잔상
잔상

두 정의가 있으면:

CARD_REFERENCE_AMBIGUOUS

상태로 표시하고
관리자가 정확한 카드를 선택하게 해.

선택 후에는 해당 cardDefinitionId를 저장.


================================
12. 카드 이름 변경
================================

이미:

cardDefinitionId = ABC

로 연결된 Structured Effect가 있다면

Card Admin에서 카드 이름을:

잔상
→ 강화 잔상

으로 바꾸더라도
기존 효과 연결은 ABC ID를 통해 계속 유지되어야 한다.

Admin UI에서는 최신 카드 이름을 표시해.


================================
13. Match Snapshot
================================

매치 시작 시 Deck에 들어있지 않은 카드라도
다른 카드 효과에서 특정 CARD_REFERENCE로 사용된다면
실제 게임에서 생성/소환 가능해야 한다.

따라서 Match Snapshot 생성 시
Deck/Champion뿐 아니라
효과에서 직접 참조하는 cardDefinitionId도 수집해.

필요하면 참조된 카드가 다시 다른 카드를 참조하는 경우도
안전하게 resolve할 수 있게 해.

단 무한 참조 루프는 방지해.


================================
14. Card Admin 분석 UI
================================

효과 분석 결과에서 특정 카드 참조를 알아보기 쉽게 표시해.

예:

✓ 특정 카드 인식

소환:
[잔상]

Card ID:
card_afterimage_001

Count:
1

Action:
SUMMON

가능하면 카드 작은 thumbnail도 표시해도 된다.

하지만 핵심은 cardDefinitionId 연결이다.


================================
15. 지원할 기본 표현
================================

최소한 아래를 지원:

"X를 소환한다"
"X를 소환합니다"
"X 1장을 소환한다"
"X를 2장 소환한다"

"X를 생성한다"
"X를 손에 생성한다"
"X를 덱에 생성한다"

"X의 복사본을 생성한다"

등 기존 Effect DSL이 지원하는 범위에서
카드 이름 Reference를 사용할 수 있게 해.

SUMMON만을 위한 하드코딩 시스템으로 만들지 말고
향후 GENERATE / CREATE / ADD_TO_HAND 등에서도
동일 CARD_REFERENCE Resolver를 재사용 가능하게 해.


================================
16. 선수 효과 분석과 Champion 효과 분석 둘 다
================================

이 CARD_REFERENCE 기능은
선수 카드 분석 전용으로 만들지 마.

공통 Effect Analyzer를 사용하는:

- 선수 카드
- 기술 카드
- Champion Ability
- Quest Reward
- 강화 Champion Ability

에서도 동일하게 사용할 수 있게 해.

Champion Token 자체 효과는 기존 정책대로
Card Admin에서 관리.


================================
17. 테스트
================================

실제 CardDefinition:

잔상
위리녀
용병
강화 용병

등을 사용해서 테스트해.

TEST 1

"잔상을 소환합니다."

→ 잔상 CardDefinition ID resolve
→ SUMMON 정상


TEST 2

"위리녀를 2장 소환합니다."

→ 위리녀 reference
→ count=2


TEST 3

"용병을 손에 생성합니다."

→ 용병 CardDefinition reference
→ HAND destination


TEST 4

없는 카드 이름

"없는카드를 소환합니다."

→ 임의 처리하지 않음
→ CARD_REFERENCE_NOT_FOUND


TEST 5

동명이인 카드

→ AMBIGUOUS
→ 관리자 선택 필요


TEST 6

참조 카드 이름 변경

→ 기존 Structured Effect의 ID 연결 유지


TEST 7

Deck에 없는 Token을 특정 효과가 소환

→ Match Snapshot에 포함
→ 정상 생성/소환


TEST 8

특정 Champion Token 소환

→ 카드 자체는 정상 생성
→ DIRECT_DEPLOY 보호는 자동 적용되지 않음


================================
18. 중요한 원칙
================================

특정 카드 이름이 효과 텍스트에 명시됐을 때:

자연어 카드 이름
↓
Card Registry 검색
↓
CardDefinition.id resolve
↓
Structured Effect에 ID 저장
↓
게임 실행 시 ID로 실제 카드 생성

이 구조로 구현해.

카드 이름 문자열 하드코딩으로 게임 로직을 만들지 마.

현재 Card Registry / Effect Analyzer / Effect Library /
Prompt Generator를 최대한 재사용하고
필요한 CARD_REFERENCE 기능만 범용적으로 추가해.

대규모 리팩터링은 하지 말고
관련 코드만 최소 수정 후 종료해.
