현재 KO 카드게임의 Desktop Match 화면 레이아웃을 크게 개선해줘.

이번 작업의 핵심 목표는 2가지다.

1. 보드와 손패를 훨씬 크게 만들어서 카드가 잘 보이게 만들 것
2. 레이아웃이 커진 뒤에도 카드 플레이 / 공격 / 소환 / 부활 애니메이션이 새 레이아웃 기준으로 자연스럽고 정확하게 작동하게 만들 것

중요:
- 단순히 CSS로 화면만 키우는 작업이 아니다
- Board/Hand 크기가 바뀌면 Presentation 좌표 계산도 함께 맞춰야 한다
- 그렇지 않으면 카드가 예전 위치 기준으로 움직여 오류처럼 보인다

이번 작업에서는:
- Game Engine 규칙
- 카드 효과
- AI 판단
- 카드 스탯
- 슬롯 개수
를 바꾸지 마.

==================================================
1. 현재 문제
==================================================

현재 Desktop Match 화면은 다음 문제가 있다.

1) 중앙 보드와 손패가 너무 작다
- 카드가 잘 안 보인다
- 이름/수치/효과를 읽기 어렵다
- 화면은 넓은데 실제 플레이 영역이 너무 작다

2) 레이아웃이 작게 만들어진 상태에 맞춰
카드 애니메이션 좌표가 짜여 있는 것처럼 보인다

그래서 보드/손패를 키우면 반드시 함께 고쳐야 할 것:
- 카드 플레이 애니메이션 출발점
- 카드 플레이 애니메이션 도착점
- 공격 애니메이션 출발점/도착점
- 소환 애니메이션 도착점
- 부활 애니메이션 도착점
- 대상 강조/선택 표시 위치

즉, 레이아웃 확대와 애니메이션 좌표 시스템 보정은 반드시 같이 처리해야 한다.

==================================================
2. 작업 범위
==================================================

이번 작업은 다음 두 축으로 진행:

A. Desktop Match 레이아웃 확대
B. Presentation 좌표 시스템을 새 레이아웃 기준으로 동기화

모바일 전용 UI는 이번 작업의 주 대상이 아니며,
Desktop 변경 때문에 Mobile이 깨지지만 않게 해라.

==================================================
3. Desktop Match Stage 확대
==================================================

Desktop 기준:
1920 × 927
1600 × 900
1366 × 768

에서 Board와 Hand가 지금보다 훨씬 크게 보이게 해.

원칙:
- Match 전체 플레이 영역이 화면 대부분을 차지
- 중앙 Board가 실제 게임의 중심
- Hand도 충분히 크게
- 불필요한 넓은 빈 공간 축소

Stage는 대략:
width 96~98vw
height 94~97vh
수준으로 활용 가능.

중앙에 작은 박스처럼 보이는 max-width / padding / margin 구조가 있으면 완화해라.

==================================================
4. Board 확대
==================================================

2 x 4 보드 구조는 그대로 유지.

상대:
[1][2][3][4]

내:
[1][2][3][4]

이 구조를 유지하면서도
현재보다 체감 35~50% 정도 크게 보이게 조정.

Board 전체가 더 커지고
Card도 더 커지고
Slot 간격은 조금 줄여
밀도 있게 보이게 만들어라.

==================================================
5. Field Card 크기 확대
==================================================

Field Card는 지금보다 확실히 커져야 한다.

목표:
- ALT를 누르지 않아도 이름/코스트/공체 정도는 쉽게 읽힘
- 짧은 효과 텍스트는 대충 읽힘
- Keyword 표시도 눈에 들어옴

예시 시작값:
fieldCardWidth = clamp(150px, 9.5vw, 205px)

정확한 수치는 실제 테스트 후 조정.

==================================================
6. Hand Card 확대
==================================================

Hand Card도 크게 만들어라.

예시 시작값:
handCardWidth = clamp(145px, 8.5vw, 195px)

손패는 최대 7장까지 겹침(overlap / fan) 레이아웃 허용.

규칙:
- 카드 수 적으면 넓게 펼침
- 카드 수 많으면 overlap 증가
- 그래도 Cost와 카드 상단 이름은 구분 가능해야 함

중요:
손패는 "작아서 안 보이는 줄줄이 배열"이 아니라
"크게 보이되 겹쳐서 관리되는 손패"가 되어야 한다.

==================================================
7. Hand 위치
==================================================

Hand는 화면 하단 중앙 기준으로 정렬.

Champion UI 때문에 손패 전체가 한쪽으로 밀려
보드 중심축과 어긋나지 않게 해라.

Hover한 Hand Card는:
- 살짝 위로
- 약간 확대
- 가장 높은 z-index

로 보이게.

==================================================
8. Champion / Log / Turn UI 우선순위 조정
==================================================

화면 중요도는 다음 순서:

1. Board
2. Hand
3. Champion 정보
4. Deck/Graveyard
5. Log / Turn Panel

즉:
로그나 우측 패널 때문에 Board와 Hand가 작아지면 안 된다.

좌측 로그, 우측 턴 UI는 기능 유지하되
Board 영역을 침범하지 않도록 폭/padding을 줄일 수 있다.

==================================================
9. 중요한 핵심: 레이아웃 확대 후 애니메이션 좌표도 반드시 재계산
==================================================

이번 작업의 핵심이다.

Board/Hand/Card Size가 커지면
기존 애니메이션 좌표를 그대로 쓰면 안 된다.

다음 Presentation들은 새 레이아웃 기준 DOM 좌표를 사용해야 한다:

- 손패에서 보드로 플레이
- 공격 이동
- 소환
- 부활
- 카드 훔치기
- 주문 Reveal 후 효과 타겟 강조
- 타겟 선택 Ring / Highlight
- Damage Number 위치
- Buff / Debuff Floating Text 위치

즉:
레이아웃을 키운 뒤에도
카드가 정확한 위치에서 시작해서 정확한 위치로 도착해야 한다.

==================================================
10. transform: scale()로 전체 화면만 확대하지 마
==================================================

중요.

match root에 단순히
transform: scale(...)
만 걸어서 해결하지 마.

그렇게 하면:
- 애니메이션 좌표
- 클릭 영역
- 타겟팅 위치
- overlay 위치
- clone motion
이 어긋날 위험이 크다.

반드시 실제 레이아웃 값:
- card width/height
- slot size
- gap
- board area size
- hand area size
를 조정해서 해결해라.

==================================================
11. 애니메이션 좌표 시스템 수정 원칙
==================================================

모든 motion animation은
하드코딩된 예전 좌표가 아니라
"현재 렌더된 실제 DOM rect"를 기준으로 계산해야 한다.

우선순위:

1. 실제 Card DOM rect
2. 실제 Slot DOM rect
3. fallback 추정 좌표

가능하면 1번/2번을 기본으로 써라.

예:
- 카드 플레이: hand card DOM rect → target slot rect
- 공격: attacker card rect → target card rect
- 소환: source effect card rect 또는 slot rect → target slot rect
- 부활: graveyard rect → target slot rect

==================================================
12. 카드 플레이 애니메이션 보정
==================================================

레이아웃 확대 후에도
카드 플레이 애니메이션은 자연스러워야 한다.

규칙:
- 내가 카드를 낼 때: 내 hand area에서 시작
- 상대가 카드를 낼 때: 상대 hand area에서 시작
- 도착점은 실제 target board slot의 현재 rect
- 보드가 커졌으면 더 큰 보드 기준 위치로 자연스럽게 날아가야 함

절대:
보드 확대 전의 옛 좌표를 기준으로 날아가면 안 된다.

==================================================
13. 공격 애니메이션 보정
==================================================

공격 애니메이션도 새 레이아웃 기준으로 맞춰라.

규칙:
- 출발점: 공격 카드의 실제 현재 rect
- 도착점: 타겟 카드의 실제 현재 rect
- 공격 clone 사용 시 원본 위치도 새 layout 기준으로 동기화
- 보드가 커졌는데 여전히 예전 작은 보드 중심을 향해 움직이면 안 됨

즉:
Board scale-up 이후에도
카드가 "실제 지금 보이는 위치"에서 출발하고
"실제 지금 보이는 위치"로 때리러 가야 한다.

==================================================
14. 소환 / 부활 애니메이션 보정
==================================================

SUMMON / REVIVE도 새 레이아웃 기준으로 수정.

SUMMON:
- destination slot rect 기준

REVIVE:
- graveyard UI rect 또는 revive source rect
- destination slot rect 기준

보드 확대 후에도
토큰/부활 카드가 정확히 큰 보드 슬롯 안으로 들어와야 한다.

==================================================
15. Floating UI 위치 보정
==================================================

다음 요소들도 레이아웃 확대 후 정확한 위치에 떠야 한다:

- Damage Number
- Heal Number
- +2/+2 표시
- -1 Cost 표시
- "회피!"
- Quest progress 소형 표시
- 타겟 선택 하이라이트
- 효과 source pulse / connection

카드 크기가 커졌는데도 예전 좌표 기준으로
카드 밖 엉뚱한 위치에 뜨면 안 된다.

==================================================
16. clone motion과 원본 카드 동기화
==================================================

레이아웃이 커지면 clone animation도 더 티가 나므로
다음을 반드시 지켜라:

- clone 생성 시 현재 카드 rect 기준으로 clone 위치 세팅
- 원본 카드는 잠시 숨김
- clone 이동
- 종료 후 clone 제거
- 원본 복원

레이아웃이 커졌는데 clone 좌표가 옛 기준이면
원본/clone 어긋남이 더 심해지므로 꼭 수정.

==================================================
17. 레이아웃 변경 후 resize에도 안정적이어야 함
==================================================

창 크기가 바뀌거나
반응형 재계산이 일어났을 때도
애니메이션 기준 좌표가 최신 상태를 사용해야 한다.

즉:
이전 렌더 시점의 stale rect를 오래 들고 있으면 안 된다.

애니메이션 시작 직전에
가능하면 최신 rect를 읽어라.

==================================================
18. Board / Hand / Animation을 하나의 시스템으로 맞춰라
==================================================

이번 수정의 목적은 단순 확대가 아니라:

"Board와 Hand가 커졌고,
그 위에서 일어나는 카드 모션도 그 새 공간 안에서 자연스럽다"

를 만드는 것이다.

즉:
레이아웃과 애니메이션을 따로따로 보지 말고
하나의 Match presentation system으로 맞춰라.

==================================================
19. 실제 테스트 항목
==================================================

반드시 TEST USER로 실제 브라우저 테스트.

A. Desktop Layout
- 1920x927에서 Board가 충분히 크게 보인다
- Hand가 충분히 크게 보인다
- 중앙 공백이 많이 줄었다

B. Self Card Play
- 내 손패에서 카드가 자연스럽게 큰 보드 슬롯으로 이동
- 예전 작은 보드 기준 좌표로 움직이지 않음

C. Opponent Card Play
- 상대 hand area에서 시작
- 상대 큰 보드 슬롯으로 정확히 이동

D. Attack Animation
- 내 카드 공격 / 상대 카드 공격
- 현재 실제 카드 위치 기준으로 이동
- 보드 커진 상태에서도 어색하지 않음

E. Summon / Revive
- 정확한 슬롯 위치에 애니메이션

F. Floating UI
- Damage Number, Buff Number, 회피 표시 등이
  카드 크기 확대 후에도 정확한 위치에 뜬다

G. Resize Stability
- 레이아웃이 조금 달라져도
  애니메이션 좌표가 최신 상태를 반영한다

20. 수정 금지
==================================================

이번 작업에서 다음은 수정 금지:

- Game Engine 규칙
- 카드 효과
- 카드 스탯
- Board slot 수

다만,
레이아웃 확대로 인해 필요한 범위 안에서의
Presentation 좌표 계산 수정은 허용/필수.
