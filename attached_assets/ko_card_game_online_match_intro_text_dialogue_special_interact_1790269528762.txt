KO CARD GAME — ONLINE MATCH INTRO V2
상대 닉네임 표시 + Champion 대치 연출 + 관리자 설정형 텍스트 대사 + Champion 조합별 특수 상호대사
※ 음성 없음. 텍스트만.
※ KO 로고/KO 텍스트 사용 금지. 중앙은 VS만 사용.

==================================================
0. 이번 작업의 목표
==================================================

온라인 매치가 시작될 때 바로 보드로 넘어가지 말고,
양쪽 플레이어와 Champion을 정식으로 소개하는 Match Intro를 만든다.

반드시 포함:

- 내 닉네임
- 상대 닉네임
- 내 Champion 이름
- 상대 Champion 이름
- 내 Champion 초상화
- 상대 Champion 초상화
- Champion별 기본 텍스트 대사
- 특정 Champion 조합에서만 나오는 특수 상호대사
- 중앙의 큰 VS 연출
- Intro 종료 후 실제 Battle UI로 자연스럽게 전환

중요:
음성 파일/음성 재생은 이번 기능에 절대 포함하지 않는다.

텍스트 대사만 사용한다.

또한 KO 로고/KO 문구는 Intro에서 사용하지 않는다.
중앙에는 VS만 사용한다.

==================================================
1. 먼저 상대 닉네임 버그부터 정확히 수정
==================================================

현재 실제 버그:
온라인 매치에서 상대 닉네임이 보이지 않는다.

다음 데이터 흐름을 실제로 추적:

Matchmaking
→ match creation
→ player public metadata
→ server match state / match envelope
→ sanitizer
→ websocket/http payload
→ client store
→ opponent mapping
→ battle HUD
→ Match Intro

어디에서 nickname/displayName이 유실되는지
first failing layer를 정확히 특정한다.

UI에 임시 문자열 "상대방"을 넣고 끝내지 말 것.

==================================================
2. Public Player Metadata
==================================================

온라인 매치에서 공개 가능한 player metadata를 정식으로 유지:

- playerId/internal reference
- displayName 또는 nickname
- selected Champion definitionId
- Champion public name
- Champion portrait/image reference

예시 개념:

publicPlayerMeta = {
  playerId,
  displayName,
  championDefinitionId,
  championName,
  championPortrait
}

이 public metadata는 다음에서 공통 사용:

- Match Intro
- Battle HUD
- reconnect
- state resync
- spectator가 현재 있다면 spectator

중복 source-of-truth 금지.

절대 노출 금지:
- email
- raw auth identifier
- private inventory
- deck contents
- hidden hand/deck identities
- randomSeed
- private account metadata

==================================================
3. Battle HUD에서도 닉네임 계속 표시

==================================================
9. Champion 특수 상호대사
==================================================

특정 Champion 조합끼리는
기본 대사 대신 전용 상호대사를 사용할 수 있게 한다.

예:

Pandora ↔ Jäger

Pandora:
"아직도 그 장난감 군대를 끌고 다니는 거야?"

Jäger:
"네가 쓰러질 때까진 충분하지."

이 조합이 매칭되면
각 Champion의 기본 Intro 대사를 사용하지 않고
이 특수 상호대사를 우선 사용한다.

==================================================
10. 특수 상호대사는 관계 데이터로 관리
==================================================

중요:
Pandora 쪽 ChampionDefinition에만
Jäger 전용 대사를 중복 저장하는 방식 금지.

내부적으로 하나의 relation/entity로 관리.

예시 개념:

ChampionIntroInteraction {
  id,
  championAId,
  championBId,
  championALine,
  championBLine,
  firstSpeaker,
  enabled
}

championA/championB 순서는 저장 방식일 뿐,
매치에서 플레이어 어느 쪽에 있는지는 runtime mapping으로 해결.

같은 조합을 A→B / B→A 두 개 중복 생성하지 않게 한다.

==================================================
13. 특수 대사 선택 우선순위
==================================================

Intro line resolver:

1. 활성화된 exact Champion pair special interaction 검색
2. 존재하면 special dialogue 사용
3. 없으면 각 Champion의 default intro line 사용
4. default line도 없으면 그 Champion 대사는 생략
5. 둘 다 대사가 없어도 Intro 자체는 정상 진행

대사 없음 때문에 match 시작이 막히면 FAIL.

==================================================
14. 누가 먼저 말하는가
==================================================

Special interaction에는 firstSpeaker 설정 지원.

예:
CHAMPION_A
CHAMPION_B

또는 실제 현재 schema에 맞는 방식.

특수 대사가 없는 기본 Intro의 경우:
일관된 규칙 사용.

권장:
상대 Champion이 먼저 말하고
내 Champion이 응수.

즉 각 클라이언트에서는:

Opponent line
→ My line
→ VS impact

로 보이게 할 수 있다.

하지만 두 클라이언트가 서로 다른 사건 순서를 보게 되어
동기화 문제가 생기는 구조라면
authoritative speaker order 또는 deterministic ordering을 사용.

핵심:
두 클라이언트에서 dialogue content mapping이 뒤바뀌면 안 된다.

==================================================
15. Intro 대사 표시 방식
==================================================

말풍선보다
게임 UI에 맞는 자막/대사 패널 권장.

예:

PANDORA
「아직도 그 장난감 군대를 끌고 다니는 거야?」

대사는 해당 Champion portrait 가까이에 표시.

첫 번째 Champion이 말할 때:
- 해당 portrait 살짝 zoom/forward
- 반대쪽은 약간 dim
- 텍스트 등장

두 번째 Champion이 말할 때:
- 강조 반전
- 두 번째 대사 등장

음성은 없음.

==================================================
16. 대사 길이 제한
==================================================

관리자에서 너무 긴 대사 입력 방지.

권장:
최대 약 60~80자.

현재 UI 폭/모바일 대응을 보고 실제 제한값 결정.

목표:
Desktop에서 1~2줄
Mobile에서도 과도한 4~5줄이 되지 않게.

DB/API/Client 모두 같은 validation.

초과 시 저장 거부 + 명확한 validation 메시지.

==================================================
17. 빈 문자열/공백 처리
==================================================

대사:

""
"   "

는 없음으로 처리.

HTML/script injection 금지.

텍스트는 safe rendering.

관리자 입력에 HTML을 허용하지 않는다.

==================================================
18. 특수 상호대사 중복 검증
==================================================

같은 Champion pair에
active relation이 여러 개 생기지 않게 한다.

예:
Pandora ↔ Jäger

이미 존재하면:
새 row 생성보다 기존 row 편집 유도.

Unique pair canonicalization 필요.

예:
min(championAId, championBId)
max(championAId, championBId)

또는 equivalent pair key.

==================================================
19. Champion 삭제/비활성화 대응
==================================================

특수 relation이 참조하는 Champion이
삭제/비활성 상태가 되면:

- Admin에서 broken reference 표시
- 앱 crash 금지
- Intro는 fallback default/no-line으로 진행

자동으로 다른 Champion 대사와 연결 금지.

==================================================

34. Admin 데이터 모델 migration
==================================================

기존 Champion data와 호환 유지.

defaultIntroLine nullable.

special interactions는 별도 relation/table/collection 권장.

migration 시:
기존 Champions는 defaultIntroLine=null.

Intro는 대사 없이도 정상.

Production migration이 필요한 구조라면
안전한 schema migration만 수행하고
실제 Champion 콘텐츠를 임의로 생성/변경하지 말 것.

Production 데이터 값 직접 수정 금지.

36. 서버에서 resolve할지 클라이언트에서 resolve할지
==================================================

권장:
서버가 match 참가 Champion pair를 알고 있으므로
Intro에 사용할 dialogue pair를 authoritative하게 resolve.

예:

resolvedIntro = {
  left/right or playerA/playerB,
  lineA,
  lineB,
  firstSpeaker
}

client는 presentation만.

이렇게 하면:
- 두 client 결과 불일치 방지
- unpublished admin relation 노출 최소화
- client에서 전체 interaction catalog를 받을 필요 없음

현재 architecture에 맞게 구현하되
두 클라이언트가 서로 다른 special dialogue를 선택하면 FAIL.

48. 완료 조건
==================================================

1. 온라인 상대 닉네임이 Intro와 Battle HUD 양쪽에서 정상 표시.
2. reconnect 후에도 유지.
3. 양 Champion 초상화가 대치하는 정식 Match Intro 구현.
4. 중앙에는 VS만 표시.
5. KO text/logo는 Intro에 없음.
6. 각 Champion에 기본 텍스트 Intro 대사를 Admin에서 설정 가능.
7. 특정 Champion pair의 특수 상호대사 등록 가능.
8. special interaction은 pair relation 하나로 관리.
9. special이 있으면 default보다 우선.
10. firstSpeaker 설정 지원.
11. 대사는 텍스트만. 음성/TTS/voice asset 전혀 없음.
12. 대사가 없어도 match 정상 시작.
13. Intro 종료 후 자연스럽게 Battle로 전환.
14. Intro 동안 gameplay input 차단.
15. Desktop/Mobile responsive.
16. private/hidden info leak 없음.
17. Production data mutation 없음.
18. tests/build/typecheck/diff 결과 보고.

핵심:
이 기능은 단순한 VS splash가 아니다.
온라인 매치 시작 순간
"어떤 플레이어가 어떤 Champion으로 싸우는지"
그리고 "두 Champion 사이에 어떤 관계성이 있는지"
텍스트 한마디씩으로 보여주는
KO CARD GAME의 정식 Champion Match Intro 시스템을 구현하라.
