현재 KO 카드게임의 관리자 카드 관리 시스템을 개선해줘.

목표는 개발자가 카드마다 별도의 코드를 직접 작성하지 않고,
관리자 화면의 "카드 효과 텍스트"에 자연어로 효과만 입력하면
시스템이 이를 분석하여 실제 게임 엔진이 실행할 수 있는 구조화된 Effect 데이터로 변환하게 만드는 것이다.

매우 중요:

사용자가 입력한 자연어를 임의 JavaScript 코드로 변환해서 실행하는 방식은 사용하지 마.

다음은 절대 사용 금지:

eval()
new Function()
데이터베이스에 JavaScript 코드 저장
자연어를 실행 가능한 JavaScript로 직접 생성
임의 코드 동적 실행

대신 기존 게임 엔진의:

Trigger Registry
Action / Effect Registry
Target Registry
Condition Registry
Value Resolver

를 조합하여 실제 카드 효과 데이터를 생성하는 방식으로 구현한다.

\==================================================

1. 내가 원하는 최종 사용 방식
   \==================================================

관리자 카드 편집 화면에서 개발자가 다음처럼 효과를 텍스트로 입력한다.

예:

"등장: 손패의 무작위 선수 카드 3장에게 +1/+1을 부여합니다."

그 아래에:

[효과 분석]

버튼을 추가한다.

버튼을 누르면 시스템이 입력된 자연어를 분석하여
게임 엔진이 이해하는 Structured Effect로 변환한다.

예:

Trigger:
ENTER\_FIELD

Action:
BUFF

Target:
ALLY\_HAND\_WRESTLER

Selection:
RANDOM

Count:
3

Attack:
+1

Health:
+1

이 결과를 바로 저장하지 말고
먼저 개발자에게 분석 결과를 보여준다.

개발자가 확인한 뒤:

[분석 결과 적용]

버튼을 눌러야 실제 카드 Effect 데이터로 저장할 수 있게 한다.

# ================================================== 2. 표시용 텍스트와 실제 효과 분리

CardDefinition에서 다음 두 개념을 반드시 분리한다.

text:
플레이어에게 카드에 보여주는 자연어 효과 설명.

effects:
게임 엔진이 실제로 실행하는 구조화된 효과 데이터.

예:

text:

"등장: 손패의 무작위 선수 카드 3장에게 +1/+1을 부여합니다."

effects:

[
{
trigger: "ENTER\_FIELD",
action: "BUFF",
target: {
zone: "HAND",
owner: "SELF",
cardType: "WRESTLER",
selection: "RANDOM",
count: 3
},
values: {
attack: 1,
health: 1
}
}
]

실제 게임 효과 판정은 text를 읽어서 매번 해석하는 것이 아니라
저장된 effects 데이터를 기준으로 실행한다.

text는 설명용이다.

# ================================================== 3. 카드 효과 분석 UI

개발자가 내용을 확인한 후에만 적용되게 한다.

# ================================================== 4. 분석 결과를 시각적으로 쉽게 보여주기

프로그래밍을 모르는 개발자도 이해할 수 있게
JSON만 보여주지 말고 사람이 읽을 수 있는 형태로 표시한다.

예:

✓ 등장할 때 발동

✓ 내 손패에서

✓ 선수 카드만

✓ 무작위 3장 선택

✓ 공격력 +1

✓ 체력 +1

필요하다면 하단에:

[고급 보기]

를 눌렀을 때 실제 Effect JSON도 확인할 수 있게 한다.

기본 화면에서는 JSON을 강제로 보여주지 않는다.

# ================================================== 5. 지원 Trigger 분석

자연어에서 다음 표현들을 현재 게임 엔진 Trigger와 연결할 수 있게 한다.

"등장:"
"등장할 때"
"필드에 나올 때"

→ ENTER\_FIELD

"퇴장:"
"퇴장할 때"

→ LEAVE\_FIELD 또는 현재 엔진의 퇴장 Trigger

"공격할 때"

→ ATTACK

"공격 후"

→ AFTER\_ATTACK

"피해를 받을 때"

→ DAMAGE\_RECEIVED

"내 턴 시작"

→ TURN\_START

"내 턴 종료"

→ TURN\_END

"액티브:"

→ ACTIVE

실제 enum 이름은 현재 게임 엔진 구조에 맞춰 사용한다.

# ================================================== 6. 지원 Action 분석

자연어를 다음과 같은 기존 공용 Effect Action으로 변환할 수 있게 한다.

DAMAGE
피해를 준다.

HEAL
회복한다.

BUFF
공격력/체력을 증가시킨다.

DEBUFF
공격력/체력을 감소시킨다.

SET\_STATS
스탯을 특정 값으로 설정한다.

DRAW
카드를 뽑는다.

GENERATE\_CARD
카드를 생성한다.

SUMMON
선수를 소환한다.

DESTROY
파괴한다.

SILENCE
침묵시킨다.

ADD\_GOLD
현재 골드를 얻는다.

ADD\_NEXT\_TURN\_GOLD
다음 자기 턴 추가 골드를 얻는다.

REDUCE\_COST
비용을 감소시킨다.

INCREASE\_COST
비용을 증가시킨다.

ADD\_KEYWORD
키워드를 추가한다.

REMOVE\_KEYWORD
키워드를 제거한다.

이외에도 기존 Effect Registry에 이미 존재하는 Action이 있다면
분석기에 등록할 수 있게 한다.

"내 손패의 카드"

→ ALLY\_HAND\_CARD

"모든 아군 선수"

→ ALL\_ALLY\_WRESTLERS

"모든 적 선수"

→ ALL\_ENEMY\_WRESTLERS

"무작위 아군 선수"

"무작위 적 선수"

# ================================================== 8. 숫자와 현재 스탯 참조 분석

고정 숫자뿐 아니라 게임 상태를 참조하는 문장도 분석할 수 있게 구조를 만든다.

예:

"+2 공격력"

→ FIXED 2

"+1/+1"

→ attack +1, health +1

"이 카드의 현재 공격력만큼"

→ SOURCE\_CURRENT\_ATTACK

"이 카드의 현재 체력만큼"

→ SOURCE\_CURRENT\_HEALTH

"대상의 공격력만큼"

→ TARGET\_CURRENT\_ATTACK

"묘지에 있는 선수 카드 수만큼"

→ GRAVEYARD\_WRESTLER\_COUNT

"현재 손패 카드 수만큼"

→ HAND\_CARD\_COUNT

"이 카드가 파괴한 카드의 공격력"

→ DESTROYED\_CARD\_ATTACK

등.

현재 Value Resolver에 존재하지 않는 값은 임의로 생성하지 않는다.

# ================================================== 10. 여러 효과가 한 문장에 있는 경우

한 카드에 여러 효과가 순서대로 적혀 있을 수 있다.

예:

"등장: 적 선수 하나를 침묵시키고 파괴합니다. 그 카드의 공격력 절반만큼 이 카드의 공격력을 증가시킵니다."

이 경우 분석 결과를 순차 Effect Chain으로 만들어야 한다.

개념적 결과:

1.

Trigger:
ENTER\_FIELD

Action:
SILENCE

Target:
ENEMY\_WRESTLER / PLAYER\_CHOICE

2.

Action:
DESTROY

Target:
SAME\_TARGET

3.

Action:
BUFF

Target:
SELF

Attack Value:
LAST\_DESTROYED\_TARGET\_ATTACK / 2

실제 엔진 구조에 맞는 Resolution Context를 사용한다.

한 효과에서 선택한 대상을
다음 효과에서도 참조할 수 있게 한다.

# ================================================== 11. 조건문 분석

자연어에 조건이 포함된 경우
지원되는 Condition Registry를 사용한다.

예:

"이 카드가 필드의 유일한 선수라면 다음 턴 +1G"

분석:

Condition:
ONLY\_ALLY\_WRESTLER\_ON\_BOARD

Action:
ADD\_NEXT\_TURN\_GOLD

Value:
1

또는:

"이 효과로 선수를 리타이어시켰다면 카드 1장을 뽑습니다."

Condition:
TARGET\_RETIRED\_BY\_THIS\_EFFECT

Action:
DRAW

Count:
1

지원하지 않는 Condition은 자동으로 임의 구현하지 않는다.

# ================================================== 12. 현재 지원하지 않는 효과 처리

가장 중요하다.

관리자가 입력한 효과가 현재 Effect Engine으로 표현할 수 없다면
억지로 비슷한 효과를 만들거나 임의 코드를 생성하면 안 된다.

예:

"등장: 상대 선수의 3턴 전 상태로 되돌립니다."

현재 엔진에 이러한 메커니즘이 없다면:

분석 실패

또는

부분 분석

상태로 보여준다.

예:

⚠ 현재 게임 엔진에서 지원하지 않는 효과가 포함되어 있습니다.

지원되지 않는 부분:
"3턴 전 상태로 되돌립니다."

필요한 신규 시스템:
새로운 Effect Handler 또는 Value Resolver

라고 보여준다.

이 상태에서는 [분석 결과 적용] 버튼을 비활성화하거나
명확한 경고를 표시한다.

# ================================================== 13. 부분 분석

문장의 일부만 이해할 수 있다면
어디까지 분석됐는지 보여준다.

예:

입력:

"등장: 적 선수에게 피해 2를 주고 시간을 멈춥니다."

결과:

✓ 등장
✓ 적 선수 대상
✓ 피해 2

✗ "시간을 멈춥니다"
현재 지원되지 않음

이 경우 잘못된 효과로 자동 저장하지 않는다.

# ================================================== 14. 분석 결과 직접 수정

AI/파서가 약간 잘못 이해했을 경우
개발자가 분석 결과를 GUI에서 수정할 수 있게 한다.

예:

분석 결과:

대상:
아군 선수

를

대상:
적 선수

로 드롭다운에서 직접 변경 가능.

또는:

대상 수:
2

→ 3

으로 수정 가능.

수정 후:

[이 결과 적용]

가능.

즉 자연어 분석은 편의 기능이고
최종 Effect Builder는 사람이 수정할 수 있어야 한다.

# ================================================== 15. 자동 효과 설명 생성

반대로 기본 카드 효과 텍스트도 생성할 수 있게 한다.

예:

ENTER\_FIELD
BUFF
ALLY\_HAND\_WRESTLER
RANDOM
COUNT 3
+1/+1

실제 실행은 항상 structured effects가 담당한다.

# ================================================== 16. 실제 카드 등록 흐름

관리자가 카드를 만들 때 최종 흐름은 다음과 같아야 한다.

7.

9.

DRAFT 저장

10.

테스트

11.

PUBLISHED

가 되게 한다.

자동 분석:

관리자 입력:

"등장: 손패의 선수 카드 한 장에게 이 카드의 현재 공격력만큼 공격력을 부여합니다."

Attack Value:

0

카드 이름을 코드에 하드코딩하지 않는다.

# ================================================== 19. 예시 3 — 워썬더

관리자 입력:

"등장: 내 덱 맨 위 카드 3장을 묘지로 보냅니다. 다음 내 턴에 추가 골드 +1을 얻습니다."

분석 결과는 두 개의 Effect로 만든다.

Effect 1:

Trigger:
ENTER\_FIELD

Action:
MILL\_TOP\_DECK

Count:
3

Destination:
GRAVEYARD

Effect 2:

Trigger:
ENTER\_FIELD

Action:
ADD\_NEXT\_TURN\_GOLD

Value:
1

MILL\_TOP\_DECK가 현재 Registry에 없다면
지원되지 않는 효과라고 알려주고 자동으로 가짜 구현하지 않는다.

# ================================================== 20. 예시 4 — 판도라 폭주 스타일 연속 효과

관리자 입력:

"등장: 카드 한 장을 침묵시키고 파괴합니다. 이 카드가 리타이어 또는 파괴시킨 카드의 공격력 절반만큼 이 카드의 공격력을 증가시킵니다."

지원 가능한 구조라면:

SILENCE
→ DESTROY
→ 결과 대상 공격력 참조
→ SELF BUFF

순서로 처리한다.

Resolution Context에서
마지막 파괴 대상과 해당 대상의 파괴 직전 공격력 등을 참조할 수 있게 한다.

현재 엔진에서 처리할 수 없다면
어느 Resolver나 Condition이 부족한지 관리자에게 보여준다.

# ================================================== 21. 효과 분석 실패는 프로그램 오류가 아님

자연어 분석 실패는 정상적인 관리자 입력 결과로 처리한다.

분석 실패했다고:

페이지 새로고침
게임 초기화
관리자 화면 초기화
Exception 페이지 표시

하지 않는다.

대신 Toast 또는 분석 결과 영역에:

"현재 지원하지 않는 효과입니다."

같은 정상적인 경고를 표시한다.

# ================================================== 22. 기존 카드와 호환

현재 코드에 이미 개별 handler로 구현된 기존 카드 효과가 있다면
당장 삭제하지 마.

기존 handler 방식과
새로운 Structured Effect 방식을 함께 지원해
현재 정상 작동하는 카드가 깨지지 않게 한다.

새로운 관리자 등록 카드부터 우선 Structured Effect 방식을 사용한다.

나중에 기존 카드들도 천천히 동일한 시스템으로 이전할 수 있게 한다.

# ================================================== 23. 카드 테스트 기능

관리자 편집 화면에서 가능하면:

[테스트 게임에서 확인]

또는

[효과 테스트]

기능을 추가할 수 있게 구조를 준비한다.

최소한 DRAFT 카드를 개발 환경의 테스트 매치에서 사용할 수 있게 한다.

일반 사용자 게임에는 PUBLISHED 카드만 사용한다.

# ================================================== 24. 반드시 테스트할 자연어 입력

다음 텍스트를 관리자 화면에서 직접 입력해 테스트해줘.

TEST 1

"등장: 자신에게 +2/+2를 부여합니다."

기본 1/1 카드

결과:
등장 후 3/3

TEST 2

"등장: 손패의 선수 카드 한 장에게 +1/+1을 부여합니다."

결과:

해당 카드 실제 버프

TEST 3

"등장: 적 선수 하나에게 피해 2를 줍니다."

결과:
대상 선택
피해 2

TEST 4

"등장: 손패의 무작위 선수 카드 3장에게 +1/+1을 부여합니다."

결과:
무작위 최대 3장 버프

TEST 5

"등장: 적 선수 하나를 침묵시키고 파괴합니다."

결과:

→ 파괴

TEST 6

지원되지 않는 임의 효과 문장을 입력.

게임/사이트 오류 없음

# ================================================== 25. 절대 하지 말 것

관리자가 입력한 자연어를:

JavaScript 코드로 변환해 DB 저장
eval 실행
new Function 실행
프론트엔드에서 임의 코드 실행
서버에서 임의 코드 실행

하지 마.

카드 이름마다:

if card.name === "여울"
if card.name === "밀크 메이드"

같은 하드코딩도 하지 마.

카드 효과는 반드시 범용 Registry와 Structured Effect 데이터로 작동해야 한다.

4. 분석 결과를 수정하는 방법
5. DRAFT 테스트 방법
6. PUBLISH 방법
7. 새로운 메커니즘이 필요할 경우 어디를 확장해야 하는지
