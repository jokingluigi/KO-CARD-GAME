KO CARD GAME — CRITICAL AI MECHANIC COMPILER CONTRACT FIX
ERROR: `analysis.trigger는 지원되지 않는 필드입니다.`

현재 심각한 문제:
AI Mechanic Compiler를 실행하면 다음 오류가 발생한다.

`analysis.trigger는 지원되지 않는 필드입니다.`

이 문제 때문에 Generate가 실패하고 AI 효과 적용기가 사실상 작동하지 않는다.

목표:
Provider가 반환하는 "해석용 메타데이터(analysis)"와
실제로 저장/실행되는 Effect DSL payload를 완전히 분리하고,
`analysis.trigger` 같은 debug/interpretation field가
Executable Effect Validator에 들어가지 않도록 고친다.

이 작업은 단순히 `analysis.trigger`만 whitelist에 추가하는 작업이 아니다.
Provider Response Contract → Parser → Normalizer → Canonicalizer → Validator → Auto Apply 전체 경로의 schema drift를 수정해야 한다.

==================================================
2. 올바른 Provider Response Contract
==================================================

Provider 응답은 최소 두 계층으로 분리해야 한다.

예시 개념:

{
  "analysis": {
    "normalizedMeaning": "...",
    "trigger": "ENTER_FIELD",
    "targetSummary": "...",
    "actionSummary": "...",
    "ambiguities": []
  },
  "compiled": {
    "format": "STRUCTURED_EFFECTS_V1",
    "effects": [...]
  }
}

또는 현재 프로젝트 naming에 맞는 equivalent.

중요:
`analysis`는 해석/debug용 metadata.
`compiled` 또는 equivalent만 executable validator로 보낸다.

절대:
validator.validate(providerResponse)
처럼 전체 provider response를 effect schema로 검증하지 말 것.

반드시:
validator.validate(providerResponse.compiled)
또는 현재 canonical extraction path를 사용.

==================================================
3. analysis는 실행 스키마가 아니다
==================================================

`analysis.trigger`
`analysis.target`
`analysis.action`
`analysis.normalizedMeaning`
등은 debug/intent summary.

이 필드는:

- 저장 Structured Effect에 들어가지 않음
- Runtime으로 전달되지 않음
- Action/Event engine에서 읽지 않음
- Auto Apply의 executable payload가 아님

단 Admin Developer Mode에서
해석 요약을 보여주는 용도로는 사용 가능.

==================================================

다음 타입을 명확히 분리:

ProviderInterpretationMetadata

예:

ProviderGenerateResponseSchema = z.object({
  analysis: AnalysisMetadataSchema,

})

Executable validator:
CompiledEffectUnionSchema only.

==================================================
5. analysis schema도 검증
==================================================

`analysis`를 무시하는 게 아니라
별도 metadata schema로 검증.

예:
analysis.trigger는 string/enum summary로 허용 가능.

하지만:
analysis에 executable arbitrary fields가 들어와도
Runtime으로 전달되면 안 됨.

즉:
metadata schema validation과
executable schema validation을 별도로 수행.

27. 완료 조건
==================================================

1. `analysis.trigger는 지원되지 않는 필드입니다.` 오류 재현 0.
2. analysis metadata와 executable DSL 완전 분리.
3. analysis.trigger는 metadata schema에서는 허용 가능.
4. executable validator에는 analysis가 절대 들어가지 않음.
5. strict unknown-field validation 유지.
6. Generate → READY → Auto Apply → Save → Reload → Runtime 정상.
7. STRUCTURED_EFFECTS_V1 / SCRIPT_V1 둘 다 정상.
8. noisy Korean compiler 회귀 없음.
9. tag filter compiler 회귀 없음.
10. Generate 1회 = provider 1회.
11. Save/Runtime provider 0.
12. Production mutation 없음.
13. tests/build/typecheck/diff 결과 보고.

핵심:
`analysis.trigger`를 executable field로 허용하는 것이 해결책이 아니다.

Provider의 "해석 메타데이터"와
실제 게임이 실행하는 "canonical effect payload"를
계약 수준에서 완전히 분리해서 고쳐라.
