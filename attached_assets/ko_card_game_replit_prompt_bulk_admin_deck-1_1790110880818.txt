KO CARD GAME — IMPLEMENT ONLY:
BULK DISASSEMBLY + ADMIN CARD GRID + INVALID DECK CARD REASONS

이번 작업에서는 아래 신규 기능 3개만 구현한다.

1. 여러 장 한 번에 분해
2. Admin 카드 목록을 컬렉션처럼 이미지 Grid로 표시
3. 덱 에디터에서 플레이 불가 원인이 되는 카드를 직접 표시

다른 버그,
Pandora,
온라인,
AI Match,
AI Mechanic Compiler,
일일 퀘스트,
출석,
공지,
보상 시스템,
메인 화면 배경/BGM

은 수정하지 마.

==================================================
0. 작업 방식
==================================================

이번 작업은 세 기능을 동시에 섞어서 개발하지 말고
아래 순서대로 하나씩 완료한다.

1. Bulk Disassembly
→ 구현
→ 테스트

2. Admin Card Grid
→ 구현
→ 테스트

3. Invalid Deck Reason UX
→ 구현
→ 테스트

마지막에 전체 typecheck/build를 실행한다.

==================================================
PART A — 여러 장 한 번에 분해
==================================================

현재 요구:

컬렉션에서 같은 카드를 여러 장 보유하고 있을 때
한 장씩 반복해서 분해하지 않고
분해 수량을 선택할 수 있어야 한다.

==================================================
1. UX
==================================================

카드 분해 시:

보유 수량 확인
→ 분해 수량 선택
→ 최종 확인
→ 서버에 요청
→ 성공 후 컬렉션 갱신

형태로 구현한다.

가능한 UX 예:

- 1장
- 5장
- 10장
- 최대
- 직접 수량 입력

현재 UI 스타일에 맞게 구현.

불필요하게 복잡한 새 modal system은 만들지 마.

==================================================
2. 수량 제한
==================================================

분해 수량은 반드시:

1 이상
보유량 이하

여야 한다.

예:

보유 7장인데
10장 분해 요청

→ 허용 금지.

==================================================
3. 서버에서 다시 검증
==================================================

클라이언트 값만 신뢰하지 마.

서버에서:

- card definition 존재
- user ownership
- current quantity
- requested quantity
- dismantle eligibility

를 다시 검증.

==================================================
4. Atomic 처리
==================================================

여러 장 분해는
중간에 일부만 처리되는 상태를 피한다.

예:

10장 분해 요청

5장 제거
→ 오류
→ 나머지 실패

같은 partial mutation 금지.

가능하면 하나의 transaction/atomic operation으로 처리.

==================================================
5. 보상 계산
==================================================

현재 카드 1장 분해 보상 규칙을 재사용.

총 보상:

1장 보상 × 분해 수량

단 Legendary / Normal / 기타 rarity별
기존 공식 분해 규칙을 그대로 따른다.

새 경제 수치 임의 생성 금지.

==================================================
6. Prismatic/특수 카드 주의
==================================================

현재 시스템에 Prismatic 또는 별도 variant가 있다면
일반 카드와 ownership bucket을 혼동하지 마.

사용자가 선택한 정확한 카드 종류/variant만 분해.

==================================================
7. 보호
==================================================

다음 금지:

- Token 직접 분해
- 소유하지 않은 카드 분해
- 수량 0/음수
- NaN
- overflow
- stale client quantity 기반 초과 분해

==================================================
8. 분해 후 상태
==================================================

성공 후:

보유 수량 즉시 갱신
보상 재화 갱신
UI stale count 없음.

페이지 새로고침 없이 반영.

==================================================
11. 카드 Grid
==================================================

각 카드 tile에 최소:

- 카드 이미지
- 카드 이름
- rarity
- 필요 시 cost 또는 간단한 식별 정보
- Published / Disabled 등 Admin 상태

를 표시.

정보를 너무 많이 넣어
카드 이미지가 작아지지 않게 한다.

==================================================
12. 이미지 우선
==================================================

실제 카드 artwork/image가 있다면
그 이미지를 tile의 중심으로 사용.

이미지가 없는 카드는
깨진 이미지 대신
fallback placeholder.

==================================================
13. 반응형 Grid
==================================================

Desktop:
여러 열.

좁은 화면:
열 수 자동 감소.

horizontal overflow 때문에
Admin이 깨지지 않게 한다.

14. 검색/필터 유지
==================================================

검색
필터

등이 있다면
기능을 제거하지 마.

==================================================
15. 카드 클릭
==================================================

카드 tile 클릭:

해당 CardDefinition 편집 화면/선택 상태로 이동.

두 번 클릭해야 하거나
이미지만 눌러야 하는 식으로 만들지 마.

tile 전체를 명확한 선택 영역으로.

역할 분리 유지.

PART C — 덱 플레이 불가 원인 카드 표시

Deck Editor에서 덱이 invalid할 때

"이 덱은 사용할 수 없습니다."

만 보여주지 말고

어떤 카드가
어떤 규칙을 위반해서
덱을 사용할 수 없는지

직접 표시해야 한다.

==================================================
18. 기존 deck validator 재사용
==================================================

Deck Editor에서 별도의 규칙을 다시 구현하지 마.

현재 authoritative deck validator를 사용.

즉:

validator
→ structured validation result
→ UI

구조.

==================================================
19. 기존 덱 규칙 유지
==================================================

현재 공식 규칙 예:

- 정확히 25 cards
- Champion 별도
- Legendary 최대 5
- 동일 Legendary CardDefinition duplicate 금지
- 일반 duplicate rule
- Token 직접 편성 금지
- invalid/deleted/unpublished definition
- 기타 현재 validator 규칙

실제 현재 코드의 authoritative rule을 사용.

새 규칙 임의 추가 금지.

==================================================
20. Validation 결과를 구조화
==================================================

가능하면 단순 문자열 하나보다:

reasonCode
message
cardDefinitionId
count
limit

형태의 structured result 사용.

예:

{
  reasonCode: "LEGENDARY_LIMIT_EXCEEDED",
  cardDefinitionIds: [...],
  limit: 5
}

==================================================
21. 원인 카드 하이라이트
==================================================

문제가 특정 카드와 연결된다면
Deck Editor에서 해당 카드를 시각적으로 표시.

예:

- 경고 테두리
- warning icon
- tooltip/text

현재 UI 스타일에 맞게 최소 수정.

==================================================
22. 전체 덱 문제와 카드 문제 구분
==================================================

예:

24/25 cards

는 특정 카드 하나의 문제가 아니다.

이 경우:

"카드가 1장 부족합니다."

처럼 deck-level reason 표시.

반면:

Token card 포함

은 해당 Token card를 직접 강조.

==================================================
23. Legendary 제한
==================================================

Legendary가 최대 5인데
6장이 있다면

단순히 6장 전부를 "잘못된 카드"라고
오해하게 만들지 마.

정확히:

Legendary 총량 제한 초과

를 표시하고
관련 Legendary cards를 표시할 수 있음.

==================================================
24. Duplicate 위반
==================================================

동일 CardDefinition이
허용 개수보다 많다면

문제가 되는 definition을 직접 표시.

예:

Card A ×3
allowed ×2

처럼 이해 가능하게.

==================================================
25. Token 직접 편성
==================================================

Token card가 deck에 들어 있다면

해당 card에:

"Token 카드는 덱에 직접 편성할 수 없습니다."

표시.

==================================================
26. Legacy Invalid Deck
==================================================

기존 저장 덱이 현재 규칙상 invalid여도

자동 삭제
자동 카드 제거
자동 25장으로 잘라내기

금지.

그대로 INVALID로 표시하고
사용자가 수정하도록 한다.

==================================================
27. Play 차단
==================================================

invalid deck이면
Match 시작 시 사용할 수 없게 하는
기존 규칙 유지.

하지만 이유를 Deck Editor에서
미리 확인할 수 있게 한다.
