KO CARD GAME — CRITICAL DECK EDITOR OWNERSHIP COUNT / DECK COUNT DESYNC FIX

증상:
덱 편집기에서 카드를 덱에 넣으면
해당 카드의 보유 수량이 갑자기 "1장"처럼 표시되거나,
보유 수량/덱 포함 수량 계산이 꼬이면서 덱이 INVALID/오류 상태가 되는 문제가 있다.

이 문제는 단순 표시 문제가 아닐 수 있다.
Collection ownership, deck copy count, available-to-add count, deck validation이
서로 같은 숫자를 재사용하고 있을 가능성이 있다.

절대 추측으로 UI 숫자만 고치지 말고,
데이터 흐름을 끝까지 추적해서 source of truth를 분리한다.

==================================================
0. 정상 개념
==================================================

반드시 아래 값들을 구분한다.

ownedCount
= 사용자가 실제로 보유한 총 카드 수량
= Collection/Inventory source of truth

deckCount
= 현재 편집 중인 덱에 들어간 해당 CardDefinition 수량

availableToAdd
= 현재 덱에 추가 가능한 남은 수량
= ownership rule이 적용되는 카드라면
  max(0, ownedCount - deckCount)
  또는 현재 프로젝트의 공식 계산식

중요:
덱에 카드를 넣었다고 ownedCount 자체가 줄어들면 안 된다.

예:

보유 3장
덱에 0장
→ ownedCount 3
→ deckCount 0
→ availableToAdd 3

1장 추가
→ ownedCount 3
→ deckCount 1
→ availableToAdd 2

2장 추가
→ ownedCount 3
→ deckCount 2
→ availableToAdd 1

덱에서 1장 제거
→ ownedCount 3
→ deckCount 1
→ availableToAdd 2

카드를 덱에 넣는 것은
"소유권 이동"이 아니다.

2. 가장 의심되는 버그 패턴 확인
==================================================

다음 가능성을 전부 조사하되,
실제 코드 증거로 원인을 특정한다.

A.
UI가 ownedCount 대신
`ownedCount - deckCount`
를 "보유 수량"이라고 표시

B.
Add Card 시 inventory cache를 직접 decrement

C.
Deck editor의 optimistic update가
collection row quantity를 mutate

D.
React Query/Zustand/Redux selector에서
deckCount를 ownedCount에 덮어씀

E.
동일 CardDefinition의 collection row와 deck row가
같은 object reference를 공유해서 mutation 발생

F.
`quantity`라는 같은 필드명을
inventory와 deck entry가 둘 다 사용하면서 merge 충돌

G.
Deck save API response가
deck copy count를 inventory quantity로 잘못 hydrate

H.
CardDefinition + Ownership + DeckEntry merge 과정에서
spread 순서가 잘못되어:

{
  ...ownership,
  ...deckEntry
}

또는 반대로
`quantity`가 덮어써짐

I.
ALT/Prism/variant ownership을 합치는 과정에서
base definition count가 1로 collapse

J.
Deck validator가 `availableToAdd`를
실제 ownership으로 오해

K.
normal card duplicate validation과
ownership validation이 뒤섞임

L.
Deck Editor에서 카드 추가 후
refetch query key가 잘못되어
stale partial response가 1장으로 표시

M.
card browser의 카드 하나를
`count=1` fixture/default로 재생성

N.
AI Deck과 Player Deck 로직이 섞여
ownership 없는 AI definition path가 적용

충돌이 실제 원인이면 타입 수준에서 명확히 분리.

4. Source of Truth
==================================================

Ownership source of truth:
사용자 Collection/Inventory

Deck source of truth:
현재 Deck draft 또는 saved deck

둘을 합쳐 view model을 만들 수는 있지만
둘 중 하나가 다른 하나를 mutate하면 안 된다.

Deck Editor에서:

addCard(definitionId)

는:
deck draft만 변경.

removeCard(definitionId)

도:
deck draft만 변경.

collection quantity는 그대로.

==================================================
6. 카드 추가 가능 여부
==================================================

카드 추가 가능 여부는
다음 두 조건을 함께 본다.

1. ownership / availability rule
2. deck construction rule

예:

ownedCount = 3
deckCount = 1
normal duplicate max = 2

→ available ownership copies = 2
→ duplicate rule remaining = 1
→ 실제 추가 가능 = 1

즉 단순히 ownedCount 하나만 보면 안 됨.

7. Legendary 규칙 유지
==================================================

기존 공식 deck rule 유지:

- deck 정확히 25장
- Champion 1개 별도
- Legendary 최대 5장
- 동일 Legendary CardDefinition 중복 금지
- Token 직접 추가 금지
- normal duplicate rule 유지
- invalid legacy deck은 자동 삭제/자동 잘라내기 금지

이번 수정으로 이 규칙을 바꾸지 말 것.

8. 일반 카드 duplicate rule
==================================================

현재 프로젝트에서 normal duplicate max가 몇 장인지
실제 canonical validator에서 확인.

UI add button과 server validator가
같은 rule을 사용해야 한다.

UI:
추가 허용

server:
저장 거절

같은 mismatch 금지.

==================================================
9. ownership validation
==================================================

Player Deck 저장 시
실제 보유 수량보다 많은 copy를 넣으면 reject.

예:

ownedCount 1
deckCount 2
→ invalid

ownedCount 2
deckCount 2
→ valid, duplicate rule도 허용한다면

ownedCount 5
deckCount 2
→ valid

중요:
덱에 넣었다고 ownedCount가 2→1로 바뀌고
그 결과 같은 덱이 self-invalid 되는 구조는 반드시 제거.

10. 미보유 카드 / Craft UI 회귀 금지

30. 완료 조건
==================================================

1. 덱에 카드를 넣어도 실제 ownedCount는 절대 변하지 않음.
2. Deck count와 owned count가 별도 상태로 관리됨.
3. availableToAdd는 계산값으로만 처리.
4. UI에서 "보유 수량"은 실제 총 보유 수량 표시.
5. ownership 충분한 정상 덱이 false INVALID 되지 않음.
6. 보유 수량보다 많은 copy는 여전히 차단.
7. normal duplicate/Legendary/25장 규칙 유지.
8. save/reload/refresh 후에도 count 일관성 유지.
9. 일반 사용자 계정에서도 동일하게 정상.
10. AI Deck 규칙과 Player Deck ownership 로직 혼동 없음.
11. Production 데이터 mutation 없음.
12. root cause와 수정 layer를 정확히 보고.

핵심:
"덱에 넣은 카드 수량"과 "내가 실제로 보유한 카드 수량"은
같은 숫자가 아니다.

Deck Editor는 inventory를 소비하는 화면이 아니다.
카드를 덱에 넣는 순간 ownership이 줄거나,
deckCount가 ownedCount에 덮어써져
자기 자신을 INVALID로 만드는 구조를 완전히 제거하라.
