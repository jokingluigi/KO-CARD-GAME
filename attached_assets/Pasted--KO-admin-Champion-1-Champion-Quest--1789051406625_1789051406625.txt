현재 KO 프로젝트의 /admin Champion 관리 기능이 이전 수정 후에도 전혀 고쳐지지 않았다.

증상은 확실하다.

1. Champion에서 Quest를 설정하면 저장되지 않는다.
2. Champion 효과 분석 버튼이 작동하지 않는다.

이번에는 추측해서 코드 몇 줄 수정하고 끝내지 마.

반드시 실제 버그를 먼저 재현하고,
실제 실패 지점을 확인한 뒤,
기능이 정상 동작하는 것을 테스트로 검증한 후에만 완료 처리해.

================================
최우선 규칙
================================

"수정했을 것 같다"
"구조상 정상이다"
"코드를 변경했다"

만으로 완료 처리하지 마.

반드시 아래 실제 사용자 흐름이 성공해야 한다.

A.
Champion 편집
→ hasQuest ON
→ Quest 입력
→ 저장
→ 페이지 새로고침
→ 다시 Champion 편집
→ Quest 데이터 그대로 존재

B.
Champion 효과 설명 입력
→ [효과 분석] 클릭
→ 실제 Analyzer 실행
→ 분석 결과 UI 표시

둘 중 하나라도 실패하면 작업 완료가 아니다.

================================
STEP 1. 먼저 실제로 버그 재현
================================

코드를 수정하기 전에 브라우저에서 직접:

/admin
→ Champion 관리
→ Champion 하나 편집

Quest ON 후 아래처럼 임시 데이터 입력:

Quest Name:
TEST QUEST

Condition:
선수 카드 3장을 생성합니다.

Target Progress:
3

Reward:
내 손의 선수 카드 1장에게 +1/+1

그리고 저장 버튼을 눌러.

반드시 확인:
- 버튼 클릭 이벤트 실행 여부
- Network 요청 발생 여부
- HTTP status
- request payload
- response body
- console error
- server log
- database write result

어느 단계에서 실패하는지 먼저 찾아.

================================
STEP 2. Quest 저장 문제 추적
================================

프론트 UI만 보지 말고 저장 경로 전체를 추적해.

Champion Form State
↓
save handler
↓
request payload
↓
API route
↓
validation schema
↓
server DTO
↓
ORM/database
↓
DB record
↓
fetch Champion
↓
edit form hydration

각 단계에서 Quest 데이터가 실제로 존재하는지 확인해.

특히 아래 필드를 console/server log로 개발 환경에서 확인해:

hasQuest
quest
questName
questDescription
questConditionText
questStructuredCondition
questTargetProgress
questRewardText
questStructuredReward
upgradedAbility
championTokenDefinitionId

실제 프로젝트 필드명이 다르면 실제 이름을 사용해.

================================
매우 중요한 저장 버그 후보
================================

다음 항목을 전부 실제 코드에서 확인해.

1.
Frontend에서는:

quest: {
  ...
}

형식인데

Backend에서는:

questName
questCondition
...

처럼 flat field를 기대하는지.

또는 반대 상황인지.

2.
targetProgress가 HTML input 때문에 string:

"3"

으로 전달되는데
validation은 number를 요구해서 실패하는지.

필요하면 저장 직전에 안전하게 Number 변환.

3.
hasQuest=true인데 optional Quest 필드가
undefined/null/"" 중 예상하지 않은 값이라
Zod/schema validation이 실패하는지.

4.
JSON/JSONB 컬럼에 Structured Effect를 저장하는데
undefined가 포함되어 serialization 실패하는지.

5.
DB schema에는 Quest 컬럼이 있는데
insert/update payload에서 누락되는지.

6.
update mutation이 Quest 필드를 spread 과정에서 제거하는지.

예:
const payload = {
  name,
  ability,
  ...
}

처럼 Quest를 빼먹었는지 확인.

7.
서버 update에서 whitelist/pick schema가
Quest 필드를 버리고 있는지 확인.

8.
저장 직후 refetch/useEffect가
old Champion data로 form을 덮어쓰는지 확인.

9.
hasQuest toggle로 conditional component가 unmount되면서
Quest form state가 소실되는지 확인.

10.
CREATE는 되는데 UPDATE만 안 되는지,
UPDATE는 되는데 CREATE만 안 되는지도 별도 확인.

================================
STEP 3. 저장 실패를 숨기지 마
================================

현재 저장이 실패하는데 UI에서 아무 표시 없이 끝난다면 그것도 수정해.

저장 실패 시 최소한 개발 중:

console.error
server error log
toast

에서 실제 원인을 볼 수 있게 해.

단 앱 전체 crash/reload/reset은 금지.

================================
STEP 4. Champion 효과 분석 버그 실제 재현
================================

Champion Admin에서 실제로:

기본 Ability 효과 설명에:

적 선수 카드 1장에게 피해 1

을 입력하고 [효과 분석] 버튼을 눌러.

그리고 확인:

1. onClick 실행 여부
2. button type
3. Analyzer 함수 호출 여부
4. API 요청 여부
5. request body
6. API response
7. response state 저장 여부
8. 분석 결과 component render 여부

버튼 클릭부터 결과 표시까지 전체 경로를 추적해.

================================
특히 button type 확인
================================

Champion Form 안의 모든 분석 버튼은 반드시:

type="button"

이어야 한다.

분석 버튼이 form submit을 발생시키면 안 된다.

다음 버튼들도 필요하면 확인:

- 효과 분석
- Quest 조건 분석
- Quest 보상 분석
- 강화 능력 분석
- Champion Token 효과 분석
- Replit Prompt 생성
- Prompt 복사

저장 버튼만 submit 역할을 가져야 한다.

================================
STEP 5. Card Admin과 비교
================================

Card Admin의 효과 분석은 현재 정상 동작한다면
그 코드를 기준 implementation으로 사용해.

Card Admin에서 실제로 동작하는:

- analyzer 호출 함수
- request schema
- endpoint
- result state
- Structured Effect preview
- NEW_MECHANIC_REQUIRED
- unsupportedParts
- prompt generator

흐름을 찾아.

Champion Admin에서 별도로 비슷하게 흉내내지 말고
가능하면 동일 shared service/hook/function을 사용해.

하지만 대규모 리팩터링은 하지 마.

================================
Champion 분석 Context
================================

Champion 분석 요청에도
카드 효과와 같은 Effect DSL을 사용하되
분석 대상 context를 전달할 수 있게 해.

예:

sourceType: "CHAMPION"
effectSlot: "ABILITY"

또는:

QUEST_CONDITION
QUEST_REWARD
UPGRADED_ABILITY
CHAMPION_TOKEN_EFFECT

현재 Analyzer가 cardId/cardType=WRESTLER 같은
Card 전용 필드를 강제로 요구하고 있다면
그것 때문에 Champion 요청이 실패하는지 확인해.

Champion 효과 분석에서는
Champion context도 정상적인 입력으로 허용해야 한다.

================================
매우 중요한 Analyzer 버그 후보
================================

다음을 반드시 확인:

- Card ID 필수 validation 때문에 Champion 분석 거부
- cardType 필수 때문에 실패
- championId를 cardId로 잘못 전송
- effectText가 아닌 다른 state 값 전송
- stale React closure로 이전 문자열 분석
- 분석 response를 Card 전용 state에 저장
- effect slot key가 undefined
- 여러 분석 textarea가 동일 state를 공유
- 분석 버튼이 submit되어 페이지/form reset
- quest toggle 때문에 analyzer component remount
- endpoint가 Card Admin 전용 path
- query invalidation으로 입력값 초기화

추측하지 말고 실제 요청/응답을 확인해.

================================
STEP 6. 분석 결과 적용
================================

지원되는 효과:

SUPPORTED
→ Structured Effect 표시
→ [효과 적용] 가능

지원되지 않는 메커니즘:

NEW_MECHANIC_REQUIRED
→ supportedParts
→ unsupportedParts
→ Replit 구현 프롬프트 생성

이해 불가:

ANALYSIS_FAILED
→ 이유 표시

아무 반응도 없는 상태는 허용하지 않는다.

================================
STEP 7. 분석과 저장 상태 분리
================================

Effect 분석을 실행해도
사용자가 아직 저장하지 않은 Champion 편집 내용이 절대 사라지면 안 된다.

Analyzer mutation의 onSuccess에서:

reset()
form.reset()
refetch 후 form 초기화
setChampion(originalChampion)

같은 동작을 하지 마.

분석 결과만 해당 analyzer state에 merge해.

================================
STEP 8. 실제 DB 확인
================================

Quest 저장 후 UI만 보고 성공 판단하지 마.

실제 database record를 확인해서
Quest 값이 저장됐는지 확인해.

그리고 다시 GET/fetch해서
동일 값이 반환되는지도 확인해.

DB에는 저장됐는데 UI에서 안 보이는 경우
hydration/read mapping 버그를 수정.

UI에는 보이는데 DB에 없다면
write/save mapping 버그를 수정.

절대 하지 말 것
================================

- 관련 없는 게임 엔진 수정 금지
- Effect Executor 전체 리팩터링 금지
- Card Admin 망가뜨리기 금지
- Champion 데이터 삭제 금지
- 임시 mock 결과로 Analyzer 성공처럼 보이게 하기 금지
- 버튼만 활성화하고 실제 Analyzer 호출 안 하는 것 금지
- 저장됐다고 가정하고 테스트 생략 금지
- 오류를 catch {}로 삼켜버리기 금지
