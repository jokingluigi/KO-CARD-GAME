현재 KO 카드게임의 Effect Library / Structured Effect DSL / Natural Language Analyzer / Game Engine에 다음 기본 메커니즘들을 미리 전부 구현해줘.

이번 작업의 목표는 새로운 카드 효과를 만들 때 아래 메커니즘들이 NEW_MECHANIC_REQUIRED로 판정되지 않고 처음부터 기본 Effect Library 기능으로 사용 가능하게 만드는 것이다.

이 메커니즘들은 UnderCards의 동작 방식을 기반으로 하지만 KO에서는 아래에 지정한 이름과 KO 전용 변경사항을 사용한다.

특정 카드 전용 효과로 구현하지 말고 Trigger / Condition / Keyword / Action / Listener 형태의 재사용 가능한 범용 메커니즘으로 구현한다.

기존 KO 엔진에 같은 기능이 이미 있다면 절대로 중복 구현하지 말고 기존 기능을 재사용하거나 필요한 부분만 확장한다.

==================================================

1. 메커니즘 이름 매핑
   ==================================================

다음 명칭을 KO의 공식 사용자 표시 명칭으로 사용한다.

MAGIC → 등장

NEED → 조건

SYNERGY → 태그

TURBO → 준비

SUPPORT → 콤보

SHOCK → 주문

SWITCH → 스위치

BULLSEYE → 핀폴

TAUNT → 도발

CHARGE → 러쉬

HASTE → 기습

DODGE → 회피

SILENCE → 침묵

PARALYZE → 기절

CATCH → 포획

ERASE → 제거

UI와 카드 텍스트에서는 반드시 KO 명칭을 우선 표시한다.

내부 enum/id는 기존 엔진 이름과 호환되는 이름을 사용해도 되지만 같은 기능을 여러 개 만들지 않는다.

==================================================
2. 등장
=====

사용법 예:

등장: 공격력 +2를 얻습니다.

기본 Trigger:

ENTER_FIELD

중요한 KO 전용 규칙:

UnderCards 원본과 다르게 KO의 "등장"은 카드를 손에서 직접 플레이했을 때만 발동하는 효과가 아니다.

선수 카드가 어떤 정상적인 방법으로든 필드에 들어오면 등장 효과가 발동한다.

포함:

* 손패에서 직접 플레이
* 다른 카드 효과로 소환
* 무작위 소환
* Generated 카드 소환
* Token 소환
* 손패/다른 Zone에서 효과로 필드에 전개
* 포획된 카드의 해방으로 필드에 전개
* Champion 효과에 의한 직접 전개

즉:

PLAY_FROM_HAND
SUMMON
GENERATED_SUMMON
TOKEN_SUMMON
DIRECT_DEPLOY

등 모든 정상적인 ENTER_FIELD 경로가 등장 효과를 발생시킨다.

단 CARD_PLAYED와 ENTER_FIELD 때문에 등장 효과가 두 번 발동하면 안 된다.

한 번의 필드 진입당 정확히 한 번만 발동한다.

효과로 등장한 카드의 등장 효과도 정상적으로 다시 Chain/Queue에 들어가야 한다.

예:

A의 등장:
B를 소환합니다.

↓

B가 효과로 필드에 등장

↓

B의 등장 효과도 발동

이 과정이 정상적으로 연쇄될 수 있어야 한다.

무한 루프 방지를 위한 기존 Effect Queue 안전장치가 있다면 유지한다.

==================================================
3. 조건
=====

사용 예:

조건: 내 손패에 Generated 선수가 있으면
등장: 카드 1장을 뽑습니다.

"조건"은 해당 등장 효과가 발동하기 위한 조건이다.

Condition이 참:

→ 등장 효과 실행

Condition이 거짓:

→ 카드는 정상적으로 필드에 들어오지만 해당 등장 효과는 실행하지 않음

즉 조건 실패 때문에 카드 플레이 자체가 실패하는 것이 아니다.

Condition은 데이터 기반 DSL로 표현한다.

예:

BOARD_COUNT
HAND_COUNT
HAS_CARD
HAS_KEYWORD
HAS_TAG
GOLD_AMOUNT
HEALTH_COMPARE
ATTACK_COMPARE
GENERATED
GRAVEYARD_COUNT
CARD_PLAYED_THIS_TURN

등 기존 Condition 시스템과 통합한다.

가능하다면 손패에서 조건이 충족된 카드는 관리자/게임 UI가 알 수 있도록 boolean 상태를 계산 가능하게 한다.

그러나 UI 때문에 게임 규칙을 복제하지 않는다.

Engine이 최종 authority다.

==================================================
4. 태그
=====

사용 예:

태그: 피해 2를 줍니다.

선수 카드에는 복수의 tag를 가질 수 있게 한다.

예:

tags:
["악마", "용병"]

태그 효과는:

이 카드를 손패에서 플레이할 때,
이번 턴에 이미 플레이한 다른 아군 선수 중
이 카드와 동일한 Tag를 하나 이상 공유하는 카드가 존재하면 발동한다.

예:

이번 턴:

악마 태그 선수 A 플레이

↓

악마 태그 선수 B 플레이

↓

B의 태그 효과 발동

중요:

* 자기 자신은 이전 플레이 카드로 계산하지 않음
* 이번 턴의 플레이 기록만 계산
* 다음 턴이 되면 기록 초기화
* 효과로 단순 소환된 카드는 "PLAYED"로 계산하지 않음
* Generated 여부와 Tag는 별개
* 여러 Tag가 있다면 하나 이상 일치하면 조건 충족

Event Log / turn state를 재사용한다.

==================================================
5. 준비
=====

사용 예:

준비: 공격력 +1을 얻습니다.

Trigger:

CARD_DRAWN

카드가 덱에서 Draw될 때 준비 효과가 발동한다.

중요:

KO에서도 Overdraw 카드의 준비 효과는 발동해야 한다.

현재 KO 최대 손패는 7장이다.

손패가 이미 7장이더라도 새로 Draw된 카드의 준비 Trigger를 감지한다.

그 뒤 해당 카드는 기존 KO Overdraw 규칙에 따라:

removedFromGame

으로 이동한다.

Graveyard로 보내지 않는다.

준비 Trigger와 Overdraw 처리 순서를 명확하고 deterministic하게 만든다.

준비 효과 실패가 Draw 시스템을 망가뜨리면 안 된다.

==================================================
6. 콤보
=====

사용 예:

콤보: 공격력 +1을 얻습니다.

Trigger:

OTHER_ALLY_ATTACK

이 카드가 필드에 있는 동안
다른 아군 선수가 공격할 때마다 발동한다.

자기 자신의 공격에는 발동하지 않는다.

한 선수가 연타 등으로 여러 번 공격하면 공격 이벤트마다 발동한다.

이미 KO에 OTHER_ALLY_ATTACK Listener가 존재하면 그대로 재사용한다.

나토마토 같은 효과도 이 범용 Trigger를 사용할 수 있어야 한다.

==================================================
7. 주문
=====

사용 예:

주문: 공격력 +1을 얻습니다.

KO에서 "주문"은:

내가 손패에서 기술 카드(TECHNIQUE)를 직접 사용할 때 발동하는 Trigger다.

중요한 KO 전용 변경:

발동 기준은 해당 기술 카드의 BASE COST가:

1G 이상

이다.

즉:

0G 기술 → 주문 발동 안 함

1G 기술 → 주문 발동

2G 기술 → 주문 발동

3G 이상 → 주문 발동

현재 Cost가 감소/증가했더라도 발동 여부는 BASE COST를 기준으로 한다.

예:

기본 3G 기술이 효과 때문에 현재 0G가 됨

→ BASE COST는 3G이므로 주문 발동

반대로:

기본 0G 기술이 현재 비용 증가로 2G가 됨

→ BASE COST가 0G이므로 주문 발동 안 함

주문 Trigger는 기술 카드 자체의 효과가 Resolve되기 전에 먼저 발동한다.

순서:

TECHNIQUE_CAST

↓

주문 Trigger들 Resolve

↓

기술 카드 Effect Resolve

그리고 다른 카드 Effect가 기술 카드를 자동으로 사용/발동시킨 경우에는 주문 Trigger를 발생시키지 않는다.

플레이어가 손패에서 직접 사용한 기술만 해당한다.

==================================================
8. 스위치
======

스위치는 카드가 현재 위치한 Board 위치에 따라 서로 다른 Effect Branch를 실행한다.

KO Board는 정확히:

0
1
2
3

네 개의 Fixed Slot이다.

구분:

왼쪽:
slot 0
slot 1

오른쪽:
slot 2
slot 3

사용 예:

스위치:
왼쪽이면 공격력 +2.
오른쪽이면 체력 +2.

구조 예:

SWITCH_POSITION {
leftEffect: ...
rightEffect: ...
}

Trigger가 발생하는 실제 시점의 CURRENT SLOT을 사용한다.

카드가 위치 이동 효과로 반대편에 이동했다면 현재 위치 기준으로 판단한다.

UnderCards의 별도 Artifact/Piece 같은 KO에 존재하지 않는 시스템은 추가하지 않는다.

==================================================
9. 핀폴
=====

사용 예:

핀폴: 카드 1장을 뽑습니다.

이 카드가 자신의 공격 또는 효과로
다른 선수의 체력을 "정확히 0"으로 만들었을 때 발동한다.

중요:

3 HP 대상에게 피해 3

→ 정확히 0
→ 핀폴 발동

3 HP 대상에게 피해 4

→ -1
→ 핀폴 발동 안 함

판정에는 Damage Result Context를 사용한다.

예:

damageBefore
damageAmount
healthBefore
healthAfter
sourceCardId

를 이용한다.

어떤 카드가 정확히 0으로 만들었는지 source attribution을 보존한다.

핀폴과 RETIRE 이벤트는 서로 다른 개념으로 유지한다.

핀폴 조건이 발생하더라도 대상의 사망 처리는 기존 KO RETIRE 규칙을 정상적으로 사용한다.

==================================================
10. 도발
======

기존 KO 도발 시스템을 재사용한다.

적의 일반 공격은 도발 선수가 존재하는 동안:

다른 선수
Champion/Player

를 정상 공격 대상으로 선택할 수 없다.

여러 도발이 있으면 유효한 도발 대상 중 선택 가능.

별도의 두 번째 Taunt 엔진을 만들지 않는다.

==================================================
11. 러쉬
======

기존 KO 러쉬를 재사용한다.

필드에 등장한 바로 그 턴부터 공격 가능.

공격 대상:

* 적 선수
* 상대 Champion/Player

둘 다 가능.

일반 선수의 소환 턴 공격 제한을 무시한다.

다음 턴부터는 일반 공격 규칙으로 자연스럽게 동작한다.

==================================================
12. 기습
======

기존 KO 기습을 재사용한다.

필드에 등장한 턴에 바로 1회 공격할 수 있지만:

적 선수만 공격 가능.

상대 Champion/Player 직접 공격 불가.

다음 턴부터는 일반 선수와 동일하게 정상적인 공격 대상 선택 가능.

==================================================
13. 회피
======

회피는 Damage Instance를 완전히 무효화한다.

기본 표기:

회피

는:

회피(1)

과 동일하게 처리한다.

향후:

회피(2)
회피(3)

같은 Count도 지원 가능하게 구조를 만든다.

Damage를 받을 때:

dodgeCharges > 0

이면 해당 Damage Instance 전체를 0으로 만들고
dodgeCharges를 1 감소한다.

예:

회피(1) 선수가 피해 99를 받음

→ 피해 0
→ 회피 소모

다음 피해는 정상 적용.

적용 대상:

* 일반 공격 피해
* 기술 피해
* Effect Damage

Damage가 아닌:

DESTROY
ERASE
SILENCE

등은 회피로 막지 않는다.

기존 회피 시스템이 이미 있으면 Count 지원만 필요한 수준에서 확장한다.

==================================================
14. 침묵
======

침묵은 대상 선수의 추가 능력과 상태 효과를 제거하고
능력을 사용할 수 없게 한다.

이번 UnderCards 기반 기본 시스템에서는 침묵 시:

* 카드 Ability 제거/비활성화
* Active 효과 비활성화
* Triggered Effect 비활성화
* 추가된 Keyword 제거
* 부정 상태 효과 제거
* 추가된 Stat 변경 제거
* Attack/Health를 해당 카드의 기본 정의값 기준으로 복원

할 수 있는 구조를 지원한다.

단 Health 처리 시 현재 엔진의 사망/상태 일관성이 깨지지 않도록
공식 Silence resolver 하나를 통해 처리한다.

중요:

Champion 자신의 효과로 직접 전개된
보호 상태 Champion Token은 기존 KO 규칙에 따라 침묵 면역이다.

Champion Token 보호 규칙을 절대로 침묵 때문에 우회하지 않는다.

==================================================
15. 기절
======

기절된 선수는 자신의 "다음 턴"에 공격할 수 없다.

그 턴의 공격 기회를 막은 뒤 기절 상태를 제거한다.

기절 상태가 이미 걸려 있는 동안에는
같은 기절을 계속 중첩해서 무한히 다음 턴을 막는 구조로 만들지 않는다.

기존 PARALYZE 상태가 있다면 재사용한다.

기절은 기본적으로 "공격 불가" 상태다.

카드의 별도 Active Ability까지 막는 효과로 임의 확장하지 않는다.

Active Ability 봉쇄가 필요하면 별도의 Condition/Status로 구현한다.

==================================================
16. 포획
======

사용 예:

"적 선수 하나를 포획합니다."

포획은:

대상 카드를 필드에서 제거하고
그 카드의 BASE COPY 정보를
포획한 Source 카드 내부 상태에 저장한다.

중요:

저장되는 것은 현재 Buff/Debuff/Damage 상태가 아니라
해당 카드의 기본 Definition을 기반으로 한 Copy다.

예:

기본 3/3 카드가
현재 버프로 10/10

↓

포획

↓

저장된 Base Copy는 3/3 기반

Captured 상태는 GameState에 직렬화 가능해야 한다.

예:

capturedCards: [
{
definitionId,
baseSnapshot
}
]

함수나 브라우저 객체를 저장하면 안 된다.

이후 다른 Effect가:

포획한 카드를 필드에 해방
포획한 카드를 손패에 추가
포획한 카드의 정보 참조

등을 할 수 있게 Target/Reference를 제공한다.

중요:

포획된 Base Copy가 이후 효과에 의해 필드에 전개되면
KO 규칙에 따라 그 카드의 "등장" 효과가 정상 발동한다.

==================================================
17. 제거
======

제거는 KO의 REMOVE_FROM_GAME과 연결한다.

대상을:

Graveyard로 보내지 않는다.

RETIRE로 처리하지 않는다.

DESTROY로 처리하지 않는다.

removedFromGame Zone으로 이동시킨다.

내부 leaveReason은 명확하게:

ERASE

또는 기존 enum 정책에 맞춰:

REMOVE_FROM_GAME

으로 기록한다.

기존 Event 시스템에서:

RETIRE
DESTROY
REMOVE_FROM_GAME

을 절대로 하나로 합치지 않는다.

제거된 카드는 일반적인 Graveyard/Retire/Destroy 시너지를 발동하지 않는다.

==================================================
18. Generated + 등장 상호작용
=======================

매우 중요하다.

Generated는 카드가 덱 시작 목록에 없었던 카드라는 별도 상태/태그다.

Generated 카드라도 필드에 들어오면:

등장

효과가 정상 발동한다.

예:

카드 A:

등장: 무작위 선수 B를 생성하여 소환합니다.

↓

B:
Generated = true

↓

B 필드 진입

↓

B의 등장 효과 발동

↓

B가 다시 C를 소환한다면 C의 등장도 정상 발동

이를 특정 카드별 예외로 만들지 않고
중앙 ENTER_FIELD Event Queue에서 처리한다.

==================================================
19. 포획 해방 + 등장
==============

포획된 카드가 나중에:

"필드에 해방"

되는 Effect가 있다면
새로운 정상적인 ENTER_FIELD로 간주한다.

따라서 해당 카드의 등장 효과가 발동한다.

단 포획 당시의 등장 효과를 다시 실행하는 것이 아니라
실제로 다시 필드에 들어오는 순간에 새 ENTER_FIELD 이벤트가 발생하는 것이다.

22. 이벤트 발생 순서
=============

Effect Chain이 안정적으로 동작하도록 중앙 Event Queue를 사용한다.

특히 다음 순서를 테스트한다.

A. 등장 연쇄

카드 A 필드 진입
→ A 등장
→ B 소환
→ B ENTER_FIELD
→ B 등장

B. 주문

플레이어가 1G 이상 Base Cost 기술 직접 플레이
→ TECHNIQUE_CAST
→ 주문 효과
→ Technique 본체 Effect

C. 준비 + Overdraw

카드 Draw
→ CARD_DRAWN / 준비 감지
→ 준비 Effect 정상 처리
→ 손패 공간 확인
→ 공간 없으면 removedFromGame

D. 핀폴

Damage
→ Health 결과 계산
→ 정확히 0 여부 기록
→ 핀폴 Trigger
→ 기존 RETIRE 처리와 정상적으로 연동

정확한 Queue 시점은 현재 엔진 구조와 충돌하지 않는 범위에서 일관되게 구현한다.

24. 테스트
=======

위 16개 메커니즘 각각 최소 1개 이상의 테스트를 작성한다.

특히 반드시 테스트:

1.

효과로 소환된 카드도 등장 발동

2.

등장으로 소환 → 또 등장으로 소환되는 Chain

3.

조건 성공

4.

5.

같은 Tag 카드 플레이 후 태그 발동

6.

다른 Tag이면 태그 미발동

7.

Overdraw된 카드도 준비 Trigger 발생 후 removedFromGame

8.

다른 아군 공격 시 콤보 발동

9.

자신 공격에는 콤보 미발동

10.

BASE COST 1G 기술 사용 → 주문 발동

11.

BASE COST 0G 기술 → 주문 미발동

12.

비용 감소로 CURRENT COST가 0이어도 BASE COST 1 이상이면 주문 발동

13.

다른 효과가 기술을 자동 발동한 경우 주문 미발동

14.

slot 0/1 → 스위치 왼쪽 Effect

15.

slot 2/3 → 스위치 오른쪽 Effect

16.

3HP에게 피해3 → 핀폴 발동

17.

3HP에게 피해4 → 핀폴 미발동

18.

러쉬가 등장 턴에 Champion 직접 공격 가능

19.

기습이 등장 턴에 선수만 공격 가능

20.

회피가 Damage Instance 전체 무효화

21.

침묵 정상 적용

22.

기절 다음 턴 공격 차단

포획 시 Base Copy 저장

25. 관리자/챔피언 시스템도 공유
===================

이 메커니즘들은 Card Admin뿐 아니라
Champion Admin의 자연어 효과에서도 같은 Effect Library를 사용한다.

예:

Champion Ability에서:

"주문: ..."

같은 Listener/Trigger가 필요하면 동일 Registry를 사용한다.

카드용 Effect Library와 Champion용 Effect Library를 따로 만들지 않는다.

26. 새 메커니즘 요청 시스템과 연결
=====================

이 작업 완료 후 위 메커니즘들은 모두 기본 지원 기능이어야 한다.

따라서 이 기능을 사용한 카드 텍스트 때문에:

NEW_MECHANIC_REQUIRED

가 발생하면 안 된다.

예:

"준비: 카드 1장을 뽑습니다."

"콤보: 공격력 +1."

"조건: 내 필드에 선수가 2명 이상이면 등장: +2/+2."

"적 선수 하나를 포획합니다."

등은 기본적으로 분석 가능해야 한다.

정말 이 목록 밖의 새로운 게임 메커니즘이 등장했을 때만 기존:

[Replit 수정 프롬프트 만들기]

흐름을 사용한다.

27. 구현 범위 제한
============

이번 작업 때문에 프로젝트 전체를 리팩터링하지 않는다.

현재 Registry / Event Queue / Effect Executor / Keyword 시스템을 먼저 확인하고 재사용한다.

특정 카드 이름 하드코딩 금지.

Math.random 직접 사용 금지.

eval 금지.

new Function 금지.

DB에 실행 가능한 JS 저장 금지.

Invalid Action 때문에 GameState reset/reload 금지.

관련 Effect/Registry/Analyzer/Test 파일만 최소 수정한다.

위 메커니즘이 정상 작동하면 추가 기능을 임의로 만들지 말고 종료해줘.
