현재까지 구현한 Effect Library, 자연어 효과 분석 시스템, NEW_MECHANIC_REQUIRED 판정, MechanicRequest 시스템을 유지해줘.

이번 단계에서는 외부 Cursor, Devin, OpenHands 같은 유료/외부 코딩 에이전트를 연결하지 않는다.

대신 기존 Effect Library로 구현할 수 없는 새로운 메커니즘이 발견되면,
관리자가 Replit Agent에 직접 붙여넣을 수 있는 "정확한 수정 프롬프트"를 자동 생성해주는 기능을 추가해줘.

중요:

* 외부 AI API 사용 금지
* Cursor API 사용 금지
* Devin API 사용 금지
* OpenHands 연결 금지
* 별도 유료 서비스 필요 없음
* 이 기능 자체가 Replit Agent를 자동 호출하지 않는다.
* 단순히 Replit Agent에 복사해서 붙여넣을 고품질 개발 프롬프트를 생성한다.

기존 정상 게임 엔진을 대규모 리팩터링하지 마.

================================

1. NEW_MECHANIC_REQUIRED 화면 수정
   ================================

자연어 카드 효과 분석 결과가:

NEW_MECHANIC_REQUIRED

이면 관리자 화면에 다음을 보여준다.

⚠ 새 메커니즘이 필요합니다.

원본 효과:
[사용자가 입력한 효과]

현재 지원되지 않는 부분:
[unsupportedParts]

그리고 버튼:

[Replit 수정 프롬프트 만들기]

를 추가한다.

기존에 외부 코딩 에이전트를 호출하려고 만든 버튼이나 흐름이 있다면
삭제로 인해 다른 시스템이 깨지지 않는 범위에서 비활성화하거나 관리자 UI에서 숨긴다.

MechanicRequest 데이터 구조는 재사용한다.

================================
2. 프롬프트 자동 생성
=============

[Replit 수정 프롬프트 만들기]

버튼을 누르면
현재 카드 효과와 Effect Library 상태를 기반으로
Replit Agent에게 그대로 붙여넣을 수 있는 개발 프롬프트를 생성한다.

이 프롬프트는 단순히:

"이 효과 만들어줘"

수준이면 안 된다.

현재 게임 엔진에서 무엇이 부족한지 최대한 구체적으로 설명해야 한다.

자동 생성 프롬프트에는 최소 다음 정보가 포함되어야 한다.

1. 원본 카드 효과 문장
2. 자연어 분석 결과
3. 지원되지 않는 부분
4. 필요한 것으로 추정되는 Trigger
5. 필요한 것으로 추정되는 Action
6. 필요한 것으로 추정되는 Target
7. 필요한 것으로 추정되는 Value Resolver
8. 필요한 Condition / Listener / Duration
9. 현재 Effect Library에서 재사용 가능한 기능
10. 새로 구현할 가능성이 높은 기능
11. 관련 게임 규칙
12. 구현 시 지켜야 할 안전 규칙
13. 테스트 요구사항

================================
3. 기존 Effect 재사용을 강하게 요구
========================

생성되는 Replit Agent 프롬프트에는 항상 다음 취지의 명령을 포함한다.

"새 코드를 만들기 전에 현재 Effect Library, Trigger Registry, Target Resolver, Value Resolver, Condition, Listener를 먼저 확인해라."

"기존 기능 조합으로 구현 가능하다면 새로운 메커니즘을 만들지 마라."

"정말 새로운 기능이 필요한 경우에만 재사용 가능한 범용 메커니즘을 추가해라."

================================
4. 카드 이름 하드코딩 금지
================

생성 프롬프트에는 반드시:

특정 카드 이름에 종속된 구현 금지

를 포함한다.

예:

금지:

if (card.name === "씨 몬스터")

if (card.id === "natotomato")

좋은 방식:

WHILE_IN_HAND_LISTENER
ALLY_WRESTLER_RETIRED
REDUCE_SELF_COST
SOURCE_CURRENT_ATTACK

같은 범용 기능을 사용한다.

================================
5. 기존 게임 보호 규칙 자동 포함
====================

모든 생성 프롬프트에 다음 규칙을 기본 포함한다.

* 기존 게임 엔진 대규모 리팩터링 금지
* 정상 작동 중인 Effect 삭제 금지
* 턴 시스템 변경 금지
* Gold 규칙 변경 금지
* 4슬롯 Board 규칙 변경 금지
* 공격 규칙 변경 금지
* Champion 시스템 임의 변경 금지
* Champion Token 보호 규칙 임의 변경 금지
* targeting 시스템 재작성 금지
* Match Snapshot 정책 유지
* GameState 직렬화 가능 구조 유지
* deterministic RNG 유지
* Math.random 직접 사용 금지
* invalid action으로 게임 reset/reload/exception 발생 금지

================================
6. 신규 메커니즘 구현 규칙
================

정말 새로운 메커니즘이 필요하다면
생성되는 프롬프트가 Replit Agent에게 다음 순서로 구현하도록 요구한다.

필요한 부분만 최소 수정:

* Effect Registry
* Effect Schema
* Effect Handler
* Trigger
* Target Resolver
* Value Resolver
* Condition
* Listener
* Duration
* Analyzer mapping
* TypeScript type
* Tests

필요하지 않은 파일은 수정하지 않는다.

================================
7. 안전 규칙
========

자동 생성 프롬프트에는 항상 다음 금지사항을 포함한다.

eval() 금지

new Function() 금지

DB에서 JavaScript 문자열 실행 금지

자연어 자체를 런타임에서 코드로 실행 금지

카드 이름 기반 분기 금지

브라우저에서 임의 코드를 실행하는 구조 금지

새로운 메커니즘은 기존 게임 엔진의 정식 TypeScript 구조에 등록한다.

================================
8. 테스트 요구사항
===========

생성되는 Replit 프롬프트에는 자동으로 다음 테스트 요구를 포함한다.

신규 메커니즘에 대해 최소:

* 정상 실행
* 대상 없음
* 잘못된 대상
* 조건 불충족
* 값 계산
* GameState 손상 여부
* 기존 Effect와 충돌 여부

랜덤 메커니즘:

* 같은 seed에서 같은 결과

지속 효과 / Listener:

* 올바른 Zone에서만 발동
* Source가 사라졌을 때 필요한 경우 Listener 제거
* 턴을 넘겨도 필요한 상태가 GameState에 정상 저장

그리고 기존 핵심 테스트도 깨지지 않는지 확인하게 한다.

================================
9. 프롬프트 미리보기
============

생성 후 관리자 페이지에 큰 텍스트 영역으로 보여준다.

제목:

Replit Agent 수정 프롬프트

내용:

[자동 생성된 프롬프트]

버튼:

[프롬프트 복사]

[다시 생성]

을 제공한다.

복사 버튼은 Clipboard API를 사용한다.

성공:

"Replit Agent용 프롬프트를 복사했습니다."

Toast 표시.

실패:

정상적인 오류 Toast만 표시하고 페이지를 reload하지 않는다.

================================
10. 프롬프트는 사람이 읽을 수 있어야 함
========================

생성 프롬프트는 JSON 데이터 덩어리만 출력하지 않는다.

Replit Agent가 바로 이해할 수 있는 자연어 개발 지시문 형태로 만든다.

예시 형태:

---

KO 카드게임에 다음 카드 효과를 지원해주세요.

원본 효과:
"이 카드가 손패에 있을 때 아군 선수가 리타이어할 때마다 이 카드의 비용이 1 감소합니다."

현재 분석 결과:
기존 Effect Library만으로는 완전히 표현할 수 없습니다.

부족한 기능:

* 손패에서 게임 이벤트를 감시하는 지속 Listener
* 아군 선수 RETIRE 이벤트 필터
* 이벤트 발생 시 Source 카드 자신의 비용 감소

먼저 현재 Effect Library를 확인하세요.

기존에 다음과 비슷한 기능이 있다면 재사용하세요:

* ALLY_WRESTLER_RETIRED
* REDUCE_COST
* WHILE_IN_HAND
* REGISTER_LISTENER

기존 조합으로 해결되지 않는 경우에만
범용적인 WHILE_IN_HAND_EVENT_LISTENER 또는 이에 준하는 기능을 추가하세요.

특정 카드 이름을 하드코딩하지 마세요.

이 기능은 향후 다음과 같은 카드에도 재사용 가능해야 합니다:

* 손패에서 아군 공격 감지
* 손패에서 카드 생성 감지
* 손패에서 아군 Retire 감지

필요한 최소 파일만 수정하세요.

...

테스트까지 작성하고
완료 후 수정한 파일과 테스트 결과만 요약해주세요.

---

이 정도 수준으로 구체적인 프롬프트를 생성한다.

================================
11. Effect Library 정보 활용
========================

프롬프트를 생성할 때 현재 실제 Effect Library 데이터를 사용한다.

하드코딩된 예전 Effect 목록을 별도로 만들지 않는다.

현재 ACTIVE 상태의:

Trigger
Effect
Action
Target
Value Resolver
Condition
Listener

를 읽어서

"현재 재사용 가능한 기능"

부분에 넣는다.

전체 목록을 무조건 전부 출력해서 프롬프트가 지나치게 길어지지 않게 한다.

현재 효과와 관련성이 높은 기능만 선택한다.

================================
12. Replit Agent 작업량 최소화
========================

생성되는 프롬프트는 Replit Agent 크레딧을 절약할 수 있도록 작성한다.

항상 다음 명령을 포함한다.

"프로젝트 전체를 다시 분석하거나 대규모 리팩터링하지 마세요."

"먼저 Effect 관련 Registry와 현재 Analyzer 결과를 확인하세요."

"관련 파일만 최소 수정하세요."

"이미 존재하는 기능을 다시 구현하지 마세요."

"요구한 기능이 정상 작동하면 추가 기능을 임의로 만들지 말고 종료하세요."

================================
13. Agent 작업 완료 후 재검사
=====================

관리자 화면에 추가로:

[메커니즘 구현 완료 - 다시 분석]

버튼을 제공한다.

사용자가 Replit Agent에서 실제 코드 수정이 끝난 뒤 이 버튼을 누르면
원래 카드 효과 문장을 현재 최신 Effect Library로 다시 분석한다.

성공하면:

✓ 이제 현재 Effect Library에서 구현 가능합니다.

Structured Effect:
[...]

[카드 효과 적용]

으로 이어진다.

여전히 불가능하면:

⚠ 아직 지원되지 않는 부분이 있습니다.

를 표시하고 새로운 unsupportedParts를 기반으로 프롬프트를 다시 만들 수 있게 한다.

================================
14. 전체 최종 UX
============

최종 사용 흐름은 다음과 같아야 한다.

관리자가 카드 효과 입력

↓

자연어 분석

↓

기존 Effect로 가능

→ Structured Effect 생성
→ [카드 효과 적용]

또는

기존 Effect로 불가능

→ NEW_MECHANIC_REQUIRED

↓

[Replit 수정 프롬프트 만들기]

↓

자동으로 현재 게임 구조에 맞는 상세 프롬프트 생성

↓

[프롬프트 복사]

↓

사용자가 Replit Agent 채팅에 붙여넣음

↓

Replit Agent가 실제 코드 수정 + 테스트

↓

관리자로 돌아옴

↓

[메커니즘 구현 완료 - 다시 분석]

↓

새 Effect를 인식하면 Structured Effect 생성

↓

[카드 효과 적용]

이 방식으로 만들어줘.

================================
15. 중요: 외부 서비스 제거
=================

이번 구현은 Cursor, Devin, OpenHands 또는 별도 AI API 연결을 요구하지 않아야 한다.

현재 2단계에서 만들어진 외부 코딩 에이전트용 인터페이스가 있다면
기존 시스템을 망가뜨리지 않는 선에서 더 이상 필수 경로가 아니게 한다.

관리자에게 외부 API Key 입력을 요구하지 않는다.

KO 프로젝트 내부에서는 프롬프트 생성까지만 담당한다.

실제 코드 수정은 사용자가 현재 사용 중인 Replit Agent에 프롬프트를 직접 붙여넣어 실행한다.

여기까지만 구현하고 추가 기능을 임의로 만들지 마.
