현재 KO 카드게임의 AI Match를 2차 개선하고
관리자 사이트에 "AI 덱 관리" 기능을 추가해줘.

기존 시스템 반드시 재사용:
- AI Match 1차
- getLegalActions()
- executeAction()
- Generic AI Effect Evaluator
- CardDefinition
- ChampionDefinition
- 기존 Deck validation
- Match/GameState

특정 카드/챔피언 이름 하드코딩 금지.

==================================================
1. 관리자 AI 덱 관리
==================================================

/admin에:

[AI 덱 관리]

메뉴 추가.

예:
/admin/ai-decks

ADMIN만 접근 가능.

관리자는 AI가 사용할 덱을:

- 생성
- 편집
- 복제
- 삭제/비활성
- 테스트

할 수 있게 해.

==================================================
2. AI Deck 데이터
==================================================

일반 User Deck과 구분되는 AI DeckDefinition을 사용해.

예:

AIDeckDefinition {
  id
  name
  description
  championDefinitionId
  cardDefinitionIds
  enabled
  displayOrder
  createdAt
  updatedAt
}

필요하면 기존 Deck 구조를 재사용/확장해도 된다.

카드 전체 데이터를 복사하지 말고 Definition ID를 저장.

==================================================
3. AI 덱 규칙
==================================================

AI 덱도 일반 덱과 동일한 기본 규칙:

- Champion 1명
- 카드 20~30장
- PUBLISHED 카드만
- PUBLISHED Champion만
- Token 편성 금지
- Champion Token 편성 금지

단 AI는 User 계정이 아니므로
UserCardCollection / UserChampionCollection 소유권 검사는 하지 않는다.

즉:

USER DECK
→ 소유권 검사 O

AI DECK
→ 소유권 검사 X
→ 카드/Champion 유효성 검사는 O

==================================================
4. AI 덱 편집 UI
==================================================

기존 Deck Editor UI/카드 Renderer를 최대한 재사용.

관리자가:

Champion 선택
→ 카드 추가/제거
→ 카드 수 확인
→ 저장

가능하게 해.

검색:
- 이름
- WRESTLER / TECHNIQUE
- Rarity

정도 지원.

AI 전용 가짜 카드는 만들지 마.

==================================================
5. AI Match에서 상대 덱 선택
==================================================

AI Match 시작 화면을 개선해.

흐름:

내 VALID Deck 선택
↓
AI 상대 덱 선택
↓
게임 시작

활성화된 VALID AI Deck만 보여줘.

각 AI 덱에:

- 이름
- Champion
- 카드 수
- 간단한 설명

표시.

==================================================
6. 랜덤 AI 덱
==================================================

사용자가 원하면:

[랜덤 상대]

선택 가능하게 해.

이 경우 enabled + VALID AI Deck 중 하나를 선택.

랜덤 선택 때문에 Game Rules를 변경하지 마.

==================================================
7. AI 덱 Snapshot
==================================================

Match 시작 시 AI Deck도
일반 Deck과 동일하게 Definition을 해석해서
Match Snapshot을 생성해.

Admin이 경기 도중 AI Deck을 수정해도
진행 중 Match에는 영향 없어야 한다.

==================================================
8. 잘못된 AI 덱
==================================================

AI Deck에 나중에:

- DISABLED 카드
- 삭제 카드
- Token
- DISABLED Champion

등이 생기면 INVALID 처리.

AI Match 후보에서 제외.

Admin 화면에 경고 표시.

자동으로 다른 카드로 대체하지 마.

==================================================
9. AI 판단 2차 개선
==================================================

AI 1차의 legal action 기반 구조는 유지하고
판단만 개선해.

AI는 카드 이름이 아니라:

- Cost
- CURRENT Attack/Health
- Keywords
- Structured Effect
- Board State
- Hand Size
- Champion HP
- Gold
- Target value

를 보고 판단.

==================================================
10. Board Value
==================================================

선수의 대략적인 가치를 Generic하게 계산해.

예:

높은 Attack
+ 높은 Health
+ 좋은 Keyword
+ 강한 지속 Effect

→ 높은 Board Value

도발:
Champion 보호 가치 추가

회피:
생존 가치 추가

기절:
현재 가치 감소

침묵:
능력 가치 제거

정확한 숫자는 별도 상수/weight로 관리 가능하게 해.

==================================================
11. DAMAGE 판단
==================================================

DAMAGE Action 평가 시:

적에게 주는 피해
→ +

내 카드에 주는 피해
→ -

치명타/즉시 RETIRE 가능
→ 추가 +

상대 Champion lethal
→ 최우선

단 실제 Damage 결과는 Engine이 계산.

AI가 GameState를 직접 수정하지 마.

==================================================
12. DESTROY / RETIRE
==================================================

현재 KO 규칙을 이해하게 해.

DESTROY:
→ 상대 고가치 선수에게 매우 높은 가치

RETIRE:
→ 대상/상황에 따라 평가

중요:
DESTROY와 RETIRE는 기존 Engine 의미를 그대로 사용.

AI용으로 규칙을 새로 만들지 마.

==================================================
13. BUFF / DEBUFF
==================================================

BUFF:
높은 가치의 아군에게 줄수록 점수 상승.

공격력/체력 증가량과 대상 생존 가능성을 고려.

DEBUFF:
높은 가치의 적에게 줄수록 점수 상승.

SILENCE:
강한 Effect/Keyword를 가진 적에게 더 높은 점수.

STUN:
이번 턴 행동 가능한 강한 적에게 높은 점수.

==================================================
14. DRAW / GENERATE
==================================================

DRAW:
손패가 적을수록 가치 상승.

Hand 7장 근처라면 가치 감소.

Overdraw 위험도 고려.

GENERATE:
생성되는 카드의 정확한 결과를 미리 보지 마.

공개된 기대값/일반적인 카드 가치 정도만 사용.

==================================================
15. SUMMON
==================================================

빈 Board Slot이 있을 때 가치 평가.

Board가 꽉 찼으면
불가능한 Action은 legalActions에서 제외되어야 한다.

소환되는 선수의 Stats/Effect 정보를 알 수 있다면
Generic Board Value 사용.

==================================================
16. 공격 판단 개선
==================================================

공격 후보를 비교해서:

1. 즉시 Champion 처치
2. 유리한 선수 교환
3. 위험한 적 제거
4. Champion Damage
5. 나쁜 교환 회피

순으로 자연스럽게 평가.

동시 전투 피해 기준으로
공격 후 예상 생존 여부를 고려해도 된다.

단 Taunt / Rush / Haste 등 합법성은
Engine legalActions를 신뢰해.

==================================================
17. 자원 사용
==================================================

AI가 매 턴 무조건 Gold를 전부 쓸 필요는 없지만
좋은 행동을 남겨두고 너무 빨리 END_TURN하지 않게 해.

Cost 대비:

- Stats
- Effect Value
- Board 영향

을 대략 비교.

==================================================
18. Action Sequence
==================================================

AI는 한 턴 전체 계획을 한 번에 고정하지 마.

매 Action 후:

새 GameState
→ 다시 legalActions
→ 다시 평가

해야 한다.

카드 효과/RETIRE/Random 때문에 상태가 달라질 수 있기 때문.

==================================================
19. PLAYER_CHOICE
==================================================

AI가 Effect Target을 선택할 때도
동일 Evaluator 사용.

예:

DAMAGE
→ 가장 가치 높은 적 또는 lethal Champion

BUFF
→ 가장 가치 높은 아군

SILENCE
→ 능력이 강한 적

단 validTargetIds 밖의 대상을 선택하면 안 된다.

==================================================
20. Unknown Effect
==================================================

미래 카드 지원이 매우 중요하다.

AI가 아직 이해하지 못하는 Effect Action이 있어도:

- crash 금지
- turn stuck 금지
- 카드 이름 하드코딩 금지

Known Effect + Stats + Cost 기준 fallback 평가.

==================================================
21. AI Evaluator Registry
==================================================

가능하면 Generic Effect Type별 AI 평가기를
Registry 형태로 관리해.

예:

DAMAGE → evaluateDamage
HEAL → evaluateHeal
BUFF → evaluateBuff
DESTROY → evaluateDestroy
DRAW → evaluateDraw

새 Generic Effect가 추가되면
카드별 코드가 아니라
Effect evaluator 하나만 추가하면 되게 해.

==================================================
22. 개발용 AI Debug
==================================================

development에서만:

선택된 Action
점수
상위 후보 몇 개

를 확인 가능하게 해.

예:

PLAY_CARD 18.2
ATTACK_WRESTLER 13.4
ATTACK_CHAMPION 8.0
END_TURN 0

Production User에게는 노출하지 마.

==================================================
23. AI 덱 테스트 버튼
==================================================

Admin AI Deck 관리에서:

[AI 테스트]

버튼 제공 가능.

선택한 AI Deck으로 기존 Test/AI Match를 시작해서
해당 덱이 실제로 정상 플레이되는지 확인.

새 Game Engine을 만들지 마.

==================================================
24. 실제 테스트
==================================================

반드시 최소 2개 AI Deck을 만들어 테스트해.

서로 다른 Champion/카드 구성으로:

- AI Match 시작
- 카드 플레이
- Technique
- 공격
- Champion Ability
- PLAYER_CHOICE
- END_TURN
- Match Result

정상 확인.

새 카드 Definition을 추가해도
AI 코드에 카드 이름을 추가하지 않고 플레이 가능한지도 확인.

==================================================
25. 수정 금지
==================================================

이번 작업에서:

- 특정 카드 AI 하드코딩 금지
- 특정 Champion AI 하드코딩 금지
- AI가 GameState 직접 수정 금지
- User 소유권을 AI Deck에 강제 적용 금지
- Game Rules 변경 금지
- Online Match 구현 금지

==================================================
최종 구조
==================================================

ADMIN
→ AI 덱 관리
→ Champion + 20~30 카드 구성
→ 저장
→ 활성화

USER
→ AI 매치
→ 내 덱 선택
→ AI 덱 선택 또는 랜덤
→ Match 시작

AI
→ legalActions
→ Generic Effect/Board Evaluation
→ executeAction
→ 상태 다시 평가
→ 반복

미래에 카드가 계속 추가돼도
기존 Effect DSL 범위 안에서는
AI Deck에 넣기만 하면 별도 카드별 AI 코드 없이
정상적으로 사용할 수 있게 해.
