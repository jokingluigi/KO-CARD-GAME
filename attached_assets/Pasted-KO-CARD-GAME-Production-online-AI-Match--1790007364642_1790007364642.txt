KO CARD GAME의 현재 Production/online/AI Match 관련 버그와 미구현 사항을
전부 조사하고 실제로 수정해줘.

이번 작업의 목표는 "코드를 수정하는 것"이 아니다.

최종 목표는:

문제 재현
→ 실제 root cause 확인
→ 최소 범위 수정
→ unit/integration test
→ 실제 브라우저에서 테스트 게임 플레이
→ 수정된 동작을 직접 확인
→ regression 확인
→ commit/push

까지 완료하는 것이다.

==================================================
최우선 원칙
==================================================

절대 코드만 읽고 PASS 처리하지 마.

반드시 가능한 항목은 실제 게임을 실행해서
브라우저에서 직접 플레이하고 결과를 확인해야 한다.

특히 다음은 실제 게임 플레이 검증 필수:

- 카드 효과
- Champion 능력
- Champion Quest
- 공격/피해/회복
- 턴 종료
- 타이머
- AI 행동
- Online PvP
- reconnect
- 애니메이션
- 카드 사용 연출
- 퀘스트 완료 알림
- 상대 닉네임
- 메인 메뉴 복귀

실제 게임에서 확인하지 못한 항목은
PASS가 아니라 UNVERIFIED로 보고해라.

"코드상 정상으로 보임"
"테스트는 통과함"

만으로 실제 gameplay PASS 처리 금지.

==================================================
현재 게임 구조 보존
==================================================

KO CARD GAME은:

Action
→ Event
→ GameState

구조를 따른다.

온라인은 server-authoritative.

RNG는 deterministic.

최근 Universal Effect Script / Structured Effect 시스템이 추가되어 있다.

기존:

- Structured Effect
- Effect Script
- PLAYER_CHOICE
- result reference
- deterministic random selector
- Champion Token
- Technique
- Quest
- AI Match
- Online PvP

를 최대한 공용 engine path에서 처리해라.

카드마다 이름/ID를 hardcoding해서 고치지 마.

예:

if (card.name === "하스이") ...

같은 방식 금지.

문제가 범용 engine/trigger/event attribution 문제라면
generic하게 수정한다.

문제 22
판도라 Champion Quest가 RETIRE를 집계하지 않음
==================================================

매우 중요.

실제 신고:

판도라 Champion ability로
용병을 RETIRE시킨 뒤에도
Quest progress가:

0/5

에 그대로 남음.

반드시 실제로 재현한다.

확인 경로:

USE_CHAMPION_ABILITY
→ RETIRE
→ RETIRE event
→ event attribution
→ quest condition matcher
→ quest progress
→ GameState
→ UI

판도라 능력이 발생시킨 RETIRE도
공식 Quest 조건에 해당한다면
정상적으로 progress +1 되어야 한다.

중요:

단순 UI 표시 문제인지
실제 server/GameState questProgress가 0인지
반드시 구분.

다음 경우 각각 테스트:

- 일반 카드 효과 RETIRE
- Champion ability RETIRE
- combat/damage에 의한 RETIRE
- 판도라 자신의 Champion ability

Quest가 어떤 RETIRE를 세도록 설계되었는지는
ChampionDefinition의 공식 condition을 authoritative source로 사용한다.

특정 판도라 이름 hardcoding 금지.

RETIRE event attribution / quest matcher를 generic하게 수정한다.

실제 테스트 게임에서:

0/5
→ 능력으로 1명 RETIRE
→ 1/5

가 되는지 확인.

가능하면 Quest 완료:

4/5
→ RETIRE
→ 5/5
→ completion
→ reward

까지 테스트.

==================================================
PASS 판정 기준
==================================================

각 문제는 다음 중 하나로 보고한다.

PASS
- 실제 gameplay에서 기대 결과 확인.

FAIL
- 재현되며 아직 수정되지 않음.

UNVERIFIED
- 테스트 환경 한계 때문에 실제 확인 불가.

NEEDS_DESIGN
- 공식 기대 동작/수치가 repo에 정의되어 있지 않음.

절대:

코드 읽음
→ PASS

unit test 통과
→ gameplay PASS

로 처리하지 마.

==================================================
Champion Token 공식 규칙 유지
==================================================

절대 회귀 금지.

- Champion Token deploy는 original Champion HP를 더하지 않음
- own base stats 사용
- Token RETIRE ≠ immediate loss
- Token active 동안 original Champion protected
- Champion ability 계속 사용 가능
- Token leave 후 original Champion HP 그대로
- Token SILENCE/DESTROY/REMOVE_FROM_GAME immunity
- regular damage/combat 가능
- HP 0이면 RETIRE 가능
- ordinary SUMMON은 Champion Token state 획득 금지
- fallback FIELD → HAND → DECK TOP

==================================================
Technique 공식 규칙 유지
==================================================

- board slot 사용하지 않음
- board full이어도 사용 가능
- 사용 후 graveyard
- PLAYER_CHOICE 사용 가능

- public cardPool만 허용
