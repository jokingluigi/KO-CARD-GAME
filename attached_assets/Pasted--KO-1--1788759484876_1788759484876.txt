현재 KO 카드게임 관리자 페이지의 자연어 카드 효과 분석 기능을 전반적으로 개선해줘.

현재는:

"등장: 골드 1 획득"

같은 매우 단순한 카드 효과조차
분석 결과를 적용할 수 없다고 표시되는 경우가 있다.

골드 효과 하나만 임시로 고치는 것이 아니라,
KO 카드게임에서 자주 사용하는 카드 효과 문장과 키워드를
다양한 자연어 표현으로 작성해도 안정적으로 분석할 수 있도록
Natural Language Effect Analyzer 전체를 개선해줘.

중요:

자연어를 JavaScript 코드로 변환해서 실행하지 마.

다음은 절대 사용 금지:

eval()
new Function()
DB에 실행 가능한 JavaScript 저장
자연어로 임의 코드 생성 후 실행

자연어 분석기는 반드시 기존 또는 확장된:

Trigger Registry
Action / Effect Registry
Target Registry
Keyword Registry
Condition Registry
Value Resolver
Effect Schema Registry

의 허용된 값으로만 변환해야 한다.

==================================================

1. 핵심 원칙
   ==================================================

관리자가 입력한 카드 효과 문장을:

Trigger
Action
Target
Selection
Count
Value
Condition
Keyword

등의 Structured Effect 데이터로 변환한다.

예:

"등장: 적 선수 하나에게 피해 2"

→

Trigger:
ENTER_FIELD

Action:
DAMAGE

Target:
ENEMY_WRESTLER

Selection:
PLAYER_CHOICE

Count:
1

Amount:
2

이렇게 변환한다.

게임에서 실제 효과를 실행할 때는
자연어 text를 다시 해석하지 말고
저장된 Structured Effect를 사용한다.

==================================================
2. 같은 뜻의 다양한 표현을 인식
===================

표현이 정확히 한 문장과 일치해야만 작동하는 방식으로 만들지 마.

예를 들어 다음 표현은 전부 같은 의미로 인식할 수 있어야 한다.

"골드 1 획득"

"골드 1 얻기"

"골드를 1 얻습니다."

"1골드를 획득합니다."

"1G 획득"

"현재 골드 +1"

→ 모두 ADD_GOLD / amount 1

이런 방식으로
Trigger, Action, Target, Keyword 등에도
synonym/alias dictionary를 사용한다.

공백, 조사, 마침표, 숫자 위치가 조금 달라도
가능한 경우 정상 인식하게 한다.

==================================================
3. Trigger 표현 인식
================

다음 표현을 동일 Trigger로 인식한다.

등장 계열:

"등장:"
"등장 :"
"등장할 때"
"등장하면"
"필드에 등장할 때"
"필드에 나올 때"
"소환될 때"

→ ENTER_FIELD

퇴장 계열:

"퇴장:"
"퇴장할 때"
"퇴장하면"
"필드에서 퇴장할 때"

→ LEAVE_FIELD 또는 현재 게임 엔진의 퇴장 Trigger

공격 계열:

"공격할 때"
"공격 시"
"공격하면"

→ ATTACK

"공격 후"
"공격한 후"
"공격을 마친 후"

→ AFTER_ATTACK

피해 계열:

"피해를 받을 때"
"데미지를 받을 때"
"피격 시"

→ DAMAGE_RECEIVED

턴 계열:

"내 턴 시작"
"내 턴이 시작될 때"
"자신의 턴 시작"

→ TURN_START

"내 턴 종료"
"턴이 끝날 때"
"자신의 턴 종료"

→ TURN_END

액티브:

"액티브:"
"액티브 사용:"
"액티브를 사용하면"

→ ACTIVE

4. 피해 효과 표현
===========

다음 표현을 DAMAGE로 인식한다.

"피해 1"
"1 피해"
"피해를 1 줍니다"
"1 데미지를 줍니다"
"데미지 1"

"2 데미지"

→ ENTER_FIELD

→ amount 1

8. 카드 드로우
=========

다음 표현을 DRAW로 인식한다.

"카드 1장 드로우"

"카드 한 장을 뽑습니다"

"1장 뽑기"

==================================================
9. 골드 효과
========

즉시 현재 골드를 증가시키는 표현:

"골드 1 획득"

"골드를 1 얻습니다"

"1G 획득"

"현재 골드 +1"

"골드 +1"

→ ADD_GOLD

다음 턴 추가 골드:

"다음 턴 골드 +1"

"다음 내 턴에 골드 1 추가"

"다음 턴에 1G 추가"

"다음 턴 추가 골드 2"

→ ADD_NEXT_TURN_GOLD

둘을 구분한다.

기본 턴 골드 최대 6G 규칙과는 별개다.

카드 효과로 현재 골드가 7G 이상이 되는 것은 허용한다.

12. 생성
======

다음 표현을 GENERATE_CARD로 인식한다.

"카드를 생성"

"손패에 생성"

"선수 카드를 한 장 생성"

"무작위 선수 카드를 생성"

예:

"등장: 무작위 선수 카드 1장을 손패에 생성합니다."

→ HAND_CARD_COUNT

"묘지의 선수 카드 수만큼"

→ GRAVEYARD_WRESTLER_COUNT

"필드의 아군 선수 수만큼"

→ ALLY_BOARD_COUNT

23. 배수 / 절반 표현
==============

Value Resolver에 modifier를 적용할 수 있게 한다.

예:

"공격력의 절반"

→ value source ATTACK
→ multiplier 0.5

"공격력의 두 배"

→ multiplier 2

"체력의 절반"

→ current health × 0.5

소수점이 나오는 경우의 반올림 규칙은
게임의 공통 rounding config를 사용한다.

아직 규칙이 없다면 임의로 정하지 말고
명확하게 별도 config로 분리한다.

26. 여러 효과가 연결된 문장
=================

다음 연결 표현을 처리한다.

"그리고"

"그 후"

"이후"

"~하고"

"~한 뒤"

"~한 후"

예:

"등장: 적 선수 하나를 침묵시키고 파괴합니다."

예:

→ DESTROY
→ DRAW 1

==================================================
27. 같은 대상 참조
============

한 문장의 다음 효과가 이전 대상에 계속 적용되는 경우
새 대상을 다시 선택하게 하지 않는다.

예:

"적 선수 하나를 침묵시키고 파괴합니다."

첫 Effect에서 선택한 적 선수를
두 번째 DESTROY에서도 SAME_TARGET으로 사용한다.

Resolution Context를 사용한다.

==================================================
28. 이전 효과 결과 참조
===============

다음 표현도 지원할 수 있게 구조를 만든다.

"파괴한 카드"

"리타이어시킨 카드"

"방금 선택한 카드"

"그 카드"

"마지막으로 소환된 카드"

이를 Resolution Context의 reference로 연결한다.

예:

LAST_TARGET
LAST_DESTROYED_CARD
LAST_RETIRED_CARD
LAST_SUMMONED_CARD

==================================================
29. 조건 표현
=========

지원되는 Condition Registry 내에서
다음과 같은 표현도 분석할 수 있게 한다.

"만약"

"~라면"

"~일 경우"

예:

"이 카드가 필드의 유일한 선수라면 골드 1 획득"

→ condition ONLY_ALLY_WRESTLER_ON_BOARD
→ ADD_GOLD 1

"이 효과로 선수를 리타이어시켰다면 카드 1장 드로우"

→ condition TARGET_RETIRED_BY_THIS_EFFECT
→ DRAW 1

지원하지 않는 조건은 억지로 변환하지 않는다.

모든 Action에 value를 요구한다면 수정한다.

Effect Schema Registry를 사용해
Action별 필수 필드를 정의한다.

예:

ADD_GOLD

필수:
amount

target:
불필요

DRAW

필수:
count

target:
불필요

DAMAGE

필수:
target
amount

BUFF

필수:
target
stat value

DESTROY

필수:
target

SILENCE

필수:
target

ADD_KEYWORD

필수:
target
keyword

이 방식으로 validation한다.

==================================================
31. 키워드만 적혀 있는 카드도 지원
=====================

카드 효과 텍스트가 단순히:

"도발"

"회피"

"기습"

"러쉬"

처럼 키워드 하나뿐일 수도 있다.

이 경우 Trigger Effect로 만들 필요 없이
CardDefinition의 keywords에 해당 Keyword를 등록하는 방식으로
분석 결과를 제안할 수 있게 한다.

예:

입력:

"도발"

분석:

✓ 기본 키워드
TAUNT

[적용]

→ card.keywords에 TAUNT 추가

반면:

"등장: 자신에게 도발을 부여합니다."

는

ENTER_FIELD
→ ADD_KEYWORD
→ SELF
→ TAUNT

로 구분한다.

==================================================
32. 직접 표시용 텍스트는 유지
==================

관리자가 작성한:

"등장: 골드 1 획득"

같은 원본 문장은 플레이어에게 보여줄 text로 유지해도 된다.

하지만 게임 로직은 Structured Effect를 사용한다.

자연어 text와 실제 실행 effects가 서로 다른 역할임을 유지한다.

==================================================
33. 분석 결과 화면 개선
===============

"적용 불가"라고만 표시하지 마.

분석 결과를 상세하게 보여준다.

예:

입력:

"등장: 골드 1 획득"

결과:

✓ Trigger: 등장
✓ Action: 현재 골드 획득
✓ Amount: 1G

상태:
적용 가능

또는:

입력:

"등장: 적 선수 하나의 시간을 역전합니다."

결과:

✓ Trigger: 등장
✓ Target: 적 선수 하나

✗ 인식하지 못한 Action:
"시간을 역전합니다"

상태:
적용 불가

필요한 신규 Effect Handler가 존재할 수 있습니다.

이렇게 표시한다.

==================================================
34. 부분 분석을 잘못 저장하지 말 것
======================

문장 일부만 분석됐다고
인식된 부분만 몰래 저장하면 안 된다.

예:

"등장: 적 선수에게 피해 2를 주고 시간을 멈춥니다."

분석:

✓ DAMAGE 2

✗ "시간을 멈춥니다"

→ 전체 효과는 부분 분석 상태.

관리자가 직접 미지원 부분을 제거하거나 수정하기 전에는
[분석 결과 적용]을 비활성화한다.

==================================================
35. 분석 결과 GUI 수정
================

분석 결과가 약간 잘못됐을 경우
관리자가 코드나 JSON을 수정하지 않고 GUI로 고칠 수 있게 한다.

예:

[피해 ▼]

수정 후 다시 validation하고

소환

==================================================
38. 기존 게임 규칙 보호
===============

다음 기존 게임 규칙도 그대로 유지한다.

기본 턴 시작 골드는 개인 턴에 따라:

1G
2G
3G
4G
5G
6G

까지 증가하고
7턴 이후 기본 골드는 계속 6G.

카드 효과 ADD_GOLD로 인해
현재 골드가 6G를 초과하는 것은 허용.

RETIRE와 DESTROY는 별개.

REMOVE_FROM_GAME은 묘지로 보내지 않음.

생성된 카드와 Champion Token도 구분.

Champion Token은 무작위 생성 pool에서 제외.

이 규칙들을 Analyzer 수정 과정에서 변경하지 마.

39. 완료 조건
=========

최종적으로 관리자가 카드 관리 화면에 자연어로:

"등장: 골드 1 획득"

"등장: 적 선수 하나에게 피해 2"

"등장: 자신에게 +2/+2"

"등장: 카드 1장 드로우"

"등장: 적 선수 하나를 침묵시키고 파괴"

"등장: 자신에게 러쉬 부여"

"도발"

"회피"

등 일반적인 KO 카드 효과를 입력했을 때

기존 Registry가 지원하는 효과라면:

자연어 분석

↓

Structured Effect / Keyword 변환

↓

분석 결과 표시

↓

적용 가능

↓

게임에서 실제 작동

해야 한다.

새로운 카드마다 별도의 카드 이름 기반 코드를 작성하면 안 된다.

기존 Registry로 표현할 수 없는 완전히 새로운 메커니즘만
신규 Effect Handler / Trigger / Target / Condition / Value Resolver 추가가 필요하다.

정상 작동하는 게임 엔진을 불필요하게 대규모 리팩터링하지 마.
