KO CARD GAME — SEV-1 ONLINE MATCH USER TRAP / STALE ACTIVE MATCH RECOVERY

현재 온라인 매치에 치명적인 장애가 있다.

실제 증상:

1. 온라인 매치가 잡히면 간헐적으로 인증 상태를 확인하지 못했다고 표시됨.
2. 매치 화면이 RECONNECTING 상태에 고착됨.
3. 턴 타이머가 00:00이 되고 턴 종료 버튼이 작동하지 않음.
4. 게임이 이미 끝났는데도 "진행 중인 매치가 있습니다"가 계속 표시됨.
5. 이미 온라인 매치를 한 번 플레이한 일부 사용자는
   active match 상태 때문에 메인 화면으로 돌아가지도 못함.
6. 새로고침/재로그인해도 기존 매치로 다시 끌려가며 탈출할 수 없는 경우가 있음.

이것은 SEV-1 장애다.

이번 작업은 다른 게임 기능을 수정하지 말고
오직 다음 lifecycle을 끝까지 해결한다.

AUTH
→ ACTIVE MATCH LOOKUP
→ WS TICKET
→ WEBSOCKET
→ RECONNECT
→ AUTHORITATIVE SNAPSHOT
→ TURN
→ MATCH FINISH
→ ACTIVE MATCH CLEANUP
→ MAIN RETURN

==================================================
0. 최우선 목표 — 이미 갇힌 사용자부터 복구
==================================================

현재 이미 stale active match 때문에
메인으로 돌아가지 못하는 사용자가 존재한다.

다음 배포 후 해당 사용자가 다시 접속했을 때
수동 DB 수정 없이 자동 복구되어야 한다.

로그인 후 active match를 조회했을 때:

MATCH = FINISHED
→ active match로 취급하지 않음
→ stale player-match/session reference 정리
→ 메인 진입 허용

MATCH = ABORTED
→ 동일

MATCH = CANCELLED
→ 동일

MATCH = EXPIRED
→ 동일

MATCH NOT FOUND
→ stale local/server reference 정리
→ 메인 진입 허용

절대:
끝난 match가 있다는 이유로
사용자를 온라인 매치 화면에 강제로 가두지 말 것.

1. ACTIVE MATCH의 정의부터 정확히 고칠 것
==================================================

active match는 단순히:

"player와 연결된 가장 최근 match가 존재한다"

가 아니다.

실제로 재개 가능한 상태만 active다.

예:

MATCHMAKING
READY
PLAYING
RECONNECTABLE

등 현재 실제 enum 기준.

반드시 제외:

FINISHED
ABORTED
CANCELLED
EXPIRED
FORFEITED
기타 terminal state

실제 enum을 검사한 뒤 사용.

새 status를 추측해서 추가하지 말 것.

3. ROUTE GUARD로 사용자를 가두지 말 것
==================================================

현재 다음 같은 구조가 있는지 확인:

if (activeMatch) {
  navigate("/online/match/" + id)
}

이때 activeMatch가 stale이면
사용자가 영원히 빠져나오지 못한다.

정상:

server confirms resumable active match
→ resume 가능

server says terminal/not found
→ clear stale state
→ Main

server request failed
→ "확인 실패" 상태
→ 재시도 가능
→ 사용자를 영구 match redirect하지 않음

AUTH/API 장애를
"active match 존재"로 취급하면 안 된다.

5. WebSocket reconnect 수정
==================================================

현재 match 화면:

RECONNECTING
00:00
턴 종료 disabled

에서 계속 고착될 수 있다.

반드시 trace:

HTTP auth session
→ WS ticket 발급
→ socket connect
→ disconnect
→ reconnect request
→ NEW ticket
→ socket reconnect
→ match subscription
→ authoritative snapshot
→ legal actions
→ timer

one-time WS ticket을
재접속 때 재사용하고 있다면 수정.

재접속 시
유효한 HTTP session 기준으로
새 ticket을 받아야 한다.

6. RECONNECT 성공 기준
==================================================

socket open만으로 reconnect 성공 처리 금지.

성공 조건:

socket connected
AND
match joined/subscribed
AND
authoritative GameState snapshot received
AND
player identity restored
AND
current turn restored
AND
legal actions restored

그때만:

RECONNECTING → PLAYING

==================================================
8. 재접속 실패 시 탈출구
==================================================

PLAYING match가 실제 서버에 존재하지만
재접속이 계속 실패할 수 있다.

사용자를 영구 화면에 가두지 말 것.

일정 횟수/시간 실패 후 UI:

[다시 연결]
[매치 포기하고 메인으로]

제공.

중요:

"메인으로" 버튼이
client local state만 삭제하면 안 된다.

매치가 실제 PLAYING이면
server-authoritative abandon/forfeit endpoint를 호출.

서버:

verify player belongs to match
→ finalize match as appropriate
→ cleanup active references
→ return success

그 후 Main.

==================================================
9. 이미 종료된 매치는 그냥 Main으로
==================================================

사용자가 재접속했을 때 server match status가 이미 terminal이면:

forfeit 호출할 필요 없음.

그냥 stale references cleanup
→ Main.

10. MATCH FINALIZE를 공통 함수로 통합
==================================================

다음 종료 경로를 조사:

normal win
normal loss
Champion defeat
turn/game finish
forfeit
disconnect timeout
manual leave
server cancellation

어떤 경로에서도 cleanup이 빠지면 안 된다.

가능하면 공통 server function:

finalizeMatch(...)

개념으로 통합.

반드시 idempotent.

같은 match에 두 번 호출돼도:

reward 두 번 지급 금지
result 두 번 기록 금지
quest 두 번 증가 금지
cleanup crash 금지

12. STALE ACTIVE MATCH SELF-HEAL
==================================================

로그인/메인 bootstrap 때:

activeMatchId 존재

→ authoritative match fetch

CASE A:
match PLAYING and player belongs
→ resume option

CASE B:
match FINISHED/terminal
→ stale link cleanup
→ Main

CASE C:
match does not exist
→ stale link cleanup
→ Main

CASE D:
player does not belong
→ invalid stale reference cleanup
→ Main

CASE E:
temporary API failure
→ destructive cleanup 금지
→ retry
→ Main 자체를 영구 차단하지 말 것

==================================================
14. 오래된 PLAYING 매치 처리
==================================================

서버 crash 등으로
DB에 PLAYING이 영원히 남은 orphan match가 있을 수 있다.

현재 match heartbeat/timestamps를 검사.

합리적인 existing timeout policy가 있으면 사용.

없다면 새 timeout을 임의로 짧게 만들지 말고
현재 architecture에 맞는 abandoned/stale determination을 구현.

예:

both players disconnected
AND
last activity older than official reconnect grace
→ finalize/expire

단 정상 플레이 중인 match를 자동 종료하면 안 된다.

25. 완료 선언 금지 조건
==================================================

아래가 해결되기 전까지 완료라고 하지 말 것.

- 이미 끝난 매치 때문에 사용자가 메인에 못 가는 문제 해결
- terminal match가 active로 조회되지 않음
- stale match reference 자동 self-heal
- real PLAYING match reconnect 가능
- reconnect 후 authoritative turn state 복구
- End Turn 정상
- reconnect 실패 시 안전한 abandon → Main 제공
- 모든 match 종료 경로에서 cleanup 수행
- normal finish 후 재로그인해도 active-match warning 없음
- Normal User E2E 또는 명확한 UNVERIFIED
- Production DB 강제 수정 없음

핵심:

이번 버그의 가장 위험한 부분은
"온라인 매치가 깨진 것"보다
"한 번 온라인 매치를 한 사용자가 stale active match 때문에
게임 전체에서 빠져나오지 못하는 것"이다.

따라서 가장 먼저
이미 갇힌 사용자를 자동 복구할 수 있는
stale active match self-healing을 구현하고,

그 다음
Auth → WS reconnect → turn restore → match finalize → cleanup
전체 lifecycle을 고쳐라.
