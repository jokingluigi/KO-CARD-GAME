KO CARD GAME — CRITICAL NORMAL-USER AUTHORIZATION REGRESSION FIX

증상:
- 동시 팩까기(Bulk Pack Open)가 Admin 계정에서만 작동
- 퀘스트 진행도 Admin 계정에서만 작동
- 일반 로그인 계정에서는 정상적인 플레이 기능이 막힘

이건 UI 문제가 아니라 권한/서버/RLS/플레이어 식별 경로가 잘못 연결된 치명적인 버그다.

정상 규칙:
- Admin 권한은 콘텐츠 관리/운영 기능에만 필요
- 일반 로그인 사용자는 자기 계정의 정상 게임 기능을 사용할 수 있어야 함
- 팩 개봉, 카드 지급, 퀘스트 진행/완료/보상 수령은 일반 플레이어 기능
- 일반 유저에게 Admin 권한을 부여해서 해결 금지
- RLS 전체 disable 금지
- service role key를 client에 노출 금지
- Production DB 직접 수정 금지

2. 의심 지점 전부 확인
==================================================

다음 중 실제 원인을 evidence로 특정:

- gameplay endpoint에 requireAdmin/adminOnly가 잘못 붙음
- 일반 플레이 기능이 /api/admin/* route를 재사용
- server handler가 isAdmin일 때만 mutation 수행
- Admin은 trusted server/service-role path, Normal은 client direct DB write
- Supabase RLS가 admin only 또는 owner 조건 오류
- auth.uid()와 profile/player id mapping 불일치
- RPC EXECUTE permission이 admin에만 있음
- 일반 계정 profile/bootstrap row 누락
- bulk open만 admin implementation 재사용
- quest event persistence가 admin/test helper에만 연결
- client에서 isAdmin일 때만 handler 호출
- normal user mutation은 성공하지만 cache invalidate가 admin query에만 연결
- dev/prod schema 또는 RLS drift

추측으로 한 군데만 수정하지 말 것.

4. 서버 authoritative 유지
==================================================

일반 유저에게 기능을 열면서 client를 신뢰하면 안 됨.

Bulk Pack Open:
client는 "내 pack X를 N개 열기"만 요청.

server가:
- authenticated user 확인
- pack ownership/count 확인
- PackDefinition 확인
- authoritative reward/RNG
- pack decrement
- collection increment
- transaction
- authoritative result 반환

client가 reward 내용을 임의 제출 금지.

Quest:
canonical Action/Event
→ server/game engine가 qualifying 여부 판정
→ quest progress
→ dedupe
→ persistence

client가 progress=999 같은 값을 직접 제출해서 신뢰 금지.

==================================================
5. Bulk Pack Open 정상화
==================================================

현재 UI의 실제 bulk 옵션(예: 5/10/ALL)을 조사해서 그대로 지원.

일반 로그인 사용자도:
- 자기 보유 팩 개봉 가능
- 실제 보유 수량보다 많이 요청하면 reject
- 다른 사용자 팩 접근 reject
- unauthenticated reject

가능하면 한 logical operation으로 atomic 처리.

==================================================
6. Bulk transaction / idempotency
==================================================

중간 실패로:
- pack만 차감
- reward만 지급
같은 half-state 금지.

DB transaction 또는 현재 infra에 맞는 atomic/idempotent pattern 사용.

더블 클릭/network retry/reconnect:
같은 operationId 재처리 시
- 추가 pack 차감 0
- 추가 reward 0

21. 완료 조건
==================================================

1. 일반 로그인 계정에서 Bulk Pack Open 정상.
2. Admin 권한 없이 자기 pack만 개봉 가능.
3. pack/reward atomic + idempotent.
4. 일반 로그인 계정에서 canonical Quest progress 정상.
5. same event 중복 진행 없음.
6. Quest completion/claim도 정상.
7. Admin은 관리 기능에만 필요.
8. 일반 유저에게 Admin 권한을 부여하지 않음.
9. RLS 전체 disable 없음.
10. service-role client 노출 없음.
11. 다른 사용자 inventory/quest 접근 차단.
12. 같은 auth bug를 공유하는 플레이어 기능 audit.
13. Production 데이터 mutation 없음.
14. 반드시 Normal Player 계정 결과를 따로 보고.

핵심:
"Admin 계정에서는 되니까 기능이 정상"이 아니다.

일반 사용자가 게임을 플레이하며 사용하는 기능은
AUTHENTICATED_PLAYER 권한으로 정상 작동해야 한다.

Bulk Pack Open과 Quest Progress가 Admin에서만 된다면
authorization architecture가 잘못 연결된 것이므로
원인을 찾아 일반 플레이어 경로를 정식으로 복구하라.
