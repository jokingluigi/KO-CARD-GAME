==================================================
현재 신고된 문제
==================================================

뒷정리맨 효과가 정상적으로 발동하지 않는다.

과거에는 다음 현상도 실제로 관찰됐다.

뒷정리맨을 플레이:

2/2 → 2/4

즉 뒷정리맨이
자신이 만든 "다음 카드용 예약 버프"를
자기 자신에게 즉시 소비했다.

그 후 다음에 플레이한 선수:

스카드 3/1

은 아무 버프도 받지 않았다.

최근에는 효과 자체가
정상적으로 발동하지 않는 증상도 신고됐다.

따라서 현재 실제 구현을 다시 확인해서
정확한 root cause를 수정해야 한다.

==================================================
1. 먼저 공식 효과 확인
==================================================

뒷정리맨의 현재 authoritative effect를 확인한다.

우선순위:

1. 현재 CardDefinition
2. effectConfig / SCRIPT / Structured Effect
3. Admin 저장 데이터
4. seed/catalog source
5. 필요한 경우 git history

카드 설명과 실제 effect config를 비교한다.

효과 수치나 대상은 추측하지 마.

예를 들어 공식 설명이:

"다음에 플레이하는 선수에게 +0/+2"

라면 그 규칙을 사용한다.

실제 공식 수치가 다르면
공식 definition을 기준으로 테스트한다.

==================================================
2. 이번 작업의 핵심 조사 지점
==================================================

특히 다음 경로를 추적한다.

PLAY_FROM_HAND
→ 뒷정리맨 effect trigger
→ queued effect 생성
→ queued effect 등록 시점
→ 다음 PLAY_FROM_HAND event
→ eligibility 검사
→ buff 적용
→ queued effect consume

확인해야 할 핵심:

A.
queued effect가 생성된 바로 그 PLAY_FROM_HAND event를
다시 잡아서 뒷정리맨 자신에게 적용되는가?

B.
effect가 생성되기 전에 listener가 등록되어
현재 event까지 consume하고 있는가?

C.
sourceInstanceId와 targetInstanceId 구분이 잘못됐는가?

D.
"다음 카드" 조건이
다음 event가 아니라 현재 event를 포함하고 있는가?

E.
queued effect가 너무 일찍 consume되어
실제 다음 선수에게 도달하지 못하는가?

F.
최근 변경으로 queued effect 자체가
등록되지 않는 상태가 되었는가?

==================================================
3. 카드 이름 hardcoding 금지
==================================================

다음과 같은 수정 금지:

if (card.name === "뒷정리맨") ...

generic queued effect / trigger timing 문제라면
공통 시스템을 수정한다.

단 다른 카드들의 기존 정상 queued effect를
깨뜨리면 안 된다.

==================================================
4. 기대 동작
==================================================

공식 effect가
"다음에 플레이하는 유효 선수에게 버프"
형태라면 기대 흐름은 다음이다.

뒷정리맨 PLAY_FROM_HAND

→ 뒷정리맨 자신의 등장/효과 resolution
→ queued effect 등록

중요:

현재 플레이 중인 뒷정리맨 자신은
그 queued effect의 대상이 아니다.

그 후 같은 플레이어가
다음 유효 WRESTLER를 PLAY_FROM_HAND

→ 그 선수에게 공식 buff 적용
→ queued effect consume

그 다음 선수에는
같은 버프가 다시 적용되지 않는다.

6. 필수 Regression Test — 자기 자신 버프 금지
==================================================

TEST A

초기 상태:

뒷정리맨이 손에 있음.

뒷정리맨 PLAY_FROM_HAND.

기대:

뒷정리맨 자신의 공격/체력은
공식 base/effect에 없는 추가 버프를 받지 않는다.

과거 버그처럼:

2/2 → 2/4

가 되어서는 안 된다
(공식 카드 효과 자체가 자기 버프를 포함하지 않는다는 전제에서).

그리고 queued effect는
정상적으로 pending 상태여야 한다.

==================================================

TEST B

예:

UI 숫자만 바뀌는 것이 아니라
실제 GameState의 stats가 변경되어야 한다.

8. 필수 Regression Test — 1회만 소비
==================================================

TEST C

뒷정리맨
→ 다음 선수 A
→ 그 다음 선수 B

기대:

A:
buff 적용

B:
동일 queued buff 추가 적용 없음

queued effect:
A에서 정확히 한 번 consume.

==================================================
9. 유효하지 않은 event가 끼어 있을 경우
==================================================

공식 effect가 "다음에 내는 선수"라면:

뒷정리맨
→ Technique 사용
→ 다음 WRESTLER

같은 상황에서
Technique이 queued effect를 소비하면 안 된다.

또:

SUMMON
REVIVE
Champion Token deploy

가 "PLAY_FROM_HAND WRESTLER"가 아니라면
이를 다음 카드로 잘못 소비하지 마.

현재 게임의 공식 trigger semantics를 따른다.

==================================================
11. 턴을 넘기는 경우
==================================================

공식 카드 설명에서
"이번 턴" 제한이 없다면

뒷정리맨
→ 턴 종료
→ 상대 턴
→ 다시 내 턴
→ 다음 WRESTLER

에서도 효과가 유지되어야 한다.

반대로 공식 효과가
"이번 턴 다음 선수"라면
턴 종료 시 만료되어야 한다.

임의로 결정하지 말고
authoritative effect text/config를 따른다.

13. 회귀 방지
==================================================

뒷정리맨을 고치면서
기존 queued/delayed effect 전체가 깨지지 않는지 확인.

최소 관련 테스트:

- queued effect 등록
- owner filtering
- PLAY_FROM_HAND filtering
- consume once
- source event 제외
- next matching event
- turn transition serialization

기존 정상 카드 이름을 hardcode해서
테스트할 필요는 없다.

generic fixture 사용 가능.
