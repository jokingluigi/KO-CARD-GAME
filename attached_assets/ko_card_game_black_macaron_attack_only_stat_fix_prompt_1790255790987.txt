KO CARD GAME — BLACK MACARON STAT CHANNEL FIX
"카드 개수만큼 공격력만 증가"인데 체력도 같이 증가하는 버그 수정

현재 버그:
블랙마카롱 효과를 기존의
"조건에 맞는 카드 개수만큼 공격력과 체력이 증가"
에서
"조건에 맞는 카드 개수만큼 공격력만 증가"
로 변경했는데,
실제 Runtime에서는 여전히 체력도 같이 증가한다.

목표:
블랙마카롱의 최신 Source Text / 최신 저장 effect / Analyzer output / Runtime을 추적해서
체력 증가가 남는 정확한 원인을 찾고,
최종적으로 해당 효과가 공격력만 증가하도록 수정한다.

중요:
단순히 UI 표시만 고치지 말고,
실제 GameState에서 health 변화가 0이어야 한다.

다음 중 어디서 health가 살아남는지 확인:

A. Source Text는 공격력만인데 Analyzer가 여전히 attack + health 생성
B. Analyzer는 attack only인데 Development stored effect가 stale +X/+X
C. stored effect는 attack only인데 runtime BUFF default가 health에도 같은 값을 적용
D. count-based value resolver가 attack/health 둘 다 반환
E. generic stat modifier helper가 omitted health를 attack 값으로 fallback

G. reload/reconnect hydration 시 legacy health modifier가 복원

==================================================
2. 공식 블랙마카롱 의미
==================================================

최신 Source Text를 Development에서 다시 읽고,
실제 문구가 "공격력만" 증가로 되어 있는지 확인.

공식 semantics:

- 조건에 맞는 카드 수를 계산
- 그 count만큼 SOURCE의 attack만 증가
- source health 변화 = 0
- source maxHealth 변화 = 0

예:

matching count = 3
Black Macaron before = 4 ATK / 6 HP

Expected after:
7 ATK / 6 HP

절대:
7 ATK / 9 HP
금지.

==================================================
3. Canonical Effect Shape
==================================================

현재 shared Effect Registry 구조에 맞는 canonical 표현을 사용.

예시 개념:

action = BUFF
values.attack = COUNT(...)
values.health = 0 또는 health field omitted

중요:
프로젝트의 canonical semantics가
"health field omitted = no health change"라면
health: 0을 억지로 넣지 말고 omitted semantics를 사용.

반대로 validator/runtime가 explicit zero를 요구하면
shared contract에 맞춰 사용.

핵심:
공격력 channel과 체력 channel이 독립적이어야 한다.

==================================================
4. Generic Stat Channel 규칙
==================================================

이번 수정은 블랙마카롱 카드만의 임시 예외가 아니라,
모든 stat effect에서 아래 invariant를 보장해야 한다:

- attack만 지정 → attack만 변경
- health만 지정 → health만 변경
- maxHealth만 지정 → maxHealth만 변경
- attack + health 둘 다 지정 → 둘 다 변경
- omitted stat field → 변화 없음
- 0 → 변화 없음

특히 dynamic value/count-based resolver에서도 동일.

==================================================
5. Count-based Value Resolver 확인
==================================================

조건에 맞는 카드 수가 N일 때:

attack delta = N
health delta = 0

다음 패턴이 있으면 제거/수정:

`{ attack: count, health: count }`

또는:

`health = values.health ?? values.attack`

또는:

`if buff amount = count then apply count to all mutable stats`

같은 fallback.

Attack/Health value resolver는 독립 channel이어야 한다.

==================================================

1. 블랙마카롱 최신 Source Text가 공격력-only라면 실제 Runtime도 attack-only.
2. matching count N → attack +N.
3. currentHealth 변화 0.

6. count/dynamic value resolver도 stat channel 독립.
7. stale stored effect가 원인이면 Development에서 effect field만 안전 수정.
8. UI도 체력 증가를 표시하지 않음.
9. AI compiler도 "공격력만"을 정확히 attack-only로 해석.
10. unrelated +X/+X, health-only 효과 회귀 없음.
11. Production mutation 없음.
12. tests/build/typecheck/diff 결과 보고.

블랙마카롱 한 장을 이름으로 예외 처리하지 말고,
"지정된 stat channel만 변경한다"는 generic runtime invariant를 바로잡은 뒤 멈춰라.
