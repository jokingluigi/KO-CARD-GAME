==================================================
PART A — /api/auth/me SERVER HANG
==================================================

1. request lifecycle 추적

/api/auth/me에 대해 최소 다음 구간을 계측한다.

REQUEST_RECEIVED
AUTH_MIDDLEWARE_ENTER
AUTH_MIDDLEWARE_EXIT
SESSION_VERIFY_START
SESSION_VERIFY_END
USER_LOOKUP_START
USER_LOOKUP_END
RESPONSE_SENT

Production secret/token/user data는 log에 남기지 마.

각 단계의 duration만 확인.

==================================================
2. route handler 자체 확인
==================================================

확인:

- handler가 모든 branch에서 return/response하는가
- await가 resolve되지 않는 branch가 있는가
- Promise를 생성하고 await하지 않는가
- next() / response.end()가 빠진 branch가 있는가
- middleware가 request를 소비하고 다음으로 안 넘기는가
- exception이 catch되었지만 response가 없는가
- Supabase/auth SDK call이 무기한 대기 가능한가
- DB profile lookup이 무기한 대기 가능한가

==================================================
3. authenticated / unauthenticated 모두 확인

/api/auth/me는 최소 다음 둘 다
유한 시간 안에 응답해야 한다.

A. valid authenticated session
→ 200 + public user/auth payload

B. no valid session
→ 현재 공식 contract의 401 또는 unauthenticated response

"로그인 안 됨"은 pending 상태가 아니다.

==================================================
4. upstream dependency hang 확인

auth/me가 외부 auth/DB dependency를 기다린다면:

- connection pool
- Supabase request
- token verification
- database profile fetch
- DNS/network call

중 어디서 block되는지 확인.

근거 없이 Supabase나 Render 탓으로 단정하지 마.

==================================================
5. timeout safety

외부 dependency가 실제로 hang할 수 있다면
server-side bounded timeout을 둔다.

단:

timeout
→ request를 영원히 pending

이 아니라

timeout
→ controlled error response

여야 한다.

인증 실패와 infrastructure timeout을
같은 "로그아웃 상태"로 위장하지 마.

예:

401 = 실제 unauthenticated
503/504 equivalent = auth service temporarily unavailable

현재 API error conventions를 따른다.

==================================================
6. response once

race:

timeout response
+
late upstream response

가 동시에 발생해
headers already sent 같은 문제가 생기지 않게 한다.

request당 response exactly once.

완료 조건
==================================================

1. /api/auth/me가 모든 코드 경로에서 응답을 종료한다.
2. unauthenticated 상태도 pending이 아니라 정상 응답한다.
3. upstream hang은 bounded error로 종료된다.
4. frontend가 인증 오류 시 무한 spinner에 머물지 않는다.
5. Retry가 가능하다.
6. infrastructure timeout 때문에 valid session을 삭제하지 않는다.
7. 반복 auth 테스트에서 forever pending이 0건이다.
8. 다른 게임 기능은 수정하지 않는다.

이 문제만 수정하고 멈춰라.
