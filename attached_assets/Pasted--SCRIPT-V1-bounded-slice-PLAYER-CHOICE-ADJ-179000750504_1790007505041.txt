현재 SCRIPT_V1 첫 bounded slice 구현은 확인했다.

하지만 이 작업은 아직 전체 목표 완료가 아니다.

현재 보고에서:

- PLAYER_CHOICE
- ADJACENT_EMPTY_SLOTS
- SAME_TARGET

Script selector/continuation이 아직 거부되고 있고,
범용 Effect Script 목표의 핵심 capability들이 일부만 구현되어 있다.

이번 작업에서는 "first bounded slice"로 다시 멈추지 말고,
기존 SCRIPT_V1 위에서 다음 핵심 2차 기능을 실제 end-to-end로 완성해라.

==================================================
최우선 원칙
==================================================

기존에 구현된 다음은 유지:

- STRUCTURED_EFFECTS_V1 backward compatibility
- SCRIPT_V1
- Runtime OpenAI/provider calls = 0
- Admin Generate 1회당 provider call 최대 1회
- 서버측 Script validation
- executable content 거부
- Production DB 직접 수정 금지
- Action → Event → GameState
- deterministic RNG
- Online server-authoritative

기존 테스트를 깨지 마.

==================================================
1. Script FILTER 구현
==================================================

SELECT 결과에 generic FILTER를 사용할 수 있게 한다.

최소:

- cardType
- tagsAny
- tagsAll
- tagsNone
- keyword
- cost
- attack
- health
- isToken
- isGenerated
- isChampionToken

비교:

EQ
NE
LT
LTE
GT
GTE

지원.

기존 tag helper를 재사용.

카드 이름 hardcoding 금지.

==================================================
2. SORT + TAKE
==================================================

다음 효과를 Script로 표현할 수 있어야 한다.

"상대 손에서 비용이 가장 높은 카드 1장"

예:

SELECT OPPONENT_HAND
→ SORT currentCost DESC
→ TAKE 1

최소 정렬 stat:

- cost
- attack
- health

ASC / DESC 지원.

동률 처리 규칙은 deterministic해야 한다.

==================================================
3. RANDOM selector
==================================================

SELECT/FILTER 결과에서 RANDOM selection을 지원한다.

반드시 기존 deterministic RNG 사용.

Math.random() 금지.

최소:

- cardPool
- hand
- deck
- board
- graveyard

에서 사용 가능.

Online에서 hidden zone RANDOM은 서버에서만 resolution.

클라이언트가 상대 hand/deck identity를 알 필요가 없어야 한다.

==================================================
4. ADJACENT_EMPTY_SLOTS
==================================================

SCRIPT_V1에서도 source card 기준
좌우 인접 빈 슬롯을 표현 가능하게 한다.

공식 semantics:

- 왼쪽 인접 슬롯이 존재하고 비어 있으면 대상
- 오른쪽 인접 슬롯이 존재하고 비어 있으면 대상
- 최대 2개
- 한쪽만 비면 1개
- 둘 다 차 있으면 0개
- edge slot에서는 존재하는 쪽만

SUMMON과 조합 가능해야 한다.

==================================================
5. Step Result Reference
==================================================

SAME_TARGET을 단순 특례로 유지하지 말고
가능하면 generic Script step-result reference를 구현한다.

예:

{
  "id": "summon-allies",
  ...
}

다음 step:

target/resultSource = "summon-allies"

처럼 앞 단계의 실제 성공 결과를 참조.

최소 지원:

- 성공적으로 SUMMON된 CardInstance들
- 실제 DAMAGE target
- 실제 BUFF target
- 실제 DESTROY/RETIRE target
- selector 결과

다른 resolution의 결과가 섞이면 안 된다.

resolution 종료 후 cleanup.

==================================================
6. SAME_TARGET backward compatibility
==================================================

기존 Structured Effect의 SAME_TARGET 동작은 유지한다.

SCRIPT_V1에서는 generic result reference로 normalize할 수 있다면 그렇게 한다.

기존 카드 데이터 migration은 하지 마.

==================================================
7. PLAYER_CHOICE Script continuation
==================================================

가장 중요하다.

SCRIPT_V1 selector가 PLAYER_CHOICE를 요구하면:

Script 실행
→ valid target 계산
→ targetingState
→ client target selection
→ SELECT_EFFECT_TARGET
→ serializable continuation
→ Script resume

까지 실제로 작동해야 한다.

UI가 Script logic을 소유하지 않는다.

GameState/continuation이 authoritative.

새로고침/reconnect/resync 후에도
pending PLAYER_CHOICE가 복구 가능해야 한다.

==================================================
8. PLAYER_CHOICE 후 Result 유지
==================================================

예:

Step A:
PLAYER_CHOICE로 적 선수 1장 선택

Step B:
그 선택 대상에게 DAMAGE

Step C:
같은 대상에게 ADD_KEYWORD

가 가능해야 한다.

continuation 전/후에도 step result가 유지되어야 한다.

==================================================
9. SUMMON → 후속 효과
==================================================

아래 exact effect가 SCRIPT_V1으로 완전히 표현되고 실행되어야 한다.

"등장: 이 카드 양옆의 빈 슬롯에 각각 무작위 선수 카드 1장을 소환하고,
그렇게 소환된 선수들에게 도발을 부여한다."

공식 의미:

Trigger:
ENTER_FIELD

Step 1:
source 기준 ADJACENT_EMPTY_SLOTS

각 빈 슬롯마다:
cardPool
→ FILTER cardType=WRESTLER
→ RANDOM 1
→ SUMMON

각 슬롯은 독립 deterministic random.

Step 2:
Step 1에서 실제 성공적으로 SUMMON된 CardInstance 전체
→ ADD_KEYWORD TAUNT

둘 다 비었으면 최대 2장.
한쪽이면 1장.
둘 다 차면 0장.

0장이어도 exception 없음.

==================================================
10. 상대 패 최고 비용 카드 변경
==================================================

다음 exact effect를 실제 Script로 지원:

"공격할 때 상대 손에서 비용이 가장 높은 카드 1장의 비용을 2 증가시킨다."

구성:

Trigger
→ SELECT OPPONENT_HAND
→ SORT cost DESC
→ TAKE 1
→ MODIFY_COST +2

hidden information은 서버에서만 처리.

상대 클라이언트에 다른 패 identity가 노출되면 안 된다.

==================================================
11. 무덤 랜덤 부활
==================================================

다음 exact effect 지원:

"내 무덤에서 비용 3 이하 선수 하나를 무작위로 부활시킨다."

SELECT MY_GRAVEYARD
→ FILTER cardType=WRESTLER
→ FILTER cost <=3
→ RANDOM 1
→ REVIVE

기존 REVIVE semantics를 재사용.

REVIVE가 일반 ENTER_FIELD trigger를 잘못 발생시키지 않도록 한다.

==================================================
12. Event History Query
==================================================

최소 CURRENT_TURN / CURRENT_RESOLUTION 범위에서
event history를 query할 수 있게 한다.

목표 effect:

"이번 턴에 RETIRE된 선수들의 공격력 합만큼 상대 챔피언에게 피해"

event snapshot/attribution을 사용.

현재 event data에 없는 값을 추측하지 마.

==================================================
13. Queued Effect
==================================================

기존 queuedEffect 구조를 일반화해서 최소:

"다음에 내가 사용하는 Technique의 비용을 0으로 만든다."

같은 effect를 Script로 표현 가능하게 한다.

새 scheduler를 만들지 말고
기존 event/queued continuation을 재사용.
