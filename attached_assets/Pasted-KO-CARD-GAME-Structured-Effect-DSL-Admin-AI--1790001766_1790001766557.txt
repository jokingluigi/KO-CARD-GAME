KO CARD GAME의 Structured Effect DSL과 Admin AI 효과 생성기를 확장해줘.

==================================================
현재 문제
==================================================

Production Admin의 AI 효과 생성 기능은 정상 작동 중이다.

현재 자연어 효과를 입력하면:

POST /api/admin/effects/generate

→ OpenAI
→ 현재 KO Effect DSL로 변환
→ schema/registry validation
→ READY 또는 NEEDS_CLARIFICATION
→ Admin preview
→ 관리자가 적용
→ 기존 저장 버튼으로 DB 저장

구조다.

아래와 같은 효과를 생성하려 했더니 현재는 NEEDS_CLARIFICATION이 반환된다.

의도하는 효과 예시:

"등장: 이 카드 양옆의 빈 슬롯에 각각 무작위 선수 카드 1장을 소환하고,
그렇게 소환된 선수들에게 도발을 부여한다."

현재 AI가 반환한 clarification:

1.
'무작위 선수 카드'를 어떤 풀에서 뽑아야 하는가?
현재 SUMMON / GENERATE는 고정 definitionRef 중심이다.

2.
양옆 빈 슬롯에 '각각' 소환하는 방식이 현재 DSL에서 명확하지 않다.

3.
직전에 소환된 카드들을 후속 효과의 대상으로 참조하는 표준 DSL이 없다.

이걸 특정 카드 전용 코드로 해결하지 말고,
KO CARD GAME에서 앞으로 여러 카드가 재사용할 수 있는
범용 Structured Effect DSL 기능으로 구현해라.

==================================================
목표
==================================================

최소 다음 세 가지 범용 기능을 추가한다.

A. CardDefinition을 조건으로 필터링한 뒤 deterministic RNG로 무작위 선택

B. 효과 원본 카드 기준 좌/우 인접 빈 슬롯을 대상으로 SUMMON 가능

C. 같은 effect resolution 안에서 직전에 SUMMON된 카드들을
후속 effect의 target으로 참조 가능

그리고 Admin AI 효과 생성기가 이 새 DSL을 이해하도록 확장한다.

최종적으로 아래 자연어가 NEEDS_CLARIFICATION 없이
정상적인 READY draft로 생성 가능해야 한다.

"등장: 이 카드 양옆의 빈 슬롯에 각각 무작위 선수 카드 1장을 소환하고,
그렇게 소환된 선수들에게 도발을 부여한다."

==================================================
1. 절대 카드별 하드코딩 금지
==================================================

절대 이런 식으로 구현하지 마.

if (card.name === "...")
if (card.id === "...")
if (sourceCard.definitionId === "...")

특정 카드 이름/ID를 engine source에 넣지 마.

이번 기능은 generic DSL capability다.

새 카드가 추가되어도
DB definition + Structured Effect DSL만으로 사용할 수 있어야 한다.

==================================================
2. 무작위 CardDefinition 선택 기능
==================================================

SUMMON / GENERATE에서 고정 definitionRef뿐 아니라
조건에 맞는 CardDefinition pool에서 무작위 definition을 선택할 수 있도록 한다.

이 기능은 반드시 generic filter 기반이어야 한다.

최소 지원해야 하는 필터:

- cardType
- tagsAny
- tagsAll
- tagsNone

현재 project에 이미 공용 tag matcher:

- hasCardTag
- sharesCardTag
- matchesCardTagFilter
- tagsAny
- tagsAll
- tagsNone

등이 있다면 반드시 그것을 재사용한다.

별도 tag 판정 로직을 만들지 마.

예시 개념:

definitionSelector: {
  mode: "RANDOM",
  filter: {
    cardType: "WRESTLER"
  }
}

정확한 property 이름은 현재 DSL 스타일을 조사해서
가장 일관적인 이름으로 정해도 된다.

하지만 의미는 명확해야 한다.

"모든 공개 선수 CardDefinition 중 무작위 하나"

같은 표현이 가능해야 한다.

==================================================
3. RNG 규칙
==================================================

절대 Math.random() 사용 금지.

온라인 PvP는 server-authoritative + deterministic RNG를 유지해야 한다.

현재 game engine이 사용하는 deterministic random source를 반드시 재사용해라.

같은 state / seed / action sequence라면
동일한 definition이 선택되어야 한다.

무작위 선택은 canonical server action resolution에서만 결정되어야 한다.

클라이언트가 별도로 random card를 선택하면 안 된다.

필요하다면 RANDOM_CARD_SELECTED 같은 event 또는
기존 event attribution 구조를 사용해서
결정된 결과가 replay/resync에서도 명확하게 유지되도록 한다.

불필요하게 새로운 RNG 시스템을 만들지 마.

==================================================
4. Random pool의 기준
==================================================

무작위 CardDefinition 선택은
state.cardPool의 canonical CardDefinition catalog를 기준으로 한다.

온라인 서버의 state.cardPool은 현재 모든 PUBLISHED 공개 카드 정의 catalog이다.

Production DB에 직접 query하는 effect engine을 만들지 마.

effect-engine은 GameState/cardPool만 사용해야 한다.

필터 결과가 0장일 경우:

- exception으로 전체 게임 crash 금지
- invalid effect configuration인지
- 정상적인 no-result resolution인지

현재 engine의 규칙을 조사해서 가장 일관적인 처리를 선택한다.

하지만 silent corruption은 금지.

테스트로 명확히 규정해라.

==================================================
5. 자기 자신/Token 등 제외 옵션
==================================================

generic selector가 재사용 가능하도록
필요하다면 다음과 같은 선택적 조건을 지원할 수 있다.

- excludeSourceDefinition
- includeTokens / excludeTokens

단, 현재 요구를 넘어서 지나치게 큰 selector framework를 만들지 마.

이번 핵심은:

cardType = WRESTLER

인 공개 CardDefinition 중 무작위 선택이다.

==================================================
6. 인접 빈 슬롯 대상 기능
==================================================

현재 board slot 구조를 조사해서
sourceCard.boardSlot을 기준으로 좌/우 인접 슬롯을 계산한다.

4-slot board라면 예:

source slot 0:
오른쪽 1만 인접

source slot 1:
왼쪽 0 / 오른쪽 2

source slot 2:
왼쪽 1 / 오른쪽 3

source slot 3:
왼쪽 2만 인접

단 실제 slot semantics는 현재 engine 구현을 authoritative source로 사용해라.

새 DSL에서는 다음 의미가 가능해야 한다.

"source의 좌/우 인접 슬롯 중 비어 있는 슬롯"

예시 개념:

placement:
  ADJACENT_EMPTY_SLOTS

또는 현재 target/values 구조와 일관된 표현.

정확한 이름은 현재 DSL 스타일에 맞춰도 된다.

==================================================
7. "각각 소환"의 정확한 규칙
==================================================

이번 요구에서:

"양옆 빈 슬롯에 각각 무작위 선수 카드 1장"

의 공식 규칙은 다음이다.

- source 기준 왼쪽 인접 슬롯이 존재하고 비어 있으면 1장 소환
- source 기준 오른쪽 인접 슬롯이 존재하고 비어 있으면 1장 소환
- 최대 2장
- 한쪽만 비어 있으면 1장
- 둘 다 차 있으면 0장
- board edge라서 인접 슬롯이 하나뿐이면 그 한 슬롯만 검사
- 일반적인 board capacity를 무시하지 않는다

각 슬롯에 사용할 random definition은
독립적으로 deterministic selection하도록 한다.

즉 두 슬롯이 비었다면
random selection을 두 번 수행하는 것이 기본이다.

같은 CardDefinition이 두 번 나오는 것도
현재 rules에서 금지되지 않는다면 허용한다.

별도 uniqueness 규칙을 임의로 추가하지 마.

==================================================
8. SUMMON 결과 참조 기능
==================================================

같은 Structured Effect resolution chain 안에서
직전 SUMMON이 생성한 CardInstance들을
후속 effect에서 target으로 참조할 수 있게 한다.

예:

Effect 1:
SUMMON random WRESTLER into adjacent empty slots

Effect 2:
ADD_KEYWORD / GRANT_KEYWORD
target = cards summoned by Effect 1
keyword = TAUNT

이 기능을 특정 TAUNT 카드 전용으로 만들지 마.

generic result reference여야 한다.

개념 예:

LAST_SUMMONED

LAST_SUMMONED_TARGETS

PREVIOUS_EFFECT_RESULTS

등.

정확한 이름은 기존 DSL과 일관되게 정해도 된다.

==================================================
9. resolution scope
==================================================

"직전 SUMMON 결과"는
현재 effect chain / active resolution 범위 안에서만 유효해야 한다.

다음 턴이나 전혀 다른 카드 효과까지 남아 있으면 안 된다.

현재 engine에 이미:

LAST_DESTROYED_TARGETS
lastAggregatedStats
active resolution frame
triggerContext
continuation

등 비슷한 개념이 있다면
그 구조를 재사용하거나 확장한다.

불필요하게 전역 GameState property를 영구 저장하지 마.

다만 PLAYER_CHOICE처럼 effect resolution이 중간에 중단되어
후속 continuation이 필요한 경우,
필요한 state는 serializable 해야 한다.

이번 immediate summon → keyword 부여 흐름은
불필요한 targeting UI를 띄우지 않는다.

==================================================
10. 후속 효과 대상은 실제 성공적으로 소환된 카드만
==================================================

LAST_SUMMONED 류 target에는:

- 실제 board에 들어간 CardInstance만 포함
- 슬롯이 없어서 소환되지 않은 카드 제외
- 생성 시도했으나 실패한 카드 제외

예:

왼쪽 빈 슬롯 있음
오른쪽 차 있음

→ 1장만 SUMMON
→ 후속 TAUNT도 그 1장에만 적용

둘 다 차 있음:

→ SUMMON 0장
→ 후속 TAUNT 대상도 0장
→ exception 금지

==================================================
11. Keyword 부여
==================================================

"도발"은 현재 project에서 사용하는 canonical keyword를 사용해라.

새로운 "도발" 문자열 시스템을 만들지 마.

현재 CardKeyword enum / keyword utility / keyword application logic를 재사용한다.

기존 keyword 부여 action이 있으면 그것을 사용한다.

없다면 generic structured action으로 추가하되
TAUNT 전용 action으로 만들지 마.

예:

GRANT_KEYWORD
keyword: TAUNT

처럼 generic해야 한다.

12. Action → Event → GameState 규칙 유지
==================================================

KO CARD GAME의 핵심 규칙:

→ Event
→ GameState

를 깨지 마.

Random selection,
SUMMON,
keyword 부여가
canonical state 변화와 event history에 일관되게 반영되어야 한다.

UI에서 임의로 결과를 만들어내지 마.

13. ENTER_FIELD 규칙 회귀 금지
==================================================

현재 공식 규칙:

ON_ENTER / 등장 효과는
WRESTLER PLAY_FROM_HAND일 때만 발생한다.

이번 random SUMMON이
소환된 카드 자신의 등장 효과를 잘못 발동시키지 않도록 회귀 테스트해라.

15. Online PvP
==================================================

온라인에서는 반드시 server-authoritative로 처리한다.

클라이언트가 random selection을 결정하지 않는다.

MATCH_SNAPSHOT
ACTION_ACCEPTED
RESYNC_REQUIRED

후에도 결과가 동일해야 한다.

최근 수정된 공개 cardPool snapshot을 이용한
definitionRef / CardDefinition resolution을 유지한다.

online sanitizer에서:

- cardPool 공개 catalog 유지
- randomSeed 숨김
- 상대 hand/deck identity 숨김
- hidden draw/generated event redaction 유지

이번 작업 때문에 sanitizer 보안을 약화시키지 마.

19. AI가 질문하지 않아야 하는 부분
==================================================

위 exact wording에 대해서는 더 이상 다음 질문을 하지 마.

- random pool이 무엇인지?
  → 공식 의미: 공개 cardPool의 WRESTLER CardDefinitions

- 몇 장인지?
  → 공식 의미: 좌/우 인접 빈 슬롯 각각 1장, 최대 2장

- 도발 대상이 누구인지?
  → 공식 의미: 바로 앞 SUMMON에서 실제 성공적으로 소환된 카드들

이 세 가지는 이제 DSL semantics로 명확하게 정의한다.
