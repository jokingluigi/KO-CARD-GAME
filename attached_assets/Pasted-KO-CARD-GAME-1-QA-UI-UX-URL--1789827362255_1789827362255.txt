KO CARD GAME의 1차 실제 브라우저 QA 결과를 기준으로 UI/UX와 상태 관리 문제를 수정해줘.

중요:
- 카드 이미지/카드 아트/이미지 URL/이미지 업로드 기능은 이번 작업에서 절대 수정하지 마.
- 기존 게임 규칙 자체를 임의로 변경하지 마.
- 기존 공용 컴포넌트가 있으면 재사용하고 중복 구현하지 마.
- DB 스키마를 불필요하게 변경하지 마.
- 수정 후 typecheck/build와 관련 테스트를 실제 실행해.
- 각 항목을 PASS / FIXED / FAIL로 보고해.

[1. 덱 편집 실시간 검증 — 최우선]

현재 문제:
덱을 수정해서 정상 상태가 되어도 이전 저장 시점의 검증 오류가 저장 전까지 계속 화면에 남아 있다.

예:
- 빈 덱 저장 후 Champion 선택 + 20장 추가해도
  "사용할 수 없는 Champion이 포함되어 있습니다"
  "카드가 20장보다 적습니다"
  등이 계속 표시됨.
- 저장 후에야 오류가 사라짐.

수정:
- 현재 편집 중인 draft 상태를 기준으로 validation 결과를 즉시 재계산할 것.
- 카드 추가/제거, Champion 변경 시 바로 VALID/INVALID 및 오류 문구를 갱신.
- 이전 서버 저장 응답의 validationErrors를 현재 편집 상태 오류처럼 계속 표시하지 말 것.
- 가능하면 deck validation 규칙을 공통 함수로 만들어 UI와 저장 검증에서 동일 규칙 사용.
- 카드 수 20~30, Champion 1명, 일반 카드 복수 제한, Legendary 총 3장 제한 등 기존 규칙은 유지.
- 기존 불완전 덱을 INVALID 초안으로 저장할 수 있는 현재 정책은 유지.

테스트:
0장 / 19장 / 20장 / 30장 / 31장
Champion 없음/있음
Legendary 3장/4장
카드 제거 후 즉시 오류
카드 추가해 정상화한 순간 즉시 오류 해제
저장 없이도 표시 상태가 정확해야 함.

[2. Collection loading / empty state 분리]

현재 문제:
Collection 진입 직후
"컬렉션을 불러오는 중..."
과
"아직 보유한 카드가 없습니다"
가 동시에 표시되는 순간이 있다.

수정:
상태를 loading / success-data / success-empty / error로 명확히 분리.
loading 중에는 empty message를 절대 렌더링하지 말 것.
loading 중 카드 수량 0을 실제 데이터 0처럼 보여주지 말 것.
가능하면 기존 디자인에 맞는 가벼운 skeleton/loading UI 사용.

[3. Deck Builder CARD LOCKER 상세보기 개선]

- 카드 효과를 덱 편집 화면에서 바로 확인할 수 있게 할 것.
- 기존 Collection/Match에서 사용하는 카드 상세/ALT popup 컴포넌트가 있다면 반드시 재사용.
- 카드 본체의 상세보기 동작과 "+" 추가 버튼 동작을 분리.
- PC click/ALT/적절한 detail interaction 지원.
- 모바일에서도 사용할 수 있는 tap 또는 long-press 대체 동작 고려.
- 카드 추가 버튼의 기존 기능은 유지.

[4. 사용자 표시 용어 통일]

내부 enum/API 값은 변경하지 말고 화면 표시만 정리.

권장 UI 표시:
WRESTLER -> 선수
TECHNIQUE -> 기술
Champion -> 챔피언
Cost -> 비용
VALID -> 사용 가능
INVALID -> 수정 필요

Gold/G 등은 현재 게임 디자인과 충돌하지 않는 범위에서 하나의 표현 체계로 통일.
장식용 영어 제목은 유지 가능.
접근성 aria-label도 사용자 UI 언어와 맞출 것.

[5. 카드 효과 텍스트 품질 점검]

카드 효과 로직은 변경하지 말고 표시 텍스트만 점검.

찾아야 할 예:
- "현재 공격과 체력을의 수치"
- "소환될때"
- "이번턴"
- 묘지/무덤 혼용
- 규칙상 다른 의미가 아닌 곳에서 용어 혼용

공식 게임 용어를 기존 엔진 의미에 맞춰 일관되게 사용.
등장 / 퇴장 / 리타이어 / 묘지 등 서로 다른 엔진 의미를 임의로 합치지 말 것.

[6. 오심정정 / 저지먼트 정의 검사]

QA에서 두 카드가 WRESTLER 0/0으로 표시됐지만 효과 설명은 즉시 효과 카드처럼 보였다.

먼저 실제 card definition과 기획 데이터를 조사해서:
- 현재 cardType
- Attack/Health
- effect
- published data
를 보고해.

임의로 TECHNIQUE로 변경하지 말고,
정의가 명백한 데이터 오류일 경우에만 수정.
불확실하면 변경하지 않고 보고.

Technique가 맞는 것으로 코드/기존 데이터에서 확정되면:
- TECHNIQUE 타입으로 일관되게 동작
- board slot을 차지하지 않음
- Attack/Health UI를 선수처럼 표시하지 않음
- Collection TECHNIQUE filter에 포함
- Deck Builder에서도 기술 카드로 표시
를 확인.

[7. Deck delete 흐름 검사]

현재 QA 자동화 브라우저가 Delete 클릭 직후 자체적으로 timeout되어 게임 버그 여부가 확정되지 않았다.

코드를 먼저 검사하고,
실제 문제를 찾지 못하면 불필요한 수정 금지.

확인:
삭제 클릭
-> 확인/취소
-> 취소 시 유지
-> 확인 시 서버 삭제
-> 리스트 즉시 갱신
-> 선택된 덱 상태 정리
-> 삭제된 덱을 대표 덱으로 참조하지 않음
-> 새로고침 후에도 삭제 상태 유지

가능하면 window.confirm 같은 native confirm을 사용 중인지도 보고해.
단, UI 리디자인은 기능 검증 후 별도 제안으로 남겨도 됨.

[8. 메인 대표 덱 상태 패널]

현재 선택된 대표 덱이 있을 경우 메인에 작은 상태 패널 추가를 검토/구현.

표시:
- 덱 이름
- 선택 Champion
- 카드 수
- 사용 가능 / 수정 필요
- "덱 수정" 버튼

INVALID 대표 덱이면 대전 전에 알아볼 수 있게 명확히 표시.
기존 메인 디자인을 과도하게 복잡하게 만들지 말 것.

[9. Deck Builder 간단 통계]

덱 편집 화면에 간결한 요약 추가:
- 선수 수 / 기술 수
- Legendary X / 3
- 비용 분포 0,1,2,3,4,5,6+

너무 큰 분석 패널은 만들지 말고 덱 구성에 실제 도움이 되는 수준으로만 구현.

[10. 인증 확인 화면 깜빡임 개선]

현재 새로고침/일부 메뉴 이동 때 전체 화면이
"인증 상태 확인 중"
으로 교체되는 경우가 있다.

보안/세션 검증은 그대로 유지하면서:
- 가능하면 앱 공통 shell/background/nav는 유지
- 필요한 content 영역만 loading 처리
- 이미 인증된 세션의 내부 route 이동에서 불필요한 전체 auth loading 화면이 재등장하지 않도록 원인 조사

- 카드 아트 수정
- 이미지 URL/asset migration
- 게임 규칙 임의 변경

- online PvP 구조 재작성
