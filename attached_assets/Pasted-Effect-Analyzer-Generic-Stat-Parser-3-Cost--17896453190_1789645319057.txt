Effect Analyzer의 Generic Stat Parser를 확장해줘.

이제 카드 효과에서 다음 3개 수치를 공통적으로 인식해야 한다.

- 비용 / Cost
- 공격력 / Attack
- 체력 / Health

==================================================
1. 자연어 Stat 변경 인식
==================================================

다음 표현들을 모두 인식:

"비용이 1 감소합니다"
"비용 -1"
"비용을 2 증가시킵니다"
"공격력 +2"
"공격력이 2 증가합니다"
"체력 +3"
"체력을 3 증가시킵니다"

각각 Generic Stat Modifier로 변환.

예:

"비용 -1"
→ MODIFY_STAT
   stat = COST
   amount = -1

"공격력 +2"
→ MODIFY_STAT
   stat = ATTACK
   amount = +2

"체력 +3"
→ MODIFY_STAT
   stat = HEALTH
   amount = +3

==================================================
2. 공격력/체력 축약 표기
==================================================

기존처럼:

+X/+Y

는:

첫 번째 = 공격력
두 번째 = 체력

으로 인식.

예:

+2/+2
→ Attack +2
→ Health +2

+3/+1
→ Attack +3
→ Health +1

-1/+2
→ Attack -1
→ Health +2

==================================================
3. 비용까지 포함한 복합 표현
==================================================

비용과 스탯이 한 문장에 같이 있어도 전부 분석해야 한다.

예:

"비용이 1 감소하고 +2/+2를 얻습니다."

→ Cost -1
→ Attack +2
→ Health +2

"비용 +1, 공격력 +3, 체력 +2"

→ Cost +1
→ Attack +3
→ Health +2

"비용을 2 감소시키고 체력을 1 증가시킵니다."

→ Cost -2
→ Health +1

SEQUENCE로 순서대로 저장.

==================================================
4. SET 표현 구분
==================================================

증가/감소와 "수치를 ~로 만든다"를 구분해.

예:

"공격력이 5가 됩니다."
→ SET_STAT ATTACK = 5

"체력이 3이 됩니다."
→ SET_STAT HEALTH = 3

"비용이 1이 됩니다."
→ SET_STAT COST = 1

"공격력/체력이 4/6이 됩니다."
→ SET_STAT ATTACK = 4
→ SET_STAT HEALTH = 6

반면:

"+4/+6"
→ Attack +4
→ Health +6

절대 혼동하지 마.

==================================================
5. 비용 최소값
==================================================

Cost 감소 시 기본적으로 기존 게임의 Cost 제한 규칙을 사용.

카드 효과가:

"(최소 1)"
"(최소 비용 1)"

이라고 명시하면:

minimumCost = 1

명시하지 않았다면 기존 Engine의 기본 Cost minimum 규칙을 사용.

Analyzer가 임의로 최소 비용을 만들어내지 마.

==================================================
6. Health 처리
==================================================

영구적으로 Health가 증가하는 경우:

maximumHealth += amount

BOARD에 있는 선수라면 일반적인 +Health 버프는:

currentHealth += amount
maximumHealth += amount

으로 처리.

Health 감소의 경우 기존 Engine의 Stat Modifier 규칙을 사용하고,
결과 currentHealth <= 0이면 기존 State-Based RETIRE Check를 실행.

단 DAMAGE와 HEALTH 감소는 서로 다른 개념이다.

"피해를 2 줍니다."
→ DAMAGE 2

"체력을 2 감소시킵니다."
→ HEALTH STAT -2

둘을 같은 Action으로 처리하지 마.

==================================================
7. Listener와 연동
==================================================

Stat 변경은 반드시 공통 Event를 발생시켜야 한다.

예:

STAT_CHANGED {
  stat
  before
  after
  delta
  sourceEffectId
  sourceInstanceId
  duration
}

따라서:

공격력 증가
→ 도쿵 / 만드릴쿤 같은 Attack Increase Listener가 감지 가능

체력 증가
→ Health 관련 Listener가 향후 추가돼도 감지 가능

비용 감소
→ Cost 관련 Listener가 향후 추가돼도 감지 가능

==================================================
8. 도쿵 예시
==================================================

도쿵에게:

"+2/+2"

적용.

먼저:
Attack +2
Health +2

그리고 도쿵은 Attack +2를 감지해서:
Health 추가 +2

최종 변화:

Attack +2
Health +4

==================================================
9. 만드릴쿤 예시
==================================================

만드릴쿤에게:

"비용 -1, +2/+2"

적용.

→ Cost -1
→ Attack +2
→ 만드릴쿤 효과 Attack 추가 +1
→ Health +2

최종:

Cost -1
Attack +3
Health +2

만드릴쿤 자신의 추가 Attack +1은
자기 Listener를 다시 발동하지 않도록 recursion guard 유지.

==================================================
10. 지속시간도 유지
==================================================

다음 표현도 인식:

"이번 턴 공격력 +2"
"이번 턴 +2/+2"
"이번 턴 비용 -1"
"다음 턴까지 체력 +3"
"영구적으로 공격력 +1"

기존 Duration 시스템으로 변환.

임시 Attack 증가를 Listener가 감지해
추가 Stat Modifier를 발생시키는 경우,
필요하다면 원본 Modifier의 duration 정보를 전달할 수 있게 해.

==================================================
11. ALT 수치 변경 로그 연동
==================================================

비용/공격력/체력이 변경되면
기존 ALT 카드 상세 수치 변경 로그에도 모두 기록.

예:

피 스타 세븐
공격력 3 → 5 (+2)

도쿵 효과
체력 4 → 6 (+2)

매드 펌킨
비용 4 → 3 (-1)

각 로그에:

stat
before
after
delta
sourceName
sourceEffectId
turnNumber
duration

가능하면 기록.

==================================================
12. 구현 원칙
==================================================

카드 이름 하드코딩 금지.

다음 구조로 통합:

Natural Language
→ Analyzer
→ Generic Stat Modification
→ Executor
→ STAT_CHANGED Event
→ Listener
→ ALT History

COST / ATTACK / HEALTH가
동일한 Generic Stat Pipeline을 사용하게 해.

Analyzer만 인식하고 실제 Match Executor가 작동하지 않는
가짜 SUPPORTED 상태는 금지.

실제 Match에서 테스트:

- Cost + / -
- Attack + / -
- Health + / -
- +X/+Y
- Cost 변경 + +X/+Y 동시 문장
- SET Cost
- SET Attack/Health
- Temporary Modifier
- Permanent Modifier
- 도쿵 Listener
- 만드릴쿤 Listener
- ALT 변경 로그

까지 확인해.
