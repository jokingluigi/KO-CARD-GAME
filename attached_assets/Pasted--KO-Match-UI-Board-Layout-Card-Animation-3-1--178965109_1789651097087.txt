현재 KO 카드게임의 실제 Match UI / Board Layout / Card Animation을 수정해줘.

이번 수정 목표는 3가지다.

1. 보드와 손패가 너무 작아서 카드가 잘 안 보이는 문제 해결
2. 카드 플레이 애니메이션 / 공격 애니메이션 중 카드가 2장처럼 겹쳐 보이는 문제 해결
3. 상대가 카드를 낼 때 내 필드 쪽에서 등장했다가 상대 필드로 이동하는 잘못된 애니메이션 경로 수정

매우 중요:
- 게임 규칙 변경 금지
- 카드 효과 변경 금지
- 슬롯 개수 변경 금지 (양쪽 4칸 유지)
- 카드의 실제 소속(owner), zone, target 판정은 기존 엔진 그대로 사용
- 이번 작업은 Presentation / Layout / Animation 수정이다
- 실제 브라우저에서 반드시 테스트하고 PASS/FAIL 보고

==================================================
1. 보드와 손패를 훨씬 크게 보이게 레이아웃 재구성
==================================================

현재 Match 화면에서:

- 중앙 보드 영역이 너무 작다
- 손패 카드가 너무 작다
- 전체 화면 대비 실제 플레이 영역 점유율이 너무 낮다

목표:
"한눈에 카드 이름, 비용, 대략적인 효과와 수치를 읽을 수 있는 크기"

수정 방향:

1) 중앙 Board Stage의 시각적 점유율을 키워라
- 현재보다 실제 플레이 보드가 훨씬 크게 보이게
- 화면이 넓으면 중앙 보드 영역이 더 크게 커지게
- 단, 우측 정보 UI / 좌측 로그 / 챔피언 UI와 충돌하지 않게

2) Field Card 크기를 키워라
- 현재 필드 카드 렌더 크기를 대략 1.35배 ~ 1.6배 수준으로 확대
- 보드 슬롯 간격은 조금 줄여도 된다
- 4칸 보드 구조는 유지

3) Hand Card 크기를 키워라
- 손패 카드도 대략 1.4배 이상 키워라
- 손패는 겹치기(overlap / fan layout)를 사용해도 된다
- 중요한 것은 "잘 보여야 한다"는 것
- 카드끼리 약간 겹쳐도 괜찮지만 읽기 불가능하면 안 된다

4) 반응형 크기 계산
- 카드 크기를 고정 px 하나로 박아두지 말고
- viewport width / height와 컨테이너 크기를 참고해 계산
- CSS clamp(), min(), max() 등을 사용해도 좋다

예시 방향:
- board card width = clamp(140px, 10vw, 220px)
- hand card width = clamp(140px, 9vw, 220px)

정확한 수치는 너가 실제 레이아웃 보고 최적화해라.

==================================================
2. 보드 레이아웃 가독성 개선
==================================================

현재 보드는 너무 작고 텅 빈 느낌이 있다.

다음 원칙으로 수정:

- 중앙 2x4 보드 슬롯이 화면 중심에 더 크게 위치
- 상대 슬롯과 내 슬롯 사이 간격은 유지하되 너무 벌어지지 않게
- 덱 / 무덤 UI는 보드 오른쪽에 계속 둘 수 있지만,
  보드 자체가 작아지지 않게 우선순위를 조정
- 좌측 로그 박스와 우측 턴 UI는 유지 가능하지만
  보드 크기를 희생하지 않는 방향으로 재배치
- 챔피언 UI도 유지하되 플레이 영역이 우선

즉:
"보드와 손패가 메인, 나머지 UI는 보조"

==================================================
3. 공격 애니메이션 / 카드 플레이 애니메이션에서 카드가 2장처럼 보이는 문제 수정
==================================================

현재 문제:
- 공격할 때 이동하는 카드와 원래 카드가 동시에 보여서 카드가 2장처럼 보인다
- 카드 플레이 애니메이션 중에도 비슷한 중복 현상이 발생할 수 있다

원인:
애니메이션용 clone 카드와 원본 카드가 동시에 보이는 상태다.

해결 원칙:

1) clone animation을 사용할 경우
- clone 생성 직후 원본 카드는 숨긴다
- 숨김 방식은 visibility:hidden 또는 opacity:0 + pointer-events:none
- 레이아웃은 무너지지 않게 유지

2) 애니메이션 종료 후
- clone 제거
- 원본 카드 복원

3) 어떤 경우에도
- 원본 + clone이 동시에 보이면 안 된다
- React rerender로 clone이 남아 있거나
  원본이 너무 일찍 다시 보이는 문제를 막아라

4) 공격 / 카드 플레이 / 소환 / 부활 / Technique reveal 등
clone 기반 animation이 있다면 공통 유틸로 정리해라

예:
beginCardMotion(instanceId)
- create clone
- hide original

endCardMotion(instanceId)
- destroy clone
- show original

==================================================
4. 상대 카드 플레이 애니메이션 시작 위치 수정
==================================================

현재 문제:
상대가 필드에 카드를 낼 때
내 필드나 내 손패 쪽에서 카드가 등장했다가
상대 필드로 이동한다.

이건 잘못된 source origin 때문이다.

반드시 고쳐라.

규칙:

- 내가 손에서 카드를 낼 때:
  내 hand area에서 시작해서 내 필드 slot으로 이동

- 상대가 손에서 카드를 낼 때:
  상대 hand area에서 시작해서 상대 필드 slot으로 이동

즉:
source rect는 action owner 기준으로 잡아라.

필요하면 다음 구조 사용:

getHandSourceRect(owner)
- owner === self → self hand container rect
- owner === opponent → opponent hand container rect

playCardAnimation({
  owner,
  cardInstanceId,
  fromZone: HAND,
  toZone: BOARD,
  targetSlot
})

여기서 owner에 따라 시작점이 달라져야 한다.

절대:
모든 카드 플레이 애니메이션이
self hand rect 하나만 기준이 되면 안 된다.

==================================================
5. 공격 애니메이션 target / origin 정확성 개선
==================================================

공격 애니메이션도 동일하게 정확한 좌표를 사용해야 한다.

요구사항:

1) 공격 시작점
- 공격하는 카드의 실제 현재 렌더 좌표

2) 공격 도착점
- targetInstanceId의 실제 현재 렌더 좌표
- stale slot index만 쓰지 말 것

3) 상대 카드가 공격해도
- 실제 상대 보드 위치에서 출발해야 함

4) 공격 애니메이션이 끝나기 전
- 원본 카드가 제자리에서 보여서 2장처럼 보이면 안 됨

5) 공격 후
- 카드가 원위치로 복귀하는 연출도 자연스럽게 처리

==================================================
6. 슬롯 기반이 아니라 실제 DOM 좌표 기준으로 애니메이션
==================================================

Presentation animation 좌표는 가능하면 다음 순서로 참조:

1. 실제 Card DOM rect
2. 없을 경우 fallback으로 slot rect
3. 정말 불가능할 때만 추정 좌표

특히 공격 / 카드 플레이 / 소환 애니메이션에서
slot 기준 추정만 쓰면 위치가 어긋난다.

==================================================
7. 손패 레이아웃 개선
==================================================

손패는 현재 너무 작고 답답하다.

다음처럼 바꿔라:

- 카드 수가 적을 땐 넓게 펼침
- 카드 수가 많아질수록 겹치기 증가
- 중앙 정렬
- 맨 앞 카드 / Hover 카드는 살짝 위로
- 선택 중인 카드 / 드래그 중인 카드는 가장 위 z-index

목표:
"손패가 작아서 카드 내용을 못 읽는 상태" 해소

==================================================
8. 모바일/작은 해상도 배려
==================================================

이번 요청은 우선 desktop 기준으로 보이지만
작은 해상도에서도 완전히 망가지면 안 된다.

원칙:
- 넓은 화면에서는 보드/손패 크게
- 좁은 화면에서는 겹치기/축소를 적용
- 하지만 지금처럼 지나치게 작아지면 안 된다

==================================================
9. 게임 플레이 우선순위
==================================================

레이아웃 재조정 시 우선순위는 다음과 같다:

1. 보드 카드 가독성
2. 손패 카드 가독성
3. 챔피언 / 체력 / 골드 확인 가능
4. 로그 / 부가 UI

즉,
로그 박스나 장식 때문에 보드와 손패가 작아지면 안 된다.

==================================================
10. 실제 테스트 항목
==================================================

반드시 실제 브라우저에서 TEST USER로 테스트.

A. Board/Hand Size
- 필드 카드가 현재보다 훨씬 크게 보임
- 손패 카드도 읽을 수 있을 만큼 커짐
- 4장 이상 손패도 overlap layout으로 잘 보임

B. Self Card Play
- 내 손패에서 카드 플레이
- 내 hand area에서 시작
- 내 필드로 자연스럽게 이동
- 카드 2장처럼 안 보임

C. Opponent Card Play
- 상대 카드 플레이
- 상대 hand area에서 시작
- 상대 필드로 자연스럽게 이동
- 내 필드 쪽에서 잠깐 나타나지 않음

D. Attack Animation
- 내 카드 공격
- 상대 카드 공격
- 둘 다 공격 시작점/도착점 정확
- clone + original 중복 표시 없음

E. Re-render Stability
- 빠르게 여러 행동이 일어나도
  clone이 남아 있거나 카드가 2장처럼 보이는 문제 없음

중요:

실제 테스트에서:
"카드가 충분히 커졌는지"
"상대 카드가 상대쪽에서 시작하는지"
"애니메이션 중 카드가 2장처럼 안 보이는지"
까지 눈으로 확인해야 PASS다.
