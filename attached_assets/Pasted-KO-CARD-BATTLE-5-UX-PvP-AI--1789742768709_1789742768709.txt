KO CARD BATTLE에서 아래 5개 버그/UX 문제를 한 번에 수정해줘.

중요:
기존 카드 효과, 온라인 PvP 규칙, AI 로직, 덱 데이터, 게임 엔진 규칙은 이번 작업과 관계없는 부분을 임의로 변경하지 마.
UI에서만 숨기거나 우회하지 말고 실제 root cause를 찾아 수정해줘.

==================================================
1. 인게임 BGM 볼륨 조절 기능
==================================================

현재 인게임에서 배경음악(BGM) 볼륨을 직접 조절할 수 없다.

기존 중앙 AudioManager를 재사용해서
Match 화면에서 BGM 볼륨을 조절할 수 있게 해줘.

요구사항:

- Match 화면에 작은 음량 설정 UI 추가
- BGM 볼륨 슬라이더 제공
- 0~100% 조절 가능
- 음소거 버튼 제공 가능
- BGM만 조절
- 공격음, 데미지음, 카드 효과음 등 SFX 볼륨에는 영향 주지 않음
- 기존 AudioManager를 우회해서 audio element를 직접 조작하지 마
- 현재 재생 중인 BGM에도 즉시 반영
- 곡이 바뀌어도 설정 유지
- Match를 나갔다 다시 들어와도 같은 브라우저에서는 설정 유지

가능하면 localStorage 또는 기존 Settings 저장 방식을 재사용.

예:

bgmVolume
bgmMuted

중앙 설정으로 관리.

Match UI를 크게 가리지 않는 작은 설정 버튼 또는 음량 아이콘 형태로 구현.

==================================================
2. 덱 편성에서 Champion 능력 표시
==================================================

현재 Deck Builder에서 Champion을 선택할 수 있지만
Champion 능력을 바로 확인하기 어렵다.

Deck Builder에서 Champion 카드/Portrait를 클릭하거나 선택하면:

- Champion 이름
- Champion Ability 이름
- Gold Cost
- 능력 설명
- Quest가 있다면 Quest 조건
- Quest Reward / 강화 능력이 있다면 해당 정보

를 확인할 수 있게 해줘.

중요:

Champion 데이터의 실제 canonical definition을 사용.

UI용 별도 하드코딩 금지.

Champion Admin / Champion Definition에서 사용 중인 실제 ability/quest 데이터를 읽어 표시.

예:

챔피언 예거

기본 능력:
1G
용병을 소환합니다.

퀘스트:
선수 카드를 7번 생성합니다.

보상:
강화된 챔피언 능력...

처럼 실제 데이터 기반으로 표현.

Champion에 Quest가 없으면 Quest 영역은 숨김.

Deck Builder의 현재 디자인/카드 목록을 깨지 말고
Champion 상세 패널 / tooltip / side panel 형태로 자연스럽게 추가.

==================================================
3. 턴 종료 버튼이 작동하지 않는 버그
==================================================

현재 Match에서 [턴 종료] 버튼을 눌러도
턴이 종료되지 않는 문제가 있다.

이건 가장 중요하게 실제 Action Pipeline 전체를 추적해서 수정해줘.

확인 순서:

Turn End Button
↓
click handler
↓
input lock / disabled state
↓
END_TURN Action 생성
↓
Game Engine / Online Action dispatch
↓
server validation if Online
↓
GameState turn transition
↓
TURN_END / TURN_START Events
↓
Draw
↓
Gold refresh
↓
UI turn transition

어디서 끊기는지 실제 root cause를 찾아 수정.

==================================================
4. 턴 종료 UI 검사
==================================================

먼저 버튼 자체가 클릭 가능한지 확인:

- disabled
- pointer-events:none
- invisible overlay
- z-index
- stale presentation lock
- pendingSelection lock
- isAnimating
- isActionPending
- reconnect lock
- wrong turn check

등.

정상적인 내 턴이고,
pendingSelection도 없고,
Game Result도 아니고,
Presentation이 종료된 상태라면
턴 종료 버튼이 정상 작동해야 한다.

==================================================
5. AI Match / Online Match 둘 다 확인
==================================================

턴 종료는:

AI Match
Online Match

둘 다 검증.

AI Match:
Player END_TURN
→ AI Turn
→ AI Action
→ Player Turn

Online:
Player A END_TURN
→ Server authoritative transition
→ A/B 양쪽 상태 갱신.

Online에서 Client가 임의로 turn 변경하면 안 됨.

==================================================
6. Turn End 중복 방지
==================================================

턴 종료 버튼 연타로:

- 두 번 Draw
- 두 번 Gold 증가
- Turn skip
- version mismatch

발생하지 않게.

Action pending 상태에서는 중복 END_TURN 차단.

하지만 Action이 성공/실패한 뒤
버튼이 영구적으로 잠기면 안 됨.

==================================================
7. Turn transition 기존 KO 규칙 유지
==================================================

턴 종료 수정 중 아래 기존 규칙 변경 금지:

- Gold carryover 없음
- 개인 턴 기준 base Gold 1→2→3→4→5→6
- 이후 base 6 유지
- turn-start draw 1
- first personal turn에도 draw
- Hand max 7
- overdraw removedFromGame

이번 버그를 고친다고 턴 규칙 자체를 새로 만들지 마.

==================================================
8. 덱 삭제 Confirm에 이상한 코드가 같이 보이는 문제
==================================================

현재 Deck Builder에서 덱을 삭제하면
삭제 확인 문구에 사용자에게 보여서는 안 되는
이상한 내부 코드/ID/객체 문자열이 같이 표시된다.

예상 원인:

- deck object 전체 문자열 변환
- deck.id 출력
- JSON.stringify
- template string에 object 직접 삽입
- internal identifier 노출

실제 원인을 찾아 수정.

==================================================
9. 덱 삭제 Confirm UX
==================================================

사용자에게는 깔끔하게:

"'<덱 이름>' 덱을 삭제하시겠습니까?"

정도만 보여줘.

예:

"예거 컨트롤 덱을 삭제하시겠습니까?"

버튼:

[취소]
[삭제]

내부 값인:

deckId
database id
UUID
object string
[object Object]
JSON
internal key

등이 사용자 화면에 절대 노출되지 않게.

==================================================
10. 삭제 로직 자체는 ID 사용
==================================================

UI 표시에는 deck.displayName / deck.name만 사용.

실제 delete request에서는
기존 canonical deckId를 그대로 사용.

즉:

표시용 텍스트와
삭제 식별자를 분리.

덱 이름이 중복되어도 올바른 deckId가 삭제되어야 함.

==================================================
11. 상대 선수의 Champion 공격 애니메이션 방향 버그
==================================================

현재 버그:

상대 Wrestler가 내 Champion을 공격하면
실제 Damage는 내 Champion에게 정상적으로 들어가지만,

공격 animation의 이동 destination이
상대 Champion 쪽으로 향하는 문제가 있다.

즉:

Game Logic Target = 정상
Presentation Target = 잘못됨

이다.

==================================================
12. 공격 애니메이션 target 계산 수정
==================================================

Presentation에서 attacker/target 위치를
PLAYER_ONE / PLAYER_TWO 또는 fixed top/bottom 기준으로 계산하지 마.

반드시 Server/Game Event의 실제:

attackerInstanceId
targetType
targetInstanceId
targetPlayerId

를 기준으로
현재 Viewer Perspective의 실제 DOM 위치를 찾는다.

Champion 대상이면:

targetPlayerId의
현재 rendered Champion DOM rect

사용.

Wrestler 대상이면:

targetInstanceId의
현재 rendered wrestler DOM rect

사용.

==================================================
13. Viewer Perspective 중요
==================================================

온라인 Match에서:

각 플레이어의 자기 Champion은 항상 아래,
상대 Champion은 항상 위.

예:

Player A 화면:

B Champion = TOP
A Champion = BOTTOM

Player B 화면:

A Champion = TOP
B Champion = BOTTOM

따라서 "attacker가 상대 Player니까 위 Champion"
같은 하드코딩 금지.

실제 TARGET PLAYER가
viewer 기준 어디에 렌더되어 있는지 계산.

==================================================
14. 문제 상황 정확히 테스트
==================================================

반드시 다음 테스트:

Player A 화면에서
Player B Wrestler가
Player A Champion 공격.

기대:

상대 Wrestler:
TOP Board
↓
BOTTOM A Champion

으로 내려오는 공격 animation.

Damage:
A Champion.

==================================================
15. 반대 방향도 테스트
==================================================

Player A Wrestler가
Player B Champion 공격.

A 화면:

BOTTOM Board
↓
TOP B Champion.

B 화면에서는 동일 Event가:

TOP Opponent Wrestler
↓
BOTTOM Own Champion

으로 표현되어야 한다.

양 Client에서 실제 target과 animation destination이 동일해야 한다.

==================================================
16. 기존 DOM rect 방식 유지
==================================================

공격 destination은 실제 animation 시작 순간의
getBoundingClientRect() equivalent를 사용.

고정 pixel 좌표 금지.
옛날 작은 Board 좌표 cache 금지.

현재 확대된 Match Layout에서도 정확해야 함.

==================================================
17. Champion Target Registry
==================================================

필요하면 Champion DOM에 안정적인 식별자를 추가:

예:

data-player-id
data-champion-player-id

등.

하지만 card name으로 DOM search하지 마.

playerId / target metadata를 사용.

==================================================
18. 공격 Clone 중복 방지 유지
==================================================

공격 animation:

original hide
→ clone 이동
→ impact
→ clone cleanup
→ original restore

기존 원칙 유지.

target 수정하다가 카드가 두 장 보이는 회귀 발생 금지.

==================================================
19. Champion Damage Presentation
==================================================

Champion 공격 시:

attack lunge
→ Champion hit reaction
→ damage number
→ Champion HP update
→ screen shake if applicable
→ attacker return

순서 유지.

Result/lethal이면
final hit presentation 이후 Result 화면.
