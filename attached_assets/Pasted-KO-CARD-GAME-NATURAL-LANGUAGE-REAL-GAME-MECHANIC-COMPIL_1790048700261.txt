==================================================
1. 핵심 개념 — AI가 메커니즘을 구성한다
==================================================

AI는 사용자의 문장을
기존 카드 이름이나 미리 준비된 효과 template과
1:1 매칭하는 역할이 아니다.

AI는 카드 효과를 작은 범용 게임 메커니즘으로 분해해야 한다.

예:

"죽으면 다음 턴에 부활"

AI 판단:

TRIGGER:
SELF_RETIRED

REMEMBER:
retired card instance/definition

SCHEDULE:
OWNER_NEXT_TURN_START

ACTION:
REVIVE remembered card

또:

"부활하면 공격력 +2"

AI 판단:

RESULT:
successful revived instance

ACTION:
BUFF result attack +2

이처럼 effect를 실제 engine operation으로 구성한다.

5. Replacement / Prevention 메커니즘
==================================================

카드게임에 필요한 다음 종류도 표현 가능하게 설계한다.

예:

"이 카드가 처음 받을 피해를 0으로 만든다."

필요 개념:

BEFORE_DAMAGE 또는 현재 engine의 equivalent hook
→ condition source/target
→ MODIFY/PREVENT event amount
→ one-shot consume

"죽는 대신 체력 1로 남는다."

RETIRE/LETHAL 전 replacement hook
→ condition
→ prevent retire
→ set health 1
→ consume effect

현재 Action → Event → GameState 구조를 훼손하지 말고
generic replacement/prevention layer를 설계한다.

카드 이름 hardcoding 금지.

6. Delayed / Scheduled 메커니즘
==================================================

다음 자연어를 표현 가능하게 한다.

"다음 내 턴 시작에 부활한다."

"2턴 뒤에 파괴된다."

"이번 턴 동안 공격력 +3."

"다음 Technique의 비용은 0."

"다음에 피해를 줄 때 피해량을 2 증가."

이를 위해 bounded declarative duration/schedule을 지원한다.

예:

CURRENT_TURN

UNTIL_END_OF_TURN

OWNER_NEXT_TURN_START

NEXT_MATCHING_EVENT

N_MATCHING_EVENTS

UNTIL_SOURCE_LEAVES

PERMANENT

실제 현재 engine semantics에 맞게 구현한다.

그 후 actual Rule AST 생성.
