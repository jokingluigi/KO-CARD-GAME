==================================================
A. ONLINE MODE SELECT BACK → MAIN
==================================================

현재 문제:

Main
→ Online
→ 빠른대전 / 친선전 선택 화면
→ Back

했을 때 Main으로 돌아가지 않고
현재 화면에 그대로 남아 있다.

공식 기대 동작:

Online Mode Select에서 Back 클릭
→ 즉시 Main 화면으로 복귀.

이 화면은 아직 실제 Match 시작 전이므로:

- surrender 처리 금지
- match result 생성 금지
- 전적 변경 금지
- disconnect penalty 금지

실제 queue/room에 들어가기 전이라면
불필요한 leave API도 호출하지 마.

==================================================
B. FALSE "상대가 다시 연결되었습니다"
==================================================

현재 문제:

상대가 실제로 disconnect/reconnect하지 않았는데도
Online Match에서 다음 행동을 할 때마다:

- 카드 PLAY
- ATTACK
- Champion Ability
- Technique
- END_TURN
- BUFF
- DAMAGE
- HEAL
- Quest progress
- 기타 GameState update

"상대가 다시 연결되었습니다"

toast가 뜬다.

공식 기대 동작:

정상 GameState update
→ reconnect toast 0회.

실제 연결 상태가:

CONNECTED
→ DISCONNECTED
→ CONNECTED

로 바뀐 경우에만
reconnect toast 정확히 1회.

==================================================
B-1. RECONNECT는 TRANSITION
==================================================

다음은 reconnect가 아니다:

true → true
initial unknown → true
일반 snapshot true → true
PLAY_CARD 이후 true → true
ATTACK 이후 true → true
END_TURN 이후 true → true

최초 match mount에서 상대가 이미 connected여도
reconnect toast 금지.

실제로 false → true가 되었고,
이전에 실제 disconnect 상태가 확인된 경우에만
reconnect 처리.

==================================================
B-2. ROOT CAUSE 확인
==================================================

특히 확인:

- opponentConnected가 snapshot마다 재초기화되는지
- state merge에서 previous connection state가 유실되는지
- 전체 opponent object reference 변경을 reconnect로 오인하는지
- useEffect dependency가 과도한지
- component remount 때 previous connection ref가 초기화되는지
- WebSocket snapshot을 reconnect event로 오인하는지
- heartbeat/presence update를 reconnect로 오인하는지
- action response의 full snapshot replace를 reconnect로 오인하는지
- component key가 action/version에 묶여 remount되는지

서버/WebSocket에 명시적:

OPPONENT_DISCONNECTED
OPPONENT_RECONNECTED

event가 이미 있다면 그것을 우선 사용.

같은 reconnect event replay/resync로
toast가 중복되어선 안 된다.
