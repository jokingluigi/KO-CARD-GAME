4. 안전한 provider variance만 허용
==================================================

Provider가 runtime 의미는 동일하지만
표현 형식만 약간 다르게 내는 경우가 있다.

이번 작업에서 허용 가능한 것은
"이미 지원되는 DSL 의미를 유지하는 안전한 canonicalization"뿐이다.

예시 개념:

- 이미 정의된 enum alias normalization
- 명백한 wrapper 제거
- nullable optional field 정리
- 서버가 소유하는 context field 주입
- 기존 DSL에서 의미가 동일한 legacy shape → canonical shape

단 실제 프로젝트의 기존 contract에 맞는 경우에만 허용.

==================================================
5. 의미 추측은 금지
==================================================

아래는 금지:

- DAMAGE를 BUFF로 추측
- selector 누락을 임의 생성
- target을 임의 변경
- unsupported effect type을 비슷한 effect로 치환
- 조건을 임의 생성
- 누락된 amount를 임의 숫자로 채움

즉:

safe shape normalization은 가능
semantic invention은 금지.
