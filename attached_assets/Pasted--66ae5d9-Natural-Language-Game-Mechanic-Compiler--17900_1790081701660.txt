==================================================
최종 목표
==================================================

Admin 사용자가 카드게임 효과를 자연어로 작성하면
AI가 해당 문장을 실제 게임 메커니즘으로 분해하고,

필요한:

- trigger
- selector
- condition
- result reference
- memory
- delayed schedule
- one-shot listener
- repeated listener
- event-history query
- replacement/prevention
- action

을 조합하여

실제 KO CARD GAME Runtime이 실행 가능한
bounded declarative Rule을 생성해야 한다.

그 Rule은 Admin form에 적용되고,
사용자가 저장한 뒤 실제 AI Match / Online Match에서
OpenAI 없이 작동해야 한다.

==================================================
중요
==================================================

이번에는:

"현재 SCRIPT_V1로 표현 가능한 범위까지만 구현하고
나머지는 후속"

으로 종료하지 마.

아래 핵심 capability까지 구현해야 완료다.

==================================================
1. DELAYED SCHEDULE
==================================================

최소 지원:

OWNER_NEXT_TURN_START
OPPONENT_NEXT_TURN_START
END_OF_CURRENT_TURN
NEXT_MATCHING_EVENT
N_MATCHING_EVENTS

필요한 경우 기존 queued effect 시스템을 일반화한다.

예:

"이 카드가 죽으면 다음 내 턴 시작에 부활한다."

RETIRE
→ capture source reference/definition
→ schedule OWNER_NEXT_TURN_START
→ REVIVE

==================================================
2. ONE-SHOT LISTENER
==================================================

다음 효과를 카드별 코드 없이 구현 가능하게 한다.

"다음에 내가 내는 선수는 +2/+2."

Rule 생성 시:

REGISTER ONE-SHOT
trigger = PLAY_FROM_HAND
owner = SELF
cardType = WRESTLER

→ matching event 발생
→ event card +2/+2
→ listener consume

중요:

Rule을 만든 source card 자신의 현재 PLAY event가
listener를 즉시 소비하면 안 된다.

==================================================
3. REPEATED LISTENER
==================================================

예:

"내가 Technique을 사용할 때마다 1 회복한다."

TECHNIQUE_PLAYED
→ same owner
→ HEAL MY_CHAMPION 1

duration이 없는 영구 listener가
source의 유효 기간 규칙을 따라야 한다.

==================================================
4. EVENT HISTORY QUERY
==================================================

최소 bounded scope:

CURRENT_RESOLUTION
CURRENT_ACTION
CURRENT_TURN
CURRENT_MATCH

지원.

filter:

eventType
owner
source
target
cardType
tag

aggregation:

COUNT
SUM

예:

"이번 턴 RETIRE된 선수 수만큼
적 챔피언에게 피해."

CURRENT_TURN
→ RETIRE events
→ WRESTLER filter
→ COUNT
→ DAMAGE opponent champion

무제한 event scan 금지.

==================================================
5. REPLACEMENT / PREVENTION
==================================================

다음 효과를 generic하게 지원:

"이 카드가 처음 받을 피해를 0으로 만든다."

현재 damage pipeline에 적합한
BEFORE_DAMAGE/equivalent hook을 사용.

one-shot prevention
→ event amount 0
→ consume

또:

"처음 죽는 대신 체력 1로 남는다."

lethal/retire replacement
→ prevent retirement
→ HP = 1
→ consume

Action → Event → GameState 구조 유지.

==================================================
6. SERIALIZABLE RULE STATE
==================================================

delayed/listener/replacement가 필요한 상태는
GameState에 serializable하게 저장한다.

금지:

closure
function
dynamic JS
eval
runtime generated code

필요 정보만 저장:

rule ID
owner
source
captured values
remaining uses
expiration
scheduled trigger

reconnect/resync에서도 복구 가능해야 한다.

==================================================
7. RECURSION / LOOP 방지
==================================================

Rule이 자신이 발생시킨 Event를 다시 잡아서
무한 반복하면 안 된다.

최소:

max chained triggers
max scheduled effects
max repeated resolution depth
max event-history results

제한.

같은 occurrence를 같은 Rule이
무한 재소비하지 못하게 한다.

==================================================
8. AI COMPILER에 새 capability 제공
==================================================

Admin AI가 다음을 이해하도록 schema/prompt를 갱신:

DELAYED
ONE_SHOT_LISTENER
REPEATED_LISTENER
EVENT_HISTORY
REPLACEMENT
PREVENTION
CAPTURE_VALUE
CAPTURE_TARGET
SCHEDULE
CONSUME

정확한 이름은 실제 canonical AST에 맞게 설계.

AI가 pseudo-action을 창작하지 않게
structured output schema와 일치시킨다.
