현재 KO Card Admin에
"선수 카드 전체 효과 구현 프롬프트 생성"
기능을 추가해줘.

목적:

현재 등록된 선수 카드들의 효과를 최신 Effect Analyzer로 전부 다시 분석하고,
Engine에서 아직 지원되지 않는 효과들을 모아서
한 번에 Replit Agent에게 구현을 요청할 수 있는
통합 프롬프트를 자동 생성하는 기능이다.

특정 카드 이름을 하드코딩하지 마.

==================================================
1. 관리자 버튼
==================================================

Card Admin 또는 선수 카드 관리 화면에:

[선수 카드 전체 구현 프롬프트 생성]

버튼 추가.

이 버튼은 현재 등록된 WRESTLER 카드들의
효과 지원 상태를 전부 검사한다.

==================================================
2. 반드시 최신 상태로 재분석
==================================================

버튼을 누르면 기존에 저장된 오래된 분석 결과만 읽지 말고
현재 최신:

- Effect Registry
- Trigger
- Action
- Target
- Value
- Condition
- Duration
- Listener
- Keyword
- Natural Language Analyzer

기준으로 모든 선수 효과를 다시 분석해.

stale cache 사용 금지.

==================================================
3. 분석 대상
==================================================

현재 CardDefinition 중:

cardType === WRESTLER

인 선수 카드들의 실제 효과 텍스트를 분석.

Token / Champion Token도 효과 분석 자체가 필요하다면 포함 가능하지만,
일반 선수 카드와 구분해서 표시해.

카드가 DRAFT여도 관리자가 개발 중인 카드라면 분석 가능하게 해.

==================================================
4. 분석 결과 분류
==================================================

각 효과를 다음 상태로 분류:

SUPPORTED

NEW_MECHANIC_REQUIRED

ANALYSIS_FAILED

SUPPORTED:
현재 Engine으로 완전히 실행 가능.

NEW_MECHANIC_REQUIRED:
효과의 의미는 이해했지만
Engine에 필요한 공통 기능이 없음.

ANALYSIS_FAILED:
문장 자체를 정확히 이해하지 못함.

==================================================
5. 통합 프롬프트에는 미구현 효과만
==================================================

SUPPORTED 카드 효과는
통합 구현 대상에서 제외.

NEW_MECHANIC_REQUIRED 효과를 중심으로
통합 프롬프트를 만들어.

각 카드에 대해 최소:

- CardDefinition ID
- 카드 이름
- 원본 효과 텍스트
- Analyzer가 이해한 부분
- unsupportedParts
- 필요한 Trigger / Action / Target / Value 등

을 포함.

==================================================
6. 중복 메커니즘 합치기
==================================================

매우 중요:

여러 카드가 같은 미구현 메커니즘을 요구하면
카드별로 각각 구현하라고 하지 마.

예:

카드 A:
현재 공격력 참조

카드 B:
현재 공격력 참조

카드 C:
현재 공격력 참조

이면 프롬프트에는:

"CURRENT_ATTACK Value resolver를 공통 메커니즘으로 구현"

한 번만 요구.

그 뒤 어떤 카드들이 이 메커니즘을 사용하는지 나열.

==================================================
7. 기존 Effect Library 우선 재사용
==================================================

생성되는 Replit 프롬프트에는 반드시 다음 원칙 포함:

먼저 현재 Effect Library를 검사한다.

이미 존재하는:

- Trigger
- Action
- Target
- Value
- Condition
- Listener
- Duration
- Sequence
- pendingSelection

등을 최대한 조합해서 사용.

기존 기능 조합으로 구현 가능한 효과라면
새 메커니즘을 만들지 않는다.

==================================================
8. 카드별 하드코딩 금지
==================================================

자동 생성 프롬프트에 반드시 포함:

금지:

if (card.name === "...")
NATOMATO_EFFECT
PURPLERAIN_EFFECT
PANDORA_CARD_EFFECT

같은 카드 전용 구현.

새 기능이 필요하면 반드시:

재사용 가능한 Generic Effect Mechanic

으로 구현.

값/대상/Zone 등을 parameter로 받게 한다.

==================================================
9. Target / PLAYER_CHOICE 포함
==================================================

효과가:

"선택한 선수"
"선택한 대상"
"손에 있는 선수 카드 하나를 선택"

등을 포함한다면
현재 공통 PLAYER_CHOICE 시스템을 사용해야 한다.

공식 의미:

대상 = WRESTLER + CHAMPION
선수 = WRESTLER
챔피언 = CHAMPION

별도 카드 전용 Target Picker를 만들지 마.

==================================================
10. Generated / Zone 규칙 포함
==================================================

자동 프롬프트는 현재 KO 공통 규칙도 유지해야 한다.

Generated가 "어디에 있든":
HAND + DECK + BOARD

Token / Champion Token:
기존 명시적 flag 사용.

RETIRE / DESTROY / REMOVE_FROM_GAME:
서로 다른 처리 유지.

ENTER_FIELD:
효과 소환 포함 모든 정상 필드 진입 시 1회.

기존 게임 규칙을 카드 구현 때문에 변경하지 마.

==================================================
11. 자동 생성 프롬프트 구조
==================================================

생성 결과는 대략 다음 형식:

KO 선수 카드 미구현 효과 통합 구현

1. 현재 Effect Library 검사
2. 이미 있는 기능은 재사용
3. 아래 Missing Mechanics만 Generic하게 추가

[MISSING MECHANIC A]
설명
필요 카드:
- 카드 A
- 카드 B

[MISSING MECHANIC B]
설명
필요 카드:
- 카드 C

[CARD EFFECTS TO SUPPORT]

카드명
원본:
"..."

분석:
...

필요 기능:
...

...

마지막:

모든 기능 구현 후
해당 선수 카드 Effect를 다시 Analyzer로 분석해서
SUPPORTED가 되는지 확인.

==================================================
12. ANALYSIS_FAILED 처리
==================================================

ANALYSIS_FAILED 카드가 있어도
전체 프롬프트 생성을 막지 마.

별도 섹션:

[분석 실패 - 수동 확인 필요]

에:

- 카드 이름
- 원본 효과 텍스트
- 실패 이유

표시.

의미를 추측해서 임의 구현하지 마.

==================================================
13. 프롬프트 UI
==================================================

버튼 클릭 후 Modal 또는 Panel:

선수 카드 효과 분석 결과

SUPPORTED: XX
구현 필요: XX
분석 실패: XX

[통합 구현 프롬프트 보기]

큰 Text Area에 생성된 프롬프트 표시.

버튼:

[프롬프트 복사]

제공.

==================================================
14. 카드별 결과도 표시
==================================================

가능하면 간단히:

나토마토
SUPPORTED

퍼플레인
NEW_MECHANIC_REQUIRED
- XXX

루나
SUPPORTED

...

형태로 확인 가능하게 해.

==================================================
15. 구현 완료 후 재분석
==================================================

같은 화면에:

[전체 구현 완료 - 다시 분석]

버튼 추가.

버튼 클릭:

모든 WRESTLER 효과를
최신 Effect Registry 기준으로 다시 분석.

이전 캐시 사용 금지.

==================================================
16. 완료 상태
==================================================

모든 선수 효과가:

SUPPORTED

이면 화면에:

CHAMPION 대신 선수 카드용으로

ALL WRESTLER EFFECTS SUPPORTED

또는

모든 선수 효과 구현 완료

표시.

==================================================
17. 실제 Replit 프롬프트의 완료 조건
==================================================

자동 생성되는 프롬프트에는 반드시:

- TypeScript compile
- 기존 테스트 유지
- 관련 Effect unit test
- 실제 Game Engine effect execution test
- PLAYER_CHOICE가 있으면 실제 선택 테스트
- 카드별 Effect가 실제 게임에서 동작하는지 확인
- Effect Registry 등록
- Natural Language Analyzer 등록
- 재분석 결과 SUPPORTED 확인

을 요구해.

단순히 Analyzer가 알아듣는 것만으로
구현 완료 처리하지 마.

==================================================
18. 중요한 금지사항
==================================================

이 기능 때문에:

- Game Engine 대규모 리팩터링 금지
- 기존 Effect Library 삭제 금지
- 카드 이름 하드코딩 금지
- arbitrary JS/eval 금지
- Analyzer와 Engine 지원 상태를 거짓으로 맞추기 금지

Analyzer가 SUPPORTED라고 판단하려면
실제 Executor가 해당 Structured Effect를 실행할 수 있어야 한다.
