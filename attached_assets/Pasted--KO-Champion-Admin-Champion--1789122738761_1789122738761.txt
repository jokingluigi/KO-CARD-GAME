현재 KO 프로젝트의 Champion Admin 효과 분석 기능을 수정해줘.

목표는 단순하다:

Champion 효과 분석을
현재 정상 작동하는 "선수 카드 효과 분석"과
기능적으로 완전히 동일하게 만들어줘.

중요:
Champion용 별도 Analyzer / 별도 Prompt Generator를 새로 만들지 마.

현재 Wrestler/Card Admin에서 실제로 정상 작동하는:

- 자연어 효과 분석
- Structured Effect 생성
- 지원 가능 여부 판정
- NEW_MECHANIC_REQUIRED
- unsupportedParts
- Replit 구현 프롬프트 생성
- 프롬프트 복사
- 구현 완료 후 다시 분석
- 효과 적용

흐름을 그대로 재사용해.

================================
1. 선수 효과 분석을 기준 구현으로 사용
================================

먼저 현재 프로젝트에서
선수 카드 효과 분석이 실제로 어떻게 동작하는지 찾아.

예:

Effect Analyzer component
Analyzer hook/service
Effect Registry
Natural Language Analyzer
Prompt Generator
Structured Effect Preview
Apply Effect
Re-analyze

현재 실제 구현을 source of truth로 사용해.

Champion 쪽에 비슷한 코드를 새로 복사해서 만들지 말고
가능하면 같은 shared component / hook / service를 사용해.

================================
2. Champion에서도 동일 기능
================================

Champion Admin의 다음 영역에서
선수 효과 분석과 같은 기능을 사용할 수 있어야 한다.

- 기본 챔피언 능력
- Quest 조건
- Quest 완료 보상
- 강화된 챔피언 능력
- Champion Token 효과

각 영역마다:

[효과 분석]

버튼을 누르면
선수 카드 분석과 동일한 파이프라인을 실행해.

================================
3. 분석 성공 시
================================

현재 Effect Library로 구현 가능한 경우:

SUPPORTED

→ Structured Effect 표시
→ 사람이 읽을 수 있는 분석 결과 표시
→ [효과 적용]

선수 카드 효과 분석과 동일하게 동작해야 한다.

================================
4. 구현 불가능한 효과
================================

현재 Effect Library에 없는 메커니즘이 필요한 경우:

NEW_MECHANIC_REQUIRED

로 분류해.

그리고 선수 효과 분석과 동일하게:

- 지원되는 부분
- 지원되지 않는 부분
- unsupportedParts

를 표시해.

그리고 반드시:

[Replit 구현 프롬프트 생성]

버튼을 제공해.

================================
5. Replit 구현 프롬프트
================================

Champion에서도
선수 효과 분석에서 사용하는 기존 Prompt Generator를 그대로 사용해.

생성 프롬프트에는 자동으로:

- Champion 이름
- 현재 분석 중인 효과 영역
- 원본 자연어 효과
- Analyzer가 이해한 내용
- 현재 지원되는 부분
- unsupportedParts
- 현재 Effect Library의 관련 기능
- 필요한 Trigger
- Action
- Target
- Value
- Condition
- Listener
- Duration
- Sequence

등 현재 선수 카드 Prompt Generator가 포함하는 정보를 동일하게 넣어.

그리고:

"이 효과를 실제 KO 게임 엔진에서 동작하도록 구현"

하도록 요청해야 한다.

================================
6. Champion 효과 슬롯 정보
================================

같은 Analyzer를 사용하되
어떤 Champion 영역인지 context만 전달해.

예:

effectContext:
CHAMPION_ABILITY

QUEST_CONDITION

QUEST_REWARD

UPGRADED_CHAMPION_ABILITY

CHAMPION_TOKEN_EFFECT

이 context는 분석 엔진을 별도로 만드는 용도가 아니라
어느 필드에 결과를 적용할지 구분하는 용도로만 사용해.

================================
7. 특정 Champion 하드코딩 금지
================================

절대로:

if champion.name === "판도라"

같은 방식으로 구현하지 마.

모든 Champion이 같은 분석 시스템을 사용해야 한다.

================================
8. Prompt 복사
================================

선수 효과 분석과 동일하게:

[Replit 구현 프롬프트 생성]

클릭

→ 큰 textarea에 Prompt 표시

→ [프롬프트 복사]

버튼 제공

복사 기능도 기존 선수 효과 분석 코드를 재사용해.

================================
9. 구현 완료 후 다시 분석
================================

Champion에서도:

[메커니즘 구현 완료 - 다시 분석]

또는 현재 선수 카드 UI와 동일한 버튼을 제공해.

버튼 클릭 시:

- 최신 Effect Registry 다시 읽기
- 기존 stale analyzer cache 사용 금지
- 원래 Champion 효과 문장 다시 분석

지원 가능해졌으면:

SUPPORTED
→ Structured Effect
→ [효과 적용]

아직 부족하면:

NEW_MECHANIC_REQUIRED
→ 남은 unsupportedParts
→ 새로운 Replit Prompt 생성 가능

================================
10. ANALYSIS_FAILED
================================

정말 문장 자체를 이해할 수 없는 경우에만:

ANALYSIS_FAILED

사용.

"현재 엔진에 기능이 없다"는 이유로
ANALYSIS_FAILED를 반환하면 안 된다.

의미는 이해되지만 구현 기능이 부족한 경우는 반드시:

NEW_MECHANIC_REQUIRED

이어야 한다.

이 기준도 선수 카드 분석과 동일하게 맞춰.

================================
11. Champion Form 보호
================================

효과 분석 / Prompt 생성 / 다시 분석을 실행해도
Champion 편집 중인 다른 입력값이 초기화되면 안 된다.

금지:

form.reset()
Champion refetch 후 전체 form overwrite
페이지 reload
컴포넌트 전체 remount

분석 결과만 해당 효과 슬롯 state에 저장해.

================================
12. 버튼 동작
================================

Champion form 안의 분석 관련 버튼은
form submit을 발생시키면 안 된다.

반드시 필요하면:

type="button"

사용.

저장 버튼만 Champion form submit을 담당하게 해.

================================
13. 코드 재사용 우선
================================

이번 작업의 핵심은:

Champion Analyzer 새 구현

이 아니라

기존 Wrestler/Card Analyzer를 Champion에서도 재사용

하는 것이다.

가능하면 구조를:

SharedEffectAnalyzer

또는 현재 프로젝트의 기존 공통 컴포넌트/서비스

형태로 사용해.

단 대규모 리팩터링은 하지 마.

================================
14. 반드시 실제 테스트
================================

Champion Admin에서 실제로 아래 테스트해.

TEST 1

기본 능력:

적 선수 카드 1장에게 피해 1

→ 효과 분석
→ 선수 카드 분석과 동일한 결과 표시
→ 효과 적용 가능


TEST 2

현재 엔진에 없는 효과 입력

→ 효과 분석
→ NEW_MECHANIC_REQUIRED
→ unsupportedParts 표시
→ Replit 구현 프롬프트 생성
→ Prompt 복사 가능


TEST 3

Quest 조건 입력

선수 카드 7장을 생성합니다.

→ 분석 결과 정상 표시


TEST 4

Quest 보상 입력
→ 분석
→ Replit Prompt 생성 가능


TEST 5

강화 Champion Ability
→ 동일 기능


TEST 6

Champion Token 효과
→ 동일 기능


TEST 7

분석 후에도 Champion의
이름 / 이미지 / Quest / 능력 / 기타 입력값이 유지됨.

================================
완료 조건
================================

최종적으로 사용자가 보기에는:

선수 효과 분석 화면과
챔피언 효과 분석 화면이

"분석 대상만 다르고 기능은 완전히 동일"

해야 한다.

즉 Champion에서도:

자연어 입력
→ 분석
→ Structured Effect
또는
→ NEW_MECHANIC_REQUIRED
→ Replit 구현 프롬프트 생성
→ 복사
→ 구현 후 다시 분석
→ 효과 적용

전체 흐름이 선수 카드와 똑같이 동작해야 한다.

관련 Champion Admin / shared Analyzer 코드만 최소 수정하고
게임 엔진이나 카드 효과 실행 규칙은 변경하지 마.

완료 후 추가 기능 만들지 말고 종료해줘.
