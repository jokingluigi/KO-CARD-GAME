KO CARD GAME — CRITICAL MAIN BGM INITIAL-LOAD FIX
문제: 메인 화면에 처음 들어오면 음악이 안 나오고, 다른 메뉴를 갔다가 메인으로 돌아와야 음악이 재생됨

현재 실제 증상:
- 앱/사이트에 처음 접속
- 메인 화면 표시
- NON_BATTLE Main BGM이 재생되지 않음
- 덱 편집/컬렉션/상점 등 다른 메뉴로 이동
- 다시 메인으로 돌아오면 그제야 BGM이 재생됨

이것은 정상 동작이 아니다.

목표:
메인 화면을 최초 진입점으로 열었을 때도
Global Non-Battle BGM 시스템이 즉시 올바르게 초기화되어야 한다.

단, 브라우저 autoplay 정책 때문에 사용자 interaction 이전 자동 재생이 금지된 경우에는:
- 앱이 깨지거나 영원히 무음으로 남지 않고
- 첫 click/tap/keyboard interaction 시
- 현재 메인 화면에서 바로 음악이 시작되어야 한다.
- 다른 메뉴로 이동했다 돌아올 필요가 절대 없어야 한다.

==================================================
0. 핵심 기대 동작
==================================================

CASE A — autoplay가 허용되는 환경

사이트 접속
→ Main route mount
→ Global Audio Manager initialize
→ Main route가 NON_BATTLE로 분류
→ Main BGM load
→ Main BGM play
→ 다른 메뉴 이동 없이 정상 재생

CASE B — autoplay가 브라우저에 의해 차단되는 환경

사이트 접속
→ Main route mount
→ play() rejected or deferred
→ Audio Manager가 "needs user interaction" 상태 유지
→ 사용자가 메인 화면에서 아무 버튼/영역을 1번 클릭
→ 같은 Main route에서 BGM 즉시 시작
→ route 이동 필요 없음

2. 가장 가능성 높은 원인 전부 검사
==================================================

A. route-change useEffect만 있고 initial mount에서 실행 안 됨

B. previousPath/ref 비교 때문에
첫 pathname은 early return됨

C. currentMusicContext 초기값이 이미 NON_BATTLE이라
state change가 발생하지 않아 effect가 안 뜸

예:
const [context, setContext] = useState("NON_BATTLE")
useEffect(() => setContext("NON_BATTLE"), [pathname])

→ 동일 값이라 downstream effect 미실행

D. audio instance가 route provider보다 늦게 생성됨

E. audio instance 생성 전 play effect가 한 번 실행되고 끝남

F. first interaction audio unlock listener가
route transition 이후에만 등록됨

G. initial `play()` promise rejection 후
retry flag를 남기지 않음

H. browser autoplay rejection을 catch만 하고
다음 user interaction에서 재시도하지 않음

I. Main route가 initial render 순간에는
UNKNOWN/NONE으로 분류되고
route change 때만 NON_BATTLE이 됨

J. auth loading/redirect 때문에
audio context가 NONE에서 멈춤

K. BGM src/preload가 async인데
loadedmetadata/canplay 이후 retry가 없음

L. muted/volume state hydrate가 늦게 끝나면서
play request가 유실됨

M. React StrictMode mount/unmount 때문에
첫 audio instance가 destroy되고
두 번째 instance가 play되지 않음

N. App-level provider가 실제로 persistent하지 않고
Main에서 mount timing race가 있음

O. initial route path `/`, `/home`, `/main`, query/hash 등
route policy에서 빠져 있음

전부 확인하되
추측으로 아무거나 수정하지 말 것.

4. 동일 context여도 최초 track 시작 필요
==================================================

다음과 같은 bug를 막는다:

previousContext = undefined
currentContext = NON_BATTLE

첫 mount:
→ Main track start

그 이후:
NON_BATTLE → NON_BATTLE
→ track 유지, restart 금지

즉:

FIRST MOUNT + NON_BATTLE
= START

NON_BATTLE → NON_BATTLE
= CONTINUE

BATTLE → NON_BATTLE
= RESUME/START

를 명확히 구분.

==================================================
5. Audio Instance 준비 race 방지
==================================================

현재 MusicContext는 NON_BATTLE인데
audio element/ref가 아직 null이라 첫 play가 유실되는지 확인.

필요하면 state machine:

audioReady
musicContext
userAudioUnlocked
desiredTrack
desiredPlaybackState

를 기준으로 reconcile.

예:

if (
  audioReady &&
  currentContext === NON_BATTLE &&
  !muted &&
  userAudioUnlocked
) {
  ensureMainBgmPlaying()
}

중요:
"effect 한 번 놓치면 영원히 재생 안 됨" 구조 금지.

각 prerequisite가 준비될 때
desired playback state와 actual playback state를 reconcile.

==================================================
6. Browser Autoplay 처리
==================================================

브라우저는 sound가 있는 audio.play()를
사용자 gesture 전에 차단할 수 있다.

이것을 route 이동으로 우연히 해결하면 안 됨.

`audio.play()`:

try:
await audio.play()

catch NotAllowedError:
→ `needsAudioUnlock = true`
→ 앱 정상 유지
→ 첫 user gesture listener 등록

첫 gesture:
- pointerdown
- click
- touchstart
- keydown

중 현재 project convention에 맞게 사용.

gesture 발생:
→ unlockAudio()
→ if current context == NON_BATTLE
   start/resume Main BGM immediately

route 변경은 필요 없음.

30. 완료 조건
==================================================

1. 메인 최초 접속 시 Global Audio Manager가 즉시 NON_BATTLE을 인식.
2. autoplay 허용 시 route 이동 없이 Main BGM 즉시 재생.
3. autoplay 차단 시 Main 화면의 첫 user interaction으로 즉시 재생.
4. 다른 메뉴 갔다 돌아와야만 재생되는 현상 0.
5. 첫 interaction이 navigation이면 navigation과 audio unlock 둘 다 정상.
6. Main → Deck → Collection → Shop에서 같은 audio instance 유지.
7. currentTime route 이동으로 reset되지 않음.
8. direct URL load에서도 정상 초기화.
9. refresh에서도 route roundtrip 불필요.
10. duplicate BGM 0.
11. Battle 진입 시 Main BGM 중지.
12. mute/volume 유지.
13. Production DB mutation 없음.
14. tests/build/typecheck/diff 결과 보고.

핵심:
"route가 한번 바뀌어야 BGM이 시작되는 구조"를 제거하고,
initial mount부터 desired audio state를 계산하며,
브라우저 autoplay가 막는 경우에는 route change가 아니라
첫 user gesture로 같은 화면에서 정상 unlock/retry되도록 수정하라.
