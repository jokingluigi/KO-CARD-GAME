==================================================
4. INVESTIGATE THE MOST LIKELY RACES
==================================================

다음 모두 실제 코드에서 확인하고
YES / NO로 증명하라.

STALE SOCKET CALLBACK

예:

old socket A
→ socket B becomes current and healthy
→ A.onclose fires
→ A incorrectly sets RECONNECTING

STALE TIMER

예:

connection/reconnect timeout created earlier
→ MATCH_SNAPSHOT succeeds
→ timer is not cancelled
→ timer later sets RECONNECTING

MULTIPLE SOCKET OWNERS

예:

socket A receives frames

but UI reads state owned by socket B / another hook / another provider.

USEEFFECT CLEANUP / REMOUNT

예:

MATCH_FOUND
→ navigate
→ state change
→ effect cleanup
→ connection state marked disconnected
→ active healthy socket remains open

SNAPSHOT FLAG INVALIDATION

accepted snapshot becomes true
then some code clears it.

SOCKET OPEN FLAG DESYNC

actual WebSocket.readyState === OPEN
but local React state still says disconnected.

HEARTBEAT / WATCHDOG FALSE FAILURE

healthy socket is incorrectly declared dead.

SESSION GENERATION MISMATCH

new/current socket is valid
but state still belongs to previous generation.
