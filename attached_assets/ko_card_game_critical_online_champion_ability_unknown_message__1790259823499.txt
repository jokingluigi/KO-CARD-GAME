KO CARD GAME — CRITICAL ONLINE CHAMPION ABILITY FIX
온라인 PvP에서 Champion Ability 사용 시 "알 수 없는 메시지"가 뜨고 고유 능력이 발동하지 않는 문제를 끝까지 추적·수정

현재 심각한 버그:
온라인 PvP에서 Champion 고유 능력을 사용하려고 하면 클라이언트가 "알 수 없는 메시지" 또는 이에 준하는 unknown/unrecognized message 오류를 표시하고, Champion Ability가 실제 서버 GameState에 적용되지 않는다.

이 작업은 단순 UI 문구 수정이 아니다.
온라인 프로토콜 → action serialization → server validation → effect execution → event broadcast → client reducer/UI까지 전체 경로를 추적해서 실제 Champion Ability가 서버 권위 상태에서 정상 실행되게 해야 한다.

절대 원칙:
- Online PvP는 server-authoritative 유지
- 클라이언트에서 고유 능력을 임의 실행해서 문제를 숨기지 말 것
- "알 수 없는 메시지" toast만 숨기지 말 것
- Champion 이름/ID hardcode 금지
- 특정 Pandora만 예외 처리 금지
- offline/AI Match path를 그대로 온라인에 복붙하지 말고 shared canonical action contract를 재사용
- Production DB 직접 수정 금지
- 실제 사용자 매치 데이터 수정 금지
- force push 금지
- 별도 요청 없으면 push 금지
- Browser unavailable이어도 구현/자동 검증 중단 금지

==================================================
4. Canonical Champion Ability Action
==================================================

온라인에서도 Champion Ability는 canonical action 하나로 표현.

예시 개념:
{
  type: "USE_CHAMPION_ABILITY",
  sourceChampionId: "...",
  targetIds: [...]
}

실제 field naming은 현재 shared action schema 사용.

중요:
- client는 사용 의도와 target만 보냄
- ability effect 자체는 client가 실행하지 않음
- server가 Champion, upgraded/base state, legal target, usage availability를 authoritative하게 resolve
- server executeAction → effect runtime → GameState mutation → broadcast

6. Targeted Ability
==================================================

Ability click
→ PLAYER_CHOICE / target selection
→ valid target highlight
→ target confirm
→ canonical online action send
→ server revalidate
→ execute

target confirm 전:
- 비용/사용횟수/Quest 상태 commit 금지

취소:
- outbound action 없어야 함
- usage count 변화 없음
- Quest 변화 없음
- pending target clear
- retry 가능

invalid/stale target:
- typed server reject
- GameState 유지
- targeting state 안전 복구
- reload/reset 금지

8. Server Authoritative Validation
==================================================

- correct turn/timing

- enough resource if applicable
- legal target
- source Champion exists
- match not finished
- target still exists
- target owner/zone/type valid
- upgraded/base ability state correct

client validation만 믿지 말 것.

==================================================

온라인 validator가 Champion Token active를 이유로 ability reject하면 수정.

==================================================
10. Champion Token HP 분리 회귀
==================================================

유지:
- Champion HP와 Token HP 별개
- Token own definition HP 사용
- Token damage가 Champion HP에 영향 없음
- Token RETIRE ≠ match loss
- Token active 동안 Champion protected
- Champion Ability 사용 가능
- Token leave 후 Champion HP unchanged
- normal SUMMON same definition은 Champion Token 아님

15. Reconnect / Retry / Double Submit
==================================================

A. target confirm 전 reconnect
→ pending choice 안전 복구 또는 canonical cancel

B. server accepted 후 ack 받기 전 reconnect
→ reconnect 후 effect exactly once

C. same actionId retry
→ idempotent / safe reject
→ duplicate damage/quest 없음

D. ability 버튼 연타
→ accepted execution 1회만
