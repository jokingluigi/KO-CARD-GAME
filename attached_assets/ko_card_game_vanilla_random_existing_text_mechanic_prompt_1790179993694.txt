KO CARD GAME — NEW GENERIC MECHANIC
VANILLA CARD + RANDOM EXISTING CARD TEXT GRANT

목표:
새 Champion에서 사용할 수 있도록 아래 메커니즘을 범용 시스템으로 구현한다.

핵심 개념:

1. "현재 바닐라(VANILLA)인 선수 카드"를 판정할 수 있어야 한다.
2. 바닐라 카드에게 현재 게임에 실제 존재하는 다른 선수 카드의 텍스트/효과를 무작위로 부여할 수 있어야 한다.
3. AI가 새 텍스트를 생성하면 안 된다.
4. 랜덤 텍스트는 실제 CardDefinition에 존재하는 기존 카드 텍스트/Structured Effect에서 가져온다.
5. 새로 부여된 텍스트가 "등장/출현(ON_ENTER)" 효과라면, 대상이 현재 FIELD에 있는 경우 그 새 효과에 한해서 즉시 "등장한 것으로 취급"하여 1회 발동한다.
6. TURN_START, SELF_ATTACK, TURN_END, ACTIVE 등 미래 Trigger는 부여 순간 실행하지 않고 이후 정상 Trigger를 기다린다.

이 작업은 특정 Champion 이름 하드코딩이 아니라
향후 다른 카드/Champion에서도 재사용 가능한 일반 메커니즘으로 구현한다.

==================================================
0. 절대 하지 말 것
==================================================

금지:

- AI/OpenAI로 랜덤 카드 텍스트 생성
- 새 효과 문장을 런타임에서 즉석 생성
- eval / new Function
- 특정 Champion 이름/ID 하드코딩
- 특정 카드 이름별 runtime branch
- Math.random
- 카드의 이름/스탯/비용/태그/희귀도/이미지까지 복사
- donor CardInstance의 현재 상태를 복사
- Production DB 직접 수정
- 모든 기존 카드 데이터를 일괄 재저장

이 메커니즘은 반드시 기존 CardDefinition / Structured Effect / Effect Registry를 재사용한다.

==================================================
1. VANILLA의 공식 정의
==================================================

KO CARD GAME에서 이번 메커니즘의 "현재 바닐라"는
"현재 시점에 실제로 작동 가능한 카드 텍스트/능력/키워드가 없는 WRESTLER CardInstance"를 뜻한다.

바닐라 판정에서 포함:

A. 원래부터 효과/키워드가 없는 선수 카드
B. SILENCE를 받아 현재 효과와 키워드가 제거/비활성화되어 결과적으로 아무 능력이 남지 않은 선수 카드

바닐라 판정에서 제외:

- 현재 활성화된 Structured Effect가 하나라도 있는 카드
- 현재 활성화된 SCRIPT가 하나라도 있는 카드
- TAUNT / RUSH / DODGE 등 현재 활성 키워드가 하나라도 있는 카드
- 새로 부여된 random text가 현재 남아 있는 카드

다음은 바닐라 여부와 무관:

- 공격력/체력 수치
- 비용
- 일시적인 stat buff/debuff
- rarity
- tags
- artwork
- generated 여부

즉 10/10이어도 능력/키워드가 없으면 바닐라일 수 있다.

==================================================
2. SILENCE와 VANILLA
==================================================

중요:

SILENCE를 받아 기존 텍스트/키워드가 제거된 카드는
현재 바닐라 조건을 만족하면 이 메커니즘의 정상 대상이다.

그리고 그런 카드에게 새 random text를 부여하면:

- 침묵 전에 갖고 있던 원래 printed text를 되살리지 않는다.
- 원래 printed keyword도 되살리지 않는다.
- 오직 "새로 부여된 텍스트/효과/키워드"만 활성화된다.

예:

원래:
"턴 시작: +1/+1"

SILENCE
→ 현재 효과 없음
→ VANILLA = true

random text grant:
"등장: 카드 1장 드로우"

결과:
- 원래 "턴 시작 +1/+1"은 복구되지 않음
- 새 "등장: 드로우 1"만 획득/실행

이후 다시 SILENCE를 받으면:
- 새로 부여된 text/keyword도 제거 또는 비활성화
- 다시 현재 바닐라가 될 수 있음

현재 SILENCE 구현이 영구적인 `isSilenced=true` blocker 때문에
새로 부여된 효과까지 무조건 막는 구조라면,
카드 전용 예외를 만들지 말고
"침묵 시점까지 존재하던 효과를 제거/억제하지만 이후 정상적으로 새로 획득한 효과는 작동할 수 있음"
이라는 generic semantics를 지원하도록 최소 수정한다.

단 SILENCE를 "정화"해서 원래 효과를 복구하는 방식은 금지.

==================================================
3. 랜덤 텍스트의 SOURCE OF TRUTH
==================================================

랜덤 텍스트는 반드시
현재 Match가 사용하는 authoritative CardDefinition pool의
실제 기존 WRESTLER 카드에서 가져온다.

우선 source:

GameState / match cardPool의 PUBLISHED WRESTLER CardDefinitions

현재 프로젝트의 match-start cardPool snapshot이 있다면 그것을 사용한다.
매 trigger마다 live Production DB를 다시 조회하지 마.

이유:
- AI Match deterministic
- Online server-authoritative
- reconnect/resync 안정성
- mid-match DB 수정에 영향받지 않음

==================================================
4. 무엇을 "텍스트 복사"하는가
==================================================

단순 description 문자열만 복사하면 FAIL.

donor CardDefinition의 실제 실행 가능한 의미를 복사해야 한다.

가능한 구성:

- visible card effect text
- Structured Effects
- SCRIPT_V1
- basic keywords (예: TAUNT/RUSH/DODGE)
- 해당 text에 필요한 trigger/action/target/value/condition/script 구조

정확한 내부 필드명은 현재 CardDefinition schema를 따른다.

복사하지 않는 것:

- donor name
- donor cost
- donor attack
- donor health
- donor rarity
- donor tags
- donor art/image
- donor ownership
- donor runtime damage
- donor runtime buff
- donor CardInstance ID
- donor listener history
- donor one-shot consumed state

즉 "카드 텍스트의 기능"만 recipient에 새 dynamic layer로 부여한다.

==================================================
5. DONOR 후보 풀
==================================================

기본 후보:

PUBLISHED WRESTLER CardDefinitions 중
실제로 복사할 수 있는 non-empty card text/effect/keyword가 있는 카드.

제외:

- 완전 바닐라 donor (복사할 텍스트가 없음)
- malformed / validation 실패 Structured Effect
- 현재 runtime에서 ordinary WRESTLER에 절대로 실행할 수 없는 구조
- 이 신규 "랜덤 텍스트 부여" 메커니즘 자체가 WRESTLER text로 존재하게 되는 경우 재귀 donor
- 명백한 무한 재귀를 만드는 effect package

중요:

Legendary라서 제외,
Token이라서 무조건 제외,
특정 카드 이름이라서 제외
같은 임의 필터 금지.

복잡한 효과라는 이유만으로 조용히 제외하지 마.

실제로 ordinary WRESTLER recipient에 적용 불가능한 후보가 있다면
generic portability rule로 제외하고
최종 보고에 definition과 이유를 적어라.

==================================================
6. deterministic RANDOM
==================================================

후보 donor 선택은 canonical deterministic RNG 사용.

Math.random 금지.

후보 순서가 DB 반환 순서 때문에 흔들리지 않도록
필요하면 definition ID 등 안정적인 canonical key로 정렬 후
deterministic RNG를 적용.

같은 seed + 같은 GameState
→ 같은 donor text 선택.

Online에서는 authoritative side가 선택 결과를 확정.

==================================================
7. 새 GENERIC CONDITION / FILTER
==================================================

현재 target/filter system에
"현재 바닐라인 WRESTLER"를 표현할 수 있는 generic condition을 추가한다.

예시 개념:

isVanilla: true

또는 현재 registry naming convention에 맞는 동등 구조.

카드 이름 하드코딩 금지.

이 filter는 최소:

- FIELD
- HAND

등 현재 target system이 허용하는 zone과 조합 가능해야 한다.

단 이번 Champion content가 실제로 사용하는 zone은
그 Champion 정의에 맞춘다.

==================================================
8. 새 GENERIC ACTION
==================================================

기존 Effect Registry를 먼저 조사한다.

이미 "copy/grant effect/text"와 동등한 generic action이 있으면 재사용.

없다면 최소 범위의 generic action을 추가.

개념 예:

GRANT_RANDOM_CARD_TEXT

또는
COPY_RANDOM_EXISTING_EFFECT

정확한 이름은 현재 Registry naming convention을 따른다.

입력 의미:

- recipient target
- donor pool source = current authoritative WRESTLER CardDefinitions
- selection = deterministic RANDOM
- copy = executable text/effect/keywords only

==================================================
9. recipient runtime state
==================================================

새 텍스트는 CardDefinition 원본을 수정하지 않는다.

반드시 CardInstance-level dynamic state로 저장한다.

예시 개념:

grantedText
grantedStructuredEffects
grantedScripts
grantedKeywords
grantedFromDefinitionId

실제 field 이름은 현재 GameState convention에 맞춤.

필수:

- serialize 가능
- clone 가능
- Online snapshot에 유지
- reconnect 후 유지
- AI Match state copy에 유지
- replay/deterministic simulation에서 유지

Production CardDefinition을 mutation하면 FAIL.

==================================================
10. SELF 의미 재바인딩
==================================================

donor text의 `SELF`는 donor 카드가 아니라
새 텍스트를 받은 recipient CardInstance를 뜻해야 한다.

예:

donor text:
"턴 종료: 자신에게 +1/+1"

recipient B가 이 text를 획득

→ B의 TURN_END trigger
→ B +1/+1

donor definition/card를 buff하면 FAIL.

==================================================
11. RESULT REFERENCE / SCRIPT
==================================================

donor text가:

- SELECT
- SAME_TARGET
- resultId
- PLAYER_CHOICE
- delayed effect
- listener
- queue
- REVIVE
- SUMMON
- STEAL

등 기존 Script/Structured Effect 기능을 사용한다면
recipient의 새 text에서도 기존 엔진 경로로 정상 실행되어야 한다.

새 별도 mini-runtime 만들지 마.

==================================================
12. "등장" 텍스트를 부여했을 때
==================================================

사용자 공식 규칙:

바닐라 카드가 랜덤 텍스트를 받았고,
그 텍스트에 "등장/출현" 효과가 있다면
그 카드가 "등장한 취급"을 해서
그 새로 받은 등장 효과를 즉시 발동시킨다.

정확한 semantics:

A. recipient가 현재 FIELD에 있을 때
→ 새로 부여된 text의 ENTER_FIELD / ON_ENTER clause만 즉시 1회 실행

B. recipient가 HAND 등 FIELD 밖에 있을 때
→ 즉시 가짜 등장시키지 않는다.
→ 나중에 정상 PLAY_FROM_HAND로 FIELD에 들어올 때 기존 ON_ENTER 규칙대로 발동

이번 Champion이 FIELD만 대상으로 한다면 A만 실제 content path에서 사용해도 됨.

==================================================
13. SYNTHETIC ENTER는 "그 새 효과만"
==================================================

매우 중요:

새 등장 효과를 즉시 실행하기 위해
카드를 실제로 FIELD에서 나갔다 들어온 것처럼 처리하면 안 된다.

금지:

- zone leave/re-enter
- summon event 재발행
- unrelated CARD_SUMMONED trigger 발동
- 다른 카드의 "아군이 등장하면" 효과를 다시 발동
- recipient의 과거 printed ON_ENTER 효과 재발동
- Quest progress를 가짜로 증가
- play count 증가
- Gold 재지불
- animation을 실제 card play로 재실행

즉 이것은:

"newly granted ON_ENTER effect local trigger"

이다.

실제 zone movement/event replay가 아니다.

==================================================
14. 여러 Trigger가 함께 있는 donor text
==================================================

예:

donor text:
"등장: 카드 1장을 뽑습니다.
턴 종료: 자신에게 +1/+1."

FIELD recipient가 이 text를 획득:

즉시:
- 등장 DRAW 1 → 1회 실행

나중:
- TURN_END +1/+1 → 정상 trigger

TURN_END까지 grant 순간에 같이 실행하면 FAIL.

==================================================
15. keyword-only donor
==================================================

기존 card text가:

"도발"
"러쉬"
"회피"
"러쉬, 회피"

처럼 기본 keyword만 가진 경우도
실제 기존 카드 텍스트이므로 valid donor candidate가 될 수 있다.

선택되면 recipient에 해당 keyword를 즉시 부여.

그 순간 recipient는 더 이상 vanilla가 아니다.

==================================================
16. ACTIVE text
==================================================

donor text가 ACTIVE 능력이라면:

- grant 순간 자동 실행 금지
- recipient가 이후 정상 Active 사용 조건을 만족할 때 사용할 수 있어야 함
- UI에서도 Active 가능 상태가 현재 시스템 규칙에 맞게 표시되어야 함
- 비용/횟수/턴 제한은 donor text의 canonical structured semantics를 따른다

==================================================
17. PLAYER_CHOICE text
==================================================

donor ON_ENTER text가 PLAYER_CHOICE를 요구하고
FIELD recipient에게 즉시 synthetic ON_ENTER가 실행되면:

valid targets >= 1
→ 정상 pending choice / continuation

valid targets = 0
→ 기존 공식 no-target semantics:

- grant 자체는 성공
- text는 recipient에 남음
- pending choice 생성 없음
- effect 부분은 no-op
- rollback 없음
- stale continuation 없음

==================================================
18. 새로운 text가 recipient를 non-vanilla로 만든다
==================================================

random text grant 성공 후:

recipient `isVanilla` = false

다시 이 메커니즘의 대상이 되려면
나중에 SILENCE 등으로
현재 active text/keyword가 다시 없어져야 한다.

같은 카드에 무한히 랜덤 text를 중첩하는 방식 금지.

==================================================
19. DONOR와 RECIPIENT 분리
==================================================

donor는 CardDefinition이다.

recipient는 현재 Match의 CardInstance다.

donor CardInstance를 실제로 찾아서 복사하는 방식 금지.

donor 카드가 덱/손/필드/묘지에 실제 존재할 필요 없음.

현재 authoritative cardPool에 definition이 존재하면 후보가 될 수 있다.

20. 표시/UI
==================================================

Card Detail / ALT Inspector / Match card tooltip 등
현재 카드 효과 텍스트를 보여주는 UI에서

가능하면:

"부여된 효과: [실제 donor text]"

필요하면 source donor 이름을 debug/admin inspector에서만 표시해도 된다.

21. SILENCE 이후 다시 부여 테스트
==================================================

Case:

A. 원래 효과 있는 카드
B. SILENCE
C. 현재 vanilla
D. random text grant
E. 새 text 정상 작동
F. 원래 printed text는 작동하지 않음
G. 다시 SILENCE
H. granted text 제거/비활성
I. 다시 vanilla 가능

반드시 이 cycle을 테스트.

37. 기존 ON_ENTER 규칙과의 관계
==================================================

기존 공식 일반 ON_ENTER:
정상 PLAY_FROM_HAND에만 발동.
SUMMON / REVIVE / Champion Token deploy는 일반 등장 발동 아님.

이번 메커니즘의 synthetic ON_ENTER는
오직 "새로 grant된 ON_ENTER clause를 즉시 1회 실행"하기 위한 특수 generic effect-resolution rule.

기존 일반 ON_ENTER 규칙을 전역으로 바꾸지 마.

완료 조건
==================================================

1. 현재 능력/키워드가 없는 WRESTLER를 generic하게 VANILLA 판정할 수 있다.
2. SILENCE 때문에 능력이 없어진 카드도 VANILLA로 판정할 수 있다.
3. random text는 AI 생성물이 아니라 실제 기존 PUBLISHED WRESTLER CardDefinition의 텍스트/실행 효과에서 가져온다.
4. donor 선택은 deterministic RNG다.
5. recipient에는 text/effect/keyword만 부여하고 이름/스탯/비용/태그/이미지는 복사하지 않는다.
6. donor SELF는 recipient SELF로 정상 작동한다.
7. FIELD recipient가 새 ON_ENTER text를 받으면 그 새 ON_ENTER만 즉시 1회 실행한다.
8. 실제 zone re-entry나 unrelated enter/summon/quest trigger를 발생시키지 않는다.
9. TURN_START/TURN_END/ATTACK/ACTIVE 등 미래 trigger는 정상 시점까지 기다린다.
10. prior SILENCE가 recipient의 원래 printed text를 복원시키지 않는다.
11. 새 granted text는 prior Silence 이후에도 정상 작동한다.
12. 이후 다시 SILENCE되면 granted text도 제거/비활성화되어 다시 vanilla가 될 수 있다.
13. granted state가 Online/reconnect/GameState serialization에 유지된다.
14. runtime OpenAI/provider call은 0이다.
15. 카드/Champion 이름 하드코딩 없이 다른 콘텐츠에도 재사용 가능한 범용 메커니즘이다.

이 generic mechanic을 구현하고 검증한 뒤 멈춰라.
