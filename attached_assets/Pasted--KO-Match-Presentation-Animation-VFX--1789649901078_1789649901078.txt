현재 KO 카드게임의 실제 Match Presentation / Animation / VFX 시스템을
카드게임답게 전면적으로 강화해줘.

이번 작업의 목표는:

"게임 규칙은 그대로인데
카드를 내고, 공격하고, 피해를 받고, 버프되고,
죽고, 부활하고, 퀘스트를 깨는 모든 순간이
눈으로 명확하게 읽히고 훨씬 드라마틱하게 느껴지는 것"

이다.

단순히 CSS 애니메이션 몇 개 추가하는 작업이 아니다.

반드시 기존:

Game Engine
→ Game Event
→ Presentation Queue
→ Animation / VFX / SFX
→ 다음 Presentation

구조를 중심으로 구현해.

==================================================
0. 절대 원칙
==================================================

매우 중요.

Animation / Presentation은
게임 결과를 계산하면 안 된다.

Game Engine이 이미 결정한:

- damageApplied
- target
- RETIRE
- DESTROY
- REMOVE_FROM_GAME
- Stat 변경
- Quest Progress
- Quest Complete
- Draw
- Summon
- Revive
- Gold
- Dodge
- Silence
- Stun
- Buff

등의 결과를 Presentation이 표현만 한다.

절대 하지 말 것:

- Animation에서 HP 계산
- UI에서 RETIRE 판단
- VFX가 GameState 수정
- 카드 이름별 Animation 하드코딩
- 특정 Champion 이름별 예외
- Animation 때문에 게임 규칙 변경
- setTimeout을 컴포넌트마다 마구 생성
- 동시에 여러 Presentation이 겹쳐 원인을 못 알아보게 만들기

==================================================
1. 연출 강도 계층을 만든다
==================================================

모든 사건을 똑같이 화려하게 만들지 마.

3단계로 구분.

--------------------------------------------------
MICRO EVENT
--------------------------------------------------

작은 상태 변화.

예:

- Attack +1
- Health +1
- Cost -1
- Keyword 획득
- Gold +1
- Quest Progress +1

연출:

카드/해당 UI 요소만 반응.

화면 전체 Shake 금지.

--------------------------------------------------
MEDIUM EVENT
--------------------------------------------------

전투나 중요한 효과.

예:

- 선수 공격
- Damage 4~6
- Dodge
- Silence
- Stun
- Summon
- Revive
- Destroy
- Retire

연출:

카드 + 보드 일부가 반응.

필요하면 적당한 Screen Shake.

--------------------------------------------------
MAJOR EVENT
--------------------------------------------------

경기의 흐름이 크게 바뀌는 사건.

예:

- 7+ Damage
- Champion 큰 피해
- Quest Complete
- Champion Token 배치
- Champion lethal
- Match victory / defeat

연출:

화면 중앙 / Match Stage 전체가 반응.

큰 Screen Shake
Hit Stop
대형 Banner
강한 SFX

등 사용 가능.

하지만 가독성을 우선.

  drawMs
  techniqueRevealMs
  questBannerMs
  questRewardMs

}

각 Component에:

200
300
500

같은 숫자를 따로 하드코딩하지 마.

향후:

NORMAL
FAST

Animation Speed 옵션을 붙일 수 있게
구조만 확장 가능하도록 해.

현재는 NORMAL만 구현해도 됨.

==================================================
3. 카드 Hover / Hand Interaction
==================================================

손패 카드부터 살아 있는 느낌을 줘.

Desktop에서 카드 Hover:

- 카드가 살짝 위로 이동
- Scale 약간 증가
- 다른 카드보다 앞에 표시
- 그림/텍스트 읽기 쉬워짐

너무 크게 확대해서
다른 UI를 완전히 가리지 마.

플레이 가능한 카드:

아주 약한 활성 Glow/Highlight.

Gold 부족 등으로 사용 불가능:

채도를 약간 낮추거나
비활성 상태 표현.

하지만 카드 Artwork가 아예 안 보일 정도로 어둡게 하지 마.

==================================================
4. Card Drag 시작
==================================================

카드를 Drag하면
현재 카드가 어떤 방식으로 사용되는지 즉시 보여줘.

WRESTLER:

→ 유효한 빈 Board Slot만 Highlight

TECHNIQUE:

→ 특정 빈 Slot이 아니라
전체 Board Play Area를 유효 영역으로 Highlight

PLAYER_CHOICE가 필요한 Technique:

→ 카드 사용 후 Target Selection으로 넘어감.

유효하지 않은 Drop 영역에는
약한 invalid 표시.

==================================================
5. Wrestler Play 연출
==================================================

손에서 선수를 정상 PLAY하면:

HAND
↓
카드가 살짝 앞으로 튀어나옴
↓
Board Slot 방향으로 이동
↓
짧게 Scale Up
↓
Slot에 착지
↓
작은 Impact
↓
원래 Board Card Scale로 안정화

Animation은 빠르고 묵직하게.

카드가 천천히 날아다니는 느낌 금지.

==================================================
6. 코스트별 소환 무게감
==================================================

기존 BASE COST 기준을 Presentation에도 활용.

0~2G:
가벼운 착지

3~5G:
중간 착지

6G+:
무거운 착지

차이는:

- SFX
- 아주 약한 Scale
- 작은 Stage reaction

정도로.

6G 카드를 냈다고
화면 전체가 2초 동안 흔들리게 하지 마.

==================================================
7. 등장 효과 발동 표시
==================================================

현재 규칙:

PLAY_FROM_HAND
→ 등장 효과 O

SUMMON
→ 등장 효과 X

REVIVE
→ 등장 효과 X

이 규칙 절대 변경하지 마.

손에서 낸 카드가 등장 Effect를 가지면:

카드 착지
↓
카드 Frame / Border가 짧게 Pulse
↓
Effect Trigger 표시
↓
실제 Effect Presentation

순서.

즉:

"카드를 냈다"

와

"등장 효과가 발동했다"

를 시각적으로 구분.

==================================================
8. Effect Source Highlight
==================================================

필드 카드의 지속 효과 / Trigger가 발동했을 때
어떤 카드 때문인지 반드시 알 수 있게 해.

예:

예거 효과 발동
→ 예거 카드가 짧게 밝아짐
→ 대상 생성 선수 방향으로 Effect 연결
→ 대상 +1/+1

보드바:
→ 공격 후 보드바 Highlight
→ Gold +1 예약 Indicator

도쿵:
→ Attack buff
→ 도쿵 효과 Highlight
→ Health 추가 증가

만드릴쿤:
→ 외부 Attack Buff
→ 만드릴쿤 Highlight
→ 추가 Attack +1

특정 카드 이름을 UI에서 하드코딩하지 마.

Event의 sourceInstanceId 사용.

==================================================
9. Generic Effect Connection
==================================================

한 카드가 다른 카드에 효과를 주는 경우
짧은 시각 연결을 추가할 수 있게 해.

예:

Source Card
→ Target Card

사이에:

짧은 streak / pulse / line

등.

0.2~0.4초 정도.

항상 레이저처럼 보이게 하지 말고
Generic Magic/Effect feedback 정도.

==================================================
10. PLAYER_CHOICE 시작 연출
==================================================

대상 선택 상태가 됐다는 것을
확실히 알아볼 수 있게 해.

pendingSelection 발생:

유효 Target:

- 밝은 테두리
- 아주 약한 pulse
- Target Indicator

유효하지 않은 Card:

- 살짝 어둡게

Target Selection과
Attack Selection은 다른 Visual Language 사용.

예:

ATTACK:
공격적인 화살/빨간 계열 accent

EFFECT TARGET:
원형 selection ring / neutral effect accent

실제 색상은 기존 Theme 시스템 사용.

==================================================
11. Target 선택 피드백
==================================================

유효 Target 클릭:

Target Card가 짧게:

Scale Up
→ pulse
→ normal

하여 선택됐다는 느낌 제공.

잘못된 Target 클릭:

GameState 변경 X

짧은:

Invalid Target

피드백만.

==================================================
12. Attack Ready 상태
==================================================

현재 공격 가능한 선수는
필드를 보는 것만으로 알 수 있게 해.

아직 공격 가능:

아주 약한 Active Border / Indicator.

이미 공격함:

Active 강조 제거.

일반 새 선수:

공격 불가.

Rush:

등장 턴 공격 가능.

Haste/기습:

등장 턴 enemy WRESTLER 공격 가능.

이 상태는 반드시
Engine legalActions / CardInstance State를 기준으로 표시.

==================================================
13. 공격 Target 선택
==================================================

공격자를 선택하면:

공격 카드가 살짝 앞으로 나오거나
짧게 기울어 준비 상태 표현.

공격 가능한 Target만 강조.

TAUNT가 있다면
실제 legal target만 강조.

Champion 보호 중이면
Champion을 Target처럼 강조하지 마.

==================================================
14. 기본 공격 전체 연출
==================================================

공격은 다음 순서:

ATTACK_SELECTED
↓
짧은 WINDUP
↓
ATTACKER_LUNGE
↓
IMPACT
↓
TARGET_HIT_REACTION
↓
DAMAGE PRESENTATION
↓
COUNTER DAMAGE
↓
RETIRE / FOLLOWUP
↓
ATTACKER_RETURN

==================================================
15. Attack Windup
==================================================

공격 시작 직전
공격 카드가:

짧게 뒤로 당겨짐
또는
Scale 0.97 정도

→ 앞으로 빠르게 튀어나옴.

Windup:

약 80~150ms.

지나치게 길게 기다리지 마.

==================================================
16. Attacker Lunge
==================================================

공격 카드는 실제 Target Card 방향으로
빠르게 이동.

약 120~220ms.

중요:

destination은:

targetInstanceId의 실제 Rendered Card 위치

를 우선 사용.

stale slotIndex만 사용하지 마.

상대가 공격해도 동일.

==================================================
17. 공격 Clone 처리
==================================================

Attack Animation은 가능하면
Presentation Clone 사용.

Clone 생성 시:

원본 Card를 잠깐 visually hidden 처리하여
카드 두 장이 동시에 보이지 않게 해.

Animation 끝:

Clone cleanup
원본 restore.

React stale clone 남지 않게 처리.

==================================================
18. Impact 순간
==================================================

공격자가 Target에 닿는 순간:

- Target 아주 짧은 Scale impact
- Attacker도 아주 짧은 impact compression
- Hit SFX
- Damage tier에 맞는 Shake
- 필요한 경우 hit flash

연출.

단:

하얀 화면 Flash를 과도하게 사용하지 마.

==================================================
19. Hit Stop
==================================================

큰 피해에는 짧은 Hit Stop 추가.

Game Engine을 멈추는 것이 아니다.

Presentation Timeline만
아주 짧게 정지.

권장:

1~3 Damage:
없음

4~6:
20~40ms

7~10:
40~70ms

11+:
60~100ms

큰 공격이 "퍽" 하고 박히는 느낌을 주는 것이 목적.

==================================================
20. Screen Shake
==================================================

기존 규칙 반드시 복구/확실히 작동:

damageApplied === 0
→ 없음

1~3
→ SMALL

4~6
→ MEDIUM

7~10
→ LARGE

11+
→ VERY_LARGE

전체 Browser body가 아니라:

MATCH STAGE

만 흔들기.

==================================================
21. Screen Shake 방향
==================================================

가능하면 완전 랜덤 떨림보다
Impact 방향을 약간 반영.

Horizontal attack:

짧은 X 방향 흔들림 중심.

큰 공격:

X + Y 혼합.

너무 심하게 화면이 움직여
카드 위치를 놓치게 하면 안 됨.

==================================================
22. 같은 Effect의 다중 Damage
==================================================

광역 Damage로 4명이 동시에 맞는 경우:

화면 전체 Shake를 4번 연속 하지 마.

같은 Effect Batch에서:

가장 큰 damageApplied를 기준으로
Screen Shake 1회.

각 대상 Card에는
각자 Hit Reaction / Damage Number.

==================================================
23. 피격 카드 반동
==================================================

피해 받은 Card:

Impact 반대 방향으로
짧게 6~16px 정도 Recoil

→ 정상 위치.

큰 Damage일수록 약간 더 강함.

Board Slot 자체 위치는 절대 변경하지 않는다.

==================================================
24. Damage Number
==================================================

실제 damageApplied가 1 이상:

Target 위에:

-1
-5
-9

등 Damage Number 표시.

Animation:

Pop
→ 약간 상승
→ Fade Out.

너무 작은 글씨 금지.

==================================================
25. HP UI 반응
==================================================

피해 직후:

currentHealth 숫자:

Scale Up
→ 새 값 표시
→ 정상 크기.

예:

6
↓
3

변경을 명확하게 보여줘.

==================================================
26. Wrestler vs Wrestler 동시 전투
==================================================

KO Combat은 simultaneous damage.

Presentation도 이를 보여줘야 함.

공격 충돌 후:

Attacker Damage Number
Target Damage Number

거의 동시에 표시.

한쪽이 먼저 맞고
나중에 다른 쪽이 반격하는 것처럼
긴 순차 Animation 금지.

둘 다 0 HP라면:

둘 다 피해 표시
↓
짧은 Pause
↓
둘 다 RETIRE.

==================================================

==================================================
36. Heal
==================================================

작은 Positive pulse

2 → 4

Floating:

+2

표시.

Damage-style recoil 없음.

==================================================
37. Silence 적용
==================================================

Silence 적용 순간:

Target Card 위를
짧게 쓸어 지우는 느낌 또는
능력 효과가 꺼지는 듯한 VFX.

이후:

SILENCE Indicator 유지.

실제 effectiveKeywords에서 제거된:

TAUNT
DODGE
RUSH
HASTE

등 Indicator도 즉시 제거.

==================================================
38. Stun
==================================================

Stun 적용:

짧은 Impact
↓
작은 Stun icon 등장
↓
Card가 약간 비활성 상태로 보임.

현재 Stun Engine Rule은 변경 금지.

==================================================
39. Taunt 지속 VFX
==================================================

TAUNT:

방패형 Border / Shield Indicator.

Field를 보는 것만으로
Taunt Card라는 걸 알아야 함.

지속 Animation은 아주 약하게.

==================================================
40. Rush 지속 VFX
==================================================

Rush:

속도감 있는 Icon / line accent.

등장 턴 실제 공격 가능하면
조금 더 강하게 활성화.

공격 후에는
활성 Animation은 약해져도 됨.

==================================================
41. Haste / 기습 VFX
==================================================

Rush와 절대 같은 Visual로 만들지 마.

→ Attack 숫자만 반응.

→ strong recoil + hit stop + heavy SFX + very large shake.

→ 중앙 Banner + Reward.

→ final impact + pause + Result.

106. 작업 완료 기준
==================================================

이번 작업은:

"애니메이션 코드가 추가됨"

이 완료 기준이 아니다.

실제 한 판을 플레이했을 때:

- 카드를 냈다는 것이 보임
- 어떤 카드 효과가 발동했는지 보임
- 누구를 공격했는지 보임
- 얼마나 맞았는지 보임
- 왜 수치가 변했는지 보임
- 왜 카드가 죽었는지 보임
- 부활인지 소환인지 구분됨
- 회피인지 0피해인지 구분됨
- 주문이 무엇인지 확인 가능
- Quest 진행/완료가 보임
- Champion이 큰 피해를 받으면 무게감이 있음
- 마지막 일격을 보고 난 뒤 승패 화면이 나옴

이 모든 것이 자연스럽게 연결되어야 완료다.

최종적으로 KO Match가
단순 Card UI가 아니라
타격감과 반응성이 강한 완성도 높은 디지털 카드게임처럼
느껴지도록 구현해줘.
