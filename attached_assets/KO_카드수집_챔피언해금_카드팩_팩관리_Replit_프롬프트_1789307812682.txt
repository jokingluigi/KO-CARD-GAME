현재 KO 카드게임에
"카드 수집 / 챔피언 해금 / 카드팩 시스템 / 팩 관리자"
1차 버전을 구현해줘.

핵심 규칙:

1. 기본 지급 카드/챔피언만 계정 생성 시 사용할 수 있다.
2. 그 외 카드는 카드팩에서 획득해야 사용할 수 있다.
3. Champion(직업)도 카드팩에서 획득해야 사용할 수 있다.
4. 소유하지 않은 카드/Champion은 덱 편집에서 사용할 수 없다.
5. Token / Champion Token은 팩에서도 절대 나오지 않고 덱에도 절대 넣을 수 없다.
6. 카드팩에는 현재 PUBLISHED 상태인 콘텐츠만 등장할 수 있다.
7. 관리자에서 PackDefinition을 자유롭게 생성/관리할 수 있어야 한다.

이번 작업에서는 상점/현금결제/재화는 연결하지 마.

==================================================
1. 매우 중요한 용어 구분
==================================================

팩 확률의:

NORMAL 90%
LEGENDARY 7%
CHAMPION 3%

에서 CHAMPION은:

CardDefinition rarity = CHAMPION

을 의미하는 것이 아니다.

반드시:

ChampionDefinition
즉 플레이어가 선택하는 "챔피언/직업 해금"

을 의미한다.

팩 Reward Category를 명확히 구분해.

예:

NORMAL_CARD
LEGENDARY_CARD
CHAMPION_UNLOCK

Champion Token 카드와 절대로 혼동하지 마.

==================================================
2. 기본 확률
==================================================

새 Pack을 만들 때 기본 확률:

NORMAL_CARD = 90%
LEGENDARY_CARD = 7%
CHAMPION_UNLOCK = 3%

관리자는 Pack별로 이 값을 수정할 수 있다.

반드시 총합 100%여야 한다.

합계가 100%가 아니면
Pack을 PUBLISH하거나 저장 완료 상태로 만들 수 없게 하고
명확한 validation을 표시해.

==================================================
3. Pack 한 개의 카드 수
==================================================

Pack Admin에서 "한 팩에서 나오는 내용물 수"를 직접 설정 가능하게 해.

예: 1 / 3 / 5 / 10

필드 예:
cardsPerPack

각 슬롯마다 별도로 Reward Category를 roll한다.

예:
cardsPerPack = 5

라면 5번 각각:
90% NORMAL
7% LEGENDARY
3% CHAMPION

확률 판정을 한다.

==================================================
4. User Collection
==================================================

계정별 카드 소유 데이터를 추가해.

예:

UserCardCollection {
  userId
  cardDefinitionId
  quantity
  obtainedAt
}

Champion은 별도로 관리.

예:

UserChampionCollection {
  userId
  championDefinitionId
  owned
  obtainedAt
}

Deck 자체가 카드 소유 정보를 저장하는 구조로 만들지 마.
Collection과 Deck은 분리한다.

==================================================
5. 기본 지급 카드
==================================================

Card Admin에 [기본 지급 카드] 옵션을 추가해.

예:
isStarterGrant = true

신규 User가 만들어지면 현재 PUBLISHED 상태의 기본 지급 카드들을
그 User의 Collection에 지급해.

중복 실행되지 않도록 idempotent하게 구현해.
어떤 카드를 기본 지급할지는 카드 이름으로 하드코딩하지 마.

==================================================
6. 기본 Champion
==================================================

Champion Admin에도 [기본 지급 Champion] 옵션을 제공해.

예:
isStarterGrant = true

신규 계정은 해당 Champion만 처음부터 사용할 수 있다.
나머지 Champion은 Pack에서 획득해야 사용할 수 있다.
특정 Champion 이름을 코드에 하드코딩하지 마.

==================================================
7. 덱 편집과 Collection 연결
==================================================

기존 Deck Editor를 수정해.

이제 일반 사용자의 카드 Collection에는
"내가 실제로 소유한 카드"만 표시한다.

조건:
card.status === PUBLISHED
isToken !== true
isChampionToken !== true

즉:
PUBLISHED
+ OWNED
+ NOT TOKEN
+ NOT CHAMPION TOKEN

인 카드만 덱 편성 후보.

==================================================
8. Champion 선택도 소유 기반
==================================================

Deck Editor의 Champion 선택 화면도
현재 User가 소유한 Champion만 표시해.

조건:
Champion PUBLISHED
+ User owns Champion

소유하지 않은 Champion은 선택할 수 없다.

==================================================
9. Token 절대 금지
==================================================

CardDefinition:
isToken === true
또는
isChampionToken === true

이면:
- Pack 후보 금지
- Collection용 일반 뽑기 금지
- Deck Editor 표시 금지
- Deck에 직접 추가 금지

서버 Deck validation에서도 다시 검사.
클라이언트 요청을 조작해 Token ID를 Deck에 넣으려 해도 서버에서 거부해.

Token은 게임 효과로만 생성/소환한다.

==================================================
10. Pack에 등장할 수 있는 일반 카드
==================================================

NORMAL_CARD 후보:

- CardDefinition
- status === PUBLISHED
- rarity === NORMAL
- isToken !== true
- isChampionToken !== true
- 해당 Pack에서 활성 후보로 지정됨

==================================================
11. Legendary 후보
==================================================

LEGENDARY_CARD 후보:

- CardDefinition
- status === PUBLISHED
- rarity === LEGENDARY
- isToken !== true
- isChampionToken !== true
- 해당 Pack에서 활성 후보로 지정됨

==================================================
12. Champion 후보
==================================================

CHAMPION_UNLOCK 후보는 CardDefinition이 아니다.

ChampionDefinition을 사용한다.

조건:
- Champion status === PUBLISHED
- 해당 Pack에서 활성 후보로 지정됨

Champion에 연결된 Champion Token CardDefinition은 이 Pool에 포함시키지 않는다.

팩에서 Champion이 나오면
해당 ChampionDefinition을 UserChampionCollection에 해금한다.

==================================================
13. 공개되지 않은 콘텐츠
==================================================

Pack 설정에 과거에 포함되어 있더라도 현재:
DRAFT
DISABLED
삭제됨
미공개

상태면 Pack opening 후보에서 제외한다.

실제 개봉하는 서버 시점에 다시 PUBLISHED 여부를 검증해.

20. Pack 카드 Pool 관리
==================================================

Pack Admin에서 어떤 카드가 해당 Pack에서 나올지 직접 선택 가능하게 해.

NORMAL Pool:
현재 PUBLISHED NORMAL 카드 목록

LEGENDARY Pool:
현재 PUBLISHED LEGENDARY 카드 목록

CHAMPION Pool:
현재 PUBLISHED ChampionDefinition 목록

각각 검색 / 체크박스 / 전체 선택/해제 제공.

==================================================
21. Token은 Admin Pack 목록에서도 숨기기
==================================================

Pack content selector에서도:
isToken = true
isChampionToken = true

CardDefinition은 후보 목록에 표시하지 마.

Backend validation도 동일하게 적용.

==================================================
22. Pack validation
==================================================

Pack PUBLISH 전에 확인:

- 이름 존재
- cardsPerPack >= 1
- 확률 합계 100
- normalRate > 0이면 NORMAL Pool 최소 1개
- legendaryRate > 0이면 LEGENDARY Pool 최소 1개
- championRate > 0이면 Champion Pool 최소 1개
- Token 없음
- Champion Token 없음

조건 실패 시 Publish 금지.

==================================================
23. 확률이 있는 Pool이 비어버린 경우
==================================================

예:
legendaryRate = 7%
하지만 현재 eligible Legendary = 0

이면 임의로 NORMAL로 확률을 넘기지 마.

Pack을 invalid/unavailable 상태로 처리하고 Admin에게 경고해.
조용히 확률을 재정규화하지 마.

==================================================
24. Pack Opening RNG
==================================================

팩 개봉 결과는 서버에서 결정해야 한다.

클라이언트 Math.random() 금지.

Game Engine deterministic RNG와도 별개의 시스템이다.
서버의 안전한 RNG를 사용해.

가능하면 Node crypto 등 cryptographically secure RNG를 사용.

==================================================
25. Pack Opening 기본 흐름
==================================================

실제 개봉 시 서버에서:

1. PackDefinition 조회
2. PUBLISHED 상태 확인
3. Pool eligibility 다시 확인
4. cardsPerPack 횟수만큼 roll
5. Reward Category 결정
6. 해당 Pool에서 무작위 Definition 선택
7. User Collection에 지급
8. 결과를 클라이언트에 반환

순서.
