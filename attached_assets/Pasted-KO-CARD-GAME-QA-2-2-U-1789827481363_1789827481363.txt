KO CARD GAME의 실제 브라우저 QA에서 확인된 아래 2가지 문제를 수정해줘.

중요:
- 이번 작업에서는 아래 2개 문제만 수정해.
- 카드 아트 / 이미지 / 이미지 URL / 에셋 업로드는 절대 건드리지 마.
- 게임 규칙을 임의로 바꾸지 마.
- DB 스키마를 변경하지 마.
- 기존 카드/챔피언/덱/유저 데이터를 삭제하거나 초기화하지 마.
- 기존 공용 컴포넌트와 기존 validation 로직이 있으면 재사용해.
- 단순히 UI 문구만 숨기지 말고 실제 원인을 찾아서 수정해.
- 작업 완료 후 반드시 typecheck/build 및 실제 브라우저 테스트까지 실행해.
- 최종 보고에서 수정한 파일, 원인, 테스트 결과를 설명해.

==================================================
1. 덱 편집 실시간 검증 오류 수정
==================================================

[현재 문제]

Deck Editor에서 과거 저장 시점의 validation error가
현재 편집 상태가 정상으로 바뀌어도 계속 남아 있다.

실제 QA에서 다음처럼 재현됨:

- Champion이 없는 빈 덱을 저장
- 이후 Champion 선택
- 카드를 20장 이상 추가
- 현재 화면상 정상 덱인데도

"사용할 수 없는 Champion이 포함되어 있습니다."
"카드가 20장보다 적습니다."

같은 이전 오류가 계속 남음.

30/30장까지 채워도
"카드가 20장보다 적습니다."
가 저장 전까지 남는 경우가 확인됨.

저장을 다시 하면 오류가 사라짐.

[목표]

Deck Editor의 validation 메시지는
"마지막 저장 상태"가 아니라
"현재 사용자가 편집 중인 draft 상태"를 기준으로 즉시 갱신되어야 한다.

[수정 요구사항]

1. 현재 Deck Editor의 상태 흐름을 조사해:
   - selected champion
   - deck card list
   - card count
   - rarity limits
   - saved deck validation result
   - server validationErrors
   가 어떻게 연결되어 있는지 확인해.

2. 카드 추가 / 카드 제거 / Champion 변경이 발생하면
   현재 draft를 기준으로 validation을 즉시 다시 계산해.

3. 이전 저장 API 응답에서 받은 validationErrors가
   현재 편집 상태의 오류처럼 계속 표시되지 않게 해.

4. 현재 draft가 정상화되는 순간
   오류 메시지도 저장 없이 즉시 사라져야 한다.

5. 현재 draft가 다시 잘못된 상태가 되면
   오류가 즉시 다시 나타나야 한다.

6. 기존 덱 규칙은 변경하지 마.

현재 규칙 예:
- Champion 정확히 1명
- 카드 20~30장
- 동일 카드 제한
- Legendary 총 3장 제한
- 불완전 덱은 INVALID 초안으로 저장 가능

7. 가능하면 validation 규칙이 여러 곳에 중복되어 있다면
   공통 함수로 정리하되,
   대규모 리팩터링은 하지 마.

8. 서버 validation과 UI validation이 서로 다른 규칙을 사용하지 않는지 확인해.

[반드시 테스트]

아래 상태를 실제 브라우저에서 확인:

- Champion 없음 + 0장
- Champion 있음 + 19장
- Champion 있음 + 20장
- Champion 있음 + 30장
- 30장에서 카드 제거 → 즉시 INVALID
- 다시 추가 → 저장하지 않아도 즉시 정상 상태
- Legendary 3장
- Legendary 4장 시도
- Champion 변경 후 validation 즉시 갱신
- 저장 후 새로고침해도 상태 정상

특히 아래 재현을 반드시 검증:

A.
빈 덱 저장
→ Champion 선택
→ 20장 추가
→ 저장 전에도
"카드가 20장보다 적습니다"
오류가 사라져야 함.

B.
19장 INVALID 저장
→ 카드 1장 추가
→ 20장
→ 저장 전에도 오류가 사라져야 함.

==================================================
2. Collection 로딩 중 잘못된 빈 상태 표시 수정
==================================================

[현재 문제]

Collection 페이지 최초 진입 시
데이터를 아직 불러오는 중인데 동시에:

"컬렉션을 불러오는 중..."

과

"아직 보유한 카드가 없습니다"

가 함께 표시되는 순간이 있음.

또 로딩 중 카드 수량이 0처럼 보여서
사용자 입장에서는
데이터가 사라졌거나 계정이 초기화된 것처럼 느낄 수 있음.

실제 데이터 로딩 완료 후에는 정상적으로
카드와 Champion이 나타남.

[목표]

Collection 화면 상태를 명확하게 분리:

- loading
- success + data 있음
- success + data 없음
- error

이 네 상태가 서로 동시에 표시되지 않게 해.

[수정 요구사항]

1. Collection의 데이터 요청 상태를 조사해.

2. loading 중에는 절대
"아직 보유한 카드가 없습니다"
같은 empty state를 렌더링하지 마.

3. empty state는
데이터 요청이 성공했고
실제로 보유 카드가 0개일 때만 표시해.

4. loading 중에는:
   - loading indicator
   또는
   - 기존 디자인과 맞는 skeleton
   만 표시해.

5. 로딩 중 카드 수량 0을
실제 데이터 0처럼 보여주지 마.

예:
나쁜 예:
카드 0
Champion 0
"아직 보유한 카드가 없습니다"
+
"불러오는 중..."

좋은 예:
"컬렉션을 불러오는 중..."
또는 skeleton

데이터 로딩 완료 후:
보유 카드 43
Champion 4
실제 목록 표시

6. API 에러가 발생했을 경우에는
empty state와 구분된 명확한 error state를 보여줘.

예:
"컬렉션을 불러오지 못했습니다. 다시 시도해주세요."

7. 기존 Collection 기능:
- 필터
- 검색
- 제작/분해
- 카드 상세
- Champion 상세
는 깨뜨리지 마.

[반드시 테스트]

실제 브라우저에서:

메인
→ Collection 최초 진입

확인:
- loading 중 empty message가 안 뜨는지
- 데이터 로딩 후 정상 목록으로 전환되는지
- 검색 결과 없음 상태와 "보유 카드 없음" 상태가 구분되는지
- 필터 결과 0건과 전체 Collection empty 상태가 구분되는지
