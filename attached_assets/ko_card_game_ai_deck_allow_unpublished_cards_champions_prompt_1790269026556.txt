KO CARD GAME — AI DECK BUILDER: ALLOW UNPUBLISHED CARDS & CHAMPIONS

목표:
AI 덱을 만들거나 수정할 때는
일반 유저에게 아직 공개되지 않은 카드와 Champion도 선택해서 넣을 수 있게 한다.

중요:
이 기능은 "AI Deck / AI Match 테스트용" 범위에만 적용한다.

일반 유저의:
- 덱 편집
- 컬렉션
- 제작
- 상점
- 카드팩
- 온라인 PvP 덱 검증

에는 미공개 콘텐츠가 노출되거나 사용 가능해지면 안 된다.

==================================================
1. 먼저 현재 status 모델 확인
==================================================

현재 CardDefinition / ChampionDefinition이 사용하는 status 값을 조사한다.

예:
- PUBLISHED
- DRAFT
- DISABLED

"미공개"가 현재 프로젝트에서 어떤 status를 뜻하는지 실제 코드/DB를 확인한다.

기본 기대:
- PUBLISHED → AI Deck에서 사용 가능
- DRAFT / unpublished → AI Deck에서 사용 가능
- DISABLED → 기본적으로 제외

단, 현재 프로젝트에서 DISABLED가 단순 "비공개 테스트용" 의미라면
그 의미를 확인하고 최종 보고에 명시한다.

절대 status 의미를 추측으로 바꾸지 말 것.

==================================================
2. AI Deck Builder 전용 콘텐츠 풀
==================================================

일반 사용자용 카드 풀과
AI Deck Builder용 카드 풀을 분리한다.

예:

getPublicDeckBuildingPool()
→ PUBLISHED only

getAiDeckBuildingPool()
→ PUBLISHED + allowed unpublished definitions

카드/Champion 이름을 hardcode하지 말 것.

AI Deck Admin 화면에서는:
- 공개 카드
- 미공개 카드
- 공개 Champion
- 미공개 Champion

을 검색/필터/선택 가능.

==================================================
3. UI 표시
==================================================

AI Deck Builder에서 미공개 콘텐츠는
일반 공개 카드와 구분되게 표시.

예:
[DRAFT]
[UNPUBLISHED]

badge.

하지만 사용 자체는 가능.

필터:
- 전체
- 공개
- 미공개

정도 추가 가능.

기존 검색/정렬/태그/비용 필터가 있으면 그대로 작동.

==================================================
4. AI Deck 저장 검증
==================================================

AI Deck 저장 validation이
PUBLISHED-only를 강제하고 있다면
AI Deck context에서만 완화한다.

중요:
공통 deck validator 전체를 무조건 느슨하게 만들지 말 것.

예:

validateDeck(deck, context)

context:
PLAYER_DECK
AI_DECK

PLAYER_DECK:
기존 공개 규칙 그대로.

AI_DECK:
미공개 definition도 허용.

==================================================
5. 일반 덱 규칙 유지
==================================================

AI Deck이더라도 기본 deck structure는 유지:

- 정확히 25 cards
- Champion 1개 별도
- Legendary 최대 5장
- 같은 Legendary CardDefinition 중복 금지
- 기존 normal duplicate rule 유지
- Token 직접 추가 금지
- Champion Token 직접 deck slot에 넣기 금지

단 AI 테스트 시스템에 이미 별도의 공식 rule override가 있다면
현재 canonical rule을 우선한다.

이번 요청은 "미공개 콘텐츠 허용"이지
덱 규칙 전체 해제가 아니다.

==================================================
6. AI Match Runtime도 미공개 definition을 실제로 로드
==================================================

가장 중요.

AI Deck Builder에서 저장만 성공하고
AI Match 시작 시:

- definition not found
- unpublished filtered out
- Champion missing
- cardPool missing

으로 실패하면 안 된다.

AI Match를 시작할 때
선택된 AI Deck이 참조하는 미공개 CardDefinition / ChampionDefinition을
실제 authoritative match state에 포함시켜야 한다.

==================================================
7. cardPool 처리
==================================================

현재 match cardPool이
"PUBLISHED definitions only"
로 구성되어 있다면
일반적으로 그 정책은 유지한다.

대신 AI Match context에서는:

public PUBLISHED pool
+
현재 AI Deck에서 직접 참조하는 allowed unpublished definitions
+
그 카드 효과가 명시적으로 참조하는 필수 definition

을 안전하게 포함할 수 있도록 한다.

예:
AI Deck에 DRAFT 카드 A가 있음
→ A definition은 AI Match cardPool에 존재해야 함.

A가 effect에서 특정 Token/CardDefinition B를 생성한다면
→ B도 runtime resolution에 필요하면 포함.

단:
AI Match 하나 때문에
모든 unpublished definition을 일반 클라이언트/public API에 무조건 노출하지 말 것.

==================================================
8. Champion도 동일
==================================================

AI Deck Champion이 미공개라면:

- AI Deck 저장 가능
- AI Match 시작 가능
- Champion maxHealth 정상
- Champion Ability 정상
- Quest 정상
- Quest Reward 정상
- Upgraded Ability 정상
- linked Champion Token 정상

이어야 한다.

ChampionDefinition status 때문에
런타임에서 ability/quest/token relation을 못 찾으면 FAIL.

==================================================
9. Champion Token / 참조 definition
==================================================

미공개 Champion이 linked Champion Token을 가지고 있다면
그 Token도 runtime dependency로 resolve 가능해야 한다.

하지만:
Champion Token을 AI Deck 카드 25장에 직접 넣는 것은 금지.

dependency로만 포함.

14. DISABLED 처리
==================================================

DISABLED 콘텐츠는 특별히 조심.

기본 정책:
DISABLED는 AI Deck Builder에서도 제외.

이유:
DRAFT = 아직 공개 전 테스트 콘텐츠
DISABLED = 의도적으로 사용 중지된 콘텐츠일 수 있음.

하지만 현재 코드/DB에서 status 의미가 다르다면
실제 schema/usage를 조사해서 그 의미를 따르고
최종 보고에 다음을 명시:

AI Deck allowed statuses:
...

AI Deck blocked statuses:
...

==================================================
15. 삭제/존재하지 않는 definition
==================================================

기존 AI Deck이
삭제되었거나 찾을 수 없는 definition을 참조하면:

- 앱 crash 금지
- 자동으로 다른 카드로 교체 금지
- silently remove 금지

AI Deck을 INVALID로 표시하고
누락 definition을 관리자에게 명확히 보여준다.

==================================================
16. Status 변경
==================================================

AI Deck에 DRAFT 카드가 들어간 상태에서:

DRAFT → PUBLISHED
→ 계속 정상

PUBLISHED → DRAFT
→ AI Deck에서는 계속 사용 가능

DRAFT/PUBLISHED → blocked status
→ AI Deck validity 재평가

단 기존 AI Deck row를 자동 삭제하지 말 것.

23. 완료 조건
==================================================

1. AI Deck Builder에서 미공개(DRAFT) 카드 선택 가능.
2. AI Deck Builder에서 미공개(DRAFT) Champion 선택 가능.
3. 해당 AI Deck 저장 가능.
4. AI Match에서 미공개 카드/Champion이 실제 정상 실행.
5. 필요한 linked/token/effect dependency도 정상 resolve.
6. 일반 사용자 Deck Editor에는 미공개 콘텐츠 노출 없음.
7. 일반 player deck API는 미공개 콘텐츠를 계속 거부.
8. Online PvP 일반 덱 규칙은 변하지 않음.
9. DISABLED status는 실제 의미 확인 후 안전하게 처리.
10. 카드/Champion 이름 hardcode 없음.
11. Production DB mutation 없음.
12. tests/build/typecheck/diff 결과 보고.

핵심:
"미공개 콘텐츠를 전체 게임에 공개"하는 것이 아니다.
오직 AI Deck 제작/AI Match 테스트 환경에서만
미공개 CardDefinition과 ChampionDefinition을 사용할 수 있도록
public player content pool과 AI test content pool을 명확하게 분리하라.
