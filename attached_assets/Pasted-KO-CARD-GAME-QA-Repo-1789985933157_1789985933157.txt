# 2. 하스이 — 잔상 소환 실패

## 현재 문제

실제 전투에서 하스이의 설명에는 `잔상 소환`이 존재하지만,
조건을 만족하고 필드에도 빈 슬롯이 있었는데 잔상이 생성되지 않았습니다.

이 항목은 한 번 더 재현해서 확정해주세요.

애니메이션 중간 상태만 보고 판단하지 말고
최종 GameState에 Token/잔상 instance가 실제 존재하는지 확인하세요.

## 조사할 것

최소 범위에서 다음을 확인하세요.

* 하스이의 현재 DB/API definition
* structured effect
* trigger
* 생성해야 하는 잔상의 CardDefinition/TokenDefinition
* effect registry 연결
* 해당 trigger에서 Event가 생성되는지
* SUMMON/deploy Action이 만들어지는지
* 빈 board slot 판정
* 실제 GameState에 entity가 추가되는지
* UI에서만 안 보이는 문제인지 실제 GameState 생성 실패인지

설명 문자열만 보고 효과를 새로 만들지 마세요.

이미 정의된 structured effect가 있다면 그것을 정상적으로 처리하도록 고치세요.

## 기대 결과

조건 충족 + 빈 슬롯 존재 시:

```text
trigger 발생
→ 잔상 생성 Event
→ 빈 board slot에 잔상 SUMMON/deploy
→ 최종 GameState와 UI에 실제 존재
```

# 3. 판도라 — Champion 능력 RETIRE가 Quest에 반영되지 않음

## 현재 문제

AI 판도라가 Champion 능력으로 용병을 RETIRE시켰지만
Quest가 계속 `0/5`로 남았습니다.

이 항목도 실제 Action → Event → GameState 기준으로 재확인하세요.

## 조사할 것

특히 다음을 비교하세요.

* 일반 전투 damage/combat에 의한 RETIRE
* Champion ability에 의한 RETIRE

두 경로 중 Champion ability 쪽에서 Quest가 구독하는 공통 RETIRE Event가 누락되는지 확인하세요.

또한:

* RETIRE event payload
* source
* owner
* acting player
* affected player
* Quest progress event
* AI와 Player가 같은 규칙을 사용하는지

를 확인하세요.

## 수정 원칙

판도라 이름을 보고 Quest를 직접 +1하는 코드는 만들지 마세요.

Champion ability에 의한 정상 RETIRE도
기존 generic RETIRE / Quest event 흐름으로 들어가도록 수정하세요.

Player와 AI가 같은 엔진 규칙을 사용해야 합니다.

## 기대 결과

판도라 Quest 조건을 만족하는 RETIRE 1회 발생 시:

```text
0/5
→ 1/5
```

AI가 능력을 사용한 경우에도 동일해야 합니다.

# 4. 예거 Quest 요구량 8 → 공식 7

## 확정 버그

실제 전투에서:

```text
시작: 0/8
1회 생성: 1/8
...
7회 생성: 7/8
```

이므로 공식 요구량과 불일치가 확정되었습니다.

## 공식 규칙

예거 Quest 요구량은 **7회**입니다.

정상:

```text
0/7
1/7
...
6/7
7/7 → Quest 완료
```

## 조사할 것

`8`이 어디서 나오는지 최소 범위로 확인하세요.

* Champion definition의 `quest_progress_required`
* API 변환
* frontend/game definition 변환
* runtime Quest instance
* UI progress denominator
* completion 조건
* legacy hardcoded fallback

UI만 8이고 실제 completion이 7인지,
실제 엔진도 8을 요구하는지 둘 다 확인하세요.

## 수정 원칙

공식 definition 값 `7`을 공통 Source of Truth로 사용하게 하세요.

예거 이름을 엔진에서 비교해서 7로 만드는 방식은 금지합니다.

# 5. 예거 기습 용병 비용 표시 — 1G가 아니라 0G

## 현재 문제

예거 능력:

* 능력 비용 1 Gold → 정상
* 생성되는 1/1 기습 용병 → 정상 생성
* 그러나 생성된 기습 용병 카드가 `1G`로 표시됨

## 공식 규칙

예거가 생성하는 기습 용병의 **카드 비용은 0 Gold**입니다.

예거 Champion 능력 자체 비용 1 Gold와 혼동하지 마세요.

## 조사할 것

* 기습 용병 CardDefinition cost
* 생성 시 instance에 cost override가 붙는지
* Token definition
* UI 표시가 definition cost인지 instance cost인지
* 실제 플레이 시 비용과 표시 비용이 같은지

## 기대 결과

```text
예거 능력 사용: -1 Gold
생성된 기습 용병: 0G
```

등장 턴 공격 기능은 현재 정상이며 유지해야 합니다.

Production 원본 데이터 자체의 수정이 필요하다면 Agent가 DB를 직접 변경하지 말고,
최종 보고에 Admin에서 바꿔야 할 필드와 값만 적으세요.

# 6. 오심정정 — 대상 선택 없이 비용만 소비

## 확정된 실제 증상

* 내 묘지에 선수 카드가 존재
* 오심정정 사용
* PLAYER_CHOICE/대상 선택 UI가 나타나지 않음
* Gold 비용은 소비됨
* 오심정정은 묘지로 이동
* 묘지의 선수는 손패로 복귀하지 않음

## 기대되는 공식 흐름

오심정정이 묘지의 선수를 선택해야 하는 효과라면:

```text
사용 요청
→ valid target 존재 확인
→ PLAYER_CHOICE
→ 묘지 선수 선택
→ server validation
→ 선택한 선수 손패 복귀
→ 오심정정 처리 완료 및 묘지 이동
```

Target 선택 없이 비용만 소비되고 효과가 사라져서는 안 됩니다.

## 조사할 것

* Technique definition
* target requirement
* PLAYER_CHOICE 생성 여부
* graveyard target filter
* effect registry
* server-side target validation
* Action 비용 지불 timing
* resolve 후 graveyard 이동 timing

## 수정 원칙

`오심정정` 이름을 엔진에 직접 하드코딩하지 마세요.

기존 target-required TECHNIQUE의 공통 처리 흐름이 깨진 것이라면
공통 원인을 최소 수정으로 해결하세요.

# 7. 주문 / TECHNIQUE 대부분이 작동하지 않음

## 현재 문제

QA에서 주문 계열 카드 상당수가 설명대로 작동하지 않습니다.

KO CARD GAME 공식 용어상 TECHNIQUE 규칙을 기준으로 조사하세요.

## 공식 TECHNIQUE 규칙

* TECHNIQUE는 board slot을 사용하지 않음
* 필드가 Full이어도 사용 가능
* 사용 후 묘지 이동
* Target 필요 시 `PLAYER_CHOICE`
* Invalid action 때문에 exception/reload/GameState reset 발생 금지

## 작업 방식

모든 주문 이름을 하나씩 하드코딩하지 마세요.

먼저 TECHNIQUE 공통 pipeline을 확인하세요.

우선 대표적으로:

1. target 없는 TECHNIQUE
2. 아군 target TECHNIQUE
3. 적 target TECHNIQUE
4. 묘지 target TECHNIQUE

를 각각 하나씩 선택해 실제 실행 흐름을 확인하세요.

오심정정에서 발견된 문제가 공통 PLAYER_CHOICE / resolve 문제라면
공통 원인을 고친 후 PUBLISHED TECHNIQUE들을 필요한 범위에서 다시 검증하세요.

## 확인 항목

각 Technique에서:

```text
사용 가능 조건
→ 비용
→ Target requirement
→ PLAYER_CHOICE
→ valid target
→ Event
→ effect resolve
→ GameState
→ 묘지 이동
```

을 확인하세요.

단순히 카드 텍스트가 존재한다는 이유로 PASS 처리하지 마세요.

# 8. Champion Token 배치 fallback 구현

## 공식 규칙

Champion Token을 deploy해야 하는데
필드가 가득 찬 경우 Token이 사라지면 안 됩니다.

공식 우선순위:

```text
1. 필드에 빈 슬롯 있음
→ 필드에 Champion Token deploy

2. 필드 Full
+ 손패에 공간 있음
→ Champion Token을 손패에 넣음

3. 필드 Full
+ 손패도 Full
→ Champion Token을 Deck 맨 위에 넣음
```

즉:

```text
FIELD
→ HAND
→ DECK TOP
```

입니다.

## 중요

이 규칙은 특정 Champion 이름 전용이 아닙니다.

Champion Token deploy의 **generic fallback 규칙**으로 구현하세요.

Champion Token의 기존 공식 규칙도 유지하세요.

* 원본 Champion HP를 Token HP에 합산 금지
* Token active 중 원본 Champion 보호
* Token RETIRE ≠ 즉시 패배
* SILENCE 면역
* DESTROY 면역
* REMOVE_FROM_GAME 면역
* 일반 damage/combat으로는 정상 RETIRE 가능

## 테스트

세 경우를 각각 테스트하세요.

### Case A

필드에 빈 슬롯 있음
→ 필드 deploy

### Case B

필드 Full + 손패 공간 있음
→ 손패 추가

### Case C

필드 Full + 손패 Full
→ Deck top 추가

Case C 이후 정상 Draw 시 해당 Token이 다음 Draw 대상으로 나오는지도 확인하세요.

# 9. Deck Editor — 보유 수량보다 많이 넣을 수 있음

## 현재 문제

Player Deck Editor에서 실제 보유 수량보다 많은 카드를 덱에 추가할 수 있습니다.

예:

```text
보유량 1
→ 덱에는 2장 이상 추가 가능
```

## 공식 규칙

유저가 Deck에 넣을 수 있는 수량은:

```text
실제 보유 수량
AND
카드 copy-limit 규칙
```

둘 다 만족해야 합니다.

개념적으로:

```text
허용량 = min(보유 수량, 규칙상 최대 수량)
```

## 현재 Deck 공식 규칙

* 카드 정확히 25장
* Champion 별도로 정확히 1명
* Legendary 전체 최대 5장
* 동일 Legendary CardDefinition 중복 금지
* Normal은 기존 중복 규칙 유지
* Token 직접 편성 금지
* Legacy Deck 자동 삭제/자동 자르기 금지

## 수정 범위

Frontend에서 `+` 버튼만 막고 끝내지 마세요.

가능하면 동일 규칙을:

* Deck Editor UI
* Deck save/backend validation

양쪽에서 검증하세요.

Client 조작으로 보유량 초과 Deck이 저장되면 안 됩니다.

Legacy Deck은 자동 삭제하거나 자동 수정하지 말고 INVALID/수정 필요로 표시하세요.

# 10. AI Deck — Normal 카드를 1장씩밖에 못 넣음

## 현재 문제

AI Deck 편집에서는 Normal 카드도 같은 CardDefinition을 1장밖에 넣지 못합니다.

## 기대 규칙

AI Deck도 기본적으로 Player Deck과 동일한 카드 copy-limit 규칙을 사용해야 합니다.

Normal은 **기존 Normal 중복 규칙**을 사용하세요.

Legendary의:

* 동일 Legendary 중복 금지
* 전체 Legendary 최대 5

같은 정상 제한까지 풀어버리면 안 됩니다.

## 조사할 것

Player deck validation과 AI deck validation이 따로 구현되어
AI 쪽에서 모든 카드에 `maxCopies = 1` 같은 fallback을 적용하는지 확인하세요.

가능하면 기존 공통 Deck validation을 재사용하세요.

AI 전용으로 정상 규칙을 복제해서 또 다른 중복 로직을 만들지 마세요.

전투 관련 문제는 코드만 보고 PASS하지 마세요.

Action

# 19. 구체적인 완료 테스트

최종적으로 최소 다음 결과를 확인하세요.

### 하스이

* 조건 충족
* 빈 슬롯 존재
* 잔상 실제 GameState 생성
* UI 표시

### 판도라

* Champion 능력으로 조건에 맞는 RETIRE 발생
* Quest `0/5 → 1/5`
* AI/Player 규칙 동일

### 예거

* 경기 시작 `0/7`
* 1회 생성 `1/7`
* 7회 생성 `7/7`
* 7회에서 Quest 완료
* 능력 비용 1G 유지
* 생성된 기습 용병 0G
* 등장 턴 공격 유지

### 오심정정

* 묘지에 정상 target 존재
* 사용
* PLAYER_CHOICE 표시
* 대상 선택
* 대상 손패 복귀
* 주문 정상 묘지 이동
* 비용이 효과 없이 증발하지 않음

### TECHNIQUE

* target 없음
* 아군 target
* 적 target
* 묘지 target

대표 카드 각각 실제 resolve 확인

### Champion Token

* FIELD
* HAND fallback
* DECK TOP fallback

세 경우 모두 확인

### Player Deck

* 보유 1장인 카드를 2장 넣을 수 없음
* 정상 copy-limit 유지
* Token 직접 편성 불가
* Legendary 규칙 유지
* invalid Legacy Deck 자동 삭제 없음

### AI Deck

* Normal이 잘못 1장으로 제한되지 않음
* Legendary 제한은 유지

### Deck Editor

* 실제 보유 수량 표시

### Quick Match

* 메인으로 복귀 가능
* 상대 찾기 버튼 정상
* 실제 matchmaking request까지 진행

### Friendly Match

* Room 생성
* Room code/참가 정보 표시
